# Phase 4 桥接练习：证据问答＋工单草稿

这是承接 [L38](../../lessons/0043-L38-phase3-capstone.html) 的非编号离线小项目。场景是根据虚构的知识库回答支持问题，或在调用方明确要求时生成一份待人工确认的工单草稿。仅用 Python 标准库，不安装依赖（建议 Python 3.11+）。

## 运行

从仓库根进入本目录：

```bash
cd code/phase4-prompt-context
python main.py
python -m unittest discover -s tests -v
```

在同一目录也可导入 `run`（`fixture_adapter` 仅用于本地测试）：

```python
from main import run

result = run("导出文件保留多久？", version="v2", intent="draft")
```

## 看什么

- **上下文选择**：先用固定问题表定位主题，再按优先级挑选完整片段。`KB-01` 是导出保留期的主证据，`KB-02` 是补充说明，无关的 `KB-03` 不进入该请求。找不到相关证据时返回 `needs_evidence`，请补充来源或明确问题，不猜测，也不调用适配器。
- **可核算预算**：以 UTF-8 字节数计量紧凑 JSON。输入含提示、问题、证据及 JSON 开销，上限 640 字节；原始适配器响应上限 320 字节。调用方只能传批准范围内的正整数上限（可以收紧，不能放宽）。证据按顺序加入，空间不足时不截断、不跳过首条；放不下首条则不调用适配器。每次最多调用一次。响应超限仍计入 `usage`，但不采纳；调用失败时输出字节数未知（`null`），未调用则用量均为 0。
- **版本对照**：`main.py` 保存 `v1` 和 `v2` 两个提示快照，结果记录 `prompt_version`。运行演示的前两行使用同一个问题、证据和预算：当前 `v1` / `v2` 分别用 301 / 387 输入字节，输出均为 177 字节，引用相同。这个对照验证提示确实进入了请求，并量出改动的开销；不是模型质量 A/B 测试。
- **结构校验和终态**：仅 `completed` 且通过校验的响应可以生成 `answered` 或 `drafted`。每条引用的 ID 和原文必须同时匹配本次所选证据；只存在于知识库还不够。应用用已验证的原文组装答案和草稿，不使用适配器提供的自由文本。拒答、未完成、无效响应和超限都不会返回部分答案或草稿。
- **起草不是授权**：`intent="draft"` 匹配纯本地 `ticket-draft` Skill 选择，只返回内存中的标题、正文和引用 ID。默认问答不匹配；`send` 意图被拒绝。没有提交接口，不写文件、不写库、不联网，也不读取密钥或执行证据内容。命令行示例只打印结果。`adapter=` 仅用于注入可信的本地测试替身，并不是隔离任意回调的沙箱。

## 证据与限制

现有 11 个 `unittest` 用例验证引用绑定、缺证据弃权、预算边界、版本对照、终态以及草稿路径未访问所监测的 I/O 边界。Fixture 只回显本次传入的摘录，并不理解提示。通过测试不能证明真实模型的回答质量、检索召回、抗提示注入能力、Token 用量、费用或延迟；字节预算也不是供应商配额。

## 可修改练习

给 `QUESTIONS` 和 `SOURCES` 增加一个合成主题及相应来源，再在 `tests/test_main.py` 加一条应命中的问答和一条措辞相近却缺证据的问答。把同一问题的 `input_limit` 收紧到仅能容纳主证据，检查 `selected_ids` 与引用随之变化，且默认问答仍不会生成草稿。
