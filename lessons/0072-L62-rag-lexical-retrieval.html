第七阶段 · 数据基础与 RAG45分钟

先做授权词法检索

先数哪些片段可读，再数哪些词命中

为什么先做词法基线？

从 L61 的可定位分块接过一批证据：文档编号、版本和段落定位已经固定，但有引用键不等于有阅读权限。两位客服问的是同一句「导出文件保留多久，过期怎么办？」一位可以看到保留条款和操作指引，另一位只能看到保留条款。这不是两个检索器表现不一致，而是两份合法视图本来就不同。本课先用能手算的词法基线分开检验可见性、命中、名次和来源。这里没有生成模型；练习交付的是可引用原文，不能把有结果自动记作答对整道题。

学习目标

  • 沿着授权池、令牌交集、稳定排序与引用回查解释一次检索。
  • 区分授权排除、词法零命中、预算截掉和证据不支持问题，并为精确匹配写反例。

1. 权限决定候选，词项只决定命中

从一次可信上下文开始：宿主已经认定请求属于 support 租户、操作者是 mei。实验把这两个标识作为参数注入，既不从问题里提取用户名，也不把夹具当成身份认证。db.authorized(tenant, user) 以同一租户的文档授权记录选择当前片段，得到这次调用唯一的排序输入。db.search 先取得这份授权池，再交给纯函数 rank；后者没有租户与用户字段，自己无法补查许可。写独立的候选排序实验时也要把授权池作为参数，不要把全库片段交给它再删几行。

如果另一租户也使用 EXPORT-POLICY v1 §1，同一个三元组可能指向另一段正文。检索先确定租户，引用回查还要带同一租户、当前用户和完整键。对找不到或不可读的键，实验的 db.source 都返回 None；业务上不把这两种状态的内部差异回显为证据。先排全库前两名再过滤，即使最终列表里只剩合法片段，也可能把原本排名靠前的授权条款挤掉；在同一授权池里排前两名与这条错误流程不等价。

通过授权门后才开始匹配。夹具预先给每段写好词项，查询也显式提交 Query(terms)，不是用空格拆中文，不暗中做同义改写。评分等于两个词项集合的交集大小：顺序无关，重复写两次「导出」不加倍，得零分就没有命中。评分高者在前，同分比较 chunk.key，最后切到 k 条。k 是上限，不是承诺填满；k=0 返回空。词也可能来自人工标签而非正文原样，如「有效期」可以命中写作「保留」的条款；最终引用仍必须取正文，不能把标签说成原文。

2. 同问同租户，逐行验算

为这道双问提供词项 ("导出", "保留", "过期", "有效期")。下表从维护者已知的合成清单推演；不可读行只写「不进入」，不计算、不展示该行的分数，更不能把这张教学对照表当作用户的搜索响应。

候选选择在评分前，k=2 在评分后
support 租户片段mei 的轨迹lin 的轨迹
EXPORT-POLICY v1 §1导出、保留、有效期 → 3，第 1同样 3，第 1
EXPORT-OPS v1 §2导出、过期 → 2，第 2未获许可，不进入
SYNC-POLICY v1 §1已授权，交集为空 → 不返回已授权，交集为空 → 不返回
EXPORT-INTERNAL v1 §1未获许可，不进入未获许可，不进入

mei 最终可以回查两段原文：「导出文件生成后保留 7 天。」和「导出文件过期后，需重新发起导出。」lin 则只拿到第一段。假如把 mei 的 k 改成 1，输出也只有第一段，但这次操作指引在已授权命中列表的第二位，是预算截掉而非没权限。如果一份片段已授权却使用「留存、期限」这样的新词项，就可能连保留条款也匹配不到。三种缺证据的外观相似，分别需要解释权限边界、名次预算或词项覆盖，不应都用放宽权限、调高 k 或更换模型来处理。

拿到前两名也不保证问题的两部分都覆盖。例如两段如果都重复「保留七天」，它们可以是不同引用键、占两个位置，但仍无法支持过期后的操作。先决定每个子问题需要哪条事实，再核对正文有没有说到，最后用 source 回查。产品若允许分项作答，可以只回答有证据的部分并标明缺项；若问答合同要求覆盖全部要点，则应整题暂不作答。无论哪种合同，都不能把「搜不到」翻译为「没有这条规定」，也不能借生成器补出缺失步骤。合成示例可检查回答用的键和原句，在真实数据上还要单独检查改版后引用是否仍可读。

3. 什么时候换索引，不换契约？

本地演示只扫描小授权池并计算集合交集，不是 SQL LIKE 也不是 BM25。语料增多后，可以用倒排索引从词项找到候选出现位置，而不必对每段正文重新分词。SQLite FTS5 或 PostgreSQL 全文搜索的分析器、查询构造与排序都有自己的合同；例如 FTS5 的 MATCH 可做短语或前缀，默认 bm25() 分数低的靠前。换实现时，先按语言与字段验证分词：编号、时间与全角半角标点要不要归一，应由业务定义并固定测试。别把这些后端的默认匹配规则混同于本课的「有一个共同词项就命中」，也不要假定默认分析器会按你需要的方式切中文。先比较同一授权语料中哪些键进候选，再看排名；索引、打分和授权是三件事。

决策卡：先把可见性和匹配作成两份记录

适用：政策词、状态码、时刻等字面线索有价值，且需要一个可手算的回归基线。边界：真实同义改写很多时，词法可能漏掉授权证据，先收集漏题再考虑下一课。

误判：只要返回行合法，就算检索正确

先从全库截取前两名，再按用户过滤；合法但靠后的证据可能永远到不了调用者。

对照：授权池 → 候选交集 → top-k

从同租户两人的授权键开始对照，再记录正分键、未截断的名次与最终来源。允许结果不足 k。

取舍：词项可解释、回归便宜，但新短语和分词差异需要维护。测试可记合成键；真实用户结果及日志都不应带出不可读正文。

  1. 先独立写出两位用户的授权键，再跑同问自检核对分数、名次和原文。
  2. 最后跑完整时刻对照，确认词项归一没有把前缀变成合法命中。

诊断：授权键不对先查授权选择；授权正确、分数不对再查词项；分数对而条目缺失，查截断位置。

Q mei 的指引在 k=2 可见，改为 k=1 后消失。授权池没变，先检查什么？
匹配与授权都已在对照中成立；这里只有截断位置变了。
Q 查询只含「留存、期限」，授权的保留条款无共同词项。本基线该返回什么？
精确交集为零；这不是对语料存在性或文档权限的判断。

import runpy

if not __debug__:
    raise RuntimeError("run without -O")
lab = runpy.run_path("code/phase7-data-rag/rag-lab/lab.py")
query = lab["Query"](("导出", "保留", "过期", "有效期"))
policy = ("EXPORT-POLICY", 1, "§1")
ops = ("EXPORT-OPS", 1, "§2")
sync = ("SYNC-POLICY", 1, "§1")
internal = ("EXPORT-INTERNAL", 1, "§1")

with lab["open_demo"]() as db:
    for user, pool, expected in (
        ("mei", {policy, ops, sync}, ((policy, 3), (ops, 2))),
        ("lin", {policy, sync}, ((policy, 3),)),
    ):
        authorized = db.authorized("support", user)
        assert {chunk.key for chunk in authorized} == pool
        hits = db.search("support", user, query, k=2)
        assert tuple((hit.chunk.key, hit.score) for hit in hits) == expected
        assert hits == lab["rank"](authorized, query, k=2)
        assert all(db.source("support", user, hit.chunk.key) == hit.chunk for hit in hits)
        assert hits[0].chunk.text == "导出文件生成后保留 7 天。"
        assert db.source("support", user, internal) is None
    assert db.source("support", "lin", ops) is None
    assert db.source("support", "mei", ops).text == "导出文件过期后，需重新发起导出。"
    assert tuple(h.chunk.key for h in db.search("support", "mei", query, k=1)) == (policy,)
print("L62 ACCEPTED")

本课最佳实践验收：时刻不是任意前缀

新的需求是为 support/lin 按完整时刻找同步政策，输入端接受合成样例里的半角 02:00 或全角冒号 02：00。只归一冒号，不把输入补成别的时刻，不额外加入「同步」来掩盖匹配错误。把不完整的 02:0 当成负控：它是现有词项的前缀，但不是合同里的完整时刻。

展开变式参考与自检
import runpy

if not __debug__:
    raise RuntimeError("run without -O")
lab = runpy.run_path("code/phase7-data-rag/rag-lab/lab.py")
Query = lab["Query"]
key = ("SYNC-POLICY", 1, "§1")

def clock_terms(raw):
    return (raw.replace("：", ":"),)

with lab["open_demo"]() as db:
    for raw in ("02:00", "02：00"):
        terms = clock_terms(raw)
        assert terms == ("02:00",)
        (hit,) = db.search("support", "lin", Query(terms), k=2)
        assert (hit.chunk.key, hit.score) == (key, 1.0)
        assert db.source("support", "lin", key).text == "同步任务每天 02:00 运行。"
        assert db.search("support", "lin", Query(terms * 2), k=2) == (hit,)
    new_time = clock_terms("03：00")
    assert new_time == ("03:00",), "归一冒号不能改动时刻"
    assert db.search("support", "lin", Query(new_time), k=2) == ()
    (prefix,) = clock_terms("02:0")
    assert prefix == "02:0"
    authorized = db.authorized("support", "lin")
    wrong_prefix_keys = tuple(c.key for c in authorized if any(t.startswith(prefix) for t in c.terms))
    assert wrong_prefix_keys == (key,)  # 前缀实现会把不完整时刻误当成可用输入。
    assert db.search("support", "lin", Query((prefix,)), k=2) == ()
print("L62 TRANSFER PASSED")

应只打印 L62 TRANSFER PASSED。若末条断言失败，核对是误做前缀匹配、错误补全，还是额外塞进了别的检索词。本练习的归一规则不等于通用时刻解析。

面试自查

先说明结论、边界和判定证据，再展开追问。

Q1两位同租户客服得到两组结果，你怎么证明不是检索不稳定？

参考回答：冻结租户、词项、语料版本和 k，只变用户，先断言授权键，再逐键比交集分、名次和来源。共享条款应一致；仅一人被授权的指引只进入这个人的排序。

追问：另一个租户复用同一引用三元组呢？

答题要点：三元组是租户内定位；回查与缓存归属不能省略租户与当前授权范围。

Q2上线后短语「留存期限」没有结果，是索引失效吗？

参考回答：先确认条款在授权池，再检查实际词项与交集。换成已知命中「保留」作正控；若只是改写词未覆盖，可先评估受控别名，而非先重建索引。

追问：能为所有未匹配词自动放宽成前缀吗？

答题要点：不能套用到需要字面精度的字段，特别是编号、时刻；用完整值正控和不完整值负控约束边界。

Q3双问的两条结果都讲保留期，可否认为证据够了？

参考回答：不能用结果条数代替覆盖。分别标记「多久」和「过期后怎么做」需要的正文；重复证据只覆盖前一项，无动作证据则明示缺失。

追问：把 k 加到 10 就行吗？

答题要点：只有正确片段在授权正分列表但被截掉时才可能有用；若是授权排除或词项漏配，扩大输出上限不能解决。

Q4把扫描换成 FTS5，为什么旧排序断言会失败？

参考回答：比较分析器、MATCH 语义与排序方向。基线是重复不加分、任一共同词就计入；FTS 的短语、布尔条件与 BM25 另有定义。先验权限不变，再重测匹配与排名。

追问：哪些断言不应因为换索引而放松？

答题要点：未经许可的内容不能进入业务候选，结果必须能按当前权限和完整版本键回查；空证据不能变成无来源的答案。
