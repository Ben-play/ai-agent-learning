从同一批旧检查点比较恢复

先比输入的来处，再比批准、回执和持久效果

升级准入不只是「v2 能跑」

L85 由旧程序生成了客服 Agent 的三类停止点。本课用标准库合同追问：对于同一个停在修订 2 的导出保留期任务，旧应用和候选能否拒绝同样的错误批准，并交付同一份稿件？如果一边换了批准或新建了任务，结果相同也不能支持兼容。

学习目标：核对原包、准备包和两臂的输入，区分宿主调用、实际 INSERT 尝试、持久行与可返回回执；根据当前来源判断能否保存或返回原草稿。

1. 原任务与批准都要绑定

每个案例先由 v1 到达指定停点，封存三个文件（before.origin）。可信宿主只在一个干净副本注入一次，关库后独立读回检查点、审批、来源和全表业务行。通过验证才封存准备包（prepared.origin）。两臂分别复制这个准备包，启动前记录各文件的 SHA-256（arms.v1.from_prepared 和 arms.v2.from_prepared）。两臂不各自注入，也不在同一份库先跑 v1 再跑 v2。

审批表中一条决定由 (tenant, actor, job, action, revision, digest) 定位，值才是 approve 或 deny。例如训练租户的 reviewer 批准 export 的 save_local_draft、修订 2 和它的稿件摘要。thread_id 只是定位，reviewed 只是编排状态；宿主还得匹配当前 Phase 5 业务快照。只把批准的修订号改成 1、仍保留修订 2 的内容摘要，也不能通过；这与使用当时真实修订 1 的批准是两种不同的错输入。

同源对照：最常见的恢复路线
给两个副本的条件宿主返回业务调用／INSERT 尝试／持久行
待批，无审批pending，保留原中断0／0／0
修订 2 明确拒绝denied；只写入拒绝结果1／0／0
主体、修订、摘要等全部匹配，来源仍有效saved；原稿和新回执1／1／1
错误主体、只错修订号或拿旧稿批准rejected；无稿件或回执0／0／0
已提交丢回复，绑定与来源仍匹配replayed；原稿和原回执1／0／1

明确拒绝会向业务库记录终止，不等于尝试写草稿。批准也不能绕过当前来源：批准后将 KB-01 的「7 天」改为「3 天」，新版和旧版都返回 source_blocked；已提交后撤掉 KB-02 的可读记录，返回 replay_withheld，不返回旧正文或回执，但也不抹去原持久行。报告中的全表是实验者的独立观察，不是给调用方的响应。

2. 用独立证据识别「看似通过」

调用数在宿主真正调用 Phase 5 保存入口时计；INSERT 由存储的写前回调记录操作 ID；Phase 8 的全表观察器另开只读连接，核对所有主体的草稿、内容和回执。v2 只有保存或重放成功才执行 finish；两臂业务效果相同不要求图格式相同。

注入器只写夹具，不能替验收器说「写的是哪一项」。手写 expected.json 指定应变字段和值，其余字段、行及未涉文件必须保持原样。例如错动作应是 submit 且任务仍是 export；若误改成错任务，两臂也会一起拒绝，但准备包应当在任何恢复前验收失败。

决策卡：配对比较，再对独立金标

适用：升级需要恢复未完成且有副作用的任务。不适用：如果无在途状态，直接做业务契约回归即可，不必维持成对历史输入。

只比较两臂返回的标签

两边都误写，仍可能一起显示成功。

核对独立全表、回执和原稿

即使两臂共同出错，金标也能否决。

代价：闭库复制和结果金标要随业务维护；可以先排空再升级，但先处理剩余在途任务，不能把它们当作已取消。

  1. 确认两臂输入来源一致，核查改动只发生在对应的工作副本。
  2. 对比错批准与有效批准，再用丢回复重放比原回执和全表。

诊断：如果发生零次 INSERT 却多出一行，先核对是否用了范围过滤、是否读错库；不以候选自己报告的计数作准。

Q 业务已提交，但调用方丢了回复。哪项证明恢复没有重复保存？
回执、尝试次数和全表行分别证明返回的是谁、有没有再试写、实际留下了几份。

from pathlib import Path
import sys

sys.path.insert(0, str(Path("code/phase10-framework-evolution/evolution-lab/checkpoints").resolve()))
from contract import run

report = run("compare", cases=("approve", "wrong_revision", "replay"))
for name, status, calls, inserts, saved in (("approve", "saved", 1, 1, 1),
        ("wrong_revision", "rejected", 0, 0, 0), ("replay", "replayed", 1, 0, 1)):
    case = report[name]
    before, prepared = case["before"], case["prepared"]
    old, new = (case["arms"][key] for key in ("v1", "v2"))
    assert old["from_prepared"] == new["from_prepared"] == prepared["origin"]
    changed = {key for key in before["origin"] if before["origin"][key] != prepared["origin"][key]}
    assert changed == (set() if name == "replay" else {"reviews.sqlite"})
    assert old["reply"] == new["reply"] and old["ledger"] == new["ledger"]
    for arm in (old, new):
        assert (arm["reply"]["status"], arm["calls"], len(arm["inserts"]), len(arm["ledger"]["saved"])) == (status, calls, inserts, saved)
    if name == "wrong_revision":
        binding = prepared["graph"]["values"]["binding"]
        fields = ("tenant", "actor", "job", "action", "revision", "digest")
        expected = dict(binding, revision=1)
        assert prepared["ledger"]["reviews"] == [[*(expected[key] for key in fields), "approve"]]
        assert binding["revision"] == 2 and new["nodes"] == []
        assert new["reply"] == {"status": "rejected", "receipt": None, "draft": None}
    if name == "replay":
        original, = before["ledger"]["saved"]
        assert new["reply"]["receipt"] == original[0] and new["reply"]["draft"] == original[-1]
        assert new["nodes"] == ["apply_review", "finish"]

from pathlib import Path
import sys

sys.path.insert(0, str(Path("code/phase10-framework-evolution/evolution-lab/checkpoints").resolve()))
from contract import run

report = run("compare", cases=("revised", "wrong_tenant"))
fields = ("tenant", "actor", "job", "action", "revision", "digest")
for name, case in report.items():
    before, prepared = case["before"], case["prepared"]
    binding = before["graph"]["values"]["binding"]
    original, = before["ledger"]["checkpoints"]
    expected_review = [*(binding[key] for key in fields), "approve"]
    expected_checkpoint = original[:]
    if name == "revised":
        assert expected_review[4] == 2
        expected_checkpoint[3] = 3
    else:
        expected_review[0] = "another-tenant"
    assert prepared["graph"] == before["graph"]
    assert prepared["ledger"] == dict(before["ledger"], reviews=[expected_review], checkpoints=[expected_checkpoint])
    for arm in case["arms"].values():
        assert arm["from_prepared"] == prepared["origin"] and arm["ledger"] == prepared["ledger"]
        assert (arm["nodes"], arm["calls"], arm["inserts"], arm["ledger"]["saved"]) == ([], 0, [], [])
        assert arm["reply"] == {"status": "rejected", "receipt": None, "draft": None}

面试自查

Q1 基线和候选都返回 saved，负责人准备放行。你先核对什么？

参考回答：查两臂的封存源与场景变更，再用独立回执和全表检查效果。

追问：两个版本都多写一笔怎么办？

答题要点：不能以互相一致作为金标；独立断言行数、归属、原稿和操作 ID。

Q2 重放时客户端带了正确线程号和 approve。可以保存吗？

参考回答：不可以把线程和恢复参数当凭证，先读宿主审批并匹配完整绑定。

追问：任务仍在原线程，但草稿修订已变呢？

答题要点：保持旧输入，不替客户端补批准；新修订需要自己的决定。

Q3 安全检查发现资料撤权，但已成功保存过。怎么回放？

参考回答：保全已提交事实，不释放旧草稿或回执；把当前资料校验放到宿主出口。

追问：报告还能列持久行吗？

答题要点：独立只读验收与应用返回是不同访问面；产品不能把演练的全表当响应。

Q4 拒绝路径显示调用数 1，但 INSERT 为 0。是坏事吗？

参考回答：不一定，明确拒绝可以记录终止；无批准或错批准则不分发。

追问：只有调用数，没有持久行计数呢？

答题要点：调用不是提交；需要另读全表，核对非预期主体也没有行。

小结与一手参考

比较输入、身份和开销各自对应的证据；兼容旧检查点的目标，是保住许可、结果和持久效果，不是保住一个成功标签。独立 LangGraph 入口另核对 Phase 6 原图快照和 Phase 10 应用夹具；两部分都只静态核对，未在本次运行。

  • LangGraph · Persistence：线程、状态快照和待运行节点。
  • SQLite · URI filenames：用 mode=ro 打开核对连接。
  • SQLite · Transactions：分清业务事务和图状态的保存边界。
