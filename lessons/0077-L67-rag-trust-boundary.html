第七阶段 · 数据与 RAG45分钟

RAG 信任边界

原文可核验，正文仍是数据，批准来自应用

为什么这课重要？

客服 Mei 问「导出文件保留多久」，系统找到原文「导出文件生成后保留 7 天。」这是证据，不是给应用下达任务的通道。即使来源是企业正式发布的知识库，索引记录也只能说明某处写了什么；能用来答保留期，并不意味着能够改变流程、代表用户同意，或获得额外的读取权限。上一课处理缓存过期，本课接着问：即使缓存完全正确，哪些决定仍然不能交给缓存里的正文？

  • 把来源可核验、事实是否可信、当前主体的读取权限与业务批准分别验收。
  • 用无指令的合成标记保留正文的数据身份，用内存模拟审核核对应用侧权限，全程执行数为零。

1. 同一条原文要过哪些判断？

判断谁提供依据能得出的结论
本次允许读吗？应用已知的租户与用户、当前资料授权限定候选集合；先定范围，再排序。
真出自这里吗？应用用文档编号、版本、定位查当前授权原文，逐字对照可复核引文。不证明原文观点正确，也不授予额外权限。
适合当这道题的证据吗？产品定义的来源等级、负责人、时效及适用范围正文可被引用或排除；不同来源冲突时，应提示分歧或转人工。
允许处理这个动作吗？应用掌握的主体、允许动作、暂存意图与独立的批准记录只对所核准的具体对象和版本有效，不能从正文推导。

「可核验」回答的是出处，并非「可信」的一次性勾选。部门公告与过期业务手册可以各自逐字查到，却不应都作为当前政策依据；一份最新公告也只在指定地区或客户范围内有效。实现上让来源字段来自受控的索引或资料库，不让正文自报来源等级；由资料负责人和生效范围决定证据能否支撑这道题。桩程序只验证身份范围和精确引文，不替组织制定来源等级，也不裁决冲突的制度。

应用拿到允许的资料后，用 Evidence 保留核验时的租户和用户，为证据加结构化标签 untrusted_data；独立练习还在正文加入不含任何指令的印刷校验标记 〔样张-蓝〕。前者是应用赋的角色，后者只是普通字符。两者同时存在说明可以完整保存、定位和核对正文，仍不给正文控制力。标签有助于保持上下文边界和审计，但它不负责强制模型服从，也不该成为唯一防线；应用仍要在送出数据和收到结构化建议的两个方向各自检查。

2. 从读取到审核，把权力留在应用

本地路径是「固定的宿主主体 → SQLite 授权范围内查询 → 精确回查来源 → 带标记的数据 → 确定性本地审核」。例如 support/mei 可用 EXPORT-POLICY v1 §1 作答；operations/mei 有相同编号和定位，却对应另一套政策，不能把响应或缓存只按编号复用。练习只测正文的证据身份和审核，不把字符串传给真实模型，也不联络外部服务。生产里应从可信认证上下文取得主体，若授权或资料版本在生成期间变化，交付前应按当前规则再查，不沿用旧的授权快照。

为了观察审批路径，应用另存一个合成的标签预览意图，包含所有者、动作、目标、版本和标签值。建议可以请求这个预览，不能为它盖章。审核只认宿主提供的暂存意图和模拟批准：当前主体必须是所有者，动作必须是 preview_label，建议与暂存意图一致，批准也须绑定同一份意图。没有批准就保持待审；哪怕版本未变，只改了标签值也要重新确认。「模拟已批准」是审核结果，不是执行完成。正控会给内存预览日志加一条，说明审核路径确实接通；拒绝不增加日志。本课结构上没有执行器，日志不是业务回执，也不测试真实执行入口。

权衡在于只读问答不必每次打断用户确认，但一旦离开只读路径，就要为人工复核承担延迟与状态维护成本。对只读界面，直接不提供执行能力比展示一套永远不该使用的能力更容易维护。排查时把证据核验结果和审批结果分列：引用失败先查租户、当前版本、定位及原文；来源通过但没有批准，是正常的待审路径，而不是去重试引用。记录关联键和类别即可，不把原文或身份凭证随意写入日志。

决策卡：查询保持只读，审核只接受宿主证据

适用：同一个界面既引用企业资料，又展示可审查的建议。边界：本课审核标签预览，不连接执行器，不证明模型对不可信输入的处理效果。

误判：出处正确就允许下一步

把引文通过、用户可读、动作获批都塞进同一个「已验证」标志。

选择：分别留证

查询以主体划界，出处按精确元组验证。审核要求宿主决定，批准匹配后依然只显示本地模拟结果。

代价：需要维护业务意图和独立审批记录，但可清楚定位哪道门失败。标记正常且审批缺失时，不要求用户更换资料。

  1. 固定原文变更主体；再固定主体变更引文版本，分别验证拒绝。
  2. 固定同一可核验证据，比对无批准、变更建议、完整匹配三种审核状态；每条独查内存预览日志的增量。

验收门槛：可核验引文不赋予审批，只有正控进入模拟日志；零业务执行来自不接执行器的设计，不是对生产效果入口的测试。

Q 当前用户可读并能核验引文，预览建议与暂存内容一致，但宿主没有批准。应记录什么？
读取和来源验证都通过，不改变独立审批状态。待批准路径没有执行。

        (replace(staged, label="另一张样签"), approval, "intent_changed", [staged]),

        assert a["review_preview"](scope, staged, proposed, decision, log) == status
        assert log.entries == expected_entries

面试自查

先说判定依据，再说最小验收用例。

Q1两篇正式公告都能逐字核验，但保留期不同，该以哪篇作答？

参考回答：逐字核验仅证明各自写了什么。用发布负责人、生效时间和适用对象判断；不能确定时展示分歧或转人工，不取排序第一的值当事实。

追问：有新的发布日期，但适用地区不同呢？

答题要点：时效和适用范围都要匹配；新不等于对当前客户有效。用地区各一条正控和不匹配例验证。

Q2缓存命中后还要回查授权和出处吗？

参考回答：要避免把缓存的历史判定当当前判定。按租户和主体隔离缓存，用授权与资料版本判定是否过期；展示引文前核对当前精确来源。

追问：用户没变，但文档版本已换，旧段落还能展示吗？

答题要点：按本课当前版本契约不能。重新查询；若产品提供历史档案，应另订历史读取与标注策略。

Q3工单预览已获批，编辑只改显示标签、没改版号，还能复用批准吗？

参考回答：不复用。批准绑定主体、动作、对象、版号和内容，不能只比版号。可用同版本改标签与完全匹配做对照，读取证据不受影响。

追问：用户界面显示「模拟已批准」，能把它当业务回执吗？

答题要点：不能。审核和真实执行是两个阶段；本课没有执行器，也不测真回执。

Q4上线前看到所有样张标记都正确，是否能据此声明系统安全？

参考回答：只能证明合成正文保留了数据身份，并且本地审核有预期结果。上线需独立验收生产身份绑定、效果入口的权限检查、权限变更与失败审计。

追问：只读助手还需要保留动作接口供以后拓展吗？

答题要点：没有业务需要时不暴露；未来加动作时增加独立权限与审批，不让提示词或来源标签代替。

小结与一手参考

按当前主体精确核验原文；事实是否可信还要看来源与适用范围；业务批准独立于引用和内容。

  • NIST SP 800-207 · Zero Trust Architecture：资源访问不依赖隐含信任，认证和授权是独立判断。
  • NIST SP 800-53 Rev. 5：查阅 AC-3（访问强制）与 AC-6（最小权限）；不是本地模拟的合规背书。
