按负载比较降本方案

一次调用更便宜，不等于完成一件事更便宜

为什么这课重要？

支持和运维租户都会问「导出文件保留多久？」两边的政策编号相同，却分别是七天与三十天。客服还可按需保存经批准的草稿，不能提交或外发。如果一次请求单价下降，却多出重试、缺引用或漏了草稿，报表里的折扣对用户没有意义。本课用同一批任务练习按尝试对账、把正确性与隔离放在排序之前，再解释成本与端到端延迟为什么可能不同步。

学习目标

  • 固定身份、语料、失败脚本与顺序，再分别比较缓存、路由和 Token 预算。
  • 从逐次尝试核算每成功任务成本与 p95，并用独立对照验质量与隔离。

1. 冻结工作负载，先决定什么算成功

export-support-load/v1 固定请求身份、租户、顺序、政策版本、预算用量、失败脚本、排队和取证延迟；每个方案都从空缓存重放同一批。宿主传入可信租户，问题文本不选择租户。预期记录独立手写：回答必须给出本租户的政策值和准确的 EXPORT-POLICY/v1 §1；批准的草稿要保留相同证据，终态恰好一条模拟写入；没有交付的路径不能凭答复措辞假装成功。这里检验字段与模拟终态，不检验开放式文本的语义质量或真实审批系统。

固定顺序；每行另有 100 个固定前缀 Token，表内 Token 数为人工设定
任务与租户必要／可选后缀；必要／计划输出排队／取证（ms）独立预期
s-lookup 支持，常规问答20 / 30；16 / 305 / 10七天、当前引文、零写入
s-repeat 支持，同题再问20 / 30；16 / 308 / 10同上；缓存组应读取本租户前缀
o-lookup 运维，同题同文档键20 / 30；16 / 305 / 10三十天、本租户引文、零写入；缓存组仍冷
s-draft 支持，已批准40 / 40；30 / 509 / 24首次超时，重试后保存一条带证据的草稿
s-recover 支持，取证回答遇到持续故障45 / 45；20 / 3512 / 20两次生成尝试都超时，安全报不可用，零写入

质量门逐题核对值、引文和终态；隔离门逐题核对返回的证据归属、所有发生缓存读取的尝试的来源归属，失败尝试也不能例外。两个门都过才进入候选。s-recover 的安全停止符合金标，但没有答复或草稿交付，不能进成功分母。因此五条行为都正确，成功仍只有四条。只统计有响应的请求会漏掉失败成本；把所有正确拒绝都计成交付也会虚抬成功率。若拒绝本身是另一产品的约定交付，要在回放前单独版本化定义，不能在看到结果后改口径。

2. 每次只改一个杠杆，观察哪一项账变了

前缀缓存：稳定的指令和格式位于固定前缀，问题与当轮政策证据在动态后缀；这里复用的是前缀用量，不是检索结果或答复，命中也仍要取证。用 (tenant, model, prefix_version) 隔离模拟状态，同名文档和相同问题都不能让两个租户共用状态。若提示模板变了却未升级前缀版号，就不能解释命中与错配；实际接入还要验证真实命名空间、匹配条件及边界，不能照搬这个键证明线上隔离。夹具把第一次用作写入，之后用作读取，甚至首次超时也完成写入；没有 TTL、驱逐、并发填充或真实厂商的计费规则。

路由：仅把预标为常规的三条问答交给 lite，草稿和故障对照留在 standard。这不是用题目字符串揣测权限，也不证明 lite 能做任意任务。本地只是改变尝试的计费与时延模型；独立标签约束结果。如果线上要做升级回退，必须记录实际路由、错误分类和升级次数，慢路由的额外尝试不能从分子删掉。即使轻路由让三条问答更快，最慢的草稿没动，整批尾部就可能不变。

输入与输出上限：输入上限针对含前缀的总量，145 优先保留证据及必要字段，只去掉可选上下文；不足以容纳必要内容就不发起生成，而非截掉引用再硬答。输出上限是另一臂，30 允许完整的最小草稿，低于它不会保存不完整草稿。实际系统须依据可核查的内容和停止原因区分压缩成功与截断，不能因为输出少就算答对。两类上限分开试，后续如叠加缓存、路由和预算，应另跑组合对照；单项差值不能相加作承诺。

3. 手算再看表：失败、等待和重试不能藏起来

教学费率用虚构的计费单位 microcredit（uc） 表示，不可换算真实货币。普通输入／前缀写／前缀读／输出的单价，standard 为 3/4/1/5，lite 为 2/3/1/3 uc/Token。标准常规问答基线为 150×3 + 30×5 = 600；缓存组的首条任务触发冷写，50×3 + 100×4 + 30×5 = 700，同租户重来才降为 50×3 + 100×1 + 30×5 = 400。运维首次仍是 700，不是 400。缓存读写只替换普通前缀输入，不重复计费。

基线草稿先付 180×3 = 540，再付 180×3 + 50×5 = 790；故障题两个尝试各 190×3 = 570。因此总额为 3×600 + 540 + 790 + 2×570 = 4270，除以四个成功得 1067.5 uc/成功任务。零成功时仍报告总额与失败，除法记 N/A，不记为零或最便宜。这里的分子只含固定的尝试费，线上还要按口径加检索或其他执行费，对账缺失用量；缺失不是零。

模拟尝试耗时是模型固定开销（标准 60、轻量 30 ms）加普通输入数、写入数、读取数整除 5，再加两倍输出数；时间系数只供练习。整条请求从排队算到终态，含取证、所有尝试及一次 40 ms 重试间隔。基线草稿为 9 + 24 + 240 + 40 + 340 = 653 ms；故障题也进延迟分布，为 12 + 20 + 250 + 40 + 250 = 572 ms。本例仅模拟已获批草稿，无异步等批耗时；线上若承诺从接单到交付，应把等待审批单列，并同时报告总时长和主动处理时长。这里的最近秩 p95 是排序后第 5 项（向上取整），样本太少，只是最大值，不是线上 SLO。

决策卡：先删掉不合格方案，再比较已交付成本

适用：有同版本任务、独立金标、逐次尝试账本和足以区分租户的正负控。不适用：拿这五行决定线上费率、默认模型或发布门槛。

误判：总额降低就是赢

压掉草稿的必需字段后尝试费更少，却少完成一件事。

选择：保存逐任务账本，按硬门、成功、成本与延迟解释

本轮前缀方案两项数值都最好，但冷请求更贵；低复用业务应该重新取样。

  1. 固定版本、失败脚本及回放顺序，先验金标和隔离，再核对是否为同批。
  2. 把每次尝试按用量类型计入总额，记录成功数及包括失败在内的端到端延迟。
  3. 按租户和任务类型看冷、热、超时和截断，下一轮只改一个可解释条件。

诊断：暖请求少花钱但整批更贵，先查冷写和命中分布；路由更快而 p95 不动，找对照中最慢的任务和重试间隔；输出更短却未交付，回查必填字段和停止原因。

Q一个方案少付了尝试费，却在批准过的草稿题丢失必填字段。怎样处理该方案？
便宜不能抵销未交付。失败也消耗费用和时间，不能删出账本。

面试自查

Q1两个租户问同一句，返回的留存期都对，却检测到一次跨租户前缀读。可以按成本上线吗？

参考回答：不可以。答复金标与尝试来源是两个门；值正确不能批准跨作用域复用。

追问：怎样区分缓存没有真正复用与隔离做对了？

答题要点：固定同题两租户，验证本租户冷写后出现正确热读，另一租户仍冷，并逐次查读的归属。

Q2服务返回安全的不可用提示，但发生两次收费尝试；成功任务成本怎么记？

参考回答：两笔都计到同批分子；这里没交付答复或草稿，所以不进分母。安全停止仍可通过质量标签。

追问：整批没有完成一件时怎么报告？

答题要点：报告总额、成功数为零、失败分类，均摊写 N/A 并挡住本轮发布比较。

Q3轻路由让三条正常查询更快，但整批 p95 不变。先改哪里？

参考回答：先按任务拆出尾部。最近秩取到草稿，它的排队、取证和重试没变；路线不一定是瓶颈。

追问：可否拿这五条的 p95 设线上承诺？

答题要点：不行；按实际构成、并发、观察窗口和端到端同口径重测，含失败及重试。

Q4团队同时开启路由和缓存，为什么不能直接相加两边的节省？

参考回答：路由会改变缓存所在的模型命名空间和命中机会，重试也可能改变；两臂不是独立的算术项。

追问：怎么验证组合有用？

答题要点：用同版本、同顺序另跑组合和冷、热对照，检查逐题门槛与尝试账，再比较成本和延迟。
