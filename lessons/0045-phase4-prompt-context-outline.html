从 L38 继承什么

复用：固定响应器、显式终态、输出验证和调用预算。本阶段新增的是任务标准、提示版本、证据选择与对照评测；不重讲 L28 的 Schema 约束或 L30 的历史裁剪。

业务边界：用虚构政策库回答问题，引用所提供的证据；缺证据时说明无法回答或请求补充。可以生成可审阅的文本草稿，但没有创建、发送或更新真实工单的能力。后续 Phase 5 才引入受控、需审批的写操作。

6 节课：每节交付一项可检查的结果

顺序主题动手验收
L39 30min把请求写成可判定任务先定答复、缺证据、工单草稿三种结果契约。为每种结果写一个例子和明确通过条件，草稿不能冒充提交成功。
L40 45minZero-shot、Few-shot 与反例同一批开发案例对照有无示例，用近邻反例区分询问和起草。离线只验证对照构造。
L41 45minPrompt 版本与回归对照 v1/v2，记录版本、案例数与失败项；保留独立验收集。总分相同也不能忽略关键退化。
L42 45min证据选择、来源与上下文预算保留原文与来源；复跑缺证据、预算不足、引用未发送材料，以及已发送却漏引主来源。
L43 55minSkills 按需加载与权限边界复用 Skills 参考页，对比起草与询问，测加载次数；匹配不等于授权。
L44 45min项目验收与交接跑离线回归，留下版本、案例、引用与预算记录；隔日重建缺证据分支。同一业务契约交给 Phase 5。

工程实践路线

每课先用给定输入跟做一步，核对预期，再展开参考；课末独立完成变式。学到 L43 立即完成证据、预算与起草触发检查点。完成 L44 后用阶段工程实践复盘整理交接，不留到最后才做全部练习。

起始项目：证据问答＋工单草稿

见起始项目说明。在课程源码仓库根目录运行；只用 Python 标准库、虚构数据和固定响应，不需要网络或密钥：

cd code/phase4-prompt-context
python main.py
python -m unittest discover -s tests -v

先观察有依据的答复、请求草稿与缺证据的区别，再改一个模板或一个验收用例。起始项目用于验证本地控制路径；它不是 RAG 索引、权限服务、真实模型评测或工单后端。

一手来源：OpenAI · Evaluation best practices（任务评测与对照） · Agent Skills 规范（元数据与按需加载）。

有疑问时，可用虚构输入、提示版本和失败用例向教学助手提问。
