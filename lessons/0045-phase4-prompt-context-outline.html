先修与边界 · 6 节草案 · 离线起始项目

从 L38 继承什么

复用：固定响应器、显式终态、输出验证和调用预算。本阶段新增的是任务标准、提示版本、证据选择与对照评测；不重讲 L28 的 Schema 约束或 L30 的历史裁剪。

业务边界：用虚构政策库回答问题，引用所提供的证据；缺证据时说明无法回答或请求补充。可以生成可审阅的文本草稿，但没有创建、发送或更新真实工单的能力。后续 Phase 5 才引入受控、需审批的写操作。

6 节草案：每节交付一项可检查的结果

顺序主题动手验收
1把请求写成可判定任务先定答复、缺证据、工单草稿三种结果契约。为每种结果写一个例子和明确通过条件，草稿不能冒充提交成功。
2Zero-shot、Few-shot 与反例只改变是否提供示例，在同一批开发案例上比较。至少用一条措辞相近但不该起草的反例排除过宽规则。
3Prompt 版本与回归提示模板与用例都进仓库。对同一输入比较 v1/v2，记录版本、案例数和变化；保留独立验收集，不拿它调提示。固定响应器只验证管线，不证明模型质量。
4按任务选择证据、保留来源、验证预算从简短政策数据选相关片段，带来源 ID 组装上下文；预算不足时不得丢弃来源标记后硬发。验收缺证据、预算不够、引用不在本次材料中三条路径。
5渐进披露：只在需要时加载 Skill复用 Skills 参考页，对比「请求起草」和「只询问政策」；后者不加载起草步骤。匹配不是工具授权，不增设独立 Skills 课号。
6项目验收与交接跑完离线回归，交付版本化提示、用例、引用与预算记录；隔日从空白重建缺证据分支。把可复用契约交给 Phase 5，不复制一套新项目。

起始项目：证据问答＋工单草稿

见起始项目说明。在课程源码仓库根目录运行；只用 Python 标准库、虚构数据和固定响应，不需要网络或密钥：

cd code/phase4-prompt-context
python main.py
python -m unittest discover -s tests -v

先观察有依据的答复、请求草稿与缺证据的区别，再改一个模板或一个验收用例。起始项目用于验证本地控制路径；它不是 RAG 索引、权限服务、真实模型评测或工单后端。

一手来源：OpenAI · Evaluation best practices（任务评测与对照） · Agent Skills 规范（元数据与按需加载）。

有疑问时，可用虚构输入、提示版本和失败用例向教学助手提问。
