完整 Function Calling 循环

在 Responses 上实现有界的请求、授权执行、回填和退出

为什么这课重要

L27 练过一次「发请求 → 执行 → 回填」。模型看完结果可能再要工具，也可能直接给答案。把这一步放进有轮数上限的循环，就有了最小 Agent Loop。

本课的任务是查北京天气，再根据结果推荐穿搭。练习的重点不是模型能不能猜中，而是应用能否区分四条路径：继续调用、正常结束、拒答或响应未完成、预算耗尽。收到文字不等于成功；模型提出调用也不等于允许执行。

1. 主练习：完整 Responses 循环

循环只依赖两个入口：request(items) 返回采用 Responses 形状的对象；dispatch(name, arguments) 负责权限、参数和执行错误，返回可序列化的受控结果。L36 会实现真实分发边界；本课先用本地响应和分发替身。

import json


def run_loop(request, dispatch, task, *, max_rounds=4):
    """max_rounds 是模型请求预算（包含最终回答），不是工具次数或超时。"""
    items = [{"role": "user", "content": task}]
    seen_ids = set()
    for round_number in range(1, max_rounds + 1):
        response = request(items)
        if response.status != "completed":
            raise ValueError(f"response not completed: {response.status}")
        if any(part.type == "refusal" for item in response.output
               if item.type == "message" for part in item.content):
            raise ValueError("model refused")

        calls = [item for item in response.output if item.type == "function_call"]
        if not calls:
            if not response.output_text.strip():
                raise ValueError("missing final text")
            return response.output_text
        if round_number == max_rounds:
            # 已没预算提交另一轮，别为了无法回填的调用再产生副作用。
            raise RuntimeError("model round budget exhausted")

        ids = [call.call_id for call in calls]
        if (any(not call_id for call_id in ids) or len(set(ids)) != len(ids)
                or seen_ids.intersection(ids)):
            raise ValueError("invalid or duplicate call_id")
        seen_ids.update(ids)
        # 原样保留完整 output，包括可能存在的不透明推理 Items。
        items.extend(response.output)
        for call in calls:
            result = dispatch(call.name, call.arguments)
            items.append({
                "type": "function_call_output",
                "call_id": call.call_id,
                "output": json.dumps(result, ensure_ascii=False),
            })
    raise RuntimeError("model round budget exhausted")

这段代码只处理自定义函数和最终文本；不处理厂商托管工具、流式消费或进程级恢复。实际系统还需要墙钟时间、工具次数、费用预算和外部写操作的幂等。call_id 用来关联协议结果，不是业务幂等键。

Q 模型发出调用但本轮响应未完成，应该怎么办？
先判断响应终态和拒答。如果不符合继续条件，不应执行工具或把临时文字当成最终答案。

2. 离线验收：测下一轮真实看到的历史

先独立完成：用一个固定响应器模拟「一轮请求两个工具 → 下一轮基于结果回答」。断言原始 Items 都在、结果按 call_id 配对、非法响应和最后一轮不触发执行。以下代码接在第 1 节之后运行；完全离线，不代表真实模型已经验证。

展开固定响应与失败路径断言
from types import SimpleNamespace as Item


def response(*items, status="completed", text=""):
    return Item(status=status, output=list(items), output_text=text)


def call(call_id, city):
    return Item(type="function_call", id=f"item_{call_id}", call_id=call_id,
                name="get_weather", arguments=json.dumps({"city": city}))


reasoning = Item(type="reasoning", encrypted_content="opaque-fixture")
beijing = call("c1", "北京")
shanghai = call("c2", "上海")
visited, executed = [], []


def dispatch(name, raw):
    assert name == "get_weather"
    city = json.loads(raw)["city"]
    executed.append(city)
    return {"temp_c": {"北京": 3, "上海": 13}[city]}


def request(items):
    visited.append(list(items))
    if len(visited) == 1:
        return response(reasoning, beijing, shanghai)
    assert items[1:4] == [reasoning, beijing, shanghai]
    assert [item["type"] for item in items[4:]] == ["function_call_output"] * 2
    assert [(item["call_id"], json.loads(item["output"])) for item in items[4:]] == [
        ("c1", {"temp_c": 3}), ("c2", {"temp_c": 13}),
    ]
    return response(text="北京更冷")


assert run_loop(request, dispatch, "比较两地天气") == "北京更冷"
assert len(visited) == 2 and executed == ["北京", "上海"]

# 分发拒绝也按原 ID 回填，不能伪装成执行成功。
def request_rejected(items):
    if len(items) == 1:
        return response(beijing)
    assert items[-1]["call_id"] == "c1"
    assert json.loads(items[-1]["output"]) == {"ok": False, "error": "forbidden_tool"}
    return response(text="本轮无权查询天气")


executed.clear()
assert run_loop(request_rejected, lambda *_: {"ok": False, "error": "forbidden_tool"},
                "验证权限拒绝") == "本轮无权查询天气"
assert executed == []

for bad, max_rounds, expected_error in [
    (response(beijing, status="incomplete"), 3, "response not completed: incomplete"),
    (response(beijing, Item(type="message", content=[Item(type="refusal")])), 3, "model refused"),
    (response(), 3, "missing final text"),
    (response(beijing, beijing), 3, "invalid or duplicate call_id"),
    (response(beijing), 1, "model round budget exhausted"),
]:
    executed.clear()
    try:
        run_loop(lambda items: bad, dispatch, "验证失败路径", max_rounds=max_rounds)
    except (ValueError, RuntimeError) as exc:
        assert str(exc) == expected_error
    else:
        raise AssertionError(f"expected {expected_error}")
    assert executed == []

# 不同模型轮次重用同一协议 ID 也不应再次执行。
executed.clear()
try:
    run_loop(lambda items: response(beijing), dispatch, "重复使用调用 ID")
except ValueError as exc:
    assert str(exc) == "invalid or duplicate call_id"
else:
    raise AssertionError("expected duplicate call_id rejection")
assert executed == ["北京"]
print("L35 ACCEPTED")

意外执行往往比返回错误更严重。若测试失败，先检查响应终态、权限分发入口和预算检查是否在执行之前，不要只改断言去迎合结果。真实模型接入后，再用同一任务重复试验，记录成功率、延迟和成本，见 L38。

3. 一个回合多个调用，不等于多轮或并发

形态例子应用如何处理
一轮多个请求模型同时请求北京和上海天气。每个请求各自校验、各自回填；第 1 节用 for 顺序执行。
多轮先查天气，下一轮才决定是否查询出行建议。依赖前一轮结果，不能把两个模型请求并发发出。
应用并发两个互不依赖的只读查询。有明确并发与错误隔离策略才并发，参见 L16；带副作用的操作不能仅凭模型同轮返回就并发。
Q 一轮给出两个自定义调用，最小循环怎么处理？
调用请求可能共享工具名，但各有独立 ID。全部处理并不要求并发；校验失败时也要按原 ID 给出受控结果。

4. 可选在线接入与兼容对照

在线片段需先配置 SDK、凭证和支持 Responses 工具的 OPENAI_MODEL，确认调用预算。复用 L27 的 WEATHER_TOOL，并用 L36 的 dispatch 接入本地天气替身。此示例的应用只授权读测试天气，不从模型生成允许集。不要用真实外部写操作做初次集成测试。

展开接入函数（非独立脚本）
import os
from openai import OpenAI

client = OpenAI()


def request(items):
    return client.responses.create(
        model=os.environ["OPENAI_MODEL"], input=items,
        tools=[WEATHER_TOOL], store=False,
    )


ALLOWED = frozenset({"get_weather"})
answer = run_loop(
    request, lambda name, raw: dispatch(name, raw, allowed=ALLOWED),
    "查北京天气并建议穿搭；如是练习数据，请标注。",
)
print(answer)

本课选手动重放：原输入、完整输出 Items 和新的工具结果按顺序保留。用服务端 previous_response_id 是另一种做法；顶层 instructions 只作用于当前请求，不会自动继承。别混用两种状态方案，也不要改写不透明推理 Items。

接口请求与回填
Responses（主线）function_call → function_call_output + call_id
Chat Completions（兼容）保留带 message.tool_calls 的 assistant 消息 → role:"tool" + tool_call_id。只在模型支持此接口的工具能力时使用。
Claude Messages（原生）tool_use → tool_result + tool_use_id，不能跨协议套字段。

总结与参考

先验终态和预算，再按 ID 执行与回填。 正常状态、无拒答且有最终文字，才是这个文本循环的成功出口。同一轮多个调用属于同一份响应；跨轮依赖上一轮结果。隔日不用看代码，重建一次预算耗尽时「零新执行」的测试。
