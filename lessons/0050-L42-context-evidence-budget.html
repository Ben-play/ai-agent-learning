证据选择、来源与上下文预算

先挑能支持答案的完整证据，再决定哪些放得下

为什么这课重要？

客服助手收到一份保留期政策和一份同步时间表。如果两份都发给模型，下一步可能花钱处理无关内容；如果裁掉保留期政策的来源标记，即使答案正确也很难复查。本课处理这一轮放什么，不重讲 L30 的多轮历史裁剪。

学习目标

能构造一个带来源的完整证据片段，说明字节预算与模型 Token 预算的区别，并诊断缺证据、输入超限和错误引用。

1. 先按任务过滤，再按预算装入

  1. 相关性优先：保留期问题选 KB-01（具体天数），KB-02（过期后的下一步）是补充，无关的 KB-03（同步时间）不选。这里用固定映射，不是 RAG 或权限实现。
  2. 片段要完整：来源 ID 贴着原文一起放入上下文。若主证据放不下，就不发请求；若只放不下补充材料，可先保留主证据，不截断到剩下半句。
  3. 按实际发送量测：起始项目算提示、问题、证据和 JSON 序列化后的 UTF-8 字节，不是 Python 字符数，也不是 Token。线上要用目标接口的计数并预留输出。
  4. 原样核对引用：返回的 ID 必须属于本次发出的集合，摘录也须与原文匹配。ID 在整个知识库里存在，不等于这次有权使用或已经发过。

在起始项目，证据片段是字典 {"source_id": "KB-01", "quote": "导出文件生成后保留 7 天。"}；多个片段放进列表，再作为 evidence 加入请求。证据是待分析的数据，不是系统指令。分开组织便于检查，但分隔符不会替应用校验权限。引用吻合也不证明材料权威或推论正确；生产还要验来源权限和结论支持度。

最佳实践：不要为塞进预算删掉来源

保留「ID + 原文」这对最小单元，先尝试不带次要片段；连主证据都放不下时就报告预算不足，不将它伪装成缺证据。

Q 已有主证据，但本次输入预算装不下完整片段。应该怎样处理？
已有证据与放不下是两个状态。明确报告预算不足，调用方才知道是收紧内容、调整预算或改任务，而不是去重复检索。

missing = ask("导出文件能否恢复？")
assert missing["status"] == "needs_evidence" and missing["usage"]["adapter_calls"] == 0

# KB-03 在知识库里，但不是本次发出的证据。
def wrong_source(_payload):
    return json.dumps({"status": "completed", "citations": [
        {"source_id": "KB-03", "quote": "同步任务每天 02:00 运行。"},
    ]})

rejected = ask(question, adapter=wrong_source)
assert rejected["status"] == "invalid_response" and rejected["usage"]["adapter_calls"] == 1
assert rejected["answer"] is None and rejected["citations"] == []

面试自查

为何把来源和摘录放一起？

便于把回答映射回本次输入，而不是只找到一个可能无关的文档。

字节数为什么不能充当 Token 数？

不同分词器对相同序列的划分不同，且真实请求还有接口级开销；本地字节只是可复现的练习单位。

主证据放不下可以先选次要片段吗？

仅当它也足以支持任务时可以。此练习不能跳过主证据，避免以看似相关但不足的文本作答。

引用吻合就说明模型回答正确吗？

不说明；还要核对引用是否支持结论、材料是否获准使用且可信。
