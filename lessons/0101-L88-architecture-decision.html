记录架构决策：保留单 Agent 也有效

先固定业务合同，再用失败也入账的对照决定谁来选下一步

为什么这课重要？

L87 解决的是「升级遇到不支持的旧任务，谁来安全接续」。这次先不动旧任务，改问新请求的入口：客服只需回答「导出文件能保留多久、过期后怎么办」，真的需要 Agent 决定查哪条资料吗？如果用已经够用的流程也得到同一份证据，加一层编排就可能只是多付等待与维护成本。判断必须来自同一批请求，而不是让每个架构各挑顺手的示例。

学习目标

  • 区分固定读取、代码控制的 workflow 和按已读证据选下一步的受限单 Agent。
  • 用精确事实、独立调用账本和失败对照写一张能复议的架构决策卡。

1. 只改变谁决定下一步，不改变权限

三臂都跑 support-evidence-v1，按同一顺序执行六个合成请求，每个试次重新打开 Phase 7 的内存 SQLite（code/phase7-data-rag/rag-lab/lab.py 的 open_demo() 与 EvidenceStore.source()）。作用域为宿主固定的 (tenant, user)，按案型限定可读证据键，再由原 SQL 同时查租户、授予记录与精确版号、定位。support/mei 与 operations/mei 在不同租户看到同键不同文，不是同一个可共享的答案。这里没有草稿写入；若已有获批本地草稿，也只能由旧课的宿主按原绑定处理，并不因此需要另一个执行者。

2. 用分发事件算合成成本与 p95

每个请求同样最多 2 次读、1 次 worker（L88 不用）、12 个合成积分；其中 1 分留给可能的本地人工工单替身，不模拟人工响应。读前要能覆盖最坏的 3 分，实际按结果收费：命中或不可见为 2 分／8 模拟毫秒，超时尝试是 3 分／24 毫秒；一次选择是 1 分／3 毫秒，交人工是 1 分／5 毫秒。分发前拒绝的检查占 0 分／1 毫秒，但没有实际分发。计划中的步骤和被拦截的步骤不能算成已用调用。

例如 workflow 的 expiry-timeout 账本是「主政策读成功 → 附录适配器超时 → 交人工」，合计 6 分、37 毫秒。适配器调用了两次，但只有第一次真正进入 SQLite 的 source()；缺授权那一行则两次进入查询，第二次不返回文档。

验收分三步：先按金标核终态、原因、主体以及每条引文的作用域、键、原文和顺序；再核实际事件的顺序、状态、主体、分发标记与独立记录的 SQLite 读取；最后按独立价表核对每笔积分、模拟毫秒与合计，并单独检查积分、读次数和 worker 上限。答对的条数不受账本差错影响，但账本或预算不过关就不能推荐该臂。符合金标的拒绝或转人工是正确处理，不计作正确答复。

决策卡：先过硬门，再选最简单的达标方案

适用：新请求有可重复的作用域、事实标签与停机路径。不适用：本表不能为未迁移的旧检查点、真实模型或写入路径背书。

误判：最快或最灵活就上线

把未完成或缺权的案型移出统计，成本和尾时看起来都更低。

选择：同一批逐条核验

先比事实、作用域、预算、分发和正确停机；再比覆盖、成本与尾时。

  1. 写下当前决策：留 workflow；不引入委托；薄函数可单独服务已知键案型。
  2. 记录反证：若固定路径在新案型中确实漏掉合法证据，且经同批独立验收的单 Agent 补齐、未过限额，可以保留单 Agent。没有一臂达标就停止复核，不升权限。

交接：附工作负载版本、金标、失败账本和取舍理由，沿用 L76 的计量与 L79 的交接惯例。

Q 薄函数 p95 最小，但过期案型只能交人工。哪一项最能支持保留 workflow？
同一队列、同一金标才能比较资格；剔除失败会改变成本、尾时和结论。

面试自查

每题先给结论，再给能推翻结论的观测。

Q1 主政策和过期附录都是固定键，两个步骤就得用 Agent 吗？

参考回答：不由步骤数决定。若分支能先写定，固定 workflow 可覆盖。

追问：如果新增适用区域只能从主政策知道？

答题要点：先试把区域解析与映射写成规则，再对照有界选择，按同批精确引文检验增益。

Q2 两个租户引用同一个文档号能共用一条答复吗？

参考回答：不能。同键不同授权和原文，来源需要绑定作用域。

追问：哪一条本地反例可证明只比引文键不够？

答题要点：用运维 30 天替换客服 7 天，键相同但作用域和原文金标都应失败。

Q3 超时没有返回来源，应该从成本里扣掉吗？

参考回答：不应。读适配器实际调用过，且交人工也是一次事件。

追问：什么证据能说明没有再查询 SQLite？

答题要点：查 source_calls 只有主政策；不能从回答为空或看见 timeout 就推断没有任何分发。

Q4 单 Agent 补齐一个 workflow 失败样本，就能改默认吗？

参考回答：先过全批硬门，检查是否误用范围、超预算或使尾时不可接受，再写回访条件。

追问：若两臂都过不了边界，增加一个 Agent 审核可直接放行吗？

答题要点：不能。先安全停止，修复与重新验收宿主边界；审核不等于授权。
