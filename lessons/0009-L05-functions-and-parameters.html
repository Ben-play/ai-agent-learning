函数定义与参数

函数签名就是工具契约 — Agent 的每个工具，本质都是一个设计良好的函数

💡 为什么这课重要？

Agent 调用工具，本质是“按工具契约生成参数，由运行时校验并执行函数，再拿返回值”。一个工具函数的参数怎么设计——哪些必填、哪些有默认、能不能只用关键字传——直接决定了它好不好用、LLM 会不会传错参。

更关键的是：到 L11 你会给函数加 @tool 装饰器、到 L14 会用 Pydantic 描述参数，那时框架会从函数签名自动生成工具 Schema。所以「把函数签名设计好」不是基本功而已，它就是 Agent 工具契约的源头。这一课你会亲手设计一个搜索工具函数。

学习目标

完成本课后，你将能够：

  • 区分位置参数、关键字参数、默认参数，并知道何时用哪种
  • 用 * 和 / 强制"仅关键字"和"仅位置"参数，写出更安全的签名
  • 用 *args / **kwargs 接收可变数量参数
  • 用 * / ** 在调用处解包列表和字典
  • 设计一个类型清晰、参数合理的 Agent 工具函数

1. 位置、关键字与默认参数

函数参数有三种最基本的传法，Agent 工具函数天天用：

def search(query, max_results=5, safe=True):
    return (query, max_results, safe)

search("ai agents")              # 位置传参：("ai agents", 5, True)
search("ai agents", 10)          # 覆盖默认值：("ai agents", 10, True)
search("ai agents", safe=False)  # 关键字传参（跳过中间的默认参数）
  • 位置参数：按顺序对号入座（query）
  • 默认参数：定义时给了默认值（max_results=5），调用可省略
  • 关键字参数：调用时写 名字=值，顺序无所谓，可读性最好
🔑 Agent 开发关联：

这里其实有两条互相独立的轴，别混在一起：

  • 要不要传（必填/可选）：由「有没有默认值」决定——query 没默认值，因此必填；max_results=5 有默认值，因此可省略。
  • 怎么传（位置/关键字）：默认情况下，任何参数（不管必填还是可选）既可以按位置传，也可以按关键字传——除非专门用 / 或 * 做了限制（下一节讲）。

所以 query 是「必填，但既能位置传也能关键字传」，而不是"必填项=位置参数"。这样 LLM 生成调用时，最少只需给一个 query 就能跑，降低出错率。

Q search("ai", safe=False) 中 max_results 的值是？
跳过中间的默认参数、直接用关键字指定后面的参数，是完全合法的。max_results 没被传，就用默认值 5。这也是为什么"可选参数用关键字传"更清晰——不用为了传最后一个参数而把中间的都写全。

2. 仅关键字（*）与仅位置（/）

这是 Python 参数机制里很有用的一招，很多人不知道，但面试常考。注意： / 仅位置语法适合"不希望参数名成为 API 契约"的底层函数；LLM 工具参数来自 JSON 对象、靠 tool(**args) 解包调用，字段名本身就是契约的一部分，所以暴露给 LLM 的 Agent 工具参数不能设计成仅位置——下面先用一个纯 Python 函数演示 / 的语法，Agent 工具签名见后面的说明。

def greet(name, /, *, lang="zh"):
    return (name, lang)
  • / 之前的参数（name）：只能按位置传，不能写 name=
  • * 之后的参数（lang）：只能按关键字传
greet("小明", lang="en")          # ✅ 正确
greet("小明")                     # ✅ 正确（lang 用默认值）

greet("小明", "en")               # ❌ TypeError：lang 只能关键字传
greet(name="小明", lang="en")     # ❌ TypeError：name 只能位置传

决策：面向对象字段调用的工具参数不要设为仅位置

术语：映射解包是用 **mapping 把映射中的字符串键转换成关键字参数。LLM 工具调用的 JSON object 反序列化后通常成为 Python dict，因此字段名本身就是契约。

❌ 同一任务：query 仅位置
def positional_tool(query, /, *, limit=5):
    return {"query": query, "limit": limit}

payload = {"query": "agent", "limit": 3}
positional_tool(**payload)  # TypeError

query 在 / 前，对象字段不能绑定给它。

✅ 同一任务：字段可按关键字绑定
def keyword_tool(query, *, limit=5):
    return {"query": query, "limit": limit}

payload = {"query": "agent", "limit": 3}
keyword_tool(**payload)
# {"query": "agent", "limit": 3}

函数体、输入和结果目标都相同，只改变 query 的传法约束。

适用：参数来自 JSON object、dict、表单字段或其他具名映射时，让公开工具签名接受关键字。不适用：纯 Python 内部函数若只由人工位置调用，且不希望参数名成为 API，可以使用 /。成本：公开的参数名会成为兼容契约，重命名需要迁移调用方。替代方案：保留一个可按关键字调用的公开工具，在内部再转调仅位置的底层函数。

别混淆：*sequence 摊成位置参数；**mapping 摊成关键字参数。对 dict 使用单星号只会摊开键。

动手自检（独立复制运行）：
def positional_tool(query, /, *, limit=5):
    return {"query": query, "limit": limit}


def keyword_tool(query, *, limit=5):
    return {"query": query, "limit": limit}


payload = {"query": "agent", "limit": 3}
try:
    positional_tool(**payload)
except TypeError:
    pass
else:
    raise AssertionError("仅位置参数不应接受同名映射字段")

assert keyword_tool(**payload) == {
    "query": "agent",
    "limit": 3,
}

怎么看结果：同一个 payload 对仅位置签名失败、对关键字兼容签名成功。自检只验证异常类型，不依赖不同 Python 版本可能变化的完整错误文本。

💡 面试常见问题：

"函数签名里的 * 和 / 有什么用？"

答：* 强制其后参数只能用关键字传，/ 强制其前参数只能用位置传。* 的好处是把接口约束写进签名、调用更可读；它不依赖参数在签名中的排列顺序，但不能保护已有的位置调用 f(1, 2)——如果你调整了位置参数的顺序，f(1, 2) 的语义仍会跟着变。/ 则适合不希望参数名成为契约的场景，但和"参数名即契约"的 Agent 工具（tool(**args)）不兼容，不建议用在工具签名上。

Q 定义 def f(a, *, b):，哪个调用会报错？
* 之后的 b 是"仅关键字参数"，必须写成 b=值。f(1, 2) 试图把 2 按位置传给 b，触发 TypeError。其余三种都合法（a 既可位置也可关键字）。

3. *args 与 **kwargs：接收可变参数

当你不确定会传进来多少个参数时，用 *args（收成元组）和 **kwargs（收成字典）：

def log_call(name, *args, **kwargs):
    return name, args, kwargs

log_call("search", 1, 2, x=3)
# ("search", (1, 2), {"x": 3})
#           ↑ args      ↑ kwargs

约定俗成叫 args/kwargs，但真正起作用的是 * 和 **。框架里常用 **kwargs 透传中立的运行配置，例如 timeout、request_id 或日志选项；对外部参数仍应校验允许的键，避免把拼写错误悄悄吞掉。

🔑 Agent 开发关联：

装饰器（L11）几乎都写成 def wrapper(*args, **kwargs)——因为装饰器要能包装任意签名的函数，必须原样接收再转发所有参数。这一课的 *args/**kwargs 是理解装饰器的前置知识。

4. 参数解包：把列表/字典摊开传进去

* 和 ** 反过来用在调用处，就是"解包"——把容器摊开成一个个参数：

def make_msg(role, content):
    return {"role": role, "content": content}

# ** 把字典解包成关键字参数
data = {"role": "user", "content": "你好"}
make_msg(**data)              # 等价于 make_msg(role="user", content="你好")

# * 把列表解包成位置参数
args = ["assistant", "好的"]
make_msg(*args)               # 等价于 make_msg("assistant", "好的")
🔑 Agent 开发关联：

LLM 返回的工具调用参数通常是一个 dict（如 {"query": "...", "max_results": 5}）。有了 **，你可以直接 tool(**llm_args) 把它摊给工具函数，而不用手动一个个取字段。这是执行工具调用最常见的写法。

Q 已知 d = {"role": "user", "content": "hi"}，哪种写法把它摊给 make_msg？
**d 把字典解包成关键字参数（role="user", content="hi"）。注意 *d 解包的是字典的键（结果是 make_msg("role", "content")，语义错了）；直接 make_msg(d) 则是把整个字典当成第一个位置参数 role。

5. 返回值与两个陷阱

返回多个值（其实是元组）

def parse(resp):
    return resp["name"], resp["args"]   # 逗号 = 打包成元组

name, args = parse({"name": "search", "args": {"q": "x"}})   # 解包接收

没有 return、或只写 return，函数返回 None。

回归检查：可变默认参数

完整原理、None 合法值时的哨兵边界和正反示例已在 L03 · 可变与不可变类型 讲过。本课只保留一段函数级回归检查：

def collect(item, acc=None):
    if acc is None:
        acc = []
    acc.append(item)
    return acc

first = collect("a")
second = collect("b")
assert first == ["a"] and second == ["b"]
assert first is not second

签名复习要点：默认对象不能携带跨调用状态；两次调用的内容和对象身份都应独立。

6. 给签名加类型：工具契约成形

把类型注解加到参数和返回值上，签名就成了一份清晰的契约（类型细节在 L13/L14 深入）：

def search_tool(
    query: str,
    max_results: int = 5,
    *,
    filters: dict | None = None,
) -> dict:
    clean_query = query.strip()
    active_filters = {} if filters is None else dict(filters)
    return {
        "query": clean_query,
        "max_results": max_results,
        "filters": active_filters,
        "results": [],
    }

光看签名，IDE 和框架就能知道：query 必填字符串、max_results 可选整数默认 5、filters 是仅关键字的可选字典、函数声明返回 dict。框架可据此生成工具 Schema；LLM 实际看到的是工具名、描述和 JSON Schema 等契约信息，不是这段 Python 源码或函数体。此外，Python 类型注解默认只是元数据，不会自动做运行时类型校验：直接调用 search_tool(123) 仍会进入函数体，再因 123.strip() 不存在而报错。外部/LLM 输入仍需由框架、Pydantic 或手写代码校验。

最佳实践：把函数签名当作工具契约

术语：调用接口由函数名和签名共同表达；fn.__name__ 提供函数名，inspect.signature(fn) 表示参数名、注解、默认值、参数传法与返回注解。

❌ 含义要读函数体才知道
def search(q, n=5, **kw):
    ...

q、n、kw 的业务含义不清，Schema 能表达的信息也很少。

✅ 签名直接表达契约
def search(
    query: str,
    *,
    max_results: int = 5,
) -> dict:
    if not isinstance(query, str):
        raise TypeError("query must be str")
    return {
        "query": query,
        "max_results": max_results,
        "results": [],
    }

必填性、类型、默认值和仅关键字约束可被 IDE、静态分析器与 Schema 生成器读取；函数体另做运行时边界校验。

为什么更优：描述性参数名、注解、默认值和仅关键字约束提高了 Schema 表达力与静态可分析性；Python 的参数绑定还会明确拒绝缺少字段、未知字段和错误的传参方式。但注解本身不会在运行时验证值：query: str 不会自动拒绝整数，外部或 LLM 输入仍要由框架、Pydantic 或函数体显式校验。代价是签名更长，新增必填参数会破坏已有调用；仅在内部适配层确实需要代理开放选项时，才使用经过允许键校验的 **kwargs。

动手自检（签名、绑定与运行时边界）：
import inspect


def search(query: str, *, max_results: int = 5) -> dict:
    if not isinstance(query, str):
        raise TypeError("query must be str")
    if not isinstance(max_results, int) or isinstance(max_results, bool):
        raise TypeError("max_results must be int")
    return {
        "query": query,
        "max_results": max_results,
        "results": [],
    }


sig = inspect.signature(search)
assert search.__name__ == "search"
assert not hasattr(sig, "name")  # 函数名属于 callable，不属于 inspect.Signature
query_param = sig.parameters["query"]
max_param = sig.parameters["max_results"]
assert query_param.default is inspect.Parameter.empty  # 必填
assert query_param.annotation is str
assert max_param.default == 5
assert max_param.kind is inspect.Parameter.KEYWORD_ONLY
assert sig.return_annotation is dict

bound = sig.bind(**{"query": "python agent"})
bound.apply_defaults()
assert bound.arguments == {
    "query": "python agent",
    "max_results": 5,
}

for bad_args in ({}, {"query": "x", "unknown": True}):
    try:
        sig.bind(**bad_args)
    except TypeError:
        pass
    else:
        raise AssertionError("缺失或未知字段应在参数绑定时失败")

try:
    search(**{"query": 123})
except TypeError as exc:
    assert str(exc) == "query must be str"
else:
    raise AssertionError("手写边界校验应拒绝错误类型")


def annotated_only(value: str) -> str:
    return value


assert annotated_only(123) == 123  # 注解本身不做运行时校验

怎么看结果：search.__name__ 证明函数名；inspect.signature 证明必填、默认值、注解和仅关键字约束可被程序读取；bind 证明缺失/未知字段会触发绑定诊断；错误类型则由手写边界校验拒绝。最后一条断言刻意证明“只有注解”不会自动校验。

知识图谱

函数参数
├── 要不要传（必填/可选）
│   ├── 无默认值 → 必填（query）
│   └── 有默认值 → 可选（max_results=5）
├── 怎么传（位置/关键字，两者默认都可用）
│   ├── 仅位置 /  → / 之前只能位置传（不建议用于 Agent 工具）
│   ├── 仅关键字 * → * 之后只能关键字传
│   ├── *args   → 收成元组（可变数量位置参数）
│   └── **kwargs → 收成字典（可变数量关键字参数）

调用处解包
├── *列表  → 摊成位置参数
└── **字典 → 摊成关键字参数（tool(**llm_args)，要求字段非仅位置）

返回值
├── return a, b → 元组（解包接收）
├── 无 return → None
└── 陷阱：可变默认参数 → 用 None 兜（见 L03）

类型注解签名 → 工具契约雏形（→ L11 @tool / L14 Pydantic）

实战练习

练习：设计一个 Agent 搜索工具函数

设计一个搜索工具，接收搜索参数并返回结构化结果，重点练习参数设计。先自己写，再看答案。

raise ValueError("...") 会立刻中断当前函数，并把"参数值不合法"这件事交给调用方处理；完整的异常捕获与处理（try/except）留到 L10 学习，这里先知道"抛出即中断"就够了。

任务清单

  1. 签名：search_tool(query, max_results=5, *, filters=None)，并加上类型注解
  2. query 必填；filters 设计成"仅关键字"参数（避免被误按位置传）
  3. query 为空（或全空格）时抛 ValueError
  4. 把 max_results 夹到 1~50 之间（防止 LLM 传入夸张的值）
  5. filters 为 None 时用空字典兜（别用可变默认参数！）
  6. 返回一个 dict：包含 query、max_results、filters、results（模拟 max_results 条结果）
💡 点击查看参考答案

参考实现

def search_tool(
    query: str,
    max_results: int = 5,
    *,
    filters: dict | None = None,
) -> dict:
    if not query.strip():
        raise ValueError("query 不能为空")

    max_results = max(1, min(max_results, 50))   # 夹在 1~50
    filters = {} if filters is None else dict(filters)

    return {
        "query": query.strip(),
        "max_results": max_results,
        "filters": filters,
        "results": [f"result {i} for {query.strip()}"
                    for i in range(1, max_results + 1)],
    }


# 测试
r = search_tool("  ai agents  ", 3, filters={"lang": "zh"})
print(r["query"])        # ai agents（首尾空格已被 strip 清理掉）
print(r["max_results"])  # 3
print(len(r["results"])) # 3
print(search_tool("x", 999)["max_results"])  # 50  （被夹住）

为什么这样设计？

  • filters 用 * 强制关键字传：调用处必须写 filters=...，语义清楚，也防止和 max_results 传混。
  • 夹紧 max_results：LLM 可能生成 max_results=100000，工具自己要有防线。
  • 返回结构化 dict 而不是纯文本：方便 Agent 后续解析（呼应 L03 的 dict 操作）。

思考题

先自己想，再点开对答案。

Q1如果要支持"多个关键词"，你会把 query 改成 *queries 吗？有什么利弊？

大多数情况不建议。作为 Agent 工具，用 queries: list[str] 比 *queries 更合适。

*queries 的好处是人手写调用时清爽：search_tool("a", "b", "c") 不用套一层列表。Python 语法上确实允许 def f(max_results=5, *queries)——*queries 不强制排在最前面，也不会把 max_results 强制变成仅关键字。但对 Agent 工具来说这种接口难以通过 JSON 对象 + **args 表达：LLM 生成的工具调用参数是一个 JSON 对象（dict），形如 {"queries": [...], "max_results": 5}，然后靠 tool(**args) 解包。**args 摊开的是关键字参数，根本喂不进 *queries 这个位置收集器——不管它在签名里排第几位。

所以工具函数应写成 search_tool(queries: list[str], max_results=5, *, filters=None)：一个明确的 list[str] 字段，既能被 **args 干净地解包，也能在 L14 直接映射成 Pydantic 字段、导出成工具 Schema。*args 适合「人写的通用函数」，而 Agent 工具契约要的是「结构化、可被 dict 解包」的参数。

Q2这个签名到 L14 会怎样变成一个 Pydantic 的 SearchInput 模型？

把每个参数变成一个带类型注解的字段，默认值照搬，约束（如 1~50、非空）从函数体里的手写校验挪进字段声明。

大致长这样：class SearchInput(BaseModel): query: str; max_results: int = 5; filters: dict | None = None。函数签名里的「类型 + 默认值」几乎一一对应到 Pydantic 字段，这也是本课反复强调「函数签名就是工具契约雏形」的含义。

关键差别在校验：本课参考实现里手写的 if not query.strip(): raise ValueError 和 max(1, min(max_results, 50))，在 Pydantic 里改成声明式约束——max_results: int = Field(5, ge=1, le=50)，非空则用 min_length 或字段校验器。Pydantic 会在构造实例时自动校验并转换类型，非法输入直接报错。这正是「外部/LLM 输入用 Pydantic、内部数据用 dataclass」的分界；而且 SearchInput.model_json_schema() 一键导出的 JSON Schema，就是喂给 LLM 的工具参数描述。

def reserve_room(
    room: str,
    *,
    attendees: int,
    equipment: list[str] | None = None,
) -> dict:
    if not isinstance(room, str):
        raise TypeError("room must be str")
    clean_room = room.strip()
    if not clean_room:
        raise ValueError("room cannot be blank")
    if not isinstance(attendees, int) or isinstance(attendees, bool):
        raise TypeError("attendees must be int")
    if not 1 <= attendees <= 20:
        raise ValueError("attendees must be between 1 and 20")
    if equipment is not None and not isinstance(equipment, list):
        raise TypeError("equipment must be list or None")
    active_equipment = [] if equipment is None else list(equipment)
    if not all(isinstance(item, str) for item in active_equipment):
        raise TypeError("equipment items must be str")

    return {
        "room": clean_room,
        "attendees": attendees,
        "equipment": active_equipment,
        "status": "reserved",
    }


def expect_error(error_type, call):
    try:
        call()
    except error_type:
        pass
    else:
        raise AssertionError(f"expected {error_type.__name__}")

排错绑定错误和数据校验错误有什么区别？

绑定错误说明映射字段与函数签名不匹配；数据校验错误说明字段已经绑定，但值的类型或范围不符合工具规则。前者由 Python 签名拒绝，后者必须由框架、Pydantic 或函数体显式拒绝；不要用开放的 **kwargs 吞掉未知字段。

面试常见问题

Q1：*args 和 **kwargs 分别是什么？

答：*args 把多余的位置参数收成元组，**kwargs 把多余的关键字参数收成字典。用于接收不定数量的参数，也是装饰器包装任意函数签名的标准写法。

Q2：函数签名里的 * 和 / 各是什么作用？

答：* 之后的参数只能按关键字传（keyword-only），/ 之前的参数只能按位置传（positional-only）。作用是把接口约束写进签名；* 的调用不依赖参数在签名中的排列顺序，但它不能保护已有的位置调用 f(1, 2) 在你调整位置参数顺序后仍保持语义。/ 适合不希望参数名成为 API 契约的底层函数，但和 Agent 工具「靠字段名 + tool(**args) 解包」的调用方式不兼容，不建议用在工具签名上。

Q3：为什么默认参数不能用可变对象？

答：默认值在函数定义时只创建一次，之后所有调用共享同一个对象。用可变对象（list/dict）会导致跨调用状态串扰。正确做法是默认写 None，在函数体内创建新对象。

Q4：调用处的 * 和 ** 是干嘛的？

答：解包。*列表 把序列摊成位置参数，**字典 把字典摊成关键字参数。执行 LLM 工具调用时常写 tool(**llm_args)，把参数字典直接摊给工具函数。

Q5：Python 函数能返回多个值吗？

答：能，但本质是返回一个元组。return a, b 打包成 (a, b)，调用处用 x, y = f() 解包接收。没有 return 时返回 None。

总结

  • 必填/可选由「有没有默认值」决定，怎么传（位置/关键字）是另一条独立的轴——默认两者都可用
