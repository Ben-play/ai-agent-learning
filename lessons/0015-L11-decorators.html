装饰器 — Agent 框架的基石

@tool、@chain、@agent 都是装饰器 — 看懂它，你就看懂了半个框架源码

💡 为什么这课重要？

翻开任何 Agent 框架，满眼都是 @tool、@chain、@agent、@retry——它们全是装饰器。装饰器让你"给函数加一层包装"而不改函数本身：加日志、加重试、加计时、把普通函数注册成工具。

本课是 Part B 的收官，也是闭包（L06）的实战出口：本课聚焦函数装饰器——接收一个 callable、返回一个替代对象，最常见的实现是返回记住了原函数的闭包 wrapper。但这不是绝对定义：装饰器也能作用在类上（如 @dataclass），返回值也不一定是"新函数"或闭包。学完你会用一个已提供的签名/Schema 构建器完成 @tool 注册装饰器——重点是装饰器如何安全地改变注册表，而不是提前实现 L13/L14 的反射与类型系统。

学习目标

完成本课后，你将能够：

  • 解释装饰器的本质（闭包 + 高阶函数）
  • 写基础装饰器，并用 functools.wraps 保留元信息
  • 写带参数的装饰器（三层结构）
  • 理解多层装饰器的叠放顺序
  • 使用已提供的 Schema 构建器，实现失败安全的 @tool 注册

1. 装饰器的本质（本课聚焦函数装饰器）

本课聚焦函数装饰器：接收一个 callable、返回一个替代对象；最常见的实现是返回一个记住了原函数的 wrapper 闭包。@deco 只是 fn = deco(fn) 的语法糖：

import functools

def timed(fn):
    @functools.wraps(fn)              # 保留原函数的名字/文档（关键！）
    def wrapper(*args, **kwargs):     # 用 *args/**kwargs 接住任意签名（呼应 L05）
        import time
        start = time.perf_counter()
        result = fn(*args, **kwargs)  # 调用原函数
        dur = time.perf_counter() - start
        print(f"{fn.__name__} 耗时 {dur:.4f}s")
        return result
    return wrapper                    # 返回的 wrapper 是个闭包（记住了 fn）

@timed
def search(query):
    return f"结果: {query}"

# 等价于 search = timed(search)
search("ai")                # search 耗时 0.0000s
print(search.__name__)      # search  ← 因为用了 wraps，否则会变成 'wrapper'

三个要点：① wrapper 是闭包（记住了外层的 fn）；② 用 *args/**kwargs 才能包装任意函数；③ 一定加 @functools.wraps(fn)，否则被装饰函数的 __name__、__doc__ 会被 wrapper 覆盖。

装饰器不止能装饰函数：装饰器语法（@X）本质上只是"把下面这个对象传给 X、再把返回值绑回同一个名字"，X 可以作用于函数，也可以作用于类。例如 @dataclass 装饰的是一个类，返回的也是（改造过的）类本身，而不是函数或闭包。本课后续例子都聚焦"函数装饰器"这一种最常见的形态，但请记住这不是装饰器的全部定义。

Q @deco 写在 def f 上方，等价于什么？
@deco 是语法糖，等价于把 f 传给 deco、再把返回值赋回 f——即 f = deco(f)。之后你调用的 f 其实是装饰器返回的新函数（通常是个闭包 wrapper）。

2. 带参数的装饰器（三层）

想写 @tag(label="audit") 这种“能传参”的装饰器，需要多一层：最外层收参数，返回一个真正的装饰器。这里选无副作用的标记示例，避免把“重试所有异常”误教成默认做法；若业务确需重试，应沿用 L10 的异常边界，只捕获明确可恢复的异常（如 TemporaryError）。

import functools

def tag(label):                       # ① 收装饰器参数
    def deco(fn):                     # ② 真正的装饰器（收函数）
        @functools.wraps(fn)
        def wrapper(*args, **kwargs): # ③ 包装逻辑
            return fn(*args, **kwargs)
        wrapper.audit_label = label
        return wrapper
    return deco

@tag(label="audit")                  # 先调用 tag(...) 得到 deco，再用 deco 装饰
def save_report(path):
    return path

assert save_report.audit_label == "audit"

记忆：不带参数的装饰器两层，带参数的三层。多出来的最外层就是用来“接收装饰器自己的参数”。

3. 多层装饰器的顺序

@timed              # 后套上（外层）
@tag(label="audit") # 先套上（内层，离函数近）
def call():
    ...

# 等价于：call = timed(tag(label="audit")(call))
# 装饰：自下而上包裹；调用：自上而下进入

规则：离函数最近的装饰器最先"套"上去（内层），最上面的最后套（最外层）。运行时，请求从最外层往里穿过每一层。

💡 面试常见问题：

"为什么装饰器里几乎总要写 @functools.wraps(fn)？"

答：wraps 会按 functools.update_wrapper 的规则复制指定元数据（如 __name__、__doc__、__annotations__），更新 wrapper 的属性字典，并设置 __wrapped__ 指向原函数。它不是把签名对象直接复制过来；inspect.signature 默认沿 __wrapped__ 链取得原签名。这样调试、文档和依赖反射生成工具 Schema 的框架才能看到原函数契约。

4. @tool：先构建完整条目，再提交注册

Agent 框架常用装饰器把普通函数变成工具。本课只追踪一条主线：装饰器先构建并验证完整的中立条目，全部成功后才写入注册表一次。

📌 本课给定的 machinery

inspect.signature、get_type_hints 和 build_schema 视为已提供组件，不要求现在自行实现。当前构建器只支持 str/int/float/bool 四种标量类型；只接受可用对象键表达的普通参数与 keyword-only 参数。复杂 typing 留到 L13，Pydantic Schema 与运行时校验留到 L14。

下面是本课唯一的规范实现。Schema 与“通过关键字传入参数”的工具契约一致：对象拒绝未声明字段（additionalProperties: False）。

import copy
import functools
import inspect
from typing import get_type_hints


class CountingRegistry(dict):
    def __init__(self):
        super().__init__()
        self.writes = 0

    def __setitem__(self, key, value):
        self.writes += 1
        super().__setitem__(key, value)


REGISTRY = CountingRegistry()
TYPE_MAP = {str: "string", int: "integer", float: "number", bool: "boolean"}
ALLOWED_KINDS = {
    inspect.Parameter.POSITIONAL_OR_KEYWORD,
    inspect.Parameter.KEYWORD_ONLY,
}


def build_schema(fn):
    """课程提供的简化 machinery：只表达四种标量类型。"""
    hints = get_type_hints(fn)
    properties, required = {}, []
    for name, parameter in inspect.signature(fn).parameters.items():
        if parameter.kind not in ALLOWED_KINDS:
            raise TypeError(
                f"参数 `{name}` 的 kind={parameter.kind.name} 不受支持"
            )
        annotation = hints.get(name, inspect.Parameter.empty)
        if annotation is inspect.Parameter.empty:
            raise TypeError(f"参数 `{name}` 缺少类型注解")
        if annotation not in TYPE_MAP:
            raise TypeError(f"参数 `{name}` 的类型 {annotation!r} 不受支持")
        properties[name] = {"type": TYPE_MAP[annotation]}
        if parameter.default is inspect.Parameter.empty:
            required.append(name)
    return {
        "type": "object",
        "properties": properties,
        "required": required,
        "additionalProperties": False,
    }


def tool(fn):
    name = fn.__name__
    if name in REGISTRY:
        raise ValueError(f"工具 `{name}` 已注册")

    input_schema = build_schema(fn)  # 这里及之前都可能失败

    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)

    entry = {                       # 先得到完整候选条目
        "fn": wrapper,
        "name": name,
        "description": (fn.__doc__ or "").strip(),
        "input_schema": input_schema,
    }
    REGISTRY[name] = entry          # 唯一一次共享状态写入
    return wrapper


def to_openai_chat_completions_tool(entry):
    """OpenAI Chat Completions endpoint 的 tools[] 元素。"""
    return {"type": "function", "function": {
        "name": entry["name"],
        "description": entry["description"],
        "parameters": copy.deepcopy(entry["input_schema"]),
    }}


def to_anthropic_messages_tool(entry):
    """Anthropic Messages API 的 tools[] 元素。"""
    return {
        "name": entry["name"],
        "description": entry["description"],
        "input_schema": copy.deepcopy(entry["input_schema"]),
    }

最佳实践：build + validate 完整条目，然后 single-writer commit

唯一决策：所有可能失败的工作——重复名称检查、签名解析、类型支持检查、Schema 构建、wrapper 与条目构建——都必须发生在 REGISTRY[name] = entry 之前。缺注解、list[str]、不支持的参数 kind 或重复名称一旦失败，registry 应与调用前完全相同。

❌ 先写再补
REGISTRY[name] = {"fn": fn}
REGISTRY[name]["input_schema"] = build_schema(fn)

后一步抛错时，会留下缺字段的半成品。

✅ 完整候选只提交一次
entry = build_and_validate_entry(fn)
REGISTRY[name] = entry

失败发生在写入前；成功路径只有一个写点。

为什么更优：先在局部变量中完成构建与验证，再执行唯一共享写入，使任一构建失败都无法暴露半成品，保护 registry 完整性、可诊断性与测试隔离。代价是要先构造完整候选，并维护失败分支和写入次数证据；对于不会失败、没有共享状态的简单映射，可直接返回值而不引入注册阶段。这里仅保证单写者场景下的失败安全，不是并发原子性；多个写者并发注册应改用锁、串行初始化或其他同步方案。

    assert REGISTRY == before == baseline
    assert REGISTRY.writes == baseline_writes
    assert REGISTRY.writes == baseline_writes  # 失败路径零写入

🔑 中立 registry，endpoint-specific adapter

registry 精确保存 fn/name/description/input_schema。发送时才转换：OpenAI Chat Completions endpoint 使用 type → function → parameters；Anthropic Messages API 使用顶层 name/description/input_schema。adapter 返回副本，不修改 registry。

⚠️ Schema 不是运行时参数校验

这个 wrapper 只是把 *args/**kwargs 原样传给函数。Schema 描述发给模型的参数契约，但直接调用工具时不会自动拦截错误类型；真正的执行前校验留到 L14。

Q @tool 装饰器靠什么读出函数的参数信息？
用 inspect.signature(fn) 读取函数的参数名、类型注解、默认值——这是"反射"。装饰器据此生成中立的工具描述（registry），发送前再由 OpenAI/Anthropic 各自的 adapter 转成对应请求格式；这份 Schema 本身不做运行时校验。这也是为什么 L05 强调"函数签名就是工具契约"、以及为什么装饰器必须用 functools.wraps 保住元信息。

知识图谱

函数装饰器
├── @deco 等价于 f = deco(f)
├── wrapper 闭包记住 fn；*args/**kwargs 转发调用
├── functools.wraps 保留元信息与 __wrapped__ 链
├── 带参数装饰器：参数层 → 装饰器层 → wrapper 层
└── 多层装饰器：装饰自下而上，调用自外向内

@tool 注册
├── 给定 machinery：inspect / get_type_hints / build_schema
├── 当前只支持 str / int / float / bool
├── 完整构建与验证 → registry 唯一写入
├── 中立条目：fn / name / description / input_schema
├── OpenAI Chat Completions：function.parameters
├── Anthropic Messages：input_schema
└── Schema 是描述；运行时校验留到 L14

TRACE = []


def traced(label):
    def decorate(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            TRACE.append(f"enter:{label}")
            try:
                return fn(*args, **kwargs)
            finally:
                TRACE.append(f"exit:{label}")
        return wrapper
    return decorate


@traced("outer")
@traced("inner")
def normalize_zone(zone: str) -> str:
    "物流分区标准化。"
    TRACE.append("body")
    return zone.upper()

import copy
import functools
import inspect
from typing import get_type_hints


class CountingRegistry(dict):
    def __init__(self):
        super().__init__()
        self.writes = 0

    def __setitem__(self, key, value):
        self.writes += 1
        super().__setitem__(key, value)


REGISTRY = CountingRegistry()
TYPE_MAP = {str: "string", int: "integer", float: "number", bool: "boolean"}
ALLOWED_KINDS = {
    inspect.Parameter.POSITIONAL_OR_KEYWORD,
    inspect.Parameter.KEYWORD_ONLY,
}


def build_schema(fn):
    hints = get_type_hints(fn)
    properties, required = {}, []
    for name, parameter in inspect.signature(fn).parameters.items():
        if parameter.kind not in ALLOWED_KINDS:
            raise TypeError(f"bad parameter kind: {name}:{parameter.kind.name}")
        annotation = hints.get(name, inspect.Parameter.empty)
        if annotation is inspect.Parameter.empty:
            raise TypeError(f"missing annotation: {name}")
        if annotation not in TYPE_MAP:
            raise TypeError(f"unsupported annotation: {name}:{annotation!r}")
        properties[name] = {"type": TYPE_MAP[annotation]}
        if parameter.default is inspect.Parameter.empty:
            required.append(name)
    return {
        "type": "object",
        "properties": properties,
        "required": required,
        "additionalProperties": False,
    }


def tool(fn):
    name = fn.__name__
    if name in REGISTRY:
        raise ValueError(f"duplicate tool: {name}")
    schema = build_schema(fn)

    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)

    entry = {
        "fn": wrapper,
        "name": name,
        "description": (fn.__doc__ or "").strip(),
        "input_schema": schema,
    }
    REGISTRY[name] = entry
    return wrapper


def execute(name, arguments):
    entry = REGISTRY.get(name)
    if entry is None:
        raise KeyError(f"unknown tool: {name}")
    return entry["fn"](**arguments)


@tool
def add(a: int, b: int) -> int:
    "两数相加。"
    return a + b


assert execute("add", {"a": 2, "b": 3}) == 5
executor_identity = execute
executor_code = execute.__code__.co_code
writes_before_extension = REGISTRY.writes


@tool
def join(parts: str, *, suffix: str = "") -> str:
    "拼接文本。"
    return parts + suffix


assert execute is executor_identity
assert execute.__code__.co_code == executor_code
assert execute("join", {"parts": "A", "suffix": "I"}) == "AI"
assert REGISTRY.writes == writes_before_extension + 1
assert REGISTRY["join"]["fn"] is join

baseline = copy.deepcopy(REGISTRY)
baseline_writes = REGISTRY.writes


def expect_rejected(fn, error_type, message_part):
    before = copy.deepcopy(REGISTRY)
    writes_before = REGISTRY.writes
    try:
        tool(fn)
    except error_type as exc:
        assert message_part in str(exc)
    else:
        raise AssertionError(f"{fn.__name__} should be rejected")
    assert REGISTRY == before == baseline
    assert REGISTRY.writes == writes_before == baseline_writes


def duplicate(value: str):
    return value


def bad_signature(*values: str):
    return values


def unsupported(tags: list[str]):
    return tags


duplicate.__name__ = "join"
expect_rejected(duplicate, ValueError, "duplicate tool: join")
expect_rejected(bad_signature, TypeError, "VAR_POSITIONAL")
expect_rejected(unsupported, TypeError, "unsupported annotation: tags")

面试常见问题

Q1：装饰器的本质是什么？

答：本课聚焦函数装饰器——接收一个 callable、返回一个替代对象；常见实现是返回记住了原函数的闭包 wrapper。@deco 等价于 f = deco(f)，用来在不改原函数的前提下增强它。但装饰器不止能用于函数：作用于类（如 @dataclass）时返回值也是类本身，不是函数或闭包。

Q2：为什么装饰器要用 functools.wraps？

答：wraps 复制指定元数据并设置 __wrapped__；inspect.signature 默认沿这条链读取原签名。否则外界只看到 wrapper 自己的名字、文档和签名，调试、文档及依赖反射的框架都会受影响。

Q3：带参数的装饰器和不带参数的结构差别？

答：不带参数两层（装饰器 → wrapper）；带参数三层（收参数 → 装饰器 → wrapper），最外层负责接收装饰器自己的参数。

Q4：@a @b def f 的执行顺序？

答：等价 f = a(b(f))。装饰时离函数近的 b 先套上（内层），a 后套（外层）；调用时从外层 a 往里穿过。

Q5：装饰器 wrapper 为什么常写成 (*args, **kwargs)？

答：为了能包装任意签名的函数——原样接收所有位置/关键字参数再转发给原函数，不限制被装饰函数长什么样。

Q6：工具 Schema 存进 registry 后，能直接发给 OpenAI 和 Anthropic 吗？

答：不能直接混用。registry 精确保存中立字段 fn/name/description/input_schema；OpenAI Chat Completions endpoint 的工具要包成 type/function/parameters，Anthropic Messages API 的工具使用顶层 name/description/input_schema。adapter 只在发送边界转换且不修改 registry；Schema 仍只是描述，不会自动校验运行时实参。

总结

  • 本课聚焦函数装饰器：接收 callable、返回替代对象（常见实现是返回闭包 wrapper）；@deco 即 f=deco(f)；装饰器也可作用于类（如 @dataclass），返回值不一定是新函数/闭包

  • 带参数的装饰器是三层结构
  • 多层装饰器：离函数近的先套，调用自外向内
