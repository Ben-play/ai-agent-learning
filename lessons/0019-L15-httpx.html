用 httpx 发起 HTTP 请求

每一次 LLM 调用、每个联网工具，本质都是一个 HTTP 请求

💡 为什么这课重要？

你调 OpenAI/Anthropic 的 SDK，底层就是在发 HTTP 请求：带上 API Key 的 header、JSON 请求体、处理状态码、读回 JSON。你写的每个"联网工具"（搜索、查天气、调内部 API）也一样。HTTP 是 Agent 的传输层地基。

2026 年首选的 Python HTTP 客户端是 httpx——因为它同时支持同步和异步（下一课并发调用要用），API 和老牌的 requests 几乎一样。

※ 本课代码需先安装 httpx：uv add httpx（或 pip install httpx）。httpx 也是 OpenAI/Anthropic 官方 SDK 内部使用的客户端。

学习目标

完成本课后，你将能够：

  • 理解 HTTP 请求的组成：方法、URL、headers、body、状态码
  • 用 httpx 发 GET/POST，带 headers 和 JSON body
  • 按状态码分类处理错误（4xx/5xx/超时）
  • 用 AsyncClient 写异步请求
  • 了解 SSE 流式响应怎么读（LLM streaming 的传输层）

1. HTTP 请求的组成

一次请求就是这几样：

  • 方法：GET（取数据）、POST（提交数据）为主
  • URL：请求哪个地址
  • Headers：元信息，如 Authorization: Bearer <key>（鉴权）、Content-Type: application/json
  • Body：请求体，调 LLM 时是一段 JSON（prompt、参数）

响应回来则有：状态码（200 成功 / 4xx 你错了 / 5xx 服务端错了）、响应 headers、响应 body（通常是 JSON）。

2. httpx 基础：GET / POST

import httpx

# 简单 GET
r = httpx.get("https://api.example.com/status", timeout=10)
print(r.status_code)       # 200
print(r.json())            # 自动把响应体解析成 dict

# POST：带鉴权 header + JSON body（模拟调 LLM）
resp = httpx.post(
    "https://api.example.com/v1/chat",
    headers={"Authorization": "Bearer sk-xxx"},
    json={"model": "claude", "messages": [{"role": "user", "content": "你好"}]},
    timeout=30,
)
data = resp.json()

复用连接：要发多个请求时，用 Client() 复用底层连接（更快），并集中配置 base_url / headers / timeout：

with httpx.Client(
    base_url="https://api.example.com",
    headers={"Authorization": "Bearer sk-xxx"},
    timeout=30,
) as client:
    a = client.post("/v1/chat", json={"messages": [...]})
    b = client.post("/v1/chat", json={"messages": [...]})   # 复用连接
# with 结束自动关闭（呼应 L10 的上下文管理器）
Q 调 LLM 时，API Key 通常放在请求的哪部分？
API Key 通常放在请求头 Authorization: Bearer <key>。放进 URL 会被日志/浏览器历史记录泄露，不安全。Headers 携带鉴权与元信息（Content-Type 等），Body 携带实际数据。

3. 按状态码处理错误

import httpx

try:
    r = httpx.post(url, json=payload, timeout=30)
    r.raise_for_status()             # 4xx/5xx 会抛 HTTPStatusError
    data = r.json()
except httpx.TimeoutException:
    ...                              # 超时：可重试（配合 L10 的 tenacity）
except httpx.HTTPStatusError as e:
    code = e.response.status_code
    if code == 429:
        ...                          # 限流：退避后重试
    elif 500 <= code < 600:
        ...                          # 服务端错误：可重试
    else:
        ...                          # 4xx 客户端错误(如 401 鉴权失败)：别重试，是你的问题
except httpx.RequestError:
    ...                              # 连接层错误(DNS、断网)
🔑 Agent 开发关联：

Agent 调 LLM 的可靠性全在这里：429（限流）和 5xx（服务端）该退避重试，4xx（如 401/400，你自己的问题）不该重试。这决定了你的 Agent 是"偶尔抽风就崩"还是"扛得住网络抖动"。重试逻辑用 L10 的 tenacity 包一层最省事。

4. AsyncClient：异步请求

httpx 的杀手锏是原生异步——把 Client 换成 AsyncClient，请求前加 await。这是下一课"并发调用多个 LLM"的基础：

import httpx, asyncio

async def call(prompt):
    async with httpx.AsyncClient(timeout=30) as client:
        r = await client.post(url, json={"prompt": prompt})   # await 非阻塞
        return r.json()

# 单个
asyncio.run(call("你好"))

同步版会"一个请求干等着"；异步版在等网络时能去干别的——所以能同时发很多请求（L16 详解）。

Q 收到状态码 429，Agent 通常应该怎么做？
429 = Too Many Requests（限流），是临时性的，正确做法是等一会儿（指数退避）再重试。相对地，4xx 里的 400/401 是你自己请求有问题（参数错/鉴权失败），重试没用，应直接修。

5. SSE 流式响应（了解）

LLM 的流式输出走的是 SSE（Server-Sent Events）：响应不是一次性返回，而是持续推送多行 data: {...}。用 httpx 的流式接口逐行读：

import json, httpx

with httpx.stream("POST", url, json={"stream": True}, timeout=None) as r:
    for line in r.iter_lines():
        if line.startswith("data: "):
            chunk = line.removeprefix("data: ")     # 剥掉前缀(呼应 L04)
            if chunk == "[DONE]":
                break
            event = json.loads(chunk)               # 逐块解析(呼应 L09)
            # 取出增量 token 显示...

看出来了吗——这正好把前面学的串起来：生成器思维（L12）+ 字符串处理（L04）+ 流式 JSON 解析（L09）+ HTTP 传输（本课）。

知识图谱

HTTP 请求组成
├── 方法(GET/POST) + URL
├── Headers → Authorization: Bearer key(鉴权) / Content-Type
├── Body → JSON(prompt+参数)
└── 响应：状态码 + headers + body(JSON)

httpx（pip install httpx）
├── get/post(headers=, json=, timeout=)
├── Client(base_url, headers, timeout) → 复用连接(with 自动关)
├── r.status_code / r.json() / r.raise_for_status()
├── 错误：TimeoutException / HTTPStatusError / RequestError
└── AsyncClient + await → 异步(→ L16 并发)

状态码策略
├── 2xx 成功
├── 429 限流 / 5xx 服务端 → 退避重试(tenacity)
└── 4xx(400/401) 你的问题 → 别重试

SSE 流式 → iter_lines + removeprefix("data: ") + json.loads

import httpx

BASE = "https://api.example.com"
HEADERS = {"Authorization": "Bearer sk-xxx"}

class LLMError(Exception):
    def __init__(self, msg, retryable: bool):
        super().__init__(msg)
        self.retryable = retryable      # 调用方据此决定要不要重试

def _parse(r: httpx.Response) -> str:
    try:
        r.raise_for_status()
    except httpx.HTTPStatusError as e:
        code = e.response.status_code
        retryable = code == 429 or 500 <= code < 600
        raise LLMError(f"HTTP {code}", retryable) from e
    return r.json()["choices"][0]["message"]["content"]

def chat(prompt: str) -> str:
    payload = {"model": "claude", "messages": [{"role": "user", "content": prompt}]}
    try:
        with httpx.Client(base_url=BASE, headers=HEADERS, timeout=30) as client:
            r = client.post("/v1/chat", json=payload)
    except httpx.TimeoutException as e:
        raise LLMError("timeout", retryable=True) from e
    return _parse(r)

async def achat(prompt: str) -> str:
    payload = {"model": "claude", "messages": [{"role": "user", "content": prompt}]}
    async with httpx.AsyncClient(base_url=BASE, headers=HEADERS, timeout=30) as client:
        r = await client.post("/v1/chat", json=payload)
    return _parse(r)

面试常见问题

Q1：为什么 2026 年选 httpx 而不是 requests？

答：httpx API 和 requests 几乎一样，但原生支持异步（AsyncClient），还支持 HTTP/2、连接池、超时更完善。Agent 要并发调 LLM，异步是刚需，所以选 httpx。

Q2：HTTP 状态码 4xx 和 5xx 的区别？各怎么处理？

答：4xx 是客户端错误（400 参数错、401 鉴权失败、429 限流），5xx 是服务端错误。429 和 5xx 通常临时性、可退避重试；其他 4xx 是你自己的问题，重试无用，应修正请求。

Q3：调 LLM 的 API Key 放哪里？为什么？

答：放请求头 Authorization: Bearer <key>。放 URL 会被日志和历史泄露；放 header 是标准且相对安全的做法（再配合环境变量管理，别硬编码）。

Q4：什么是 SSE？和 LLM streaming 什么关系？

答：SSE（Server-Sent Events）是服务端持续推送多行 data: 事件的协议。LLM 流式输出就走 SSE——逐行读、剥掉 data: 前缀、解析 JSON、取增量 token 显示。

总结

  • HTTP 请求 = 方法 + URL + Headers(鉴权) + Body(JSON)；响应看状态码
  • httpx：get/post(headers=, json=, timeout=)，多请求用 Client 复用连接
  • raise_for_status() + 分类捕获 TimeoutException / HTTPStatusError
  • 429/5xx 退避重试，4xx（你的问题）不重试
  • AsyncClient + await 是并发调 LLM 的基础（→ L16）
  • SSE 流式 = iter_lines + 剥 data: 前缀 + 解析 JSON（串起 L04/L09/L12）
