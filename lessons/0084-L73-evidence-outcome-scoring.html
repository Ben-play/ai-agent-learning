第八阶段 · Agent 工程化35分钟

证据与环境终态评分

用获准原文验证答复，用写入边界和持久状态验证动作

为什么不能用一份好看的轨迹当验收结果？

客服答对了「导出保留七天」，但引用指向不存在的段落；草稿代理说「未写入」，数据库里也确实没有新记录，但它可能尝试了写入，只是事务失败。两者的共同问题是把一个看得见的信号当成了足够的证明。

学习目标

  • 能分开诊断当前授权、定位、原文、入包、事实值和支持。
  • 能解释旧草稿何时要重验来源，并区分阻止提交和不再返回已保存内容。
  • 能对照真实插入尝试和独立落盘读回，区分拒绝和回滚。

1. 让引用能在指定主体与快照下复查

沿用阶段七的合成语料，交班卡问导出保留期与同步时间。第一条金标是 support 租户的 EXPORT-POLICY v1 §1，原文「导出文件生成后保留 7 天。」；第二条是 SYNC-POLICY v1 §1，原文「同步任务每天 02:00 运行。」。这不是让评分器从候选答复提取数字作标准，金标在任务文件中预先标注，检索则走现有资料库的授权查询；候选是把包内合成事实转成结构化答复的脚本，不是模型。两个路径复用合成事实，但不会用候选回传的内容覆盖金标或资料库。

定位：按本轮受信的租户和用户，以及文档号、版本和段落查询；不能让答复里自填的租户切换主体。引文：定位查到后，核对整段逐字相等；删除一个词也要失败。这里没有对短引文的容错规则。入包：资料库可读仍不能证明该片段送进了候选；保留实际证据包，并检查引用出现在包中。事实与支持：核对数值，再核对人工指定的事实与段落配对。拿同步原文证明保留期，定位、原文和入包都过，但不构成支持。若库中有证据而没有被包送入，也不能从库补齐后给候选打通过。留存各轴，团队才能区分授权、版本映射、组包和事实生成的问题。

缺证的正确表现不是给一个泛泛的「无法回答」，而是根据任务契约标明缺失事实。验收用例中 Lin 问过期处理，词法候选里没有获准的过期政策；猜对实际业务值也无法免责。评分同时核对回答形状、事实集合和缺口，避免空答复因为没有错误断言而通过。即使答复省略了某条引用，证据包若包含越权内容仍须失败；不能用最后一句无害的话把上游权限问题抹掉。

2. 从实际写入入口和数据库读取不同事实

阶段五的本地草稿工作流把提议、检查点和保存记录分开。待审批本来就要写检查点，这是允许的状态更新；本课计数的是保存草稿的插入尝试，不是所有 SQL 写操作。使用已有的 on_draft_write_attempt 观察器，在草稿插入语句之前记录真实执行路径。另开连接读取所有作用域已提交的草稿行，同时校验作用域、任务键、操作编号及内容。候选自述「没写」不当证据；硬编码一串步骤也不当这次的轨迹。写入观察器有范围，本实验不涉及其他表、远程工具或生产系统，不能从零次草稿写入推断全系统没有副作用。

旧草稿由阶段五实际生成。宿主在待审批事务开启前用 before_stage 核对草稿标题、正文和旧来源 ID，再用阶段七资料库按当前主体核验各个映射的版本、段落与整段原文。映射不是从请求、候选或金标推断的：例如 KB-02 的「超过保留期需重新发起导出。」是受审的旧改写，当前要求 EXPORT-OPS v1 §2 的原文「导出文件过期后，需重新发起导出。」；两句不冒充逐字相等。Lin 能读保留期，但不能读过期处理，因此导出草稿不显示、不暂存。未知来源、无法核对的正文、撤权或修订均不自动换新来源。

预览返回前重验；批准保存和返回已存草稿时，也根据数据库读回的实际检查点重验。待审批后撤权或修订，批准不能触发插入；拒绝仍可结束待审批，不释放正文。提交后丢回包，来源保持有效时 replayed 返回同一操作编号和草稿；若之后才撤权，replay_withheld 不返回草稿，已提交记录保留，零次新插入。这里由离线宿主顺序执行资料变更和审批，不是跨库并发原子性的保证。

回滚对照不同：在临时库里放一个固定触发器，让已批准路径实际走到插入入口，随后事务中止，结果为一次尝试、零条记录。故障注入不发生在拒绝路径。

评分优先用可核对的结果，但不强制内部步骤除了必要契约以外都相同。例如两种实现可以用不同查询或不同中间状态生成同一草稿；只要满足审批前不触发保存、提交内容准确、重放不重复落盘等边界，就不因轨迹形状不同扣分。相反，如果关键观察缺失，报告应标记试验不能验收，而不能把没有记录视为没有发生。阶段八前两课的轨迹和关联键在这里服务于诊断，不是业务终态的替代品。

决策卡：证据和副作用单独验收

适用：同一代理可答复也可保存草稿。边界：只声明观测到的存储边界，轨迹只用来定位。

误判：对上数字或终态就过

正确数字配错段也放行，把回滚当作从未调用。

选择：同时保存独立观察

核验获准定位、逐字原文和本轮包；另查插入入口、持久记录和回放标识。

代价：维护受信旧来源映射，在每个边界重读资料和存储；换来可归因的失败，不会把旧批准变成永久读权限。

  1. 从受信主体出发重新读取指定版本和段落；逐项核对实际包与独立金标。
  2. 用写入口观测和独立数据库读取对照拒绝、批准、回滚与重放。
  3. 单独改变定位或引文，再用触发器制造一次无落盘尝试，验证每条规则确实能失败。

诊断：定位对而引文错，先查文本提取或映射；零行有尝试，查审批和执行边界，不先修改答复格式。

Q 正确数字配给存在但无关的包内引文；另一次草稿写入回滚。哪项记录准确？
出处是关联证据的起点，不是支持结论；回滚撤销记录，不撤销已经发生的尝试。

本课最佳实践验收：零条落盘不是零次写入

换成审批场景：对照已拒绝草稿和插入失败的批准草稿。批准对照只在临时 SQLite 文件内安装固定触发器。用实际观测检验 no_draft_write()，再用正常保存的金标检查回滚结果。最后在内存构造一个仅用于校验评分器的对照期望：允许回滚状态，但要求零尝试。这样唯一应该失败的就是写入尝试数。再把导出草稿的主体换成 Lin，确认没有预览或检查点。

from pathlib import Path
import runpy
from tempfile import TemporaryDirectory

if not __debug__:
    raise RuntimeError("run without -O")
e = runpy.run_path("code/phase8-agent-engineering/engineering-lab/evaluation/main.py")
tasks = {t["id"]: t for t in e["load_datasets"]()["acceptance"]}
for task_id, state in (("ACC-EXPORT-DENY", "denied"), ("ACC-EXPORT-PENDING", "pending")):
    task = tasks[task_id]
    observed = e["observe_draft"](task["request"])
    assert observed["steps"][-1]["state"] == state
    assert all(e["no_draft_write"](step) for step in observed["steps"])
    assert e["grade_draft"](observed, task["expected"])["passed"]
save = tasks["ACC-EXPORT-SAVE"]
with TemporaryDirectory() as tmp:
    rolled = e["observe_draft"](save["request"], block_draft_insert=True, temp_parent=tmp)
    assert not list(Path(tmp).iterdir())
step = rolled["steps"][-1]
assert (step["result"], step["state"], step["attempts"], step["rows"]) == ("insert_blocked", "pending", 1, 0)
assert not e["no_draft_write"](step)
failed = e["grade_draft"](rolled, save["expected"])
assert not failed["passed"] and "step_1.rows" in failed["failures"]
zero_attempts = dict(save["expected"], steps=[rolled["steps"][0], dict(step, attempts=0)])
failed = e["grade_draft"](rolled, zero_attempts)
assert not failed["passed"] and failed["failures"] == ["step_1.attempts"]
blocked = e["observe_draft"](dict(save["request"], actor="lin"))
assert blocked["draft"] is None and blocked["operation_ok"] and blocked["cleanup_ok"]
assert blocked["steps"] == [dict(action="stage", result="source_blocked", state=None, attempts=0, rows=0)]
print("L73 TRANSFER PASSED")

面试自查

Q1 答案数字对、文档也存在，为什么还要检查精确段号？

参考回答：文档存在不说明那个版本和段落能在本轮主体下读到。定位、原文、值、支持分别核验。

追问：把旧段号自动改成新段号呢？

答题要点：那是修复并产生了新答复；必须重新组包和验收，不能篡改旧报告。

Q2 已批准的草稿显示一次写入、零条新记录，是成功吗？

参考回答：不是。持久终态未满足保存契约；一次尝试可帮助定位事务回滚。

追问：这能作为拒绝路径完全没有写过的证据吗？

答题要点：不能；拒绝路径要求实际插入尝试也为零，且复查终态无草稿记录。

Q3 丢回包后再次得到成功应怎样验证不是重复写入？

参考回答：重开当前数据库，核对同一操作编号和内容、仍只有一条记录、恢复步骤零次插入。

追问：只看到一条记录够吗？

答题要点：不够，唯一约束可能拒绝了额外插入；须观察写入入口。

Q4 改版后轨迹少了一次内部查询，验收是否失败？

参考回答：轨迹变化本身不构成失败，看是否仍满足授权、证据、批准和副作用规则。

追问：什么时候次数本身属于契约？

答题要点：禁止调用次数、写入幂等、工具预算等直接影响约束时，须按对应执行边界计数。

知识地图与小结

  1. 主体 → 当前版及定位 → 原文 → 实际包：核验证据流。
  2. 事实金标 → 值与证据配对 → 缺口与形状：核验答复，而非措辞。
  3. 审批 → 插入尝试 → 独立落盘查询 → 重放：核验副作用，而非乐观日志。
