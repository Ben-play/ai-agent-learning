第八阶段 · Agent 工程化30分钟

版本化任务集与重复试验

固定问题、状态和期望，再让每轮从干净环境出发

为什么不能只拿昨天的对话做回归？

同样一句「请准备交班草稿」，昨天看到的是待审批，今天重试却显示已保存。两次可能都对：昨天的试验留下了本地记录，今天没有从空环境开始。另一个常见错觉是把开发时看过的题目改写成验收题；通过率提高，也可能只是因为答案或案例模板早已被用来调参。对能检索、写入和恢复的系统，回归的单位不只是提示与答复，而是任务契约、初始状态、可观察结果与清理。

这一课让四种行为在同一个离线入口相遇：根据有权读取的证据回答，没材料时拒答，批准后保存本地草稿，以及从已提交但回包丢失的状态恢复。另保留拒绝与等待审批用例，避免套件只测成功路径。

学习目标

  • 能区分候选输入、独立金标和试验初态。
  • 能用四个独立负例检查重复编号、同族、带填充的族标签和规范化后重题。
  • 能从逐轮报告证明同轮恢复保留状态、跨轮重复重新建库。

1. 把题目、试验和预期分别固定下来

仓库的 evaluation/fixtures/v1/ 存放真实的版本化文件：dev.json 与 acceptance.json 各自声明 dataset_version 和 split，每条任务有稳定的 id、人工指定的语义族 family 和任务类型 kind。request 是本轮允许进入候选路径的输入；expected 是评分器的标签，不回流进候选。若让脚本按题号查出金标或把批准结果塞进候选提示，套件就只证明了读文件成功。候选可以知道本次问哪些事实或收到什么审批，但不知道哪些答案能拿分。

初态是运行契约的一部分，不是用户自然语言。本课问答每轮重建阶段七的内存资料库；租户和用户由可信试验入口绑定，脚本从有权限的词法命中中读取原文。交班卡用 Mei，可看「导出文件生成后保留 7 天。」与「同步任务每天 02:00 运行。」；另一题用 Lin 查导出过期处理，当前主体没有权读对应政策，因此与猜中答案相比，标注缺口并拒答才合格。草稿每轮创建新的临时 SQLite 文件，从空检查点和零条保存记录开始；同一轮内用请求指定的任务键和版本暂存草稿，再按审批动作推进。清理时先关闭连接，再删除整个临时目录；不擦除仓库任何已有记录。

题集版本、代码修订以及重复次数要一起报告。同一事实的引用位置变了、草稿终态的产品要求变了、验收任务移出了开发集，都可能改变指标口径。保留旧版，发布新版并说明变更原因；比较两份报告时先找共同任务及相同预期，不能把新旧分母直接拼起来。如果线上问题需要复现，先用合成数据表达触发条件，把新任务交给未负责调参的人复核，再定义何时纳入正式验收。这个公开教程不存在保密验收；真实发布需要在流程上隔离访问、审阅和调参权限。

2. 分组隔离与重复隔离，解决的是两件事

开发集给日常定位和改动用；验收集用来回答改动是否达到预先约定的门槛。按 DEV- 与 ACC- 编号很容易审查，但改一个前缀不能消除见过题目的影响。先按原始工作流或语义族分组，再切分；同一导出草稿的保存、拒绝、丢回包用例都在验收侧。入口同时拒绝重复编号、跨分区复用的语义族与规范化后重复的问题。族标签必须是非空、首尾无空白的规范字符串；例如 sync-lookup 可用，带首尾空格的 sync-lookup 直接拒绝，不把它当成新族，也不悄悄改写。问题规范化折叠宽窄字符、空格和标点，可以抓到「同步任务几点开始？」与只改问号的抄题；它不会理解同义改写，必须靠维护者把「每天什么时候同步」标为相同语义族。共同事实并不自动构成污染：开发的单事实查询与验收的两事实交班是不同任务，但这种拆分只能说没有重用已知任务族，不能声称证据、事实或近似措辞从未见过。

任务编号跨轮不变，试验序号从一开始单独递增。每次试验重建数据、运行操作、按终态评分，再清理；不要先把所有任务写进一个数据库再清空一张表，因为旧检查点、授权或缓存仍可污染下一次。相反，恢复测试内部必须保留同一轮数据库，并重新打开连接验证结果可恢复；若把重放当作下一轮并清空，测试已经失去了恢复所需的前提。固定脚本的两次一致只说明在本地有可重复的工程基线，不代表大模型概率、生产并发或远程服务稳定性。遇到偶发变化，保留逐行报告与预算条件，不挑成功的一次，也不把同一任务重复十遍当成十道独立题。

分区任务数每任务试验数合格试验一个可定位的观察

acceptance6212 / 12重放每轮先丢回包，已保存一条；恢复后仍是一条，且没有再尝试写入。

每行报告的 id 与 trial 只用于关联结果。保存失败时，先确认读到哪份数据，再查是否真的从待审批开始；不要拿第二轮的状态替第一轮补成绩。

决策卡：先隔离语义族，再隔离试验状态

适用：一个工作流要支持审批及恢复，但验收只有两条聊天记录。边界：可以共用合成资料快照，不能共用上轮的落盘状态。

误判：只改编号和库路径

把开发题换一种问法塞进验收，用上轮留下的任务行演示第二次成功。

选择：固定版本和初态

同族不跨分区，候选与金标隔开；同轮恢复保留状态，新轮必重建。

代价：人工维护语义族、分别跑隔离库，会增加标注和运行时间；换来可比较的分母与可复现的恢复试验。

  1. 审查任务族、题号、授权主体、起始状态、预期与清理。
  2. 先在开发侧调试，验收时固定数据版本与次数，保存每行结果。
  3. 分别复制编号、改写题目和重复跑保存用例，检查分区校验与状态隔离各自能否暴露错误。

诊断：分母不对先查分区或重复次数；第二轮没从 pending 出发先查库生命周期；试验稳定但仍失败，再查引用或审批语义。

Q 改写同一道开发题，同时想验证验收中的恢复，哪种安排正确？
相同任务族和相同试验状态分别在两个层面隔离。恢复不是新试验。

from copy import deepcopy
import runpy

if not __debug__:
    raise RuntimeError("run without -O")
e = runpy.run_path("code/phase8-agent-engineering/engineering-lab/evaluation/main.py")
splits = e["load_datasets"]()
dev = dict(dataset_version="p8-eval-v1", split="dev", tasks=splits["dev"])
acceptance = dict(dataset_version="p8-eval-v1", split="acceptance", tasks=splits["acceptance"])
e["validate_splits"](dev, acceptance)
for task_id, family, question, reason in (
    ("ACC-IMPORT", "sync-lookup", "每天同步何时开始？", "family overlap"),
    ("ACC-IMPORT", " sync-lookup　", "每天同步何时开始？", "invalid family"),
    ("ACC-IMPORT", "imported-lookup", "同步任务几点开始 ?", "question overlap"),
    ("DEV-SYNC-QA", "imported-lookup", "什么时候处理交班卡？", "duplicate ID"),
):
    trial = deepcopy(dev["tasks"][0])
    trial["id"], trial["family"], trial["request"]["question"] = task_id, family, question
    contaminated = dict(acceptance, tasks=[*acceptance["tasks"], trial])
    try:
        e["validate_splits"](dev, contaminated)
    except ValueError as exc:
        assert reason in str(exc), str(exc)
    else:
        raise AssertionError(f"missed {reason}")

面试自查

Q1 改写一条调参题，再把它放进验收，为什么不算独立？

参考回答：同一语义族和工作流仍被用来调参；题号改变不等于能力被独立测试。

追问：题目规范化后不同，还能怎么拦？

答题要点：维护族标签，由独立审阅确认语义改写和业务来源；规范化只是最便宜的一层。

Q2 重放用例第二轮读到第一次写的草稿，报告显示通过，怎么排查？

参考回答：把试验边界和任务内动作边界分开。每试验新开空库；只在当前试验的提交和恢复之间保留同一个库。

追问：只在每次结尾删掉一条草稿足够吗？

答题要点：不够，检查点或同一作用域的其他数据仍可能残留；隔离整个临时存储更清楚。

Q3 两轮里所有样本都过，能说通过率是生产成功率吗？

参考回答：只能说在固定版本、脚本和合成场景中 12 次都过。重复同一任务并没有扩大任务分布。

追问：验收分母从十二变成十八时应怎样报告？

答题要点：任务数仍为六，重复次数改变；保留版本、每任务结果和新的试验分母。

Q4 审批产品契约改变，旧预期不再有效，该如何更新？

参考回答：先由业务确认新的结果和允许的副作用，再发布新数据版本并保留历史。

追问：怎样向评审解释通过率发生变化？

答题要点：固定代码或数据作对照；按共同题与新题拆分并指出哪些变更来自口径而不是能力。
