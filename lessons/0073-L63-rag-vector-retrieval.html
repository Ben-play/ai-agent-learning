Embedding 与向量检索

先验证精确余弦排序，再判断近似索引是否值得

为什么词法没有命中，不一定是权限问题？

用户换个说法：「导出的留存期限是多久？」把这道改写题表示为「留存、期限」，L62 的词项交集就找不到本来可读的保留条款。如果查询与文档在一个合适的向量空间相近，就有机会在词不相同的情况下找到证据。这节只验证向量给定后候选如何打分、截断和回查。贯穿整课的三维数字由人写入，连「改写落到正确方向」也是预先安排的；它不测试任何嵌入模型是否真的理解这句话，也不报告线上质量或延迟。

学习目标

  • 在同一授权池手算余弦相似度，定位空命中和名次差异。
  • 比较精确扫描与近似候选的职责，读懂一份待运行的 pgvector 对照计划。

1. 先过授权，再比较向量的方向

查询入口依然由宿主提供租户和操作者。db.search 先从同租户的当前文档与许可取 db.authorized，再把片段和 Query(terms, vector) 交给排序器；mode="vector" 只读取查询向量，不让词项影响顺序。向量不是引用，不携带许可，也不会因为相近而授予任何访问权。查到命中后仍用租户、用户、文档编号、版本和段落定位回读正文，不能把相似分当作答案的置信度。

Embedding（嵌入）是把文本编码成一组数值。典型数据流分两路：入库时编码分块并保存向量及模型版本；查询时按兼容的编码约定把问句变为查询向量。两路在检索时才用同一种距离作比较。这里省掉编码调用，直接把三维文档向量写进夹具，查询也直接传入三维数，所以可以单独验算排序，不把编码效果算进实验结果。

余弦相似度等于向量点积除以两个长度的乘积。夹角小的向量方向相近；同向为 1，正交为 0，反向为 −1。把非零向量放大正倍数，方向不变，分数也不应变化，因此不能用未归一化的点积代替。输入必须维数一致、维数非空且元素有限；零向量没有定义良好的方向，夹具把这对向量视作零分，不产生向量命中。非正分被剔除，正分按降序排，同分按片段键排，再切至 k。这道正分门槛是本课约定，并非所有向量数据库的缺省行为，更不是相关性的通用阈值。共享实验库在写入时也检查三维与数值有效性；一条坏向量不应发布成新版，再让整个授权池的向量和混合查询失败。

这不是索引演示：本地 SQLite 负责授权选择，Python 对授权池中每个片段逐一计算，完全不跳过邻居。若有 n 段、每向量 d 维，评分做约 n × d 的运算，另有最多 n 条的排序；这里没有用堆提速。称它为精确线性扫描基线，指的是相对于这些固定向量没有近似漏邻居，不是说浮点没有误差，也不是说所有排出来的片段都真的支持问题。上线前应固定文档与查询的向量模型、维度、版本及其编码约定；模型或分块版本变了，应重新建立相匹配的向量并重测，不因维数相同就假设向量空间可以混用。

3. pgvector 对照：索引与计划示意，未运行

NOT RUN（未运行）：本课离线验收不使用 PostgreSQL 或 pgvector。下面是给已有 pgvector 0.8.2 扩展的隔离数据库看的 SQL 对照，不是部署脚本。临时表模拟 support/mei 已完成授权的当前快照；topic 只是业务筛选，不承担权限验证。实际系统要由服务端按当前身份强制实施租户与文档许可，不能让客户端挑授权范围，也不能用近邻索引或这个临时表替代权限设计。使用余弦时，pgvector 的 <=> 是距离，越小越近；有限非零向量中，距离小于 1 等价于余弦相似度为正。

BEGIN;
CREATE TEMP TABLE l63_visible (
    doc_id text, version integer, locator text,
    topic text NOT NULL, embedding vector(3) NOT NULL,
    PRIMARY KEY (doc_id, version, locator)
);
INSERT INTO l63_visible VALUES
    ('EXPORT-POLICY', 1, '§1', 'export', '[1,0,0]'),
    ('EXPORT-OPS',    1, '§2', 'export', '[0.45,0.89,0]'),
    ('SYNC-POLICY',   1, '§1', 'sync',   '[0,0,1]');
ANALYZE l63_visible;

PREPARE l63_query (vector, text, integer) AS
SELECT doc_id, version, locator, embedding <=> $1 AS distance
FROM l63_visible
WHERE topic = $2 AND (embedding <=> $1) < 1
ORDER BY embedding <=> $1 ASC
LIMIT $3;

-- 无向量索引时记录精确计划和结果键。
EXPLAIN (ANALYZE, BUFFERS) EXECUTE l63_query('[1,0,0]', 'export', 2);
EXECUTE l63_query('[1,0,0]', 'export', 2);

CREATE INDEX l63_visible_hnsw ON l63_visible USING hnsw (embedding vector_cosine_ops);
ANALYZE l63_visible;
-- 同一查询：只有选中 HNSW 索引扫描才是近似对照。
EXPLAIN (ANALYZE, BUFFERS) EXECUTE l63_query('[1,0,0]', 'export', 2);
EXECUTE l63_query('[1,0,0]', 'export', 2);
-- 在 0.8.0+ 可重新记录计划与结果，比较迭代扫描的代价。
SET LOCAL hnsw.iterative_scan = strict_order;
EXPLAIN (ANALYZE, BUFFERS) EXECUTE l63_query('[1,0,0]', 'export', 2);
EXECUTE l63_query('[1,0,0]', 'export', 2);
DEALLOCATE l63_query;
ROLLBACK;

索引用 vector_cosine_ops 配余弦距离；为保留可选的近邻索引计划，排序直接用距离运算符升序加 LIMIT，不能等价改写成按 1 - 距离 降序并假定计划不变。极小表很可能仍选顺序扫描：先看计划节点是否实际走 Index Scan 及索引名，再看实际返回行、过滤掉的行、耗时和缓冲区。EXPLAIN ANALYZE 会实际执行查询，但它输出的不是业务结果集，也不等同客户端端到端延迟，所以另跑同一 EXECUTE 留下结果键。这两个导出片段没有同分；基线在扩展集上遇到边界同分时，应固定精确并列规则或单独标注并列，不能把近似索引未承诺的同分次序当作回归。

按 pgvector 的官方 Filtering 说明，若计划使用近似索引，普通 WHERE 过滤发生在索引返回候选之后。业务过滤或权限条件都可能让合法返回量低于上限，即使同样的精确过滤能满额。这与课程的「先取授权池再扫描」物理流程不同；服务端仍必须在交给应用之前强制过滤，不得用应用层的事后丢弃替代授权。过滤很有选择性时，可先用普通索引限制小集合再做精确排序；近似计划则可尝试提高搜索范围 hnsw.ef_search，或从 pgvector 0.8.0 起用迭代扫描继续取候选，直到够量或达到扫描上限。严格次序不等于穷尽邻居；余弦索引本身也不收零向量。每种变化都要重测召回、结果条数、时延和缓冲区，HNSW 的建索引时间与内存还要另外核算。

决策卡：授权池小，先保留精确；近似用实测换成本

适用：同一批可见片段上需要检验改写题，或精确扫描已经超出实际预算。边界：事故复盘不能仅凭索引存在或向量值非零宣布优化成功。

误判：有索引，改写题一定更准

索引可能根本没被选中；即使选中也只影响找邻居的成本和近似误差，不能改善模型表示。

对照：冻结输入与许可，再测索引

相同快照、查询向量、过滤条件和 k 下，比对精确与近似返回键。精确集非空时，用键交集数除以精确返回键数计邻居 Recall@k；为空单列。

取舍：精确基线用于定位索引损失；人工题集与证据标注用于判断嵌入是否有用。单次计划演示不能替代多次、按过滤选择性分组的实际测量。

  1. 用精确基线自检记录两人的授权键、分数和首条引用。
  2. 跑方向与幅度对照；另有真实测试库时，才对同一快照采集精确与近似计划和返回键。

诊断：精确路径也漏目标，先查授权池和向量；仅近似路径漏目标，才核对实际索引节点、过滤和扫描范围。

Q 查询从 (1,0,0) 变成 (3,0,0)，其余不变。余弦分数应怎样？
向量长度与点积同时乘三，归一后方向与分数不变。
Q 指定索引已创建，但计划只有顺序扫描，能得出什么结论？
计划未选择近似索引，不能将这次结果或耗时归给它。

import runpy
from math import hypot, isclose

if not __debug__:
    raise RuntimeError("run without -O")
lab = runpy.run_path("code/phase7-data-rag/rag-lab/lab.py")
query = lab["Query"](("留存", "期限"), (1., 0., 0.))
policy = ("EXPORT-POLICY", 1, "§1")
ops = ("EXPORT-OPS", 1, "§2")
sync = ("SYNC-POLICY", 1, "§1")

with lab["open_demo"]() as db:
    for user, authorized_keys, ranked_keys in (
        ("mei", {policy, ops, sync}, (policy, ops)),
        ("lin", {policy, sync}, (policy,)),
    ):
        pool = db.authorized("support", user)
        assert {c.key for c in pool} == authorized_keys
        assert db.search("support", user, query, mode="lexical", k=2) == ()
        hits = db.search("support", user, query, mode="vector", k=2)
        assert tuple(h.chunk.key for h in hits) == ranked_keys
        assert hits == lab["rank"](pool, query, mode="vector", k=2)
        assert isclose(hits[0].score, 1.0)
        assert db.source("support", user, policy).text == "导出文件生成后保留 7 天。"
        if user == "mei":
            assert isclose(hits[1].score, .45 / hypot(.45, .89))
    assert db.source("support", "lin", ops) is None
print("L63 ACCEPTED")

展开变式参考与自检
import runpy
from math import isclose

if not __debug__:
    raise RuntimeError("run without -O")
lab = runpy.run_path("code/phase7-data-rag/rag-lab/lab.py")
terms = ("夜间", "批次")
key = ("SYNC-POLICY", 1, "§1")
reverse = (0., 0., -1.)

with lab["open_demo"]() as db:
    def search(vector):
        return db.search("support", "lin", lab["Query"](terms, vector), mode="vector", k=1)

    for vector in ((0., 0., 1.), (0., 0., 4.)):
        (hit,) = search(vector)
        assert hit.chunk.key == key and isclose(hit.score, 1.0)
    assert db.source("support", "lin", key).text == "同步任务每天 02:00 运行。"
    assert search(reverse) == search((0., 0., 0.)) == ()
    # 此授权夹具中的向量均为单位向量，点积等于余弦。
    wrong_keys = tuple(c.key for c in db.authorized("support", "lin")
                       if abs(sum(x * y for x, y in zip(c.vector, reverse, strict=True))) > 0)
    assert wrong_keys == (key,)
    for invalid in ((0., 1.), (0., 0., float("nan"))):
        try:
            search(invalid)
        except ValueError:
            continue
        raise AssertionError("invalid vector entered scoring")
print("L63 TRANSFER PASSED")

应只打印 L63 TRANSFER PASSED。幅度一变分数就变，检查是否漏除长度；反向也命中，检查是否取绝对值或误把距离的排序方向用于相似度。

面试自查

回答时先说你比较了什么，再说能够推出什么。

Q1合成改写题成功，能不能宣布新嵌入模型提高了召回？

参考回答：不能，查询和片段坐标是人工指定，实验只检验给定向量、授权与余弦的行为。评估模型要用带目标证据的独立改写样本和模型实际输出，在同一快照上与词法比较。

追问：如果两种模型恰好都输出 768 维呢？

答题要点：形状兼容不等于语义空间兼容；记录并匹配模型版本及编码约定，不随意用一个模型查另一个模型的库。

Q2换 HNSW 后某用户只能拿到三条，精确查询却有五条，先查什么？

参考回答：确认同用户、同快照、同过滤条件和 k，看实际计划是否用了 HNSW；若用了，过滤可能在近似候选之后，候选被剔除而搜索范围不足。用精确返回键作对照，再量调搜索范围或迭代扫描的影响。

追问：可以把权限过滤去掉，靠重排控制结果吗？

答题要点：不可以，排序不是授权。若合法池很小，先按权限取小集合做精确排序也可能更合适。

Q3索引创建成功，为什么查询按相似度降序时未用索引？

参考回答：核对距离运算符、索引操作符类和排序形状。余弦索引需要直接按 embedding <=> query 升序与 LIMIT；按变换表达式降序不满足这个形式。即使形式正确，小表也可能选择扫描，须看实际计划。

追问：怎么分辨「建了索引」和「本次走了索引」？

答题要点：在同一查询的 EXPLAIN (ANALYZE, BUFFERS) 里确认实际扫描节点及索引名，并另取结果键比较。

Q4最近邻均是导出主题，但没有说多久，是否应答「约七天」？

参考回答：不能用相似分推导事实。标出应覆盖的条款，在授权池、正分列表、top-k 及引用回查依次找它；仅有操作步骤就不能回答保留期限。

追问：增大 k 后多了两段重复的操作说明，算改善吗？

答题要点：不算这道题的证据覆盖提高；要有可准确定址、确实包含保留时长的正文才算。

小结与一手参考
