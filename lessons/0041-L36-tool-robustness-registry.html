工具健壮性与注册系统

注册不等于授权，展示不等于执行：用参数模型、权限检查和受控回填闭合工具层

为什么这课重要？

L35 已把“请求工具 → 执行 → 回填”接成循环。但模型给出的工具名和参数仍然是不可信输入。工具已注册，不代表本轮允许执行；没有展示给模型，也不是服务端权限控制。参数 Schema 能帮助生成，不能代替运行时校验。

本课保留 L11 的装饰器学习目标：用 @tool(参数模型) 登记函数与契约，再让 dispatch 真正执行授权与校验。示例搜索和天气都是本地 stub，不联网，也不把这个小注册表称作完整生产框架。

学习目标

  • 区分注册集合、展示集合、本轮允许执行集合，由应用决定权限
  • 用 Pydantic 2 参数模型统一 Schema 与运行时约束，拒绝越界、错类型和多余字段
  • 用装饰器登记参数模型、Schema 和真实函数，保留元信息
  • 把未知、越权、非法参数和工具异常转成受控 tool 结果，保留调用关联 ID
  • 说明流式拼接的完成边界与工具定义的输入开销，运行零执行反例自检

1. 先定义参数契约，再谈“自我修正”

校验与执行必须分开。参数未通过校验时，不能先调用函数再捕获异常。以搜索为例，query 不能为空，max_results 必须为 1–50 的整数；不能默默把字符串 "5" 转成整数，也不能接受未声明字段。

下面用 L14 的 Pydantic 描述契约。model_json_schema() 从同一模型导出结构，model_validate() 在执行前检查输入。即使接口支持严格结构输出，应用仍需做权限和运行时校验；只有已经编码进 Schema 且该接口支持的约束才可能得到相应的生成约束，事实和业务许可并不因此成立。

import functools
import inspect
import json
from pydantic import BaseModel, ConfigDict, Field, ValidationError


class ToolArgs(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid")


class SearchArgs(ToolArgs):
    query: str = Field(min_length=1, max_length=200)
    max_results: int = Field(default=5, ge=1, le=50)


class WeatherArgs(ToolArgs):
    city: str = Field(min_length=1, max_length=80)

校验失败可以回填字段位置和错误类型，让模型在剩余轮次/预算内纠正，但不保证一定自愈。越权错误不能靠模型反复请求来解锁；工具执行异常还可能已经产生副作用，是否重试要结合 L31 的幂等策略。

Q 模型传入 max_results=-1，应该如何处理？
参数模型先校验，失败就返回受控错误，真实函数执行次数为零。回填可以帮助模型修正，但重试次数必须受限，不能绕过约束。

2. 装饰器注册：契约、Schema、函数放在一起

手动维护 Schema、工具清单和名字分支，容易不同步。L11 的装饰器可以集中登记这些信息。本例让 @tool(SearchArgs) 显式绑定参数模型，函数签名只检查字段名和可按关键字调用；参数类型、默认值与范围以模型为准，dispatch 把验证后的完整参数传给函数。

不再用四个 Python 类型名的映射冒充完整 Schema。那种做法不涵盖嵌套模型、可选值、枚举或业务约束。本例直接导出 Pydantic JSON Schema，但也不承诺它天然兼容每家厂商的 Schema 子集；真正接入仍需按选定接口适配并验证。本页的工具清单包装是 Chat Completions 风格，不是跨厂商通用格式。

REGISTRY = {}
EXECUTIONS = []  # 仅用于离线观察哪些函数真正运行过


def tool(args_model):
    def register(fn):
        name = fn.__name__
        if name in REGISTRY:
            raise ValueError("工具名重复")
        signature = inspect.signature(fn)
        if set(signature.parameters) != set(args_model.model_fields):
            raise ValueError("函数参数名与参数模型不一致")
        supported = {inspect.Parameter.POSITIONAL_OR_KEYWORD,
                     inspect.Parameter.KEYWORD_ONLY}
        if any(p.kind not in supported for p in signature.parameters.values()):
            raise ValueError("教学实现只支持具名参数")
        REGISTRY[name] = {
            "fn": fn,
            "args_model": args_model,
            "schema": {
                "name": name,
                "description": (fn.__doc__ or "").strip(),
                "parameters": args_model.model_json_schema(),
            },
        }

        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            return fn(*args, **kwargs)
        return wrapper
    return register


@tool(SearchArgs)
def web_search(query: str, max_results: int = 5) -> dict:
    """搜索资料的离线示例；需要外部证据时使用。"""
    EXECUTIONS.append("web_search")
    return {"query": query, "n": max_results, "source": "offline_stub"}


@tool(WeatherArgs)
def get_weather(city: str) -> dict:
    """查询天气的离线示例，不提供真实天气。"""
    EXECUTIONS.append("get_weather")
    return {"city": city, "temp": 22, "source": "offline_stub"}


def tools_param(names):
    # 只决定展示内容，不设置 dispatch 的执行权限。
    return [{"type": "function", "function": REGISTRY[n]["schema"]}
            for n in names]

装饰器仍做了“读取函数元信息 → 登记 → 保留普通函数调用方式”这条学习线。直接调用 web_search(...) 是应用内部的 Python 调用，不会经过下面的权限和校验守卫；模型请求必须走 dispatch，不应暴露任意 Python 调用路径。

3. 分发：展示子集 ≠ 执行授权

先分清三个集合：

  • 注册集合：应用安装了哪些工具，来源是 REGISTRY。
  • 展示集合：本轮发送给模型的工具定义，由 tools_param(names) 选择，影响上下文与选择空间。
  • 允许执行集合：应用依据当前用户、任务和权限计算的 allowed_tools，显式传给 dispatch。不能从模型返回的名字或参数反推授权。

可以把展示集设置为允许集的相关子集，但两者不自动等同。本课例子同时只展示并允许 web_search：即使模型猜中已注册的 get_weather，服务器仍拒绝。真实系统还需资源级权限，例如“允许查天气”不等于“允许读取任意客户数据”。

执行顺序固定为：已知名字 → 本轮授权 → JSON 解析 → 参数模型校验 → 函数调用。前三类拒绝与参数错误都必须零执行。错误回填只给稳定代码和必要字段，不泄露原始参数、异常栈、路径或密钥。

def tool_error(code, message, **extra):
    return {"ok": False, "error": {"code": code, "message": message, **extra}}


def dispatch(name: str, args: dict | str, *, allowed: frozenset[str]) -> dict:
    if not isinstance(name, str) or name not in REGISTRY:
        return tool_error("unknown_tool", "工具不存在，请选择已提供的工具")
    if name not in allowed:
        return tool_error("forbidden_tool", "本轮无权执行该工具，不要重试此动作")
    entry = REGISTRY[name]
    # 兼容 L35 已解析的 dict，也接受协议中的原始 JSON 字符串。
    try:
        raw = json.loads(args) if isinstance(args, str) else args
    except json.JSONDecodeError:
        return tool_error("invalid_json", "参数不是完整合法的 JSON")
    try:
        args = entry["args_model"].model_validate(raw)
    except ValidationError as exc:
        # 不直接返回 e.errors() 中可能含有的原始输入/上下文。
        fields = [{"field": ".".join(map(str, e["loc"])), "type": e["type"]}
                  for e in exc.errors(include_input=False, include_context=False,
                                      include_url=False)]
        return tool_error("invalid_arguments", "请按参数契约修正", fields=fields)
    try:
        data = entry["fn"](**args.model_dump())
        json.dumps(data, ensure_ascii=False)  # 保证本例结果可以通过 JSON 通道回填
    except Exception:
        # 工具可能已经产生副作用；不能承诺异常时零执行或盲目自动重试。
        return tool_error("tool_failed", "工具执行失败；请按应用重试策略处理")
    return {"ok": True, "data": data}


def tool_message(call_id, result):
    # 本页采用 Chat Completions 风格；其他原生接口由各自 adapter 回填。
    return {"role": "tool", "tool_call_id": call_id,
            "content": json.dumps(result, ensure_ascii=False)}


# 这两个值由应用在发请求前决定，并在本轮处理期间保持不变。
allowed_tools = frozenset({"web_search"})
advertised_tools = tools_param(["web_search"])
# L35 循环收到完整 call 后，使用同一份 allowed_tools：
# result = dispatch(call.function.name, call.function.arguments,
#                   allowed=allowed_tools)
# messages.append(tool_message(call.id, result))

dispatch(name, args, allowed=...) 兼容 L35 已解析的参数字典，也接受完整 JSON 字符串；无论走哪个入口，都不绕过授权或参数模型校验。注册表同时保存 Schema 和运行时参数模型，校验不再是“这里可以接”的注释。回填保留 tool_call_id，让错误与原请求一一对应；同轮有多个工具调用时，仍需为每个调用返回结果。是否继续尝试由 L35 的有界循环决定，不能无限“自愈”。

Q 只向模型展示 web_search，能否因此认定其他注册工具已被禁止？
展示清单是模型输入，授权是服务器端决策。筛选可以减少输入，但 dispatch 仍需显式检查应用传入的 allowed_tools；不允许的工具即使已经注册也不能执行。

4. 流式与 Token：输入准备不等于执行许可

流式先拼齐，再走同一个 dispatch

工具参数可能分片到达。适配器要按调用索引/ID分别累积，保留工具名字与关联 ID，不能收到一片就执行。流结束不等于工具调用完整：还要确认所选接口的完成状态；中断、截断或取消都不能执行。即便正常完成，JSON 仍须解析和校验。

以下是已由厂商适配器归一化的数据，不是新的 SDK 字段规范。completed 在这里是本地 fixture；线上必须来自已核实的完成事件，不能因网络连接关闭就设为 True。代码依赖前面三个核心块。

parts = [
    {"index": 0, "id": "stream-1", "name": "web_search", "arguments": '{"query":"'},
    {"index": 0, "arguments": '课程","max_results":2}'},
]
completed = True  # fixture；真实中断/截断时应为 False
buffers = {}
for part in parts:
    buf = buffers.setdefault(part["index"], {"id": "", "name": "", "arguments": ""})
    for key in ("id", "name"):
        if part.get(key):
            buf[key] = part[key]  # 适配器已提供完整身份字段，而不是名字碎片
    buf["arguments"] += part.get("arguments", "")

stream_messages = []
if completed:
    for buf in buffers.values():
        if not buf["id"] or not buf["name"]:
            raise ValueError("完成事件缺少工具身份；不得执行")
    for buf in buffers.values():
        result = dispatch(buf["name"], buf["arguments"], allowed=allowed_tools)
        stream_messages.append(tool_message(buf["id"], result))
else:
    # 不执行；由应用记录中断并走有限重试/取消流程。
    stream_messages = []

工具定义也占上下文

本轮实际发送的工具定义是输入的一部分，应纳入 L30 的完整请求预算。全局注册很多工具不意味着每轮都发送；tools_param(names) 只取相关子集可以减少输入。成本还取决于缓存、模型和接口，见 L37；不能把每轮逻辑输入都等同于全价计费。

description 写清用途、边界和区别，不必越长越好。更聚焦的工具集可能改善选择，但要通过任务集评测，不保证工具越少越准。无论怎么筛选，执行端的授权检查都不能删。

5. 离线自检：拒绝路径必须零执行

运行方式：按顺序复制 l36-args-core、l36-registry-core、l36-dispatch-core 和下方 l36-registry-check，保存为一个文件，用已有 Python 运行 py -I 文件名.py。需要本机已有 Pydantic 2；没有时可使用已装依赖的项目虚拟环境 Python，不联网安装。l36-stream-example 是可选独立示意，不是自检依赖。

for index, (name, raw, expected) in enumerate(cases):

6. 动手练习：扩展装饰器，不绕过守卫

不照抄完整注册实现，复述 @tool(Args) 的三项登记内容，并新增一个只做整数相加的本地工具。

  1. 写 AddArgs(ToolArgs)：a 为整数，b 为大于 0 的整数。
  2. 用装饰器绑定函数，确认函数参数名与模型一致，元信息保留。
  3. 仅展示 add，但分别用空允许集和包含 add 的允许集调用 dispatch。
  4. 用计数器验证：未授权、b=0、b 为字符串、多余字段均不执行；合法调用恰好执行一次。
参考方向

登记项是 schema + args_model + fn。模型用 b: int = Field(gt=0)，从模型导出 Schema，dispatch 仍先检查允许集、再校验参数。展示 add 不会自动授权；授权 add 也不会放过 b=0。无需新增框架、手写类型映射或为每个工具新增 dispatch 分支。

隔日闭卷重建时，重点检查“谁决定权限”和“何时才发生第一次执行”，而不是只记住装饰器语法。

Q 关于这个工具注册实现，哪句正确？
注册提高可维护性，但不是权限系统。生成阶段的 Schema 与执行阶段的校验共享模型，dispatch 仍需本轮允许集；流式完成只代表可以准备解析，不证明参数合法。

速查卡

注册：@tool(Args) → schema + args_model + fn；wraps 保留元信息
契约：Pydantic 模型是参数类型、默认值和范围的来源
集合：已注册 ≠ 已展示 ≠ 本轮允许执行
分发：已知名字 → 授权 → JSON → 参数校验 → 执行 → 受控结果
拒绝：未知/越权/非法参数均零执行；不要直接暴露异常或原始输入
回填：保留调用 ID，错误代码稳定；修正次数与预算都要有界
流式：按调用归组拼接，确认完成状态，再进同一个 dispatch
预算：本轮发送的工具定义计入输入；缓存计价与选择质量另行评测
边界：教学注册表不是完整框架，也没有代替资源级权限或幂等机制

总结

  • 先讲契约：参数模型统一 Schema 与运行时约束，不用简易类型映射冒充全 Schema
  • 再讲注册：装饰器把参数模型、Schema 和真实函数一起登记
  • 执行有守卫：本轮允许集由应用决定，未知/越权/非法参数零执行
  • 错误有通道：受控结果保留调用 ID，不泄露内部异常，不能无限重试
  • 输入有边界：流式先确认完整，工具定义计入预算；本地通过不等于真实 SDK 验证
面试答法：展示清单只影响模型输入，服务器必须用本轮允许集授权；参数模型在副作用之前验证，失败回填受控错误并关联原调用；注册表负责集中管理契约与函数，不取代授权、资源权限或幂等。下一课进入 L37 成本工程。
