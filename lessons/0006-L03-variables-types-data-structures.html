1. 变量：标签，不是盒子

很多初学者把变量想象成"盒子"，值装在盒子里。这是错的。

Python 变量是标签（引用），贴在对象上：

a = [1, 2, 3]
b = a          # b 和 a 指向同一个列表对象
b.append(4)
print(a)       # [1, 2, 3, 4]  ← a 也变了！

内存模型：

a ──→ [1, 2, 3, 4] ←── b
      （同一个对象）
🔑 Agent 开发关联：

LLM 返回的 response 对象经常被多个变量引用。如果你修改了一个引用的数据，其他引用也会受影响。这是 Agent 开发中常见的 bug 来源。

Q 下面代码的输出是什么？ 
x = [1, 2]
y = x
y = y + [3]
print(x)
y = y + [3] 创建了一个新列表对象，y 重新指向新对象。x 仍然指向原来的 [1, 2]。
如果是 y.append(3)，那 x 就会变了。

2. 可变与不可变类型

上一节看到：多个变量可以指向同一个对象。那么改动这个对象，会不会"牵连"其他变量？答案取决于这个对象能不能被改——这就引出了 Python 类型的一条根本分界：可变 vs 不可变。但在讲可变/不可变之前，先认清楚 Python 最基础的四种"标量"类型——它们都是不可变的，是后面一切容器的地基。

四种标量类型：是什么、怎么创建、怎么区分

类型字面量示例含义
int42整数
float3.14小数（浮点数）
str"42"文本（字符串）
boolTrue真/假

创建：直接写字面量即可——42 是 int，3.14 是 float，"42"（带引号）是 str，True/False（注意首字母大写，且不带引号）是 bool。

怎么区分：42 和 "42" 长得像，但一个是数字一个是文本——加引号就是 str，不加就是数字。区分不确定时，用 type() 或 isinstance() 检查：

type(42)          # <class 'int'>
type("42")        # <class 'str'>
isinstance(42, int)     # True
isinstance("42", int)   # False

# 类型之间不会自动"猜"你的意图，转换失败会直接报错
int("abc")        # ❌ ValueError: invalid literal for int() with base 10: 'abc'
# 异常处理（try/except）会在后续课系统讲，这里只需要知道"转换可能失败"

何时用：数量、计数用 int；测量值、比例（如 confidence=0.7）用 float；文本、名字、JSON 里的字符串值用 str；开关、条件判断用 bool。四种标量都是不可变——这就引出下面的分类：

Python 的数据类型分为两大阵营：

不可变（Immutable） 可变（Mutable）
int float str bool
tuple frozenset		 list dict set
值不能修改，修改会创建新对象 值可以原地修改

不可变类型的"陷阱"

s = "hello"
s[0] = "H"    # ❌ TypeError: 'str' 不支持 item assignment

# 正确做法：创建新字符串
s = "H" + s[1:]  # "Hello"

可变类型作为默认参数的陷阱

def add_item(item, lst=[]):    # ⚠️ 危险！
    lst.append(item)
    return lst

print(add_item("a"))  # ["a"]
print(add_item("b"))  # ["a", "b"]  ← 不是 ["b"]！

原因：默认参数 [] 只在函数定义时创建一次，之后每次调用共享同一个列表对象。

# 正确做法
def add_item(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst

最佳实践：需要新可变对象时，用 None 或专用哨兵

什么时候会遇到：工具函数在 Agent Loop 中被调用多次，第二次结果却带着第一次的数据。

❌ 默认列表只创建一次
def collect(item, items=[]):
    items.append(item)
    return items

print(collect("a"))
print(collect("b"))  # ['a', 'b']
✅ 每次需要时创建
def collect(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

print(collect("a"))
print(collect("b"))  # ['b']

为什么更优：用 None 或唯一哨兵触发函数内新建容器，会把对象生命周期限定到单次调用，从而提升状态隔离性和行为确定性，避免上一轮数据污染下一轮。代价是增加分支并要明确 None 的业务语义；当确实需要跨调用累计状态时，改用显式传入的容器、实例属性或专门状态存储，而不是借默认参数隐式共享。

动手自检（整块复制即可运行）：
def collect(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

first = collect("a")
second = collect("b")
assert first == ["a"]
assert second == ["b"]
assert first is not second
print("no shared state")

怎么看结果：打印 no shared state 即通过；最后一条身份断言证明两次调用拿到的不是同一个列表对象。记住后果链：默认对象只创建一次 → 多次调用共享 → 上一轮状态进入下一轮。

None 也可能是合法业务值：只有当 None 表示“未传入”时才拿它当哨兵。如果“显式传 None”和“没有传参”必须区分，就使用唯一对象：

_MISSING = object()

def normalize(value=_MISSING):
    if value is _MISSING:
        return []
    return value

assert normalize() == []
assert normalize(None) is None
Q def f(item, lst=[]) 这样写，反复调用会怎样？
默认参数 [] 只在函数定义时创建一次，之后每次调用都共享同一个列表对象——上一次 append 进去的元素会"残留"到下一次。这就是"可变默认参数陷阱"。正确做法：默认值用 None，在函数体里再 lst = []。

3. 引用计数与垃圾回收

CPython（最常用的 Python 实现）主要用引用计数管理内存，辅以循环垃圾回收处理循环引用；其他 Python 实现（如 PyPy）不保证对象在引用归零时立即释放。每个对象有一个计数器，记录有多少变量指向它：

import sys

a = [1, 2, 3]
print(sys.getrefcount(a))  # 2（a 本身 + getrefcount 的参数）

b = a
print(sys.getrefcount(a))  # 3

del b
print(sys.getrefcount(a))  # 2

当引用计数降为 0，对象被回收（CPython 下通常是立即回收；这是实现细节，不是语言规范保证）。

💡 面试常见问题：

"Python 的垃圾回收机制是什么？"

答：以 CPython 为例，主要靠引用计数，辅以分代回收处理循环引用。小整数、短字符串等有缓存/驻留优化，但这是 CPython 的实现优化，不是语言保证，其他实现可以不这样做。

4. 四大容器：list / dict / tuple / set

前面三节讲的是“单个值”的性质（引用、可变性、回收）。但 Agent 代码里的数据几乎都是成组的——一串工具、一组消息、一份配置。Python 用四种容器来装它们，各有各的取舍：list（有序可变）、dict（键值查找）、tuple（不可变；元素都可哈希时能当 key）、set（去重）。前面学的“可变/不可变”能帮助理解它们，但 dict key / set 元素的精确要求是“可哈希”。

先学会一眼区分：怎么创建、括号长什么样

四种容器最容易让初学者懵的，是它们的字面量括号很像——尤其 {} 到底是 dict 还是 set？下面这张表一次看清「怎么写出来、靠什么认出来」：

容器字面量写法一眼认出的特征有序?可变?可重复?
list[1, 2, 3]方括号 []✅✅✅
tuple(1, 2, 3)圆括号 ()（认逗号）✅❌✅
dict{"a": 1, "b": 2}花括号 + 冒号 键:值✅✅key 不可重复
set{1, 2, 3}花括号、无冒号、只有值❌（不要依赖遍历顺序）✅❌（重复值会合并）

区分口诀：看括号 → [] 是 list、() 是 tuple；花括号 {} 再看里面——有冒号 : 是 dict，没冒号只有值是 set。

# 除了字面量，也能用「构造函数名」创建（还能做类型转换，见第 7 节）
list("abc")        # ['a', 'b', 'c']
tuple([1, 2])      # (1, 2)
dict(a=1, b=2)     # {'a': 1, 'b': 2}
set([1, 1, 2])     # {1, 2}   ← 顺带去重
⚠️ 两个必踩的坑（初学者 90% 会中）：
  • {} 是空 dict，不是空 set！空集合只能写 set()。因为花括号被 dict 占了，Python 没法从空 {} 分辨你要哪个，默认给 dict。
    type({}) → dict；type(set()) → set。
  • 单元素 tuple 必须带逗号：(1,)。(1) 只是"加了括号的数字 1"，类型是 int——是逗号而非括号造就了 tuple。
    type((1)) → int；type((1,)) → tuple。

list — 有序、可变、可重复

# 创建
tools = ["search", "calculator", "weather"]

# 常用操作
tools.append("file_reader")     # 末尾添加
tools.insert(0, "planner")      # 指定位置插入
tools.pop()                     # 移除末尾并返回
tools.remove("calculator")      # 按值删除
tools.sort()                    # 原地排序
len(tools)                      # 长度

# 切片（Agent 开发中用于截取对话历史）
messages = ["msg1", "msg2", "msg3", "msg4", "msg5"]
recent = messages[-3:]          # 最近 3 条消息
except_last = messages[:-1]     # 除最后一条外的所有消息

切片怎么读？方括号里写 [起点:终点]，取出从"起点"到"终点前一个"的一段（含头不含尾），两边都能省略。再加上负数下标从末尾倒数（-1 是最后一个、-2 是倒数第二……），就能读懂上面两行：

  • messages[-3:] — 从"倒数第 3 个"取到末尾 → 最后 3 条（终点省略=一直到底）
  • messages[:-1] — 从头取到"最后一个之前" → 去掉末尾那条（起点省略=从头开始）

Agent 里常用它裁剪对话历史（如"只保留最近 N 轮"来省 token）。切片对 str、tuple 同样适用。

dict — 键值对、有序（Python 3.7+）、可变

dict（字典）是"用名字查值"的容器。list 靠位置下标（tools[0]）取值，dict 则靠一个键（key）取到对应的值（value）——就像查字典：给一个词（key），翻到它的释义（value）。每一对就叫一个"键值对"，写成 "键": 值。

为什么 Agent 开发离不开它？原始 JSON、配置和工具参数经常表示为 dict；官方 SDK 响应也可能是类型化对象，需要按其接口读取。对于真正的具名映射，config["model"] 比“配置里的第 0 个”直观得多。

# 创建（Agent 的核心数据结构）
config = {
    "model": "demo-model",
    "timeout_seconds": 30,
    "max_results": 10
}

# 访问
config["model"]                       # "demo-model"
config.get("retry_limit", 2)           # 带默认值的安全访问

# 修改
config["timeout_seconds"] = 45         # 修改
config["log_calls"] = True             # 新增

# 遍历
for key, value in config.items():
    print(f"{key}: {value}")

# 字典推导式
tools = {"search": 10, "calc": 5, "weather": 8}
limited = {k: min(v, 8) for k, v in tools.items()}
# {"search": 8, "calc": 5, "weather": 8}

tuple — 有序、不可变、可重复

# Agent 中用于不可变的配置
POINT = (39.9, 116.4)           # 北京坐标
API_VERSION = ("v1", "stable")

# 解包
x, y = POINT
name, version = API_VERSION

# tuple 的不可变性保护数据不被意外修改
# 适合用作 dict 的 key
locations = {
    (39.9, 116.4): "北京",
    (31.2, 121.5): "上海"
}

set — 无序、不可重复

set（集合）是一袋“不重复的东西”。它有两个特点：自动去重（相等且哈希相同的重复值只保留一个）、无序（不提供可依赖的元素顺序，所以不能用下标取值；即使某次打印看似稳定，也不要把这个顺序当契约）。它的拿手好戏是两件事：去重，以及集合运算——判断“哪些在 A 不在 B”“A 和 B 共有哪些”。如果既要去重又要保留首次出现顺序，可用 list(dict.fromkeys(calls))。Agent 里常用 set 做权限白名单检查。

可哈希（hashable）表示对象在其生命周期内具有稳定的哈希值，并且能参与相等性比较，因此可作为 dict 的 key 或 set 的元素。常见的 str、int 和只包含可哈希元素的 tuple 都可哈希；list、dict、set 不可哈希。“不可变”是好记的近似规则，但不是完整定义：例如 tuple 若包含 list，仍不可哈希。

# 去重（Agent 中用于去除重复工具调用）
calls = ["search", "calc", "search", "weather", "calc"]
unique_calls = set(calls)       # {"search", "calc", "weather"}

# 集合运算
allowed = {"search", "calc", "weather", "file"}
requested = {"search", "hack", "weather"}
blocked = requested - allowed   # {"hack"}
approved = requested & allowed  # 包含 "search" 和 "weather"，顺序不保证

# 真实断言：验证集合语义，不比较打印顺序
assert unique_calls == {"search", "calc", "weather"}
assert blocked == {"hack"}
assert approved == {"search", "weather"}
assert len({"search", "search"}) == 1

最佳实践：先判断数据语义，再选择容器

先问四个问题：要保留顺序吗？要按名字取值吗？数据应保持不变吗？要自动去重吗？

Agent 场景选择为什么
按顺序保存工具调用list有序，也允许重复调用
按字段名保存模型配置dict通过键读取具名值
保存不应原地修改的坐标tuple不可变，能表达固定组合
权限白名单与工具去重set值唯一，支持集合运算
❌ 只因为“都能装”就全用 list

字段含义、唯一性和不可变约束只能靠注释维持。

✅ 让容器表达约束

读代码的人看到类型，就知道数据能否重复、是否有序、怎样取值。

为什么更优：按顺序、具名、浅层不可变或唯一性选择容器，会让数据约束由类型和操作直接表达，从而提升可读性、正确性与后续修改的安全性。注意 tuple 只保证不能替换它持有的元素引用，不会把内部可变对象“冻住”；需要深层不可变时还要限制或复制嵌套值。转换容器会分配内存，错误选择也可能丢失顺序或重复项；需要去重并保留首次出现顺序时，可用 list(dict.fromkeys(values))，需要具名且强校验的固定字段时则改用 dataclass 或 Pydantic 模型。

动手自检（证明四种容器语义）：
history = ["search", "search", "calc"]
assert history == ["search", "search", "calc"]  # 顺序与重复都保留

config = {"model": "demo", "timeout": 30}
assert config["model"] == "demo"                 # 通过字段名访问

nested = ("fixed", [1])
try:
    nested[0] = "changed"
except TypeError:
    pass
else:
    raise AssertionError("tuple 元素引用不能替换")
nested[1].append(2)
assert nested == ("fixed", [1, 2])                # 只是浅层不可变

requested = {"search", "search", "weather"}
allowed = {"search", "calc"}
assert requested == {"search", "weather"}        # 自动去重
assert requested & allowed == {"search"}          # 交集
assert requested - allowed == {"weather"}         # 差集

怎么看结果：静默结束即通过：list 同时证明顺序和重复，dict 证明具名访问，tuple 证明浅层而非深层不可变，set 证明去重以及交集/差集运算。

Q 下面哪个对象可以作为 dict 的 key？
dict 的 key 必须是“可哈希（hashable）”的：对象需要在其生命周期内保持稳定哈希值，并支持相等性比较。tuple (1, 2, 3) 的所有元素都可哈希，所以能当 key；list、dict、set 不可哈希。
“不可变通常可哈希”只是记忆钩子，不是定义；含 list 的 tuple (1, [2, 3]) 虽然 tuple 本身不可变，仍然不可哈希。
Q type({}) 的结果是什么？
{} 是空 dict，不是空 set——花括号被 dict 占用了。要建空集合只能写 set()。这是初学者最常踩的坑：type({}) → dict，type(set()) → set。

5. 推导式：Python 的数据转换利器

推导式是 Python 最强大的语法特性之一，Agent 开发中大量使用。

先看懂它怎么读。推导式就是把"建一个空列表 → for 循环 → 满足条件就 append"这三步，压成一行。它的骨架是：

[  表达式   for 变量 in 可迭代对象   if 条件  ]
   └拿什么┘  └───── 遍历谁 ──────┘  └筛选┘

三块对照普通循环，一一对应（for/if 的完整语法会在 L04 · 流程控制 系统讲解；这里只需要按图读取"三步对应"，本课不考循环控制细节）：

# 普通写法（三步）
result = []                    #  []        ← 建列表
for x in items:                #  for x in items
    if x > 0:                  #      if x > 0   ← 筛选
        result.append(x * 2)   #          x * 2  ← 拿什么

# 推导式（一行，顺序：先写"拿什么"，再写 for，最后 if）
result = [x * 2 for x in items if x > 0]

读的时候从中间的 for 起：先看"遍历谁"，再看右边"筛不筛"，最后回到左边"每个拿出来做什么"。if 可省略（不筛选时）。掌握这个骨架，下面几种推导式都是同一个模子。

列表推导式

# 传统写法
results = []
for tool in tools:
    if tool["enabled"]:
        results.append(tool["name"])

# 推导式（一行搞定）
results = [tool["name"] for tool in tools if tool["enabled"]]

# 带条件转换
statuses = ["success", "error", "success", "pending"]
icons = ["✅" if s == "success" else "❌" for s in statuses]
# ["✅", "❌", "✅", "❌"]   ← 三元只有两个分支：不是 success 的都归 ❌

字典推导式

# 从 LLM 响应中提取工具调用
response = {
    "tool_calls": [
        {"name": "search", "args": {"q": "python"}},
        {"name": "calc", "args": {"expr": "1+1"}}
    ]
}

# 提取工具名和参数
tool_map = {tc["name"]: tc["args"] for tc in response["tool_calls"]}
# {"search": {"q": "python"}, "calc": {"expr": "1+1"}}

集合推导式

# 提取所有唯一工具名
all_calls = ["search", "calc", "search", "weather"]
unique = {call for call in all_calls}
# {"search", "calc", "weather"}

嵌套推导式（谨慎使用）

# 扁平化嵌套列表
nested = [[1, 2], [3, 4], [5, 6]]
flat = [x for sublist in nested for x in sublist]
# [1, 2, 3, 4, 5, 6]

6. dict 深度操作

嵌套访问：安全取值

LLM 的响应往往是“套娃”式的多层 dict/list。取深处的值时，最直接的写法是一层层用 [] 点进去——中间层缺失、下标越界或结构类型不符都会明确报错。正确目标不是“永不报错”，而是按字段契约区分：允许缺失时返回默认值，必填缺失或类型错误时尽早失败。

# LLM 响应通常有多层嵌套
response = {
    "choices": [{
        "message": {
            "tool_calls": [{
                "function": {
                    "name": "search",
                    "arguments": '{"q": "python"}'
                }
            }]
        }
    }]
}

# ❌ 危险的写法（任何一层缺失就报错 KeyError / IndexError）
name = response["choices"][0]["message"]["tool_calls"][0]["function"]["name"]

先看常见误区：链式 .get() 只在“每个中间值都是预期的 dict”时安全；它不能普遍替代结构校验。缺失的 list 用 [{}] 兜底也仍可能遇到空列表越界；若键存在但值为 None 或其他类型，下一次 .get() 仍会报错。

# 仅在结构已知且中间层都是 dict 时可用
profile = {"user": {"name": "Ada"}}
name = profile.get("user", {}).get("name")
assert name == "Ada"

# 键存在但类型不符：链式 .get 并不安全
broken = {"user": None}
# broken.get("user", {}).get("name")  # AttributeError

因此，允许缺失的多层 dict/list 路径更适合使用下面这一个本课规范版本的 safe_get(data, *path, default=MISSING)。业务必填字段仍应直接读取或显式校验，让错误尽早暴露。这个封装作为进阶阅读：它把“要走的路径”当参数传进去，用到了两个新东西：

  • isinstance(d, dict)——判断 d 是不是某种类型（这里问“它还是个 dict 吗”）。本课第 7 节会细讲。
  • *path——让函数接收任意多个路径参数，收集成一个元组。这是 L05 · 函数参数 的内容，本课不要求你独立写出这种写法，能读懂、会调用即可。

规范契约：只遍历 dict（含 defaultdict 等子类）与 list。dict 缺键、list 越界返回调用者提供的 default；默认的唯一 MISSING 哨兵能区分“路径不存在”和“字段真实存了 None”。dict 路径键必须可哈希；读取前先判断成员是否存在，因此不会触发 defaultdict.__missing__ 或创建键。list 下标必须是非负的 int，且不能是 bool；字符串、布尔值、负数下标，以及在标量等不兼容对象上继续遍历，都抛带路径位置的 TypeError。除显式 hash(key) 失败外，成员比较或自定义映射产生的其他 TypeError 原样传播，不会被误报为“不可哈希”。

# ✅ 本课唯一的 safe_get 规范实现（进阶阅读）
MISSING = object()


def safe_get(data, *path, default=MISSING):
    current = data
    for position, key in enumerate(path):
        if isinstance(current, dict):
            try:
                hash(key)
            except TypeError as exc:
                raise TypeError(
                    f"path[{position}]={key!r}: dict key must be hashable"
                ) from exc
            if key not in current:
                return default
            current = current[key]
        elif isinstance(current, list):
            if isinstance(key, bool) or not isinstance(key, int):
                raise TypeError(
                    f"path[{position}]={key!r}: list index must be a non-negative int, "
                    f"not {type(key).__name__}"
                )
            if key < 0:
                raise TypeError(
                    f"path[{position}]={key!r}: list index must be non-negative, "
                    f"got {type(key).__name__}"
                )
            if key >= len(current):
                return default
            current = current[key]
        else:
            raise TypeError(
                f"path[{position}]={key!r}: cannot traverse "
                f"{type(current).__name__}; expected dict or list"
            )
    return current

name = safe_get(response, "choices", 0, "message", "tool_calls", 0, "function", "name")
assert name == "search"

适用边界：读取“允许缺失”的外部 dict/list 响应路径。它不负责 JSON 反序列化、类型转换、Schema 验证，也不遍历 tuple 或对象属性。不适用边界：请求 id 等必填字段时使用 response["id"]，或先显式验证后读取，不能用默认值掩盖缺失。

defaultdict：自动创建默认值

defaultdict、Counter、ChainMap 都来自 Python 自带的 collections 标准库，不用另外安装。defaultdict 和 Counter 是 dict 子类；ChainMap 是组合多个映射的独立动态视图类型，不是 dict 子类。

from collections import defaultdict

# 统计工具调用次数
call_count = defaultdict(int)    # 默认值为 0
calls = ["search", "calc", "search", "weather", "search"]
for call in calls:
    call_count[call] += 1
# {"search": 3, "calc": 1, "weather": 1}

# 按类型分组工具
tools_by_type = defaultdict(list)  # 默认值为 []
tools = [
    {"name": "search", "type": "web"},
    {"name": "calc", "type": "math"},
    {"name": "weather", "type": "web"},
]
for tool in tools:
    tools_by_type[tool["type"]].append(tool["name"])
# {"web": ["search", "weather"], "math": ["calc"]}

ChainMap：分层查找视图

ChainMap 不会复制或合并出一个独立 dict；它保留对原字典的引用，提供一个按从左到右优先级查找的动态分层视图。底层字典后续变化会反映在视图中；通过这个视图进行普通赋值或删除时，只作用于第一个映射。

from collections import ChainMap

# Agent 配置的分层优先级视图
user_config = {"theme": "dark", "timeout_seconds": 20}
project_config = {"theme": "light", "max_results": 50}
default_config = {"theme": "system", "timeout_seconds": 30, "max_results": 10}

# 查找优先级：user > project > default
config = ChainMap(user_config, project_config, default_config)
assert config["theme"] == "dark"
assert config["max_results"] == 50

project_config["max_results"] = 80
assert config["max_results"] == 80       # 视图反映底层修改
config["max_results"] = 100              # 写入第一个映射 user_config
assert user_config["max_results"] == 100

其他常用 dict 方法

setdefault(key, default) 会在调用函数前先求值所有实参，所以即使 key 已存在，昂贵的默认值表达式仍会执行。下面两段在返回/存储结果上相近，但在是否调用昂贵函数上不等价：

# dict | 运算符（Python 3.9+）

# Counter：计数器（Agent 中统计 token、工具调用）
from collections import Counter

word_count = Counter(words)
print(word_count.most_common(2))  # [("hello", 3), ("world", 1)]

最佳实践：按字段契约读取外部嵌套数据

先澄清：safe_get() 是本课自己编写的教学辅助函数，不是 Python 内置函数，也不是标准库 API；实现和契约以本节上方的“本课唯一规范实现”为准。下面的折叠自检为方便独立复制运行，会原样包含同一实现。

❌ 所有错误都吞成 None

真实存储的 None、允许缺失、必填 id 缺失和结构错误混在一起，错误会在更远处爆发。

✅ 先区分字段契约

可选路径用 safe_get；缺失默认返回 MISSING 或指定默认值；必填字段直接索引或显式验证。

为什么更优：按字段契约分别处理可选缺失、必填缺失和结构错误，会让错误在信息最完整的位置暴露，从而提升数据完整性与可诊断性。代价是要维护路径规则、哨兵语义和正反分支测试；路径越长，错误信息和静态类型也越难表达。适用：结构允许缺少部分 dict key 或 list 元素的外部响应。不适用：必填字段、任意对象属性遍历、tuple 路径、类型转换或完整 Schema 校验。字段约束持续增长时，应改用 Pydantic 等模型，而不是继续扩展通用路径函数。

💡 面试常见问题：

"isinstance 和 type 的区别？"

答：isinstance 支持继承关系检查（子类也返回 True），type 精确匹配类型。一般推荐用 isinstance。

判断什么时候不该用 safe_get？

字段是业务继续运行的必要条件，或需要完整结构验证时。例如响应必须有 id 才能追踪请求，就应直接用 fixture["id"] 或显式校验；需要验证全部字段类型时应使用 Schema/Pydantic。safe_get 只用于允许缺失的 dict/list 路径，不负责 tuple、对象属性、转换或深层 Schema 校验。

知识图谱

变量与类型
├── 变量 = 引用（标签），不是值
├── 不可变类型：int / float / str / bool / tuple
│   └── 常见类型多可哈希；tuple 还要求全部元素可哈希
├── 可变类型：list / dict / set
│   └── 默认参数陷阱
└── 引用计数 → 垃圾回收

四大容器（认括号：[]=list ()=tuple {冒号}=dict {无冒号}=set；空集合=set()）
├── list：有序、可变、可重复
│   └── 切片：messages[-3:]
├── dict：键值对、有序（3.7+）
│   ├── .get() 单层可选访问
│   ├── safe_get() 可选 dict/list 路径（MISSING 区分缺失与 None）
│   ├── .setdefault() 获取或设置默认值（默认表达式会提前求值）
│   ├── .update() 合并字典
│   └── dict | 运算符（3.9+）
├── tuple：有序、不可变
│   └── 解包：x, y = point
└── set：无序、不可重复
    └── 集合运算：- & |

推导式
├── 列表：[x for x in items if cond]
├── 字典：{k: v for k, v in items}
└── 集合：{x for x in items}

collections 模块
├── defaultdict → 自动默认值
├── ChainMap → 多字典优先级的动态分层视图

面试常见问题

Q1：Python 可变类型和不可变类型的区别？

答：不可变类型（int/str/tuple）的值不能原地修改，相关操作通常创建新对象；可变类型（list/dict/set）可以原地修改。dict key 和 set 元素要求可哈希，而非笼统地要求“不可变”；例如含 list 的 tuple 就不可哈希。

Q2：Python dict 的底层实现是什么？

答：以 CPython 为例，dict 使用紧凑哈希表。通过 key 的哈希值定位候选槽位，平均查找复杂度是 O(1)，最坏情况可退化。Python 语言从 3.7 起保证 dict 保持插入顺序；CPython 的具体内存布局是实现细节，不应解释成语言规范要求“额外维护链表”。

Q3：tuple 和 list 的区别？什么时候用 tuple？

答：tuple 不可变，list 可变。只包含可哈希元素的 tuple 可以作为 dict key，list 不行。tuple 通常比同内容的 list 占用更少；适合表达不应原地修改的固定组合，或在满足可哈希条件时作为 key。

Q4：defaultdict 和普通 dict 有什么区别？

答：defaultdict 在执行 d[key] 且 key 不存在时，会通过 __missing__ 创建并保存默认值，而不是抛出 KeyError；get()、成员测试和迭代不会触发这一步。它常用于计数和分组场景。

Q5：什么是可变默认参数陷阱？怎么避免？

答：函数的默认参数如果是可变对象（如 list/dict），会在函数定义时创建一次，之后每次调用共享同一个对象。避免方法：用 None 作为默认值，在函数体内创建新对象。

Q6：isinstance 和 type 的区别？

答：isinstance 支持继承关系检查（子类也返回 True），type 精确匹配类型。一般推荐用 isinstance，更符合多态设计。

总结

  • Python 变量是引用（标签），不是值

  • 四大容器各有适用场景，dict 是 Agent 开发的核心
