演练迁移失败与恢复路径

先拒绝不认识的旧形状，再从不变的输入接续

如果不是所有旧任务都能读怎么办？

前两课验证了使用命名字段的旧检查点；这次 v1 另有一种真正可读的历史形状：binding 不是对象，而是六项有顺序的列表，依次是租户、主体、任务、动作、修订和内容摘要。它也带 schema: 1，例如 ["training", "reviewer", "export", "save_local_draft", 2, "…"]。v2 没有经验证的列表解码器，不把它猜成命名字段。这里不是「故意写个不存在的版本号」：这份数据由 v1 正常推进所得，v1 能按原约定处理。

学习目标：让两个新进程在同一候选副本上拒绝且不调度或写入；从同一准备包交给 v1 独立续跑，验证回退不扩大授权，并识别必须停止对账的情况。

1. 先预检，再选择运行路径

  1. 先封存 v1 原包。只在一个干净副本录入审批或注入故障，关库并用独立金标核对实际变化和其余字段。候选与旧路径各复制同一准备包，不在任何一臂补批准、换来源或修回执。
  2. 候选只读预检拒绝列表形状，返回 migration_refused。两个新进程先后打开同一候选副本：每次在分发与业务调用前停下，不写入、不返回草稿或回执；检查点与全表不变，各文件前后摘要都等于准备包。
  3. 另一个新进程用 v1 打开从未交给候选的副本，确认起跑摘要相同。识别列表形状并不授予权限：只有当前来源、稿件修订、决定和回执各自符合契约才继续。

「回退」在这里是切回旧运行路径，继续处理未改的旧检查点，不是回滚候选已改写的数据库，更不撤销已提交动作。线上若已有候选写入，要先确认在途动作、同时存在的状态格式与副作用，再设计回退或补偿；不能覆盖已保存的业务数据。

旧路径不是强行重跑：分别验证它确实会做什么
旧路径工作副本的条件返回INSERT 尝试／全表行
待批，宿主录入匹配拒绝denied，无回执0／0
待批后获匹配批准；或原本已批未保存saved，原稿和确定的操作回执1／1
已提交丢回复，来源和回执都匹配replayed，原回执和原稿0／1
错主体或拿旧稿批准当前稿rejected，不分发，不返回回执或正文0／0
已提交，但来源撤权replay_withheld，不分发，不返回回执或正文0／1（保留原行）

要把「认得旧形状」与「可以续跑」分别验收。错批准与撤权都要核对零节点、零业务调用、零 INSERT，以及持久记录和对外返回。已提交事实不等于当前可以放行旧结果。

2. 把拒绝、可恢复和可发布分开

决策卡：不能证明可迁移，就保留可核验的旧路径

适用：历史任务尚未完成，而候选对部分状态缺乏已验解码器。不适用：候选已写入后，不把切回旧副本当作被改数据的回滚。

猜字段并继续发单

可能把旧批准接到错稿上，也可能重写刚提交的效果。

只读识别、停机、按原路径处理

保留拒绝证据，旧版也只处理验证通过的业务动作。

代价：要保留旧运行环境和给人工对账留容量；替代方案是停收后排空，或先写可审计的显式迁移及反向兼容测试。

  1. 用同一候选副本重启两次，核对每个文件摘要与零分发。
  2. 跑旧路径正控和坏回执，分别核对拒绝、单写、重放与停止。

诊断：只要候选改变一个文件，或旧路径暗中补写丢失回执，本方案就不能按原证据放行。

Q 已保存标记仍在，但独立只读查询找不到原回执行。应如何处理？
缺回执行和已保存标记冲突，无法证明可安全重写。先保留证据，再核对原操作。

from pathlib import Path
import sys

sys.path.insert(0, str(Path("code/phase10-framework-evolution/evolution-lab/checkpoints").resolve()))
from contract import run

report = run("fallback", cases=("approve", "wrong_actor", "old_review", "source_revoked"))
for name, case in report.items():
    before, prepared = case["before"], case["prepared"]
    assert prepared["graph"] == before["graph"]
    binding = prepared["graph"]["values"]["binding"]
    assert isinstance(binding, list)
    if name == "wrong_actor":
        assert prepared["ledger"]["reviews"] == [[binding[0], "another-reviewer", *binding[2:], "approve"]]
    elif name == "old_review":
        old_binding = before["old_binding"]
        assert old_binding["revision"] == 1 and old_binding["digest"] != binding[5]
        assert prepared["ledger"]["reviews"] == [[*binding[:4], 1, old_binding["digest"], "approve"]]
    elif name == "source_revoked":
        assert [s[2] for s in before["ledger"]["sources"]] == ["KB-01", "KB-02"]
        assert prepared["ledger"]["sources"] == before["ledger"]["sources"][:1]
    assert before["origin"] != prepared["origin"] and len(case["refused"]) == 2
    for attempt in case["refused"]:
        assert attempt["reply"] == {"status": "migration_refused", "receipt": None, "draft": None}
        assert (attempt["nodes"], attempt["calls"], attempt["inserts"]) == ([], 0, [])
        assert attempt["origin"] == attempt["after"] == prepared["origin"]
        assert attempt["graph"] == prepared["graph"] and attempt["ledger"] == prepared["ledger"]
    old = case["arms"]["v1"]
    assert old["from_prepared"] == prepared["origin"]
    assert old["ledger"]["reviews"] == prepared["ledger"]["reviews"]
    if name == "approve":
        row, = old["ledger"]["saved"]
        assert old["nodes"] == ["review", "apply_review"] and old["calls"] == 1
        assert old["inserts"] == [row[0]] and old["reply"] == {"status": "saved", "receipt": row[0], "draft": row[-1]}
    else:
        status = "replay_withheld" if name == "source_revoked" else "rejected"
        assert old["reply"] == {"status": status, "receipt": None, "draft": None}
        assert (old["nodes"], old["calls"], old["inserts"]) == ([], 0, [])
        assert old["after"] == prepared["origin"]
        assert old["ledger"] == prepared["ledger"] and old["graph"] == prepared["graph"]
        assert old["ledger"]["saved"] == before["ledger"]["saved"]
print("L87 ACCEPTED")

面试自查

Q1 状态标了 schema: 1，却含未知形状。能尝试按顺序解码吗？

参考回答：先停止调度，不猜布局；用经验证的旧路径或明确定义的转换。

追问：如何证明不是候选造了个无法读取的样本？

答题要点：由旧程序产生，旧运行路径能处理同一源的副本，业务金标也通过。

Q2 候选日志写了两次「未迁移」。还要观察什么？

参考回答：在同一个副本上重启，核对三文件摘要、调度记录、业务调用和 INSERT。

追问：两个独立新副本各运行一次够吗？

答题要点：那不能发现某次运行给下次留了标记或损坏；要重开同一份。

Q3 灰度中的候选已经写了业务行，此时切旧副本安全吗？

参考回答：本课不证明安全；不能用旧数据覆盖事实。先停止新增写，辨认哪些输入和副作用已变。

追问：业务允许撤销时怎么做？

答题要点：作为独立补偿动作设计权限、审批、回执和效果验证。

Q4 CI 只显示本地合同标记，能开始 Phase 11 的部署练习吗？

参考回答：不能把本地结果当真实 LangGraph 兼容证明，报告应拆成通过与待验两列。

追问：固定 SDK 上的应用迁移通过后，能说升级了 SDK 也行吗？

答题要点：不能；同 SDK 的应用迁移与 SDK 版本迁移是两个变量。

小结与一手参考

未知旧形状先拒绝且不改输入，再以原路径续跑可证实的业务。丢回复可对账，矛盾回执不补写；演练结论只覆盖已测环境。

  • LangGraph · Graph migrations：图变化与运行中线程兼容。
  • Python · subprocess.run：独立进程、参数列表与退出结果。
  • SQLite · Transactions：事务撤销不等于应用回退。
