继承、多态与 __call__

__call__ 让对象“像函数一样被调用” — 是 Python 封装有状态工具的一种方式

💡 为什么这课重要？

Python 可以用可调用对象封装有配置或状态的工具：对象保存 name/schema 等信息，再通过 __call__ 提供 tool(query="...") 的调用方式。普通函数、协议或框架包装器也能实现工具接口；ABC + __call__ 只是其中一种设计。

本课用抽象基类（ABC）声明子类必须提供 run，再用多态统一调用不同实现。要注意：@abstractmethod 只检查抽象方法是否被覆盖，不会验证覆盖方法的参数签名是否兼容，也不会保证返回值符合注解或业务契约，这些仍需类型检查、测试或运行时校验。

本课关键决策：无状态工具优先用函数；确需实例配置或状态时才用可调用对象；只有确需名义契约时才引入 ABC。

学习目标

完成本课后，你将能够：

  • 用继承和 super() 复用父类逻辑
  • 理解多态：同一接口、不同实现
  • 用 ABC + @abstractmethod 强制子类实现方法
  • 用 __call__ 让对象可被调用
  • 用 __repr__ 让对象打印时清晰可读

1. 继承与 super()

看下面的 class SearchTool(Tool)：括号里的 Tool 就是父类（基类），SearchTool 是子类——子类自动拥有父类的属性和方法，还能覆盖（override）同名方法写自己的实现。super() 是子类调用父类实现的入口：它按方法解析顺序（MRO）找到父类版本并调用，让子类"先复用父类逻辑，再补充自己的差异"。复杂的多继承 MRO 属于进阶话题，本课不展开。

class Tool:
    def __init__(self, name):
        self.name = name
    def describe(self):
        return f"工具：{self.name}"

class SearchTool(Tool):
    def __init__(self, name, engine):
        super().__init__(name)      # 调用父类的 __init__，复用它的逻辑
        self.engine = engine
    def describe(self):
        base = super().describe()   # 也能复用父类方法再扩展
        return f"{base}（引擎：{self.engine}）"

t = SearchTool("search", "bing")
print(t.describe())    # 工具：search（引擎：bing）

super() 让子类"站在父类肩上"——不重复父类代码，只补充或改写差异部分。

本课统一术语：“工具”指执行一项能力的可调用实现，可以是函数或对象；“工具对象”特指实现了 __call__ 的实例；“注册表”是从工具名到可调用实现的映射。

2. 抽象基类 ABC：定义契约

有时你想规定"凡是工具，必须实现 run 方法"，否则不许实例化。用 ABC + @abstractmethod：

from abc import ABC, abstractmethod

class BaseTool(ABC):
    name: str = "base"

    @abstractmethod
    def run(self, **kwargs) -> dict:
        ...                          # 只声明契约，不实现

class SearchTool(BaseTool):
    name = "search"
    def run(self, query, max_results=5):
        return {"q": query, "n": max_results}

try:
    BaseTool()
except TypeError as exc:
    assert "abstract method" in str(exc)
else:
    raise AssertionError("BaseTool 不应可实例化")

assert SearchTool().run(query="ai") == {"q": "ai", "n": 5}
print("ABC example passed")

@abstractmethod 在这里保证 run 这个名字已被具体子类实现，因此 BaseTool() 失败而正例仍能继续执行；它不比较 BaseTool.run(**kwargs) 与 SearchTool.run(query, max_results=5) 的兼容性，也不检查实际返回值是不是 dict。

Q 一个含 @abstractmethod 的 ABC，直接实例化会怎样？
含未实现抽象方法的抽象类不能被实例化，会抛 TypeError。只有实现了所有抽象方法的子类才能实例化。这正是"强制所有工具都实现 run"的机制——把契约写进代码。

3. __call__：让对象像函数

给类定义 __call__，它的实例就能"被调用"。严格地说，Python 对这类特殊方法按类型查找，大致是 type(obj).__call__(obj, ...)；只给某一个实例赋值 obj.__call__ = ... 不会让它变成可调用对象。这让工具既是对象、又能 tool(...)：

from abc import ABC, abstractmethod

class BaseTool(ABC):
    name: str = "base"

    @abstractmethod
    def run(self, **kwargs) -> dict: ...

    def __call__(self, **kwargs) -> dict:   # 对象()  →  实际执行 run
        return self.run(**kwargs)

    def __repr__(self):
        return f"<Tool {self.name}>"

class SearchTool(BaseTool):
    name = "search"
    def run(self, query, max_results=5):
        return {"q": query, "n": max_results}

tool = SearchTool()
print(tool(query="ai"))    # {'q': 'ai', 'n': 5}   ← 像函数一样调用！
print(tool)                # <Tool search>         ← __repr__ 生效

最佳实践：按实现集合的变化频率选择分发方式

唯一决策：实现是固定的小集合，还是会频繁新增？前者优先显式分支，后者优先注册表分发。

固定小集合：显式分支
if name == "search":
    result = search(**args)
elif name == "calc":
    result = calc(**args)

选项长期固定且很少时，控制流直接、可见，是有效方案。

频繁扩展：注册表分发
tool = registry.get(name)
if tool is None:
    raise KeyError(f"unknown tool: {name}")
result = tool(**args)

新增实现只注册，不扩充分支链。

取舍：注册表把名称解析与具体实现放入数据映射，使执行器不随实现数量增长而修改；代价是多一次间接查找，可用实现也不如分支一目了然。左栏沿用比较组件的 bp-wrong 样式只为保持版式一致，不表示显式分支是错误。

动手自检（整块复制即可运行）：
class AddTool:
    def __call__(self, *, a, b):
        return a + b

class JoinTool:
    def __call__(self, *, parts):
        return "".join(parts)


def register(registry, name, tool):
    if name in registry:
        raise KeyError(f"duplicate tool: {name}")
    registry[name] = tool


def execute(registry, name, args):
    tool = registry.get(name)
    if tool is None:
        raise KeyError(f"unknown tool: {name}")
    return tool(**args)

registry = {}
register(registry, "add", AddTool())
assert execute(registry, "add", {"a": 2, "b": 3}) == 5

old_add = registry["add"]
try:
    register(registry, "add", AddTool())
except KeyError as exc:
    assert exc.args == ("duplicate tool: add",)
else:
    raise AssertionError("重复工具名应被拒绝")
assert registry["add"] is old_add  # 失败后旧条目保持不变

execute_code = execute.__code__.co_code
register(registry, "join", JoinTool())  # 只扩展注册表
assert execute.__code__.co_code == execute_code
assert execute(registry, "join", {"parts": ["A", "I"]}) == "AI"
try:
    execute(registry, "missing", {})
except KeyError as exc:
    assert exc.args == ("unknown tool: missing",)
else:
    raise AssertionError("未知工具名应明确失败")

结果解释：重复注册默认失败且旧条目不变；增加 JoinTool 后 execute 的代码未变；未知名称产生精确的错误。

实现形态边界：注册表决策不强制每个实现都写成类：无状态时可使用普通函数，需要保存实例状态或配置时再使用可调用类。无论选哪一种，注册表只负责名称到可调用实现的分发；参数校验、权限、超时和副作用审批仍属于系统边界。这里是通用 Python dispatcher 教学模型，不是任何 Agent SDK 的固定接口。

Q 定义了 __call__ 的类，它的实例 obj 能做什么？
__call__ 让实例可被调用；特殊方法从类型上查找，大致执行 type(obj).__call__(obj, ...)，因此只给实例赋值同名属性并不够。这种可调用对象适合封装状态或配置；无状态工具通常用普通函数就够了。

4. 多态 & 组合优于继承

多态：不同工具都接受同一个调用外壳，Agent 就能用同一种方式调用它们，不用关心具体类型。这里的统一仅指调用入口；完整可替换性还要求各实现遵守相同的参数与结果契约。下面的工具都共享 run(**kwargs) / tool(**args) 这一外壳，但各自参数不同，因此不能把任意一组 args 无条件传给所有工具（下面是示意，完整可运行版见本课练习）：

# 示意：每个调用都携带与目标工具匹配的 args
calls = [
    (SearchTool(), {"query": "ai"}),
    (CalcTool(), {"a": 2, "b": 3}),
]
for tool, args in calls:
    result = tool(**args)      # 统一调用外壳，不等于所有参数都可互换

组合优于继承：能用"把对象装进另一个对象"解决的，就别用深继承。比如 Agent 持有一组工具（组合），而不是去继承工具。继承层级太深会让代码难懂难改。

💡 上面示意用 list 遍历，是为了直观体会"同一循环调用不同工具"的多态。而实战里 Agent 拿到的是 LLM 给的工具名，需要"按名字找工具"——所以本课练习会把 tools 存成 dict（{name: tool}），用 tools[call["name"]] 取。结构变了，但"统一接口调用"的多态思想不变。

知识图谱

继承
├── super().__init__() → 复用父类
└── 子类可扩展/改写父类方法

ABC 抽象基类
├── @abstractmethod → 声明契约
└── 含抽象方法 → 不能实例化（强制子类实现）

__call__ → 对象可像函数调用
├── tool(**args) 触发 run（呼应 L05 解包）
└── 工具 = 对象(带 name/schema) + 可调用

多态 → 同接口不同实现（统一调用工具）
组合优于继承 → Agent 持有工具，而非继承工具

练习：实现一个可调用的 Agent 工具基类

用 ABC 定义 BaseTool，子类通过实现 run 得到一个可调用、可自我描述的工具。先自己写，再看答案。

任务清单

  1. BaseTool(ABC)：类属性 name、description；抽象方法 run(**kwargs) -> dict
  2. 实现 __call__：转发到 run
  3. 实现 __repr__：形如 <Tool search: 搜索网页>
  4. 实现 SearchTool 和 CalcTool 两个子类
  5. 把工具实例放进注册表 {name: tool}，按 call["name"] 查到工具后统一 tool(**args) 调用（体会多态；正文第 4 节的 list 只是入门示意，练习用 dict 是因为真实场景要按名字找工具）

from abc import ABC, abstractmethod

class BaseTool(ABC):
    name: str = "base"
    description: str = ""

    @abstractmethod
    def run(self, **kwargs) -> dict:
        ...

    def __call__(self, **kwargs) -> dict:
        return self.run(**kwargs)

    def __repr__(self):
        return f"<Tool {self.name}: {self.description}>"

class SearchTool(BaseTool):
    name = "search"
    description = "搜索网页"
    def run(self, query, max_results=5):
        return {"tool": self.name, "query": query, "n": max_results}

class CalcTool(BaseTool):
    name = "calc"
    description = "计算两个数之和"
    def run(self, a, b):
        return {"tool": self.name, "result": a + b}   # 明确的数值参数，不对字符串做 eval

tools = {t.name: t for t in [SearchTool(), CalcTool()]}

# 模拟 Agent 执行：LLM 给出工具名 + 参数
calls = [
    {"name": "search", "args": {"query": "ai agents"}},
    {"name": "calc", "args": {"a": 1500, "b": -300}},
]
for call in calls:
    tool = tools[call["name"]]
    print(repr(tool), "→", tool(**call["args"]))   # 统一方式调用不同工具（多态）

思考题

先自己想，再点开对答案。

Q1如果新增一个 WeatherTool，Agent 的调用循环需要改吗？

不需要改循环——这正是多态 + 统一接口的威力。

WeatherTool 只要照样继承 BaseTool、实现自己的 run，它就自动获得了和其它工具一样的调用方式：tool(**args) 触发 __call__ 再转发到 run。Agent 的循环 for call in calls: tools[call["name"]](**call["args"]) 是对着 BaseTool 这个统一接口编程的，它压根不关心具体是哪个子类。

要改的只有注册表那一行——把新工具加进 tools 字典（如 tools["weather"] = WeatherTool()）。调用逻辑一个字都不用动。这就是多态的核心价值：新增实现，而非修改调用方，也贴合「对扩展开放、对修改封闭」的开闭原则。

Q2为什么用"Agent 持有工具字典"（组合）比"Agent 继承各种工具"更好？

因为 Agent 和工具是「has-a（有）」关系，不是「is-a（是）」关系；组合灵活、可运行时增删，继承则僵硬且会爆炸。

从语义看，「Agent 拥有一组工具」是自然的，而「Agent 是一个搜索工具、同时又是一个计算工具」根本讲不通——这正是 is-a 与 has-a 的区别，用错就是把继承当箩筐。

从工程看，组合的好处非常实在：工具集是一个 dict，能在运行时动态增删（按用户权限、按场景开关工具），一个 Agent 可以持有任意多个工具；而 Python 在执行 class 语句时创建类，继承关系通常在类创建的那一刻就确定下来，之后不会像组合那样按实例、按运行时去替换持有的对象，明显不如组合灵活。更要命的是，「继承各种工具」意味着多继承，工具一多就组合爆炸、方法解析顺序（MRO）混乱、耦合严重、难以维护。所以各大框架都是「Agent 持有工具集合」这套组合设计——这就是本课「组合优于继承」的落地。

课末自检：证明跨领域插件可组合扩展
from abc import ABC, abstractmethod

class BaseTransform(ABC):
    def __init__(self, name, owner):
        self.name = name
        self.owner = owner

    @abstractmethod
    def transform(self, text):
        raise NotImplementedError

    def __call__(self, text):
        return self.transform(text)

class PrefixTransform(BaseTransform):
    def __init__(self, owner, prefix):
        super().__init__("prefix", owner)
        self.prefix = prefix

    def transform(self, text):
        return self.prefix + text

class UpperTransform(BaseTransform):
    def __init__(self, owner):
        super().__init__("upper", owner)

    def transform(self, text):
        return text.upper()


def register(registry, transform):
    if transform.name in registry:
        raise KeyError(f"duplicate transform: {transform.name}")
    registry[transform.name] = transform


def execute(registry, name, text):
    transform = registry.get(name)
    if transform is None:
        raise KeyError(f"unknown transform: {name}")
    return transform(text)

try:
    BaseTransform("base", "system")
except TypeError as exc:
    message = str(exc)
    assert "abstract class BaseTransform" in message, message
    assert "abstract method" in message, message
    assert "transform" in message, message
else:
    raise AssertionError("BaseTransform 应因未实现抽象方法 transform 而不可实例化")

prefix = PrefixTransform("text-team", "Agent: ")
registry = {}
register(registry, prefix)
assert prefix.owner == "text-team"
assert execute(registry, "prefix", "ready") == "Agent: ready"

old_prefix = registry["prefix"]
try:
    register(registry, PrefixTransform("other-team", "Replaced: "))
except KeyError as exc:
    assert exc.args == ("duplicate transform: prefix",)
else:
    raise AssertionError("重复转换名称 prefix 应被拒绝")
assert registry["prefix"] is old_prefix
assert execute(registry, "prefix", "ready") == "Agent: ready"

execute_fn = execute
execute_code = execute.__code__
upper = UpperTransform("text-team")
register(registry, upper)
assert execute is execute_fn
assert execute.__code__ is execute_code
assert upper.owner == "text-team"
assert execute(registry, "upper", "agent") == "AGENT"
try:
    execute(registry, "missing", "x")
except KeyError as exc:
    assert exc.args == ("unknown transform: missing",)
else:
    raise AssertionError("未知转换名称 missing 应明确失败")
print("L08 ACCEPTED")

面试常见问题

Q1：__call__ 有什么用？举个场景。

答：让实例可以像函数一样被调用（obj()）。典型场景是 Agent 工具：对象携带 name/schema 等元信息，又能 tool(**args) 直接执行，兼得对象与函数的优点。

Q2：抽象基类（ABC）解决什么问题？

答：声明抽象方法，并阻止仍有未实现抽象方法的类被实例化。它适合统一一组类的方法名，但不校验覆盖方法是否采用兼容签名，也不保证返回值满足注解或业务契约。

Q3：什么是多态？在 Agent 里怎么体现？

答：同一接口、不同实现。Agent 用同一句 tool(**args) 调用任意工具，不关心具体类型——新增工具也不用改调用代码。

Q4："组合优于继承"是什么意思？

答：优先用"对象持有其他对象"来复用功能，而非建立深层继承树。继承耦合强、层级深了难维护；组合更灵活。Agent 持有工具集合就是组合。

总结

  • super() 复用父类逻辑，子类只写差异
  • ABC + @abstractmethod 阻止抽象实现被实例化，但不校验兼容签名或返回行为
  • __call__ 让对象像函数被调用，是 Python 封装有状态工具的一种方式
  • __repr__ 让对象打印清晰，便于调试
  • 多态 = 同接口不同实现，Agent 用统一方式调用所有工具
  • 组合优于继承：Agent 持有工具，而非继承工具
