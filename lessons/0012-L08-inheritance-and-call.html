继承、多态与 __call__

__call__ 让对象"像函数一样被调用" — 这正是 Agent 工具的核心模式

💡 为什么这课重要？

Agent 框架里的"工具"几乎都是一个可调用对象：它既是对象（能带状态、能自我描述 name/schema），又能像函数一样 tool(query="...") 调用——秘密就是 __call__。

再配合抽象基类（ABC）定义"所有工具都得实现 run"，和多态让 Agent 用统一方式调用不同工具——这三者组合，就是各大框架 BaseTool 的设计骨架。

学习目标

完成本课后，你将能够：

  • 用继承和 super() 复用父类逻辑
  • 理解多态：同一接口、不同实现
  • 用 ABC + @abstractmethod 强制子类实现方法
  • 用 __call__ 让对象可被调用
  • 用 __repr__ 让对象打印时清晰可读

1. 继承与 super()

看下面的 class SearchTool(Tool)：括号里的 Tool 就是父类（基类），SearchTool 是子类——子类自动拥有父类的属性和方法，还能覆盖（override）同名方法写自己的实现。super() 是子类调用父类实现的入口：它按方法解析顺序（MRO）找到父类版本并调用，让子类"先复用父类逻辑，再补充自己的差异"。复杂的多继承 MRO 属于进阶话题，本课不展开。

class Tool:
    def __init__(self, name):
        self.name = name
    def describe(self):
        return f"工具：{self.name}"

class SearchTool(Tool):
    def __init__(self, name, engine):
        super().__init__(name)      # 调用父类的 __init__，复用它的逻辑
        self.engine = engine
    def describe(self):
        base = super().describe()   # 也能复用父类方法再扩展
        return f"{base}（引擎：{self.engine}）"

t = SearchTool("search", "bing")
print(t.describe())    # 工具：search（引擎：bing）

super() 让子类"站在父类肩上"——不重复父类代码，只补充或改写差异部分。

2. 抽象基类 ABC：定义契约

有时你想规定"凡是工具，必须实现 run 方法"，否则不许实例化。用 ABC + @abstractmethod：

from abc import ABC, abstractmethod

class BaseTool(ABC):
    name: str = "base"

    @abstractmethod
    def run(self, **kwargs) -> dict:
        ...                          # 只声明契约，不实现

class SearchTool(BaseTool):
    name = "search"
    def run(self, query, max_results=5):
        return {"q": query, "n": max_results}

BaseTool()          # ❌ TypeError：有未实现的抽象方法，不能实例化
SearchTool().run(query="ai")   # ✅ {'q': 'ai', 'n': 5}
Q 一个含 @abstractmethod 的 ABC，直接实例化会怎样？
含未实现抽象方法的抽象类不能被实例化，会抛 TypeError。只有实现了所有抽象方法的子类才能实例化。这正是"强制所有工具都实现 run"的机制——把契约写进代码。

3. __call__：让对象像函数

给类定义 __call__，它的实例就能"被调用"。这让工具既是对象、又能 tool(...)：

from abc import ABC, abstractmethod

class BaseTool(ABC):
    name: str = "base"

    @abstractmethod
    def run(self, **kwargs) -> dict: ...

    def __call__(self, **kwargs) -> dict:   # 对象()  →  实际执行 run
        return self.run(**kwargs)

    def __repr__(self):
        return f"<Tool {self.name}>"

class SearchTool(BaseTool):
    name = "search"
    def run(self, query, max_results=5):
        return {"q": query, "n": max_results}

tool = SearchTool()
print(tool(query="ai"))    # {'q': 'ai', 'n': 5}   ← 像函数一样调用！
print(tool)                # <Tool search>         ← __repr__ 生效
🔑 Agent 开发关联：

这就是 Agent 执行工具的标准姿势：Agent 拿到 LLM 给的参数字典 args，直接 tool(**args) 调用（呼应 L05 的解包）。Python 函数本身也是对象，能读取 __name__/__doc__/__annotations__ 等元信息，也能挂到注册表里——并非纯函数绝对做不到元信息。可调用对象真正的优势是：能把可变状态、配置项和行为一起封装进同一个实例（比如 self.api_key、self.max_retries），这是单个函数不方便做到的。

Q 定义了 __call__ 的类，它的实例 obj 能做什么？
__call__ 让实例可被"调用"——obj(...) 会触发 obj.__call__(...)。这是"可调用对象"，让工具兼具对象的状态/元信息与函数的调用方式，是 Agent 工具设计的核心模式。

4. 多态 & 组合优于继承

多态：不同工具都实现了 __call__，Agent 就能用同一种方式调用它们，不用关心具体是哪个类（下面是示意，完整可运行版见本课练习）：

# 示意：tools 里可以是任意实现了 __call__ 的工具，args 为 LLM 给的参数
tools = [SearchTool(), CalcTool()]
for tool in tools:
    result = tool(**args)      # 同一接口，各自的实现 —— 这就是多态

组合优于继承：能用"把对象装进另一个对象"解决的，就别用深继承。比如 Agent 持有一组工具（组合），而不是去继承工具。继承层级太深会让代码难懂难改。

💡 上面示意用 list 遍历，是为了直观体会"同一循环调用不同工具"的多态。而实战里 Agent 拿到的是 LLM 给的工具名，需要"按名字找工具"——所以本课练习会把 tools 存成 dict（{name: tool}），用 tools[call["name"]] 取。结构变了，但"统一接口调用"的多态思想不变。

知识图谱

继承
├── super().__init__() → 复用父类
└── 子类可扩展/改写父类方法

ABC 抽象基类
├── @abstractmethod → 声明契约
└── 含抽象方法 → 不能实例化（强制子类实现）

__call__ → 对象可像函数调用
├── tool(**args) 触发 run（呼应 L05 解包）
└── 工具 = 对象(带 name/schema) + 可调用

多态 → 同接口不同实现（统一调用工具）
组合优于继承 → Agent 持有工具，而非继承工具

实战练习

练习：实现一个可调用的 Agent 工具基类

用 ABC 定义 BaseTool，子类通过实现 run 得到一个可调用、可自我描述的工具。先自己写，再看答案。

任务清单

  1. BaseTool(ABC)：类属性 name、description；抽象方法 run(**kwargs) -> dict
  2. 实现 __call__：转发到 run
  3. 实现 __repr__：形如 <Tool search: 搜索网页>
  4. 实现 SearchTool 和 CalcTool 两个子类
  5. 把工具实例放进注册表 {name: tool}，按 call["name"] 查到工具后统一 tool(**args) 调用（体会多态；正文第 4 节的 list 只是入门示意，练习用 dict 是因为真实场景要按名字找工具）
💡 点击查看参考答案 
from abc import ABC, abstractmethod

class BaseTool(ABC):
    name: str = "base"
    description: str = ""

    @abstractmethod
    def run(self, **kwargs) -> dict:
        ...

    def __call__(self, **kwargs) -> dict:
        return self.run(**kwargs)

    def __repr__(self):
        return f"<Tool {self.name}: {self.description}>"

class SearchTool(BaseTool):
    name = "search"
    description = "搜索网页"
    def run(self, query, max_results=5):
        return {"tool": self.name, "query": query, "n": max_results}

class CalcTool(BaseTool):
    name = "calc"
    description = "计算两个数之和"
    def run(self, a, b):
        return {"tool": self.name, "result": a + b}   # 明确的数值参数，不对字符串做 eval

tools = {t.name: t for t in [SearchTool(), CalcTool()]}

# 模拟 Agent 执行：LLM 给出工具名 + 参数
calls = [
    {"name": "search", "args": {"query": "ai agents"}},
    {"name": "calc", "args": {"a": 1500, "b": -300}},
]
for call in calls:
    tool = tools[call["name"]]
    print(repr(tool), "→", tool(**call["args"]))   # 统一方式调用不同工具（多态）

思考题

先自己想，再点开对答案。

Q1如果新增一个 WeatherTool，Agent 的调用循环需要改吗？

不需要改循环——这正是多态 + 统一接口的威力。

WeatherTool 只要照样继承 BaseTool、实现自己的 run，它就自动获得了和其它工具一样的调用方式：tool(**args) 触发 __call__ 再转发到 run。Agent 的循环 for call in calls: tools[call["name"]](**call["args"]) 是对着 BaseTool 这个统一接口编程的，它压根不关心具体是哪个子类。

要改的只有注册表那一行——把新工具加进 tools 字典（如 tools["weather"] = WeatherTool()）。调用逻辑一个字都不用动。这就是多态的核心价值：新增实现，而非修改调用方，也贴合「对扩展开放、对修改封闭」的开闭原则。

Q2为什么用"Agent 持有工具字典"（组合）比"Agent 继承各种工具"更好？

因为 Agent 和工具是「has-a（有）」关系，不是「is-a（是）」关系；组合灵活、可运行时增删，继承则僵硬且会爆炸。

从语义看，「Agent 拥有一组工具」是自然的，而「Agent 是一个搜索工具、同时又是一个计算工具」根本讲不通——这正是 is-a 与 has-a 的区别，用错就是把继承当箩筐。

从工程看，组合的好处非常实在：工具集是一个 dict，能在运行时动态增删（按用户权限、按场景开关工具），一个 Agent 可以持有任意多个工具；而 Python 在执行 class 语句时创建类，继承关系通常在类创建的那一刻就确定下来，之后不会像组合那样按实例、按运行时去替换持有的对象，明显不如组合灵活。更要命的是，「继承各种工具」意味着多继承，工具一多就组合爆炸、方法解析顺序（MRO）混乱、耦合严重、难以维护。所以各大框架都是「Agent 持有工具集合」这套组合设计——这就是本课「组合优于继承」的落地。

面试常见问题

Q1：__call__ 有什么用？举个场景。

答：让实例可以像函数一样被调用（obj()）。典型场景是 Agent 工具：对象携带 name/schema 等元信息，又能 tool(**args) 直接执行，兼得对象与函数的优点。

Q2：抽象基类（ABC）解决什么问题？

答：定义"契约"——用 @abstractmethod 强制所有子类实现指定方法，否则不能实例化。用来统一一组类的接口，比如所有工具都必须有 run。

Q3：什么是多态？在 Agent 里怎么体现？

答：同一接口、不同实现。Agent 用同一句 tool(**args) 调用任意工具，不关心具体类型——新增工具也不用改调用代码。

Q4："组合优于继承"是什么意思？

答：优先用"对象持有其他对象"来复用功能，而非建立深层继承树。继承耦合强、层级深了难维护；组合更灵活。Agent 持有工具集合就是组合。
