主流 LLM API 上手

共享任务契约，保留原生接口差异：Responses、Messages 与兼容接口

💡 为什么这课重要？

Phase 2 已经讲过模型选型和 Token 成本。本课把同一个任务交给不同接口，比较输入、终止状态、正文和用量。目标不是背字段，而是为后面的工具循环建立有边界的适配层。

截至 2026-11-06 核验，OpenAI 官方推荐新项目使用 Responses，Chat Completions 仍受支持。本课两者都讲：前者用于新项目实践，后者用于理解后续兼容接口示例。Claude 使用官方 Anthropic SDK；Google 等厂商的原生 API 不在本课冒充已实现。

学习目标

  • 区分模型推理、应用历史与服务端会话存储。
  • 看懂 Responses / Messages / Chat Completions 的输入和返回差异。
  • 先检查终止状态和拒答，再消费正文；不假设第一个内容块必然是文本。
  • 记录模型、API 和 SDK 版本；区分在线集成测试与离线 fixture 验收。

1. 共同契约不等于相同字段

角色表示输入是谁提供的；内容块 / Item表示文本、工具请求等不同类型的数据。不同厂商不一定都返回“一条文本消息”。应用先明确任务、允许操作和输出目标，再由 Adapter（适配器）转换成厂商接口。

职责应用负责什么
任务与权限可信规则、用户输入、可执行工具和业务门槛
厂商适配输入结构、事件类型、工具关联 ID、终止原因和 usage
历史管理选择手动回传或服务端会话；保留工具交互和必要的不透明状态

模型不会自动记住另一次独立请求，但 API 可以在应用之外保存会话。Responses 的 previous_response_id 或 Conversations 与手动重放是不同方案；有状态服务不等于免费历史、不等于长期业务记忆，也不替代数据保留审查。见官方迁移指南。

Q 使用服务端会话后，哪项判断仍然成立？
状态可以由服务保存，但访问权限、保留策略和历史输入计费仍要核查。手动回传历史不是唯一方案。

2. OpenAI 主线：Responses API

在项目中先用 uv add openai 声明依赖并保留锁文件；设置 OPENAI_API_KEY 和具备访问权的 OPENAI_MODEL。以下是联网且会计费的可选实践，不会被离线验收自动执行。API 形状按官方文档核对。

import os
from openai import OpenAI

client = OpenAI()  # 凭证由 SDK / 环境提供，不写入源码
response = client.responses.create(
    model=os.environ["OPENAI_MODEL"],
    instructions="用一句中文解释概念。",
    input="什么是向量数据库？",
    store=False,  # 本例手动管理历史，不据此推断其他保留政策
)
if response.status != "completed":
    raise RuntimeError(f"响应未完成: {response.status}")
refused = any(
    part.type == "refusal"
    for item in response.output if item.type == "message"
    for part in item.content
)
if refused:
    raise RuntimeError("模型未提供可消费的答案")
print(response.output_text)
print(response.usage)  # Responses: input_tokens / output_tokens 等

output_text 是文本便捷读取器；完整 output 还可能含工具调用与推理 Items。延续工具循环时，不能只回传这段文本而丢掉其他必要 Items。store=False 下按官方要求保留可重放的完整输出及不透明推理信息；不要自己解析、改写这些信息。

本例故意不带通用 temperature：参数支持取决于模型与接口，不能照搬旧参数表。先查询能力，再显式配置。

3. Claude 原生接口：Messages

使用 uv add anthropic 并锁定版本。设置 ANTHROPIC_MODEL 和 SDK 支持的凭证来源。本例同样需要网络与调用预算；它不把 OpenAI 字段透传给 Claude。

import os
from anthropic import Anthropic

client = Anthropic()
with client.messages.stream(
    model=os.environ["ANTHROPIC_MODEL"],
    max_tokens=4096,
    system="用一句中文解释概念。",
    messages=[{"role": "user", "content": "什么是向量数据库？"}],
) as stream:
    message = stream.get_final_message()

if message.stop_reason != "end_turn":
    raise RuntimeError(f"响应未正常结束: {message.stop_reason}")
text = "".join(block.text for block in message.content if block.type == "text")
print(text)
print(message.usage)  # input_tokens / output_tokens；缓存字段另行核对

system 使用这里演示的顶层形式，max_tokens 是输出上限。返回的 content 是带类型的块列表，不保证第一块是正文；stop_reason 还可能表示工具请求、拒答或输出耗尽，不能一律当成功。流式细节在 L26，工具回填在后续课程。

官方依据：Messages API。新模型默认行为、参数支持和 SDK 主版本应分别核验，不以本页示例推断所有部署平台支持相同特性。

4. 兼容接口是边界，不是能力等价证明

Chat Completions 仍受支持，本例只演示普通文本。支持该接口不等于支持该接口的全部能力：例如 GPT‑6.2 Astra / Sol 的工具调用须走 Responses。本课程的 L27 和 L35 均以 Responses 为主，Chat Completions 作为兼容对照。

import os
from openai import OpenAI

client = OpenAI()
reply = client.chat.completions.create(
    model=os.environ["OPENAI_MODEL"],
    messages=[{"role": "user", "content": "什么是向量数据库？"}],
)
choice = reply.choices[0]
if choice.finish_reason != "stop" or choice.message.refusal:
    raise RuntimeError("本例只消费正常完成的纯文本答案")
print(choice.message.content)
print(reply.usage)  # prompt_tokens / completion_tokens

自定义 base_url 只能改变目标端点，不能自动补齐缓存、推理状态、工具语义、事件和计费差异。快速试验可以使用已确认支持的兼容端点；需要厂商原生能力时使用官方 SDK。不要把本课 Anthropic 调用替换成 OpenAI shim。

Q 换成兼容端点后，最需要补做哪项工作？
兼容表示支持某些接口形状，不表示全部语义等价。适配层要处理能力、状态和 usage 的实际差异。

5. 离线示例：先辨认接口，再取正文

用以下虚构 fixture 练习纯文本适配：确认该接口的成功终态、排除拒答，再取正文。字典模拟各接口字段，Responses 的 output_text 是对 SDK 便捷属性的替身；测试不发请求，也不处理工具调用。

决策卡：统一交付规则，不统一终态字段

适用：同一份摘要要支持多个原生接口。不适用：工具流程不能只留正文，必须保留调用和关联状态。

误判：摘要非空就交付

Responses 已有一段摘要，但后续消息包含拒答。只读 output_text 会交付本应拦住的正文。

对照：按原生接口验收

同一响应即使是 completed，也先查全部消息块是否拒答；Messages 和 Chat 则检查各自的停止原因。

取舍：多维护一层映射，换来统一且可检验的交付规则；兼容接口的字段形状不能替代该检查。

  1. 运行下方参考，先验三个正常终态。
  2. 保持正文不变，改终态或加入后置拒答，再验是否拦截。

def text_only(api, payload):
    if api == "responses":
        if payload["status"] != "completed":
            raise ValueError("not completed")
        if any(part["type"] == "refusal" for item in payload["output"]
               if item["type"] == "message" for part in item["content"]):
            raise ValueError("refused")
        return payload["output_text"]
    if api == "messages":
        if payload["stop_reason"] != "end_turn":
            raise ValueError("incomplete")
        return "".join(b["text"] for b in payload["content"] if b["type"] == "text")
    if api == "chat":
        choice = payload["choices"][0]
        if choice["finish_reason"] != "stop" or choice["message"].get("refusal"):
            raise ValueError("not completed")
        return choice["message"]["content"]
    raise ValueError("unknown API")

response = {"status": "completed", "output_text": "甲", "output": [
    {"type": "reasoning"}, {"type": "message", "content": [{"type": "output_text", "text": "甲"}]},
]}
message = {"stop_reason": "end_turn", "content": [
    {"type": "thinking"}, {"type": "text", "text": "乙"},
]}
choice = {"finish_reason": "stop", "message": {"content": "丙", "refusal": None}}
assert text_only("responses", response) == "甲"
assert text_only("messages", message) == "乙"
assert text_only("chat", {"choices": [choice]}) == "丙"

later_refusal = {"type": "message", "content": [{"type": "refusal", "refusal": "未提供答案"}]}
for api, data in [
    ("unknown", {}),
    ("responses", dict(response, status="incomplete")),
    ("responses", dict(response, output=[*response["output"], later_refusal])),
    ("messages", dict(message, stop_reason="max_tokens")),
    ("messages", dict(message, stop_reason="refusal")),
    ("chat", {"choices": [dict(choice, finish_reason="length")]}),
    ("chat", {"choices": [dict(choice, message={"content": "丙", "refusal": "未提供答案"})]}),
]:
    try:
        text_only(api, data)
    except ValueError:
        pass
    else:
        raise AssertionError(f"{api} 不应放行失败或拒答")
print("L25 ACCEPTED")

本课最佳实践验收：换接口后，班车公告还能发布吗？

公告编辑器要保留拒绝发布的原因。四条候选正文相同，但接口和终态不同。复制起点，实现 build_outbox(rows)，返回两份字典：可发布的编号 → 正文，被拦截的编号 → 原因（refused 或原生终止值）。仅 A、D 可发布；B、C 应有不同的拦截原因。不需要前面的代码、SDK 或密钥。

notice = "北门班车停运。"
message = {"type": "message", "content": [{"type": "output_text", "text": notice}]}
refusal = {"type": "message", "content": [{"type": "refusal", "refusal": "未提供答案"}]}
responses = {"status": "completed", "output_text": notice, "output": [message]}
chat = {"finish_reason": "stop", "message": {"content": notice, "refusal": None}}
rows = [
    ("A", "responses", responses),
    ("B", "chat", {"choices": [dict(chat, finish_reason="length")]}),
    ("C", "responses", dict(responses, output=[message, refusal])),
    ("D", "chat", {"choices": [chat]}),
]

def build_outbox(rows):
    published, blocked = {}, {}
    for notice_id, api, payload in rows:
        if api == "responses":
            status = payload["status"]
            if status != "completed":
                blocked[notice_id] = status
            elif any(part["type"] == "refusal" for item in payload["output"]
                     if item["type"] == "message" for part in item["content"]):
                blocked[notice_id] = "refused"
            else:
                published[notice_id] = payload["output_text"]
        elif api == "chat":
            choice = payload["choices"][0]
            reason = choice["finish_reason"]
            if reason != "stop":
                blocked[notice_id] = reason
            elif choice["message"]["refusal"]:
                blocked[notice_id] = "refused"
            else:
                published[notice_id] = choice["message"]["content"]
        else:
            raise ValueError("unknown API")
    return published, blocked


published, blocked = build_outbox(rows)
assert published == {"A": "北门班车停运。", "D": "北门班车停运。"}, published
assert blocked == {"B": "length", "C": "refused"}, blocked
print("L25 TRANSFER PASSED")

总结与下一课

  • 同一个业务目标可以跨厂商复用，但协议状态不能无损地简化成一个字符串。
  • Responses 是 OpenAI 新项目推荐方向；Chat Completions 的兼容价值仍在。
  • Claude 使用原生 SDK；各接口先验正常终态、排除拒答，再按类型提取内容。
  • 凭证不写入源码；项目声明依赖并保留锁文件，生产可使用密钥管理与工作负载身份。
