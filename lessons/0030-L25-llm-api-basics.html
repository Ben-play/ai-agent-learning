主流 LLM API 上手

共享任务契约，保留原生接口差异：Responses、Messages 与兼容接口

💡 为什么这课重要？

Phase 2 已经讲过模型选型和 Token 成本。本课把同一个任务交给不同接口，比较输入、终止状态、正文和用量。目标不是背字段，而是为后面的工具循环建立有边界的适配层。

截至 2026-11-06 核验，OpenAI 官方推荐新项目使用 Responses，Chat Completions 仍受支持。本课两者都讲：前者用于新项目实践，后者用于理解后续兼容接口示例。Claude 使用官方 Anthropic SDK；Google 等厂商的原生 API 不在本课冒充已实现。

学习目标

  • 区分模型推理、应用历史与服务端会话存储。
  • 看懂 Responses / Messages / Chat Completions 的输入和返回差异。
  • 先检查终止状态和拒答，再消费正文；不假设第一个内容块必然是文本。
  • 记录模型、API 和 SDK 版本；区分在线集成测试与离线 fixture 验收。

1. 共同契约不等于相同字段

角色表示输入是谁提供的；内容块 / Item表示文本、工具请求等不同类型的数据。不同厂商不一定都返回“一条文本消息”。应用先明确任务、允许操作和输出目标，再由 Adapter（适配器）转换成厂商接口。

职责应用负责什么
任务与权限可信规则、用户输入、可执行工具和业务门槛
厂商适配输入结构、事件类型、工具关联 ID、终止原因和 usage
历史管理选择手动回传或服务端会话；保留工具交互和必要的不透明状态

模型不会自动记住另一次独立请求，但 API 可以在应用之外保存会话。Responses 的 previous_response_id 或 Conversations 与手动重放是不同方案；有状态服务不等于免费历史、不等于长期业务记忆，也不替代数据保留审查。见官方迁移指南。

Q 使用服务端会话后，哪项判断仍然成立？
状态可以由服务保存，但访问权限、保留策略和历史输入计费仍要核查。手动回传历史不是唯一方案。

2. OpenAI 主线：Responses API

在项目中先用 uv add openai 声明依赖并保留锁文件；设置 OPENAI_API_KEY 和具备访问权的 OPENAI_MODEL。以下是联网且会计费的可选实践，不会被离线验收自动执行。API 形状按官方文档核对。

import os
from openai import OpenAI

client = OpenAI()  # 凭证由 SDK / 环境提供，不写入源码
response = client.responses.create(
    model=os.environ["OPENAI_MODEL"],
    instructions="用一句中文解释概念。",
    input="什么是向量数据库？",
    store=False,  # 本例手动管理历史，不据此推断其他保留政策
)
if response.status != "completed":
    raise RuntimeError(f"响应未完成: {response.status}")
refused = any(
    part.type == "refusal"
    for item in response.output if item.type == "message"
    for part in item.content
)
if refused:
    raise RuntimeError("模型未提供可消费的答案")
print(response.output_text)
print(response.usage)  # Responses: input_tokens / output_tokens 等

output_text 是文本便捷读取器；完整 output 还可能含工具调用与推理 Items。延续工具循环时，不能只回传这段文本而丢掉其他必要 Items。store=False 下按官方要求保留可重放的完整输出及不透明推理信息；不要自己解析、改写这些信息。

本例故意不带通用 temperature：参数支持取决于模型与接口，不能照搬旧参数表。先查询能力，再显式配置。

3. Claude 原生接口：Messages

使用 uv add anthropic 并锁定版本。设置 ANTHROPIC_MODEL 和 SDK 支持的凭证来源。本例同样需要网络与调用预算；它不把 OpenAI 字段透传给 Claude。

import os
from anthropic import Anthropic

client = Anthropic()
with client.messages.stream(
    model=os.environ["ANTHROPIC_MODEL"],
    max_tokens=4096,
    system="用一句中文解释概念。",
    messages=[{"role": "user", "content": "什么是向量数据库？"}],
) as stream:
    message = stream.get_final_message()

if message.stop_reason != "end_turn":
    raise RuntimeError(f"响应未正常结束: {message.stop_reason}")
text = "".join(block.text for block in message.content if block.type == "text")
print(text)
print(message.usage)  # input_tokens / output_tokens；缓存字段另行核对

system 使用这里演示的顶层形式，max_tokens 是输出上限。返回的 content 是带类型的块列表，不保证第一块是正文；stop_reason 还可能表示工具请求、拒答或输出耗尽，不能一律当成功。流式细节在 L26，工具回填在后续课程。

官方依据：Messages API。新模型默认行为、参数支持和 SDK 主版本应分别核验，不以本页示例推断所有部署平台支持相同特性。

4. 兼容接口是边界，不是能力等价证明

Chat Completions 在本课程后续若干示例中用于解释工具往返。它仍受支持，但不是 OpenAI 新项目的唯一接口：

import os
from openai import OpenAI

client = OpenAI()
reply = client.chat.completions.create(
    model=os.environ["OPENAI_MODEL"],
    messages=[{"role": "user", "content": "什么是向量数据库？"}],
)
choice = reply.choices[0]
if choice.finish_reason != "stop" or choice.message.refusal:
    raise RuntimeError("本例只消费正常完成的纯文本答案")
print(choice.message.content)
print(reply.usage)  # prompt_tokens / completion_tokens

自定义 base_url 只能改变目标端点，不能自动补齐缓存、推理状态、工具语义、事件和计费差异。快速试验可以使用已确认支持的兼容端点；需要厂商原生能力时使用官方 SDK。不要把本课 Anthropic 调用替换成 OpenAI shim。

Q 换成兼容端点后，最需要补做哪项工作？
兼容表示支持某些接口形状，不表示全部语义等价。适配层要处理能力、状态和 usage 的实际差异。

5. 离线近迁移验收：先辨认接口，再取正文

以下 fixture 全为虚构，不发送请求。先独立实现：给三个纯文本、已正常完成的响应提取正文，并拒绝未知接口。真实工具/拒答/截断分支由原生 Adapter 负责，L38 会练这些控制路径。

参考实现与精确自检（可独立运行） 
def text_only(api, payload):
    if api == "responses":
        if payload["status"] != "completed":
            raise ValueError("incomplete")
        return payload["output_text"]
    if api == "messages":
        if payload["stop_reason"] != "end_turn":
            raise ValueError("incomplete")
        return "".join(b["text"] for b in payload["content"] if b["type"] == "text")
    if api == "chat":
        choice = payload["choices"][0]
        if choice["finish_reason"] != "stop" or choice["message"].get("refusal"):
            raise ValueError("not completed")
        return choice["message"]["content"]
    raise ValueError("unknown API")

assert text_only("responses", {"status": "completed", "output_text": "甲"}) == "甲"
assert text_only("messages", {"stop_reason": "end_turn", "content": [
    {"type": "thinking"}, {"type": "text", "text": "乙"}
]}) == "乙"
assert text_only("chat", {"choices": [{"finish_reason": "stop", "message": {"content": "丙"}}]}) == "丙"
for api, data in [("unknown", {}), ("responses", {"status": "incomplete"})]:
    try:
        text_only(api, data)
    except ValueError:
        pass
    else:
        raise AssertionError("应拒绝未知接口或未完成响应")
print("L25 ACCEPTED")

怎么看结果：只出现 L25 ACCEPTED，证明这几个本地分支通过；不证明 SDK 兼容、网络可用或模型能力。在线实践要另外记录模型、API、SDK版本、终止原因与实际 usage，且先确认调用预算。

总结与下一课

  • 同一个业务目标可以跨厂商复用，但协议状态不能无损地简化成一个字符串。
  • Responses 是 OpenAI 新项目推荐方向；Chat Completions 的兼容价值仍在。
  • Claude 使用原生 SDK；先检查终止状态，再按类型提取内容。
  • 凭证不写入源码；项目声明依赖并保留锁文件，生产可使用密钥管理与工作负载身份。
