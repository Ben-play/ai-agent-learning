用失败题判断是否混合检索

融合的是两张排名，不是两份权限或两套分数

为什么先收集两种失败题？

L62 的词法能把「过期、重新生成」映射到操作指引，却可能不认只含「留存、期限」的改写；L63 的向量能按方向找邻居，却可能把保留条款排在操作指引之前。把两个结果混在一起不是默认升级。先找出两路各自漏掉的授权事实，固定问题、用户与输出预算，再问融合能否在相同预算下补回缺失。若两路总漏掉同一条证据，或一条精确查询本来就该锁定时刻，融合可能没收益、甚至更差。所有坐标都是人工夹具，排名故意制造了这两类现象；没有调用模型，也不能从小样本推出线上收益。

学习目标

  • 沿着同一授权池手算 RRF，并区分一路候选深度、融合去重和最终 k。
  • 用证据目标和固定预算对照三种方式，在精确字段上发现融合反例。

1. 先选一份候选池，再产生两张排名

从可信的租户与用户开始，db.search 用当前文档与许可取一次 authorized。同一批授权片段给两路使用，不从别的用户或租户借结果，也不因某一路没命中而绕过授权另搜。词法按共同词项数排序，向量按余弦相似度排序；各自只保留正分，同分按片段键排。融合接收名次而不是原始分数：词法的 2 是两个词项，余弦的 0.451 表示方向相似程度，两者不能拿来直接相加。只要各路进入融合的名单和名次不变，原始分差的变化就不会改变融合结果。

倒数排名融合（RRF）从第 1 名起计数：每路排第 r 的片段贡献 1 / (60 + r)，缺席则贡献 0，同一片段把各路贡献相加。这里 60 是固定的平滑常数，不是输出条数、召回深度或可信概率；它减小相邻名次的贡献差，两路出现的片段有时能压过只在一路排第一的片段。即便两路都认为某条靠前，分数也只能说明排序的共识，不能代替回答所需的原文。本课对同一个 (doc_id, version, locator) 累加，最终只返回该片段一次；同分再按这个键稳定打破。分块版本不同或位置不同即是不同片段，不能简单按标题合并。

夹具先生成各自完整的正分列表，融合完才取最终 k。实际系统可能因响应预算而限制每路候选深度，但那是另一个参数：如果先把每路都裁成最终输出的一条，原本排第二的证据就不能再给融合提供贡献；即便最终首位没变，也可能改变分数、并列和后续排名。输出上限为零就不发候选；可读正分候选不足时不补零分。合并同一个键也不消除语义冗余：两段都说「七天」可能占两个位置，对「过期后怎么做」仍然没有帮助。要把去重看成候选处理，把是否覆盖各个事实看成独立结果。

2. 同一授权池，比较两类已知失败

固定租户 support、用户 mei 和最终 k=1。先从正文标定目标：「过期后怎么操作」需要 EXPORT-OPS v1 §2；「留存期限」需要 EXPORT-POLICY v1 §1。两个查询都给固定向量 (1., 0., 0.)，但提交的词项不同。表中的「保留」指保留条款，「指引」指过期处理；同步条款两路都是零分，不进入融合。内部文档不在授权池。

过期、重新生成		词法：指引

固定预算下，词法首条支持第一题、第二题为空；向量首条只支持第二题，第一题是有结果却没有正确证据；混合两题都命中目标。只把用户换为 lin 时，操作指引根本不能进任何一路；第一题仍可能返回保留条款，但正文没提供操作证据，不能拿排名最高的一条硬答。测目标覆盖时用各用户合法且应支持的目标，无法取得支持的题单列验证不作无据回答，不能记成普通召回漏失。

诊断命中异常时，记录每路授权目标有没有参与、是否为正分、位于第几名、融合后是否被截。这样可分辨权限排除、表示不合适、支路截断和融合排序问题；最后回查的仍是引用键和正文，而不是任何一路的分数。即使夹具显示两题对两题，真实验收还应分术语、同义改写、多个目标、无证据等题组，比较同样最终条数下的支持率与重复片段占位，再量两路检索与合并的时延和资源。这个例子只比较排序内的成本。先取一次冻结的授权池，再对相同两题重复三种排序，分别报告命中目标的次数、分支评分次数和本机墙钟中位数。不包含 SQLite 查询、嵌入、网络和模型生成，不能外推到线上；三条片段的计时也可能有抖动。

从仓库根执行 python -I -X utf8 code/phase7-data-rag/rag-lab/compare_retrieval.py。报告的 covered 对应词法、向量、混合的 1 / 2、1 / 2、2 / 2；每题分支评分次数对应 3、3、6。后者不包含融合、排序或内存开销，因此还要把墙钟值另记一列，不给它设通过阈值。

3. 哪种情况下保留混合？

决策卡：固定预算，用三份失败清单作决定

适用：标注表明精确术语和改写分别被不同支路漏掉。不适用：精确字段有硬约束，或未经混合的简单方案已满足目标与预算。

误判：合并后结果更多就更好

同时增大 k 和支路深度，看到更多重复片段，分不清收益来自融合、预算变大还是只返回了冗余证据。

对照：同一授权池，同一交付预算

同用户、题集、授权池和 k 对照三路；按问题分组报目标覆盖、无证据处理和成本，再决定用词法、向量、混合或精确字段分流。

取舍：RRF 省去校准量纲，但也丢掉原始分差；支路错误会带入融合。双路排序和去重需付出额外工作，不等于已经测到特定延迟。

  1. 先标每题必须回查的证据键，再跑三路对照。
  2. 保持 k 不变，跑强约束时刻反例；按题型决定是否走融合。

诊断：融合首条变差且目标仍在某条支路，查支路深度、并列与截断；两路都没有目标则先查授权和表示。

Q 指引在词法第 1、向量第 2。融合前误把向量只留一条，直接改变什么？
向量支路里已找不到指引这条，融合少加 1/62，即使首条排序碰巧没变也不等价。
Q 两个不同引用键都只说「保留七天」。什么仍然缺失？
去重处理键的重复；覆盖检查题目的每部分是否有支持原文，不能互相代替。

展开三路对照参考与自检
import runpy
from math import isclose

if not __debug__:
    raise RuntimeError("run without -O")
lab = runpy.run_path("code/phase7-data-rag/rag-lab/lab.py")
ops = ("EXPORT-OPS", 1, "§2")
policy = ("EXPORT-POLICY", 1, "§1")
Query = lab["Query"]
exact = Query(("过期", "重新生成"), (1., 0., 0.))
paraphrase = Query(("留存", "期限"), (1., 0., 0.))

def keys(hits):
    return tuple(h.chunk.key for h in hits)

with lab["open_demo"]() as db:
    for query, lexical, hybrid, excerpt in (
        (exact, (ops,), (ops, policy), "导出文件过期后，需重新发起导出。"),
        (paraphrase, (), (policy, ops), "导出文件生成后保留 7 天。"),
    ):
        for mode, expected in (
            ("lexical", lexical), ("vector", (policy, ops)), ("hybrid", hybrid),
        ):
            full = db.search("support", "mei", query, mode=mode, k=3)
            assert keys(full) == expected
            assert db.search("support", "mei", query, mode=mode, k=1) == full[:1]
        (first,) = db.search("support", "mei", query, mode="hybrid", k=1)
        assert db.source("support", "mei", first.chunk.key).text == excerpt
        assert isclose(first.score, 1 / 61 + (1 / 62 if query == exact else 0))
        if query == exact:
            assert not isclose(first.score, 1 / 61)  # 支路先截到 1 会丢掉向量贡献。
    assert keys(db.search("support", "lin", exact, mode="hybrid", k=3)) == (policy,)
    assert db.source("support", "lin", ops) is None
    assert db.search("support", "mei", exact, mode="hybrid", k=0) == ()
print("L64 ACCEPTED")

本课最佳实践验收：时刻查询不是主题推荐

换成 support/lin 的同步排班工单：给定精确字段 02:00，只可返回一条确实支持该时刻的证据。本题故意附上与导出主题同向的夹具向量 (1., 0., 0.)。词法给同步条款第一，向量给保留条款第一；融合分相同，按键保留条款在前。现在要实现一个精确字段路径：只提交这个词项并使用词法，再用「无条件混合」作故意错误的对照。不能把 k 增到 2 来改变题目的交付约束。

展开变式参考与自检
import runpy
from math import isclose

if not __debug__:
    raise RuntimeError("run without -O")
lab = runpy.run_path("code/phase7-data-rag/rag-lab/lab.py")
Query = lab["Query"]
policy = ("EXPORT-POLICY", 1, "§1")
sync = ("SYNC-POLICY", 1, "§1")

def lookup_exact_clock(db, Query, clock):
    q = Query((clock,), (1., 0., 0.))
    return db.search("support", "lin", q, mode="lexical", k=1)

with lab["open_demo"]() as db:
    (correct,) = lookup_exact_clock(db, Query, "02:00")
    assert correct.chunk.key == sync
    assert db.source("support", "lin", sync).text == "同步任务每天 02:00 运行。"
    q = Query(("02:00",), (1., 0., 0.))
    ranked = db.search("support", "lin", q, mode="hybrid", k=2)
    assert tuple(h.chunk.key for h in ranked) == (policy, sync)
    assert all(isclose(h.score, 1 / 61) for h in ranked)
    wrong = db.search("support", "lin", q, mode="hybrid", k=1)
    assert wrong == ranked[:1] and "02:00" not in wrong[0].chunk.text
    assert lookup_exact_clock(db, Query, "03:00") == ()
    (irrelevant,) = db.search("support", "lin", Query(("03:00",), q.vector), mode="hybrid", k=1)
    assert irrelevant.chunk.key == policy
print("L64 TRANSFER PASSED")

应只打印 L64 TRANSFER PASSED。如果两条路径都声称有时刻证据，检查是否把「有结果」当成「支持问题」；若并列后首条漂移，检查是否遗漏键的稳定决胜条件。

面试自查

先按同一快照和固定预算说明怎么验证，再展开追问。

Q1词法给一条 3 分，向量给另一条 0.9 分，可以加权相加吗？

参考回答：未经校准不能把不同量纲当成同一标准。先用 RRF 以可解释名次作基线；若业务确需原分，再用独立标注比较校准方案，记录缺席支路的处理。

追问：原始词法第一比第二高十倍，RRF 会因此拉大差距吗？

答题要点：不会。名次未变，贡献也不变；这就是不做分数校准的取舍。

Q2两个检索服务各自权限正确，为什么不直接合并缓存结果？

参考回答：确认结果属于同一租户、当前用户和语料／授权快照才有可比性。各自对当时调用者正确，不代表对眼前请求仍正确。重取或校验归属，并按当前身份回查引用。

追问：两行文档编号相同就应去重吗？

答题要点：不能把别的租户混入，当前租户内仍要比文档、版本和定位完整键；相同编号的不同段可支持不同事实。

Q3每路先取 1 条再融合，和融合后取 1 条有何区别？

参考回答：前者丢掉第二及之后的支路贡献，后者允许那些贡献影响首条。用本课指引在向量第 2 的用例比较 1/61 和 1/61 + 1/62，不能只比较碰巧一致的键。

追问：出于时延只能缩小支路深度，怎样确定取值？

答题要点：固定最终 k、题组与授权快照，逐级试支路深度，记录有效覆盖、并列和时延；不能只看混合列表更长了多少。

Q4混合在改写题有增益，却使时刻查询首条变差，怎么决策？

参考回答：按任务分组。硬约束字段走精确路径，改写题再与向量及混合比较。把精确值有据正例、未收录值的空结果和错误主题候选纳入回归，同预算核对实际支持，而非只看平均分。

追问：要不要立刻上重排序修复？

答题要点：先看正确候选有没有到达预算允许的重排窗口；没有就该修候选或分流。重排只能改变已有授权候选的顺序。

授权选候选，支路排候选，融合合名次，最终按证据任务验收。先看失败题有没有互补，再用固定预算找出哪类输入反而不该混。
