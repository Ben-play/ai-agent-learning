第七阶段 · 数据与 RAG55分钟

热缓存中的撤权、改版与删除

问句没变，不代表上一次的证据和回答仍然有效

为什么这课重要？

support/mei 问「导出文件保留多久？」第一次答七天，下一次命中缓存也答七天。此后可能发生三件互不等价的事：梅失去读取资格、七天改为十四天、这份政策不再存在。只用冷启动请求测这三类变更，容易漏掉旧答案从另一层缓存直接返回的问题。清掉引用标签也没用：正文中那句旧规则已经是依赖源文档的衍生内容。

学习目标

  • 把源记录、检索缓存和答案缓存的依赖列清楚，先证明两层都热再改变一个条件。
  • 用旧键、上下文、引用、回答与未受影响的正控证明失效，不把全部拒答当安全通过。

1. 先分清缓存放的是键，还是已经写好的话

沿用 SQLite 夹具：support/mei 和 support/lin 都可读 EXPORT-POLICY v1 §1，正文是「导出文件生成后保留 7 天。」；两人也能读 SYNC-POLICY v1 §1。只有 mei 获准读导出过期处理。另一个租户有同名、同版本和同定位的 EXPORT-POLICY，却写着三十天。这说明 (doc_id, version, locator) 只标识租户内片段，不能自行证明来源可读或跨租户等价。姓名也只是可信宿主注入的测试作用域，不是认证凭据。

同一请求在两层缓存中的依赖
数据位置值的形状使用前核对
当前 SQLite文档活动版本、片段（原文、词项、固定向量）、逐人授予source(tenant, user, key) 必须找到授权的精确当前键；旧键不重定向到新版。
检索缓存预算内选中片段的有序键元组，包括空元组按键查当前原文并重绘完整证据包；任一依赖不可读，就重跑检索和打包。
答案缓存Answer(text, context, citations) 与原证据包里的全部依赖直接返回前也读回依赖并比较内容；答案正文及引用必须对应同一当前片段，不能只换标签。

检索键是 (epoch, tenant, user, Query, Plan)；计划固定检索模式、候选数、重排线索和证据预算。答案键还加上本题所需词项。这个确定性替身只摘录入包后第一条含有全部所需词项的片段；默认用查询词项；粗粒度或纯向量查询可以显式传 required_terms，没有所需词项也拒答。这是手工标签规则，不是语义蕴含或真实问答质量评测。若无合格片段，返回「没有可用证据，无法回答。」及空引用、空回答上下文，即使检索包并非空。

例如查询词项 ("导出", "过期")：林有权限读保留期，且「导出」使该片段入包，但它不支持过期后的动作，答案应拒答；梅能读到过期处理，应摘录动作并引用 EXPORT-OPS v1 §2。检索包与回答引用可不同；答案缓存仍登记检查过的全部入包片段。真实系统还要绑定模型、提示、模板等生成合同的版本。

2. 按顺序走一遍冷读、热读和变更

对 mei 的保留期题执行四步：第一次 retrieve 做一次实际检索；第一次 answer 命中检索缓存并合成一次；再取证命中第二次；再提问直接命中答案一次。工作计数依次是 (searches, retrieval_hits, compositions, answer_hits) = (1, 2, 1, 1)。相同文字返回两遍不能证明热命中；计数证明第二层不是每次都重算。用同一个问题让 lin 也预热，发现隔离错时才不会被单用户测试掩盖。

每个场景重新打开同一初始库，只做一个变更。成功变更后核心把粗粒度 epoch 加一；缓存宿主在下一次调用观察到变化，清空两个字典，再用当前授权检索。变更后首个入口故意走 answer：它必须实际增加一次检索和一次合成，旧检索命中和旧答案命中都不能增长。随后调用检索入口，应只命中新建的证据包；这样可区分「两个缓存都更新了」和「只是第一次绕过一个缓存」。

每个场景都从原来的七天规则和两份热缓存开始
唯一变更当前源库mei 旧问题lin 同一问题
撤销 mei 的保留期文档授权v1 仍在，只有 lin 仍能读这两人原先共见的 v1无证据；空上下文、空引用、安全文字仍是七天，引 v1
用 v2 替换活动保留期片段两人的授权不变，v1 精确查找失败，两人读 v2十四天，引 v2，不保留七天正文同样十四天，引 v2
删除保留期文档活动文档及其授予、片段行级联删除无证据；不得返回旧文本无证据；不得返回旧文本

这组词法查询使用「保留、有效期」，与仍存在的过期处理片段没有词项重合。每个变更后再用 mei 查未预热的「同步」，应得到原同步政策和 02:00：旧答消失但同步也拒答，不算通过。阶段检查点再改用混合检索和重排；这时保留期仍可能入包，但不能取代过期处理来作答。

3. 区分不可再返回、主动清理和底层擦除

粗代际与当前源复查在本进程的顺序调用里互相补充。清空字典保守但会冲掉其他人及其他租户可以继续使用的条目；依赖复查也不是零成本。相反，只在读取时检查旧键仍存在，会漏掉已有片段没变但新规则应当排到前面的情况（尤其是无证据缓存没有键可查）。代际改变使这种查询也重新排序。TTL 可以限制闲置内存或允许陈旧数据的停留时间，但不能给撤权提供即时边界。这里没有 TTL、跨进程消息、并发屏障或崩溃重建，变更到下次请求之间旧对象仍可能驻留内存。

本实验有活动检索数据，没有独立的外部索引。正文、手工词项与固定向量同存于活动 chunks 行，授权后直接读这些行评分；重排顺序是临时结果，入包键和衍生答案分别缓存在内存。检查点分别验证活动授权读／排名、重建证据包和回答；单元测试另查删除时活动文档、片段和授予行的级联，不等于测试了外部索引同步和清理。

活动行删除也不能证明底层字节、备份、日志、副本或已发给用户的回答被擦除。线上需要列清各索引、派生摘要、上下文快照、答案与审计记录的持有者和保留期，再单独验证多进程变更传播、索引追赶及恢复后的删除策略。不能从这里的本地顺序测试推出即时一致或物理擦除。

决策卡：先切断读路径，再验证变更是否准确

适用：回答从可撤权、可改版的证据生成，又希望重用结果。不适用：缓存命中无法绑定可信作用域和版本，或业务要求更强一致性却无法证明；此时优先不用该结果缓存。

误判：清检索缓存就够了

答案入口绕过检索，仍带出七天、旧上下文及旧引用；到期再清也不能撤回已经返回的内容。

对照：两层分开预热，变更后各看入口

同时观察源键、证据包、正文与命中计数；其他用户或未变文档仍可正常回答。

取舍：低流量先用粗代际和权威读回，把正确性做实；失效放大到影响负载时，再评估逐文档、逐授权的依赖索引及事件可靠性，不用命中率掩盖错误。

  1. 记录变更前真命中，独立做撤权、改版和删除，而不是在同一个库里把三次结果混成一条。
  2. 用旧请求证明不能回放，用其他用户和新请求证明没有误伤。

诊断：旧源已查不出但旧文字仍返回，先查答案入口；两层都冷但取出旧证据，再查实际检索依赖的索引或副本。

Q仅撤销 mei 对保留期文档的授权。两人各自的检索和答案已预热。在本课的粗代际策略下，两人各自下次问保留期会怎样？
粗代际使两人的缓存重建，但不改变 lin 的授权；mei 的旧正文和引用都不能沿用。

def check_answer(answer, key, text):
    assert answer.text == text
    assert answer.citations == ((key,) if key else ())
    if key:
        doc, version, locator = key
        assert f"[{doc} v{version} {locator}]" in answer.context and text in answer.context
    else:
        assert answer.context == ""


for event in ("revoke", "revise", "delete"):
    with lab["open_demo"]() as db:
        caches = lab["EvidenceCaches"](db)
        for user in users:
            first = caches.retrieve("support", user, query, plan)
            before = caches.answer("support", user, query, plan)

阶段检查点：重排选中的动作证据如何失效

接上 L62–L65：「导出的文件已经过期，我现在应该怎么做？」固定粗粒度检索输入、动作词项和预算如下。比较基线与重排；撤权、改版、删除分别用初始库，先证实重排路径的两层缓存都热。变更后先发原问题走答案入口，再检查重建的证据包。

起点：固定查询、预算和改版内容

Query(("导出", "保留"), (1., 0., 0.))；重排线索与答案所需词项均为 ("过期", "重新生成")。
混合检索取 2 条；只装 1 条，最多 80 字符 / 180 UTF-8 字节。
v2 §2 正文：导出文件过期后，需先核对筛选条件，再重新发起导出。

通过标准：初始基线只装保留期，不能答动作；重排能答。改版后检索包和答案都使用 v2；撤权和删除后保留期仍入包，但答案拒答。用保留期题作正控。

from dataclasses import astuple, replace
import runpy

if not __debug__:
    raise RuntimeError("run without -O")
lab = runpy.run_path("code/phase7-data-rag/rag-lab/lifecycle/main.py")
q = lab["Query"](("导出", "保留"), (1., 0., 0.))
cues = ("过期", "重新生成")
baseline = lab["Plan"](mode="hybrid", candidate_k=2, top_k=1, max_chars=80, max_bytes=180)
ranked = replace(baseline, cues=cues)
policy, ops, v2 = ("EXPORT-POLICY", 1, "§1"), ("EXPORT-OPS", 1, "§2"), ("EXPORT-OPS", 2, "§2")
old_text = "导出文件过期后，需重新发起导出。"
new_text = "导出文件过期后，需先核对筛选条件，再重新发起导出。"
refusal = ("没有可用证据，无法回答。", "", ())

for event in ("revoke", "revise", "delete"):
    with lab["open_demo"]() as db:
        c = lab["EvidenceCaches"](db)
        scope = ("support", "mei", q)
        assert tuple(h.chunk.key for h in db.search(*scope, mode="hybrid", k=2)) == (policy, ops)
        assert c.retrieve(*scope, baseline).citations == (policy,)
        assert astuple(c.answer(*scope, baseline, required_terms=cues)) == refusal
        before = c.retrieve(*scope, ranked)
        old = c.answer(*scope, ranked, required_terms=cues)
        assert (old.text, old.context, old.citations) == (old_text, before.context, (ops,))
        assert before.citations == (ops,) and old_text in before.context
        assert c.retrieve(*scope, ranked) == before
        assert c.answer(*scope, ranked, required_terms=cues) == old
        assert astuple(c.stats) == (2, 3, 2, 1)

        if event == "revoke":
            db.revoke("support", "mei", ops[0])
        elif event == "revise":
            revised = replace(db.source("support", "mei", ops), version=2, text=new_text)
            db.replace_document("support", ops[0], 2, (revised,))
        else:
            db.delete_document("support", ops[0])

        fresh = c.answer(*scope, ranked, required_terms=cues)
        assert astuple(c.stats) == (3, 3, 3, 1)
        rebuilt = c.retrieve(*scope, ranked)
        assert db.source("support", "mei", ops) is None

面试自查

先给结论，再说明对照组与验证位置。

Q1产品报告撤权后偶尔仍显示旧答，但直接检索没有旧文。该从哪里查起？

参考回答：先确认直接答案缓存是否绕过检索。让两层先真实命中，撤权后先走答案入口，检查是否实际重新检索、合成，是否同时去掉旧上下文、引用与正文。

追问：保留原答案但删除引用行，有没有完成撤权？

答题要点：没有。改写、摘要与缓存正文也是源依赖；没有可读证据就不能继续披露旧文。

Q2文档从 v1 更新到 v2，旧页定位没变，能把旧引用改个版号继续返回吗？

参考回答：不能。旧答案可能仍是七天，而新版是十四天。旧键精确查找应失败；重新检索、打包和合成，核对新版键、上下文及答句。其他有权用户也应看到新版。

追问：旧缓存是「没有证据」，为什么也可能失效？

答题要点：它没有旧键可核对，新文档却可能提供证据；还要按相关查询或语料代际失效，不能只检查已引用来源。

Q3团队想用一份语义缓存服务所有客服，因为问题几乎一样。哪一项必须先对照？

参考回答：问题相似不保证权限、当前版本或答案适用范围相同。至少验证同名用户跨租户、同租户不同授权、同题不同生成合同，不把语义相似当作准入决策。不能证明隔离时，先关闭共享答案缓存。

追问：代际清空使未受影响的租户也重算，是否说明访问控制错了？

答题要点：不一定；重算是缓存开销。未受影响的请求仍应得到同样的合法结果，不能因为全量清空而拒答。

Q4SQLite 级联删除通过，就能对客户承诺所有旧内容已擦除吗？

参考回答：不能。本地活动行与读取路径通过，不代表副本、备份、派生摘要、日志或客户端副本已物理擦除。先按数据流列清存留范围和保留期限，再逐项核实删除或隔离。

追问：多个工作者之间正在传播变更时，怎样避免把本地顺序结果误当线上保证？

答题要点：定义一致性要求，分别测并发读取、丢失／重放事件、索引延迟和恢复；必要时在交付前做权威复验或拒答。
