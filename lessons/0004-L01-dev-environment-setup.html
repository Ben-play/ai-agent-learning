开发环境搭建

工欲善其事，必先利其器 — 搭建专业级 Python 开发环境

你可能已经有部分环境了——没关系，按步骤检查，缺什么补什么。不需要全部重装。
💡 为什么这课重要？

写 Agent 之前，得先有一套趁手的工具。这一课不讲编程，讲的是把地基打平：装对 Python 版本、用现代包管理器（uv）、把每个项目的依赖隔离开、把 API Key 安全地存起来。这些看似琐碎，但少了任何一环，后面调 LLM API 时就会卡在"包装不上""key 泄露""版本冲突"这类和业务无关的坑里。花 15 分钟把环境理顺，是为后面 15 节课省下无数个抓狂的小时。

本课目标

  • ✅ 确认 Python 3.11+ 已安装
  • ✅ 配置 uv 包管理工具（比 pip 快 10-100 倍）
  • ✅ 搭建 VS Code Python 开发环境
  • ✅ 掌握虚拟环境的创建和使用
  • ✅ 完成第一个实战小项目
1
检查 & 安装 Python

打开终端，按平台运行对应命令：

# Windows PowerShell（优先用 py，Python 官方安装器自带的启动器）
py --version
# 如果 py 不可用，再试
python --version
# macOS / Linux
python3 --version

应该看到类似 Python 3.11.x 或 3.12.x 的输出。

结果操作
3.11 或更高✅ 跳到下一步
3.10 或更低⬇️ 需要升级
Windows：py/python 均无输出⬇️ 还没装 Python，需要安装（注意 Windows 通常没有 python3 命令，看到 python3 报错不代表没装 Python）
macOS/Linux：python3 提示 command not found⬇️ 需要安装

安装/升级 Python：

全平台最稳的路径是官网安装包：从 python.org/downloads 下载安装，Windows 安装时务必勾选 "Add python.exe to PATH"。

macOS / Linux 上如果想同时管理多个 Python 版本，可以选用 pyenv（可选，非必需）：

# macOS / Linux 可选：用 pyenv 管理多版本
curl https://pyenv.run | bash
# 安装脚本结束后会打印 PATH 配置提示——按提示改好 shell 配置文件后
# 重新打开一个新终端窗口，让配置生效，再继续下面的命令
pyenv install 3.12
pyenv global 3.12

（pyenv 的 shell 初始化细节不在本课展开，跟着安装脚本输出的提示操作即可。）

安装后重新检查版本：

# Windows PowerShell
py --version
# macOS / Linux
python3 --version
# 应该输出 Python 3.11.x 或 3.12.x
2
安装 uv 包管理工具

uv 是 2024-2025 年 Python 生态最重要的工具之一，比 pip 快 10-100 倍。Agent 开发中你会频繁安装依赖，uv 能节省大量时间。

# Mac / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"

验证安装：

uv --version
# 应该输出类似 uv 0.x.x

uv 常用命令速查：

命令作用
uv init myproject创建新项目
uv add requests安装依赖
uv add --dev pytest安装开发依赖
uv run python main.py在虚拟环境中运行脚本
uv sync同步所有依赖
uv pip list查看已安装的包

--dev 表示把依赖记录进 dev 依赖组；uv sync / uv run 默认仍会同步 dev 组。生产环境要显式使用 --no-dev 等选项排除。

3
配置 VS Code

VS Code 是 Agent 开发最主流的编辑器。安装以下扩展：

# 用命令行安装扩展（如果已安装 VS Code CLI）
code --install-extension ms-python.python
code --install-extension ms-python.vscode-pylance
code --install-extension charliermarsh.ruff
code --install-extension ms-python.debugpy

或者在 VS Code 中手动安装：

  1. 打开 VS Code
  2. 按 Cmd+Shift+X（Mac）或 Ctrl+Shift+X（Windows）打开扩展面板
  3. 搜索并安装：
    • Python (ms-python.python) — Python 语言支持
    • Pylance (ms-python.vscode-pylance) — 智能提示和类型检查
    • Ruff (charliermarsh.ruff) — 代码格式化和 lint
    • Python Debugger (ms-python.debugpy) — 调试支持

4
创建第一个项目 & 虚拟环境

虚拟环境让每个项目的依赖互相隔离，避免版本冲突。这是 Python 开发的基本纪律。

mkdir my-first-agent
cd my-first-agent
uv init
# 此时生成 main.py；.venv 尚未创建
uv run main.py
# 首次 uv run 会创建 .venv 并同步项目环境

uv init 之后你会看到这样的目录结构（还没有 .venv）：

# my-first-agent/
# ├── .python-version    # Python 版本
# ├── pyproject.toml     # 项目配置
# ├── README.md
# └── main.py            # 示例文件

查看 pyproject.toml：

[project]
name = "my-first-agent"
version = "0.1.0"
requires-python = ">=3.11"

运行 uv run main.py 后，会看到输出 Hello from my-first-agent!，同时目录下多出一个 .venv（首次 uv run 才会创建虚拟环境并同步依赖，这一步之前是不存在的）。

5
安装常用依赖

Agent 开发最常用的几个包，先装上：

# 核心依赖
uv add httpx           # 异步 HTTP 客户端（调 LLM API 用）
uv add pydantic        # 数据验证（Agent 工具定义用）
uv add python-dotenv   # 环境变量管理（API key 存储用）

# 开发依赖
uv add --dev pytest    # 测试框架
uv add --dev ruff      # 代码 lint 和格式化
uv add --dev mypy      # 类型检查

验证安装：

uv pip list
# 应该能看到 httpx, pydantic, pytest 等
6
配置环境变量（API Key）

LLM API 需要 API Key。我们用 .env 文件管理，永远不要把 key 写在代码里。

# Windows PowerShell
New-Item .env -ItemType File
# macOS / Linux
touch .env

也可以直接在 VS Code 资源管理器里右键 → New File，新建一个名为 .env 的文件。

在 .env 中添加（后续课程会用到）：

# .env（不要提交到 Git！）
OPENAI_API_KEY=sk-xxx
ANTHROPIC_API_KEY=sk-ant-xxx

在 .gitignore 中添加：

# .gitignore
.env
__pycache__/
*.pyc
.venv/

在 Python 中使用：

from dotenv import load_dotenv
import os

load_dotenv()  # 加载 .env 文件

api_key = os.getenv("OPENAI_API_KEY")
print(f"Key loaded: {api_key[:10]}...")  # 只打印前10位

实战任务

任务：搭建完整的 Agent 开发项目

按照以下步骤，从零搭建一个可运行的项目：

  1. 用 uv init agent-hello 创建项目
  2. 安装依赖：uv add httpx pydantic python-dotenv
  3. 创建 .env 文件（先随便写个假的 key）
  4. 创建 main.py，写入以下代码：
"""我的第一个 Agent 项目骨架"""
from dotenv import load_dotenv
from pydantic import BaseModel
import os

# 加载环境变量
load_dotenv()

# 下面的 BaseModel、函数定义、类型注解不是本课考点
# 当前只需要照抄运行，验证环境是否搭好就行
# BaseModel 会在 L02 讲，函数在 L05 讲，类型注解在 L13 讲
class Message(BaseModel):
    """消息模型 - 后续 Agent 的基础数据结构"""
    role: str
    content: str

def main():
    # 验证 .env 是否成功加载
    api_key = os.getenv("OPENAI_API_KEY")
    if not api_key:
        raise RuntimeError("未从 .env 读取到 OPENAI_API_KEY")
    print(f"✅ .env 加载成功，Key 前缀：{api_key[:6]}...")

    # 验证 Pydantic
    msg = Message(role="user", content="Hello, Agent!")
    print(f"✅ Pydantic 工作正常: {msg.model_dump()}")

    # 验证类型提示
    def greet(name: str) -> str:
        return f"你好, {name}! 准备好学 Agent 了吗？"

    print(f"✅ {greet('同学')}")

# __name__ == "__main__" 这行也不是本课考点，L14 会讲，这里照抄能跑就行
if __name__ == "__main__":
    main()
  1. 运行：uv run main.py
  2. 看到输出里出现 .env 加载成功 这几个字，就算成功！（如果抛出 RuntimeError，说明 .env 没建对或 OPENAI_API_KEY 没写）
Windows PowerShell 故障提示：如果运行时出现 UnicodeEncodeError，先执行 $env:PYTHONIOENCODING="utf-8"，再运行 uv run main.py。这个设置只影响当前终端会话。
