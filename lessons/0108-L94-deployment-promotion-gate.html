第十一阶段 · 生产部署与持续迭代 · 必修35分钟

CI/CD：为部署设置晋级门禁

同一制品逐关核验；本地绿灯不等于生产批准

为什么这课重要？

L93 把问答和草稿审批接到持久状态上。现在这个客服 Agent 的候选包构建成功，保留期答复仍然是「7 天」，但如果引用突然消失，值班人员还能核对来源吗？如果新版本写入不同形状的审批检查点，切回旧版本还能接住待审批任务吗？构建成功不回答这两个问题。

学习目标

  • 区分构建、晋级与部署，并用构建摘要、写入 schema、配置指纹和精确回退目标描述候选。
  • 在同一 Phase 8 输入上复验绿、红、绿；再用独立合同否决缺失、过期或绑错的证据，准确报告生产仍被阻断。

1. 先固定制品，再决定能否晋级

构建把源码打成可交接的制品，例如镜像。本课用固定字节串替身，不构建真实镜像。晋级是依据证据允许同一制品进入下一环境，不是在下一环境重新构建一个同标签包。部署才改变目标环境正在运行的版本。CI 可反复复验构建与回归；CD 可以把通过检查的制品交给下一道环境门，也可以停在批准之前。这里不配置或运行远程工作流。

清单（manifest）是一个 dict，可序列化为 JSON。外层是 contract_version、environment、candidate 和 rollback_target。后两项各是有四个字段的对象；下表给出 environment="classroom" 的输入形状（摘要为便于阅读仅显示前缀，校验用完整 64 位十六进制串）。

同一个清单里的两个精确身份
字段candidaterollback_target
build_version：构建名support-agent-1.4.2support-agent-1.4.1
artifact_sha256：制品字节的摘要0223f007…b4d31f46…
writer_schema：该版实际写出的状态格式编号21
config_fingerprint：非秘密配置的摘要03d2ad2b…07e10d14…

构建名便于人读，不证明字节相同。sha256(bundle).hexdigest() 对字节串 bundle 计算摘要；配置则先用固定键序、无多余空格的 JSON 序列化，再算 SHA-256。例如候选用 {"approval":"host-only","store":"sqlite-v2"}，所以只变键顺序不改变指纹，变存储模式则会改变。验证器独立重算已知制品、核对提交字节，并从固定运行元数据生成写入 schema 和配置指纹；清单和证据把同一错值互抄也不能通过。摘要标识内容，不证明发布者身份；配置输入只含允许公开的设置，不放密钥。

写入 schema 不是 API 返回结构，也不是「读得出来」的承诺。旧版本能读取自己的 v1，不代表它能读取候选新写的 v2。将回退地址写成 latest 既无法固定回退制品，也没有说明恢复哪个写入器配置；精确绑定这些身份只是演练前提，不等于已证明可以覆盖或降级数据库。若灰度已写入新格式，应先查在途批准与真实副作用，再验证兼容回退或单独设计补偿（L97）。

2. 一份回归事实，两种兼容结论

真实执行的本地回归：复用 L79 的 Phase 8 CLI 收集器及 provenance 输入清单；在三个独立进程执行基线、drop-citation、恢复基线路径。故障开关不改用例、阈值或源文件；前后核对同一个输入指纹。该指纹是 Phase 8 的源码和夹具清单摘要，不是上表的制品摘要，不证明阶段 8 测过真实镜像。

固定清单与有效课堂证据下的实际回归及晋级判断
运行门禁退出码／通过用例依据及结果
基线0／6 of 6保留期有引文，课堂 eligible
移除引用1／5 of 6retention.citations 不符；命中 citation_contract 和 success_rate，课堂 blocked
恢复0／6 of 6整份门禁报告回到基线；输入指纹不变，课堂 eligible

实际校验的离线合同，输入是假设标签：evidence 是另一份对象，包含 kind="synthetic-compatibility-v1"、环境、候选与回退身份、observed_at 和 observations。其中 observations 是计数字典，例如 {"legacy_shape_refusals":2,"candidate_dispatches":0,"candidate_writes":0,"rollback_saves":1,"rollback_replay_writes":0}。意思是候选两次拒绝旧形状、零分发且零写；旧路径在匹配批准时保存一次，重放零新增写。这些是课堂假设，不是 L94 读取的真实兼容运行。

独立规则核对精确字段与计数，先区分没有证据、格式错误和内容不符，再核对时间：用固定评审时刻 1800000000（Unix 秒）减去采集时刻，允许 0 到 900 秒；未来时间也拒绝。基准标签是 300 秒前；证据整份缺失会得到 evidence:missing。true、{"passed":true} 或一条成功日志都不能替代结构化证据。任何离线合同失败，即使回归绿灯，课堂仍阻断。

真实 L87 证据仍未核验：L87 的部署前置条件是先在获准的固定环境完成 Phase 6 真实图验收，再运行完整的真实 LangGraph 兼容演练（Python 3.11–3.13、LangGraph 1.2.24、SQLite saver 3.1.3）。报告必须同时核对 phase6_original_snapshots 与 phase10_application_fixtures，不能用 --native-only、标准库替身、静态检查或成功字符串顶替。课堂工具不接收真实 L87 证明，不具备生产批准或部署能力：l87_evidence.status 始终为 not_verified，production 永远为 blocked。没有 SDK 安装、云端调用或生产环境变更。

决策卡：门禁绑定证据，不认单个绿灯

适用：同一客服 Agent 的固定制品进入下一环境前，要同时核验行为和旧状态兼容性。不适用：不能据此证明真实模型质量、生产身份权限或在线状态可回退。

误判：构建过了，就按最新标签发布

标签可漂移，旧报告可能对的是另一份制品、配置或回退目标。

选择：固定身份，分别核两份证据

回归看实测退出码与失败字段；兼容看环境、状态、目标与证据新鲜度。

代价：保留旧制品、配置和可复验样本；过期需重测。没有可验证回退路径时，替代方案是暂停晋级并先验证向后兼容迁移，或安排停收后排空，而非放宽门槛。

  1. 用同一 Phase 8 指纹复跑绿、红、绿；红灯必须指向丢引用，进程崩溃不算成功抓到故障。
  2. 另换兼容证据中的一个绑定，复跑课堂晋级；确认回归可绿而晋级仍被阻断。

诊断：先看 phase8_replay.reasons 是否表明本地回归不可复现，再读 offline_contract.reasons 找证据缺失、时间或身份路径；不要因报告整体打印成功而解锁生产。

Q 同一构建名、回归仍绿，候选制品字节已经不同。怎么办？
构建名不等于制品身份。换制品后须按新的完整绑定重跑证据，不可重标旧报告。

本课最佳实践验收：给绿灯配一份绑错的回退证据

从有效课堂证据复制三份变式：第一份不提交证据；第二份把采集时刻改成评审时刻前 901 秒；第三份保留回退构建名，只在证据的回退身份中用候选摘要替换回退摘要。第三份需跑完整 promote_offline()，证明 Phase 8 基线仍绿，并且所有课堂晋级都被阻断。用新取的原样输入做正控，避免误改清单或让故障影响对照。

from copy import deepcopy
import runpy

if not __debug__:
    raise RuntimeError("run without -O")
lab = runpy.run_path("code/phase11-deployment/deployment-lab/release_gate.py")
manifest, fresh = lab["sample_contract"]()
assert lab["validate_contract"](manifest, None) == {"passed": False, "reasons": ["evidence:missing"]}
stale = dict(fresh, observed_at=1_800_000_000 - 901)
assert lab["validate_contract"](manifest, stale) == {
    "passed": False, "reasons": ["evidence.observed_at:stale"]}
assert not lab["validate_contract"](manifest, {"passed": True})["passed"]
wrong = deepcopy(fresh)
wrong["rollback_target"]["artifact_sha256"] = manifest["candidate"]["artifact_sha256"]
assert wrong["rollback_target"]["build_version"] == manifest["rollback_target"]["build_version"]
assert wrong["rollback_target"]["artifact_sha256"] != manifest["rollback_target"]["artifact_sha256"]
blocked = lab["promote_offline"](manifest, wrong)
assert blocked["baseline"]["passed"] and blocked["phase8_replay"]["passed"]
assert blocked["offline_contract"] == {

assert set(blocked["classroom_promotion"].values()) == {"blocked"}
control = lab["promote_offline"](manifest, fresh)
assert blocked["baseline"] == control["baseline"]
assert control["classroom_promotion"]["restored"] == "eligible"
assert blocked["production"] == control["production"] == "blocked"

面试自查

先给决定，再说明什么证据能改变决定。

Q1 同名制品换了字节，保留期样本仍通过，可以沿用昨天的兼容报告吗？

参考回答：不能；先比制品摘要、写入 schema、配置及回退目标，旧证据必须绑定本次候选。

追问：制品没变，但存储配置改了呢？

答题要点：新的配置指纹也会打破绑定；用新配置复验写入形状和旧路径。

Q2 回归脚本非零退出，就证明抓到了丢引用吗？

参考回答：不一定。要看到同指纹、精确失败字段、两道预期门槛和恢复对照。

追问：夹具找不到，脚本也退出 1，怎么交接？

答题要点：记为复验不可用而非引用回归，保持阻断，修输入后重跑三臂。

Q3 旧包和配置都能精确定位，灰度写过 v2 后能直接切回 v1 吗？

参考回答：不能由身份推断兼容。先停止扩量，检查已写状态、待审批任务及副作用。

追问：候选根本没有写入过呢？

答题要点：情况更接近 L87 的旧路径接续；仍须核对未改输入、当前批准和已提交回执，不覆盖数据库。

Q4 有人把真实 LangGraph 的成功字符串贴进环境批准备注，能解锁生产吗？

参考回答：不能。要在获准的固定环境独立核对完整 L87 两部分及候选绑定，再由真实部署系统按权限审批；课堂没有该能力。

追问：已经独立验证了两部分，还要环境保护规则吗？

答题要点：技术证据验证兼容，环境规则验证谁能进入哪一环境；不能相互替代。

小结与一手参考

构建产出制品；晋级验证指定制品、状态与证据；部署另需环境授权。本课实跑本地回归与课堂合同，不代表真实旧检查点兼容或生产准入。

  • GitHub Actions · Managing environments for deployment：环境可以设置保护规则，如限制来源分支／标签、审批后才让作业执行或访问环境密钥；可用功能视方案和仓库可见性而定。平台环境保护不替你核验应用兼容性，本课只阅读参考、不创建环境。
  • Python 3.11 · hashlib：用 SHA-256 标识确定的字节，摘要本身不是签名。
