Prompt 版本与回归

把模板放进版本控制，用同一批用例比较改动

为什么这课重要？

给客服助手多加一句「尽量提供帮助」，也许改善了正常问答，却让它在缺证据时开始猜测。只有保留旧版本和同一份判定标准，才能指出哪里变好了、哪里退步了。

学习目标

能记录一个可复跑的 Prompt 版本，区分开发集、验收集和回归集的用途，并从逐案差异而不是总分判断改动。

1. 版本标识回答「到底跑了什么？」

在仓库中保留模板内容和唯一版本，改内容时分配新版本（例如 v1 → v2），不要覆盖已评测的快照。每次报告至少记录模板版本、案例集版本、案例数和失败 ID。实际调用还要固定或记录模型、接口、模型配置及证据集版本；本课只演示离线记录。

集合何时使用不能做什么
开发集挑例子、调提示、观察变化。不能把调出来的高分当成独立验收。
独立验收集模板候选确定后，按预定门槛检查。案例曝光后若用来继续调提示，不能再说它没被用来调参。
回归集保留关键能力和曾失败的案例，每次改动复跑。反复运行并据此修复的案例不等于独立验收集。

最佳实践：把危险退化写成硬门槛

缺证据瞎答、未请求却起草等结果不能被其他题加分抵消。一次从「会」变「不会」即可阻断当前候选；新旧版本都失败的关键例同样不许过门。起始项目以 PROMPT_SNAPSHOTS 保存两个实际版本；从仓库根运行 python code/phase4-prompt-context/main.py 可看前两行的版本和字节差异。这证明模板进入了请求，不证明哪版质量更好。

Q 你用验收题的错误答案反复调 Prompt。这批题现在适合做什么？
这些题已经影响了提示设计，可以留作开发或回归；要估计未见案例表现，应另留独立用例。

2. 动手：总分一样也可能有退步

下面是人工构造的试验结果，不是起始项目的模型输出。先找出哪题修好了、哪题退步了，以及为何不能发布。再打开参考对照。

展开逐案比较与离线自检
expected = {"support": "answered", "no-source": "needs_evidence", "draft": "drafted"}
critical = {"no-source"}
observations = {
    "v1": {"support": "answered", "no-source": "needs_evidence", "draft": "answered"},
    "v2": {"support": "answered", "no-source": "answered", "draft": "drafted"},
}


def report(version):
    observed = observations[version]
    if observed.keys() != expected.keys():
        raise ValueError("必须比较同一批案例")
    failed = {case_id for case_id in expected if observed[case_id] != expected[case_id]}
    return {"prompt_version": version, "case_set": "demo-1", "cases": len(expected),
            "passed": len(expected) - len(failed), "failed": failed,
            "critical_ok": not (failed & critical)}


old, new = report("v1"), report("v2")
assert old["cases"] == new["cases"] == 3
assert old["passed"] == new["passed"] == 2
assert old["failed"] - new["failed"] == {"draft"}
assert new["failed"] - old["failed"] == {"no-source"}
assert old["critical_ok"] and not new["critical_ok"]

observations["v3"] = {"support": "answered", "draft": "drafted"}
try:
    report("v3")  # 不能把漏测关键题当成全对。
except ValueError as exc:
    assert str(exc) == "必须比较同一批案例"
else:
    raise AssertionError("漏测也被计为有效结果")
print("L41 ACCEPTED")

用 python -I 文件名.py 执行。两个版本都是 2/3，但 v2 在「缺证据不猜」上失败，不应通过。真实模型可能波动；记录试验次数，必要时对每题重复，不从这组手写结果推断模板优劣。

面试自查

只记录 Prompt 名称够吗？

不够。要能恢复当时的内容与运行数据；名称可以重用，版本快照与案例版本不应被覆盖。

为什么一定要比较相同用例？

题目不同会改变难度和构成，分数变化不能归因为一个提示改动。

回归测试全过等于线上质量好？

只证明覆盖的检查通过，不证明未覆盖任务或真实模型表现。

两个版本的总分相同怎么选？

先看禁止失败是否发生，再对照逐案差异以及成功任务的用量和时延。
