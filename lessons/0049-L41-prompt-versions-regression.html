Prompt 版本与回归

把模板放进版本控制，用同一批用例比较改动

为什么这课重要？

给客服助手多加一句「尽量提供帮助」，也许改善了正常问答，却让它在缺证据时开始猜测。只有保留旧版本和同一份判定标准，才能指出哪里变好了、哪里退步了。

学习目标

能记录一个可复跑的 Prompt 版本，区分开发集、验收集和回归集的用途，并从逐案差异而不是总分判断改动。

1. 用运行清单锁定「到底跑了什么」

回归要问的是「改动后，原来通过的用例是否变坏」，所以先保留旧版，不能原地覆盖。清单不能只写「客服提示最新版」：它要让别人拿回当时的模板、输入与判定规则。同一批题更换了标准，或同一份模板换了证据，也不是只改提示的比较。

  • 模板快照：v1 和 v2 各指向一份固定文本，含演示和变量占位。记录装配逻辑与证据快照，或保存脱敏后的完整请求，才能核对实际交给模型的内容。
  • 主案例集版本：demo-1 固定用于两版主对照的案例 ID、请求、证据和期望；另记评分规则和必过清单的版本。它不是模型标识，模型换了也不自动改变题集。
  • 运行与结果：真实试验另记接口、模型快照、采样设置及每题试验次数；保留逐案输出、判定、失败 ID 和总数。本课只对照手写记录，没有模型。能重建请求不表示模型每次返回相同文本。

2. 同一套题、同一个分数，不同的门槛结论

假设 demo-1 有下表三题。本例只检查状态，每题一分。看候选结果前，先约定 no-source 必过：没有恢复政策就不能作答。两列输出均为人工构造，并非模型推理的结果。

no-source：无恢复政策，needs_evidence（必过）needs_evidence，通过answered，失败

3. 查对照是否有效，再决定用哪批题重跑

若报告只剩两题，先查漏跑，不要拿 2/2 对比 2/3。若题、证据或判定有意改动，就分配新的版本，用新的基准把旧版和候选一起重跑。线上发现具体退化后，可以把它加入回归集；把完整契约拆成状态、证据支持度和禁止动作分别验，才能定位是哪一项没守住。

开发集让你看错因、挑示例和改模板；回归集长期守住已知能力和旧错；独立验收集（holdout）留到候选确定后再检查，不参与设计。若看过验收失败并据此改过提示，就把相关题转作开发或回归，另留未参与调优的新题，覆盖不同的请求与证据组合，而不是只把已曝光的题换个说法。

最佳实践：用逐案硬门槛决定能不能交付

适用与限制：模板改动可能修好常见问题，却破坏「缺证据不猜」之类的业务约束。面向已知风险的回归门槛可以每次跑，但不拿它估计未见题的表现。

错误做法：同分就放行

同一批 3 题，v1 和 v2 都得 2 分。看见 v2 修好了起草题便放行，漏掉它在 no-source 题无证作答。

推荐做法：核对关键案例

同一份 2/3 的结果，逐案列出修复的 draft 和退步的 no-source，阻断 v2。即使关键题在两版都失败，候选也不能过门。

取舍：先定必过案例，再逐案比较，避免高分掩盖禁止行为；代价是要维护案例和判定标准。总分适合在过门后的候选之间作补充对照。用开发题调 Prompt、用回归题守住约束；若独立验收题已经被拿来调提示，把它转作开发或回归，另留新题作独立验收。

  1. 锁定模板快照、案例集版本和预期状态，再运行原逐案对照，指出哪题修好、哪题阻断。
  2. 想核对实际快照时，从仓库根运行 python code/phase4-prompt-context/main.py，看前两行的版本与输入字节；固定响应器不评估模板措辞。

4. 动手：总分一样也可能有退步

下面是人工构造的试验结果，不是起始项目的模型输出。先找出哪题修好了、哪题退步了，以及为何不能发布。再打开参考对照。

跟做：先算一组失败集合

failed = {"no-source"}
critical = {"no-source"}
# TODO：用集合判定这一版能不能过门；不要用总分。

通过标准：这组要阻断；把失败集合换成只有 draft 时应通过同一门槛。再把判定接回第 2 节的逐案报告。

展开逐案比较与离线自检
expected = {"support": "answered", "no-source": "needs_evidence", "draft": "drafted"}
critical = {"no-source"}
observations = {
    "v1": {"support": "answered", "no-source": "needs_evidence", "draft": "answered"},
    "v2": {"support": "answered", "no-source": "answered", "draft": "drafted"},
}


def report(version):
    observed = observations[version]
    if observed.keys() != expected.keys():
        raise ValueError("必须比较同一批案例")
    failed = {case_id for case_id in expected if observed[case_id] != expected[case_id]}
    return {"prompt_version": version, "case_set": "demo-1", "cases": len(expected),
            "passed": len(expected) - len(failed), "failed": failed,
            "critical_ok": not (failed & critical)}


old, new = report("v1"), report("v2")
assert old["cases"] == new["cases"] == 3
assert old["passed"] == new["passed"] == 2
assert old["failed"] - new["failed"] == {"draft"}
assert new["failed"] - old["failed"] == {"no-source"}
assert old["critical_ok"] and not new["critical_ok"]

observations["v3"] = {"support": "answered", "draft": "drafted"}
try:
    report("v3")  # 不能把漏测关键题当成全对。
except ValueError as exc:
    assert str(exc) == "必须比较同一批案例"
else:
    raise AssertionError("漏测也被计为有效结果")
print("L41 ACCEPTED")

用 python -I 文件名.py 执行。两个版本都是 2/3，但 v2 在「缺证据不猜」上失败，不应通过。真实模型可能波动；记录试验次数，必要时对每题重复，不从这组手写结果推断模板优劣。

本课最佳实践验收：总分提高，关键旧错还在

设备归还助手修好了「写交接草稿」，却和旧版一样，在没有登记记录时声称设备已归还。为这批已知风险写一个发布门槛：不光找新增失败，还要查候选是否满足每项必过规则。

展开独立参考：区分旧错和新增退化
expected = {"hours": "answered", "draft": "drafted", "unconfirmed": "needs_evidence"}
critical = {"unconfirmed"}


def failures(observed):
    if observed.keys() != expected.keys():
        raise ValueError("案例必须齐全且一致")
    return {case for case in expected if observed[case] != expected[case]}


def compare(baseline, candidate):
    old, new = failures(baseline), failures(candidate)
    return {"fixed": old - new, "regressed": new - old, "blocked": new & critical}


# 人工记录：不代表模型真实运行。
old = dict(hours="answered", draft="answered", unconfirmed="answered")
new = dict(old, draft="drafted")
report = compare(old, new)
assert report["fixed"] == {"draft"} and not report["regressed"], report
assert report["blocked"] == {"unconfirmed"}, "关键旧错不能因总分上升放行"
assert not compare(old, dict(new, unconfirmed="needs_evidence"))["blocked"], "修复后应过此门槛"
print("L41 TRANSFER PASSED")

整块复制后用 python -I 文件名.py 运行，应只打印 L41 TRANSFER PASSED。若无新增失败就放行，检查是否用 regressed 代替了候选的必过规则。这里评审的是已知回归；挑好候选再用未参与调优的验收集评估。

面试自查

先合上答案，按「结论 → 理由 → 如何验证」作答，再展开追问。

Q1两份报告都写 v2，同一用例却从能回答变成缺证据。先怀疑模型波动吗？

参考回答：先确认两次究竟跑了什么。用版本快照核对实际模板、装入的证据、运行设置和判定规则。名称没变不代表内容没变；若请求不同，就不能把结果差异先归给模型波动。

追问：脱敏后留存完整请求，就能重现同一句模型回答吗？

答题要点：不一定。能复查请求，不保证输出相同；真实试验另记模型和采样设置，必要时重复。

Q2候选在独立验收里答错一道题。你看了错因改提示，再把那道题换个措辞，能继续当独立验收吗？

参考回答：不能。这个案例已经影响了提示设计，改写题面恢复不了独立性。原题可转到开发或回归；先定候选，再用没参与调优的新请求及证据组合验收，才能检查是否只修好了已知题。

追问：原题修好后，每次改提示还要跑它吗？

答题要点：如果对应的是需要长期守住的行为，就把它留在回归集；但不能拿它代表新案例表现。

Q3同一套 40 题，旧版过 37 题，新版过 39 题；新版唯一败在必过题「没库存记录却承诺有货」，旧版也错。放不放？

参考回答：不放。逐题对照能确认两道普通题修好了，但必过项仍在候选的失败清单里。门槛看候选有没有违反承诺条件，不只看有没有新增错误；得分提高不抵消这类关键旧错。

追问：修好库存题后，只补跑这道就能放行吗？

答题要点：不能。对冻结的题集重跑修订版，确认没有新的退步；通过这道门槛仍不等于满足全部发布条件。

Q4基线是 11/12，候选是 11/11。查到候选有一道必过题运行超时，报告把它略掉了。怎么修这个对照？

参考回答：报告不完整，必过门槛不能放行。对照计划与实跑的案例 ID，保留这题的超时和运行记录，不把它记成通过，也不删掉分母。按预先约定的超时规则复跑，再用完整的同一批题比较。

追问：如果修复时换了题目的证据快照，只补跑候选的漏测题够吗？

答题要点：不够。为变动后的题集分配新版本，让基线和候选都按新基准重跑。
