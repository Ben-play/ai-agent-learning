作用域、闭包与 Lambda

闭包是封装状态的常见方式之一 — 也帮助理解计数器、限流器与装饰器

💡 为什么这课重要？

闭包是实现装饰器（L11）、限流器和状态计数器的常见方式之一：函数可以“记住”定义时引用的外层变量。理解闭包，有助于看懂 @tool 一类装饰器如何保存配置；这些功能也可以用类等方式实现。

而 lambda + 高阶函数（map/filter/sorted 的 key），是处理 LLM 返回的列表数据的利器——排序工具、过滤结果、聚合成本，一行搞定。

本课关键决策：无状态逻辑用普通函数；只需封闭少量状态时用闭包；状态复杂、行为增多时改用类。

学习目标

完成本课后，你将能够：

  • 用 LEGB 规则判断一个变量到底指向谁
  • 解释闭包的原理，并用它保存状态（面试常问）
  • 正确使用 global / nonlocal
  • 用 lambda + sorted(key=) 排序结构化数据
  • 用 map / filter / reduce / partial 做数据变换

1. LEGB：变量到底指向谁

Python 查找一个名字时，按 L → E → G → B 的顺序找：

  • Local 局部（当前函数内）
  • Enclosing 外层函数（闭包所在层）
  • Global 模块全局
  • Built-in 内置（len、print…）
x = "global"

def outer():
    x = "enclosing"
    def inner():
        # 这里读 x：Local 没有 → 找 Enclosing → "enclosing"
        return x
    return inner()

print(outer())   # enclosing
Q LEGB 中，函数优先在哪一层找变量？
查找顺序是 L→E→G→B：先看自己函数内部（Local），找不到才逐层往外。理解这个顺序，才能预测变量到底取到哪个值，也才能理解闭包为什么能"看见"外层变量。

2. 闭包：带记忆的函数

闭包是引用了定义时外层作用域中自由变量的函数；即使外层函数已经执行完，这些绑定仍可随闭包保留。把内层函数返回出去是创建和使用闭包的常见方式，但定义本身不要求函数必须被返回。要在闭包里重新绑定外层变量，可用 nonlocal：

def make_counter():
    calls = 0
    total_ms = 0
    def record(ms):
        nonlocal calls, total_ms      # 声明：改的是外层的变量，不是新建局部
        calls += 1
        total_ms += ms
        return {"calls": calls, "total_ms": total_ms}
    return record

counter = make_counter()
counter(10)
print(counter(20))   # {'calls': 2, 'total_ms': 30}  ← 状态被记住了

没有 nonlocal，calls += 1 会被当成"新建一个局部 calls"，报 UnboundLocalError。

只是读取模块级全局变量，函数内部并不需要 global 声明——直接读就行；只有当你要在函数内重新绑定这个全局变量名时，才必须声明 global：

total_calls = 0

def peek_global():
    # 只读，不需要 global
    return f"目前共调用 {total_calls} 次"

def record_global():
    global total_calls        # 声明：改的是模块全局变量
    total_calls += 1

record_global()
record_global()
print(total_calls)            # 2
print(peek_global())          # 目前共调用 2 次

global 与 nonlocal 对照：global 指向模块级变量（不管嵌套多少层函数，都是同一个模块全局）；nonlocal 指向最近一个含有该名字绑定的非全局外层作用域，不一定只是语法上紧邻的一层。两者都只在“函数内要重新绑定外部变量名”时才需要。

最佳实践：循环创建零参数回调时固定当次绑定

适用场景：在循环中按事件配置创建一组零参数回调，交给调度器或注册表稍后调用；每个回调必须保留自己的标签和路由。

不适用场景：回调在本轮循环结束前立即执行、函数没有引用循环变量，或调用方契约本来就要求传入参数时，不需要额外绑定；不要为了使用闭包而改变真实接口。

❌ 零参数回调共享最后一次循环绑定
def make_callbacks(specs):
    callbacks = []
    for spec in specs:
        callbacks.append(
            lambda: (spec["label"], spec["route"])
        )
    return callbacks

每个 lambda 都是零参数，但都在调用时读取同一个 spec 自由变量；循环结束后，它指向最后一项。

✅ 具名工厂创建独立的零参数回调
def make_route_callback(label, route):
    def callback():
        return label, route
    return callback


def make_callbacks(specs):
    callbacks = []
    for spec in specs:
        callbacks.append(
            make_route_callback(spec["label"], spec["route"])
        )
    return callbacks

每次调用工厂都会创建新的外层作用域，label 和 route 在创建时绑定；返回的回调仍保持零参数契约。

机制：闭包捕获的是名字绑定，不是循环当时值的自动快照；自由变量在回调执行时解析。具名工厂的每次调用都会产生一组独立绑定，因此延后调用不会串到最后一项。

相关属性：这提升正确性、可预测性、可测试性和接口可替换性；坏例与修复例都保持相同的零参数接口，比较的是绑定策略，而不是不同签名。

成本：需要多一个具名函数和一次间接调用，代码比短 lambda 稍长；好处是签名诚实、可命名测试，也能容纳创建时校验。

替代方案：若已有 dispatch(label, route)，可用 functools.partial(dispatch, label, route) 绑定全部参数并得到零参数 callable。少量固定配置适合具名工厂；配置项未知、校验分支复杂、状态会演进或需要多个操作与诊断时，应改用明确的配置对象和可调用类。

自检：证明相同接口、延迟绑定、创建时绑定与可变引用边界
import inspect


def make_bad_callbacks(specs):
    callbacks = []
    for spec in specs:
        callbacks.append(
            lambda: {
                "label": spec["label"],
                "route": spec["route"],
                "retries": spec["options"]["retries"],
            }
        )
    return callbacks


def make_route_callback(label, route, options):
    def callback():
        return {
            "label": label,
            "route": route,
            "retries": options["retries"],
        }
    return callback


def make_fixed_callbacks(specs):
    callbacks = []
    for spec in specs:
        callbacks.append(
            make_route_callback(
                spec["label"], spec["route"], spec["options"]
            )
        )
    return callbacks


specs = [
    {"label": "docs", "route": "/documents", "options": {"retries": 1}},
    {"label": "billing", "route": "/invoices", "options": {"retries": 2}},
]
bad = make_bad_callbacks(specs)
fixed = make_fixed_callbacks(specs)

# 公平比较：两组回调全部都是零参数接口。
assert all(len(inspect.signature(cb).parameters) == 0 for cb in bad + fixed)

# 延迟到循环结束后调用：坏例都读取最后一个 spec。
assert [cb() for cb in bad] == [
    {"label": "billing", "route": "/invoices", "retries": 2},
    {"label": "billing", "route": "/invoices", "retries": 2},
]

# 工厂在创建时分别绑定 label/route。
assert [cb() for cb in fixed] == [
    {"label": "docs", "route": "/documents", "retries": 1},
    {"label": "billing", "route": "/invoices", "retries": 2},
]

# 字符串字段的源绑定改变不影响回调，但捕获的可变 options 内容仍可见。
specs[0]["label"] = "renamed"
specs[0]["route"] = "/moved"
specs[0]["options"]["retries"] = 4
assert fixed[0]() == {
    "label": "docs",
    "route": "/documents",
    "retries": 4,
}

诊断：若坏例不是两个 billing，调用可能没有真正延后；若修复例签名含参数，修复改变了接口；若两个修复回调返回相同路由，工厂仍共享了循环绑定；若最后的 retries 不是 4，代码已复制或替换配置，而不是保留同一可变引用。

边界：创建时绑定固定的是传给工厂的对象引用，不是深复制。需要不可变快照时，只传不可变字段或显式复制并说明复制深度；需要持续维护复杂配置不变量时，用配置类型加可调用类比裸闭包更清楚。

💡 面试常见问题：

"什么是闭包？global 和 nonlocal 区别？"

答：闭包是引用并保留定义时外层作用域绑定的函数；它不要求必须被返回。global 声明重新绑定的是模块全局名字；nonlocal 声明重新绑定的是最近一个含该绑定的非全局外层作用域里的名字。

3. Lambda + 高阶函数：处理列表数据

闭包让你看到：在 Python 里函数本身也是"值"——能被返回、能被记住。顺着这个思路再进一步：函数既然是值，就能当参数传给另一个函数。这一节的 sorted/map/filter 就是这么用的，而 lambda 正是"随手写个小函数当参数"的最简方式。

lambda 参数: 表达式 是一种匿名的单表达式函数——没有函数名，函数体只能写一个表达式，表达式的结果会被隐式返回（不用写 return）。它和 def 定义的函数一样可以被反复调用、赋值给变量：

def add_one(x):
    return x + 1

add_one_lambda = lambda x: x + 1

# 和 def 函数一样，可以重复调用，不是"一次性"的
assert add_one_lambda(1) == 2
assert add_one_lambda(10) == 11

怎么选：lambda 只能写单个表达式，写不了多语句、多行逻辑，也没法加文档字符串；短小的 key/callback（比如 sorted 的排序依据）适合用 lambda 图个简洁，逻辑稍复杂（分支、多步骤、需要命名复用）就应该用 def。

最常配 sorted / map / filter 用来处理 LLM 返回的列表：

tools = [
    {"name": "search", "cost": 10},
    {"name": "calc", "cost": 3},
    {"name": "weather", "cost": 8},
]

# 按成本排序（key 决定"按什么排"）
cheapest = sorted(tools, key=lambda t: t["cost"])[0]
print(cheapest["name"])          # calc

# map：提取所有工具名
names = list(map(lambda t: t["name"], tools))     # ['search','calc','weather']

# filter：留下便宜的工具
cheap = list(filter(lambda t: t["cost"] < 9, tools))   # calc, weather

# reduce：聚合总成本
from functools import reduce
total = reduce(lambda acc, t: acc + t["cost"], tools, 0)   # 21

# partial：固定住某个参数，生成新函数
from functools import partial
def call(model, prompt): return f"{model}: {prompt}"
call_claude = partial(call, "claude")
print(call_claude("你好"))       # claude: 你好

提示：能用推导式（L03）就用推导式，可读性更好；map/filter 在配合现成函数、或链式场景时更简洁。

Q sorted(data, key=lambda x: x["cost"]) 里 key 的作用是？
key 是一个"取排序依据"的函数，对每个元素调用它、按返回值排序。这里按 x["cost"] 排。key 不改变元素本身，只决定排序顺序——处理 LLM 返回的字典列表时极其常用。

知识图谱

作用域 LEGB
├── Local → 当前函数
├── Enclosing → 外层函数（闭包层）
├── Global → 模块全局（global 声明可改）
└── Builtin → 内置

闭包 = 引用并保留定义时外层作用域绑定的函数
├── nonlocal → 改最近含该绑定的非全局外层作用域
├── 用途：计数器 / 限流 / 重试状态
└── 装饰器的底层（→ L11）

lambda + 高阶函数
├── sorted(key=lambda ...) → 排序依据
├── map / filter → 变换 / 筛选
├── reduce → 聚合
└── partial → 固定参数生成新函数

实战练习

练习：用闭包实现一个 Agent 计数器

实现一个记录工具调用的计数器：每次调用记录"调用次数"和"累计耗时"。先自己写，再看答案。

任务清单

  1. 写 make_tracker()，返回一个内部函数 record(tool_name, ms)
  2. 用闭包保存：总调用次数、累计耗时、每个工具各自的调用次数
  3. record 返回当前统计快照（dict）
  4. 关键：用 nonlocal 修改外层计数
💡 点击查看参考答案

defaultdict(int) 回忆（详见 L03）：访问缺失的 key 时，会自动调用 int() 得到 0 作为初始值，因此 per_tool[tool_name] += 1 不会因为 key 不存在而抛 KeyError。

from collections import defaultdict

def make_tracker():
    calls = 0
    total_ms = 0
    per_tool = defaultdict(int)      # 每个工具的次数

    def record(tool_name, ms):
        nonlocal calls, total_ms
        calls += 1
        total_ms += ms
        per_tool[tool_name] += 1     # dict 是可变对象，不用 nonlocal 也能改内容
        return {
            "calls": calls,
            "total_ms": total_ms,
            "per_tool": dict(per_tool),
        }
    return record


track = make_tracker()
track("search", 120)
print(track("search", 80))
print(track("calc", 15))
# {'calls': 2, 'total_ms': 200, 'per_tool': {'search': 2}}
# {'calls': 3, 'total_ms': 215, 'per_tool': {'search': 2, 'calc': 1}}

思考题

先自己想，再点开对答案。

Q1为什么 per_tool（dict）不需要 nonlocal，而 calls（int）需要？

因为 nonlocal 只在你要重新绑定外层变量名时才需要；per_tool 是原地改内容、没有重新赋值，而 calls 每次都被重新赋一个新值。

per_tool[tool_name] += 1 本质是 per_tool.__setitem__(...)——它修改的是 dict 对象的内容，变量名 per_tool 始终指向同一个 dict，从没被重新赋值。Python 只有在函数内对某个名字赋值时，才会默认把它当作新的局部变量；这里没有对 per_tool 赋值，所以它顺着 LEGB 在外层作用域被找到、直接改就行。

calls += 1 则等价于 calls = calls + 1——这是一次赋值，会让 Python 把 calls 判定为局部变量；而 int 是不可变对象，「加一」只能靠重新绑定名字来实现。不加 nonlocal，右边读一个「尚未赋值的局部 calls」就会抛 UnboundLocalError。一句话：改可变对象的内容不用 nonlocal，重新给名字赋值才要。

Q2如果两个地方各 make_tracker() 一次，它们的计数会互相影响吗？

不会。每次调用 make_tracker() 都会创建一套全新的、彼此独立的状态。

每调用一次 make_tracker()，函数体就重新执行一遍：calls = 0、total_ms = 0、per_tool = defaultdict(int) 都是新建的局部变量，返回的那个 record 闭包只「记住」属于自己这一次的这几个变量。

于是 t1 = make_tracker() 和 t2 = make_tracker() 各自捂着独立的 calls/per_tool，t1 记了 100 次调用，t2 依旧从 0 开始，互不干扰。这正是闭包相比模块全局变量的优势——每个实例有隔离的状态，天然适合给「每个 Agent / 每个会话」各配一个独立计数器或限流器。

本课最佳实践验收：批量创建独立的事件路由回调

任务目标

批量生成统一的零参数事件回调，证明每个回调保留创建时的路由绑定，同时准确暴露共享可变配置的引用语义。

操作清单

  1. 实现具名工厂 make_route_callback(label, route, options)。
  2. 在循环中为两条事件配置创建回调，循环结束后再调用。
  3. 断言每个回调都是零参数，且标签、路由彼此独立。
  4. 修改源配置，证明不可变字段的创建时绑定与可变引用边界。

通过标准

  • 所有回调保持零参数接口
  • 延后调用仍返回各自 label/route
  • 替换源 label/route 不改变已创建回调
  • 原地修改共享 options 可被观察
  • 标准输出仅有唯一 L06 ACCEPTED

适用：调用方要求同一零参数协议、回调由已知的少量固定字段批量配置且稍后执行。不适用：立即调用、没有循环变量捕获，或调用方本应传参的场景；此时直接函数调用更简单。

机制与属性：工厂每调用一次就建立独立作用域，在创建时绑定当次 label/route；这保证路由正确性、接口一致性和可测试性。成本与替代：多一个函数层级；已有多参数函数时可用 functools.partial。配置字段未知、嵌套复杂、需要验证、状态或多个行为时，应使用配置对象配合可调用类或专门工厂，而不是继续扩张闭包参数。

课末自检：证明事件路由独立、零参数契约与引用边界
import inspect


def make_route_callback(label, route, options):
    def callback():
        return {
            "label": label,
            "route": route,
            "headers": options["headers"],
        }
    return callback


def build_callbacks(configs):
    callbacks = []
    for config in configs:
        callbacks.append(
            make_route_callback(
                config["label"], config["route"], config["options"]
            )
        )
    return callbacks


configs = [
    {
        "label": "document-created",
        "route": "/index",
        "options": {"headers": {"priority": "normal"}},
    },
    {
        "label": "invoice-paid",
        "route": "/notify",
        "options": {"headers": {"priority": "high"}},
    },
]
callbacks = build_callbacks(configs)

assert all(len(inspect.signature(cb).parameters) == 0 for cb in callbacks)
assert [cb() for cb in callbacks] == [
    {
        "label": "document-created",
        "route": "/index",
        "headers": {"priority": "normal"},
    },
    {
        "label": "invoice-paid",
        "route": "/notify",
        "headers": {"priority": "high"},
    },
]

# label/route 在创建时分别绑定，之后替换源字段不会串改回调。
configs[0]["label"] = "document-deleted"
configs[0]["route"] = "/archive"
assert callbacks[0]()["label"] == "document-created"
assert callbacks[0]()["route"] == "/index"
assert callbacks[1]()["label"] == "invoice-paid"
assert callbacks[1]()["route"] == "/notify"

# options 是同一个可变对象引用；原地修改其嵌套内容仍然可见。
configs[0]["options"]["headers"]["priority"] = "urgent"
assert callbacks[0]()["headers"] == {"priority": "urgent"}
assert callbacks[1]()["headers"] == {"priority": "high"}

print("L06 ACCEPTED")

结果诊断：标准输出必须只有一行 L06 ACCEPTED。签名断言失败表示回调协议被改变；两个结果标签或路由相同通常表示仍在延迟读取同一个循环变量；替换源字段后结果改变表示未做创建时绑定；priority 看不到 urgent 则说明实现复制了配置，已越过“保留可变引用”的边界。

面试常见问题

Q1：什么是闭包？举个实际用途。

答：闭包是引用并保留定义时外层作用域绑定的函数，不要求必须被返回。它是不建类而保存状态（计数器、限流器）以及实现装饰器的常见方式之一。

Q2：global 和 nonlocal 有什么区别？

答：global 让函数内的赋值重新绑定模块全局名字；nonlocal 重新绑定最近一个含该绑定的非全局外层作用域里的名字。都用于“我要改的是外面那个，别新建局部”。

Q3：为什么闭包里 count += 1 不加 nonlocal 会报错？

答：因为对变量赋值会让 Python 把它当成局部变量，而 += 需要先读取它——读一个"还没赋值的局部变量"就抛 UnboundLocalError。加 nonlocal 表明改的是外层变量。

Q4：map/filter 和列表推导式怎么选？

答：多数情况推导式可读性更好、更 Pythonic。map/filter 在直接复用现成函数（如 map(str, xs)）或需要惰性求值时更简洁。

  • 变量查找按 LEGB：Local → Enclosing → Global → Builtin
  • 闭包引用并保留定义时外层作用域绑定，是轻量保存状态和实现装饰器的常见方式之一
  • 重新绑定外部名字：global 指模块全局；nonlocal 指最近含该绑定的非全局外层作用域
  • 可变对象（dict/list）改内容不需要 nonlocal，重新赋值才需要
  • lambda + sorted(key=) / map / filter / reduce / partial 处理列表数据
