幻觉全解

幻觉既来自统计学习误差，也会被“猜比弃权得分高”的评估机制放大

💡 为什么这课重要？

几乎每个用过 LLM 的人都被幻觉坑过：模型一本正经地编造了一个不存在的 API、一篇没写过的论文、一段查无此人的引用。把原因只归为“训练数据有噪声”并不完整；模型目标、知识覆盖、统计误差、推理过程和评估方式都可能参与其中。

2025 年论文《Why Language Models Hallucinate》提供了一组很有用的两层解释：预训练中的普通统计分类错误解释幻觉如何产生；许多评测里“尝试作答”比“表达不确定”更容易得分，则解释了猜测行为为何会被持续鼓励。它不是所有幻觉的唯一理论，但能帮助工程师理解为什么只清洗数据或要求“别编”并不够。学完这课，你会分层分析成因，并知道怎么检测、缓解和设置风险兜底（arXiv 2509.04664）。

学习目标

完成本课后，你将能够：

  • 准确定义幻觉：生成的事实性内容相对相关证据或上下文是错误的或无支持；流畅、自信只是常见危险表现，不是定义条件
  • 用两层视角解释幻觉：预训练统计错误如何产生，评估激励如何鼓励猜测
  • 掌握 4 种检测手段：Self-Consistency、LLM-as-judge、要出处、置信度信号
  • 掌握 4 种缓解策略：RAG、CoT、Self-Consistency、允许弃权
  • 说清为什么在 Agent 里幻觉会级联放大，以及为何只能缓解不能根除

1. 什么是幻觉

幻觉（Hallucination）：模型生成的事实性内容相对相关证据或上下文是错误的，或没有得到其支持。它不必语气自信，也不必表达流畅；即使模型用“可能”“据我所知”等试探措辞说出无依据的事实性内容，仍然可能是幻觉。流畅、自信、看起来和正确答案一样是常见且尤其危险的表现，但不是定义条件。

回想 L17 讲的本质：LLM 在做概率预测——预测"下一个 Token 最可能是什么"。它优化的目标是"统计上像人话"，而不是"事实上正确"。这两者经常一致，但并不等价：

问："某某人的生日是哪天？"（模型训练里没见过这个冷门人物）

模型内部逻辑（简化）：
  "……的生日是"之后，语料里最常跟一个具体日期
  → 生成一个"看起来很合理"的日期，如 "1987 年 3 月 12 日"
  → 语法完美、格式正确、语气自信
  → 但它是编的（statistically plausible ≠ factually correct）

典型幻觉形态：编造事实（不存在的人/事/数据）、虚构引用（假论文、假 URL、假 API 函数名）、逻辑自洽的错误（推理链条通顺但前提是假的）。记住这句话："统计上合理"不等于"事实正确"——幻觉就活在这条缝里。

Q 对"幻觉"最准确的定义是？
幻觉的定义核心是：生成的事实性内容相对相关证据或上下文是错误的或无支持。它可以自信，也可以试探；可以流畅，也可以笨拙。流畅、自信的幻觉尤其危险，因为它和真答案难以区分，但这些表现不是判定幻觉的必要条件。根源是 LLM 优化"统计上像人话"而非"事实正确"（见 L17 概率预测本质）。

2. 为什么发生：产生机制与评估激励

这是本课的核心。数据质量确实会影响幻觉，但不能解释全部现象。2025 年论文《Why Language Models Hallucinate》（官方解读：openai.com）把问题拆成两层：

  1. 预训练中的统计错误解释“怎么产生”。模型从有限样本学习事实分布，对罕见事实、相似实体和训练覆盖不足的内容会发生普通分类错误。干净数据能减少一部分问题，却不能让开放世界里的每个事实都变成确定真值。
  2. 评估激励解释“为什么还在猜”。许多准确率型评测里，答对得分，答错和弃权都不得分；猜测尚有机会命中，表达不确定却没有收益。这种计分方式会让“敢答”在榜单上占便宜，并削弱模型校准不确定性的动力。

可以用不倒扣分的选择题理解第二层：空着和答错都得 0 分时，蒙一个还有概率得分。但这个类比只解释评估激励，不代表所有幻觉都由 benchmark 造成；知识缺口、检索失败、上下文误读和推理错误也可能导致错误答案。工程上要先判断是哪一层出了问题，再选择检索、校验、工具或弃权策略。

💡 一句话记牢这篇论文：统计错误让幻觉产生，奖励猜测的评估让它持续。这是重要解释之一，不是“所有幻觉只有一个根因”。要减少风险，既要改进知识与验证，也要让“不确定 / 不知道”成为可接受输出。
Q 按《Why Language Models Hallucinate》(2025)，哪项最准确地概括其两层解释？
论文给的是两层解释：预训练中的普通统计错误解释幻觉如何产生；许多准确率型评测让“猜”比“弃权”更可能得分，解释猜测行为为何持续。它没有把评估激励说成所有幻觉的唯一根因（arXiv 2509.04664）。

3. 检测方法：怎么知道它在编

既然幻觉看起来和真答案一样，就需要主动检测手段。四种实用方法（参考 Hallucination Mitigation Techniques）：

方法怎么做信号
① Self-Consistency在支持采样参数的 API 上，对同一问题多次采样答案明显发散 = 高风险；一致仍需事实核验
② LLM-as-judge用另一个模型核查这条回答是否有依据裁判模型判"无依据/矛盾" = 疑似幻觉
③ 要出处并验证要求模型给出引用来源，再去核实链接/文档真实存在出处打不开/查无此文 = 编的
④ 置信度信号看模型输出的不确定性（logprobs 较客观；自陈置信度不可靠——幻觉既可能自信，也可能试探）低置信 / 模糊措辞 = 需人工复核

① Self-Consistency 是风险信号，不是真值证明：多次采样明显发散，说明答案不稳定、值得升级核查；但高度一致也可能是一致地错，尤其当模型共享同一个错误记忆或错误前提。因此它适合做粗筛，不能替代外部事实源、计算工具或人工验证。

⚙️ 工程落地：③“要出处并验证”适合做成自动化管线——让模型输出带 URL / 文档 ID，再由程序核实来源是否存在、是否真的支持结论。它会在后续 RAG 与可靠性课程中继续展开，不是下一课 L20 的主题。

最佳实践：把回答分歧当升级信号，不把回答一致当真值

适用：同一事实型问题可获得多个独立样本，且错误答案需要分级发布 / 人工复核。不适用：只有一个确定性权威数据源可直接查询时，应直接验证来源而不是多采样。本卡只做一个决定：样本发散就升级风险；样本一致仍须证据门，绝不自动判真。

❌ 多数一致就发布
answers = sample_same_question(3)
if len(set(answers)) == 1:
    publish(answers[0])

同一任务、输入与 release 接口，却把共享错误记忆造成的“一致地错”误当事实证明。

✅ 一致性只决定风险升级
decision = gate(
    answers=answers,
    evidence=evidence,
)
assert decision in {"release", "escalate", "reject"}

发散触发升级；一致答案也只有被证据支持才发布，无依据则拒绝或转人工。

为什么更优：先把一致性分类为风险信号，再单独验证 evidence，动作上拆开了“稳定性”与“真实性”；机制上覆盖一致地错、彼此发散、证据支持三类 fixture；结果提高事实正确性、可靠性、可解释性与错误遏制能力。真实成本是多次采样增加延迟与 Token，证据获取也会失败或冲突；低风险创意任务可以只用分歧做多样性信号。高风险事实一旦没有可核验证据，即使一致也不发布；如果已有权威 API / 数据库，直接查询它比自洽投票更好。

动手自检（纯标准库、离线、静默通过）：
def release_gate(answers, evidence):
    unique = set(answers)
    if len(unique) > 1:
        return {"decision": "escalate", "reason": "divergent"}

    answer = answers[0]
    if evidence.get("supports") == answer:
        return {"decision": "release", "reason": "evidence-backed"}
    return {"decision": "reject", "reason": "consistent-but-unverified"}


fixtures = {
    "consistently_wrong": {
        "answers": ["1901", "1901", "1901"],
        "evidence": {"supports": "1903"},
        "expected": "reject",
    },
    "divergent": {
        "answers": ["1901", "1903", "unknown"],
        "evidence": {"supports": "1903"},
        "expected": "escalate",
    },
    "evidence_backed": {
        "answers": ["1903", "1903", "1903"],
        "evidence": {"supports": "1903"},
        "expected": "release",
    },
}

for fixture in fixtures.values():
    outcome = release_gate(fixture["answers"], fixture["evidence"])
    assert outcome["decision"] == fixture["expected"]

assert release_gate(["1901"] * 3, {"supports": "1903"})["reason"] == (
    "consistent-but-unverified"
)
assert release_gate(["a", "b", "a"], {"supports": "a"})["reason"] == "divergent"

结果诊断：无输出且退出码为 0 即通过。一致错误 fixture 被 release，说明仍把 agreement 当 truth；发散 fixture 被多数票直接发布，说明升级门缺失；证据支持 fixture 被拒绝，说明 evidence 没有进入发布判定。

边界：Self-Consistency 测量输出稳定性，不验证世界事实；证据也必须检查来源真实且确实支持结论。

4. 缓解策略：目标是"缓解"不是"消除"

先立场：对开放式通用生成，工程上不应承诺“零幻觉”；目标是降低错误发生率、提高可检测性并限制影响。下面四种手段解决的是不同环节，不能把其中任何一项包装成绝对保证：

  1. RAG（检索增强生成）——给回答增加外部依据。先从可信文档库检索相关内容，把资料放进上下文，让模型尽量“根据材料答”而不是只凭参数记忆。它常能减少无依据生成，但检索可能漏召回、资料可能过期、模型也可能误读证据，因此仍要做引用核查。RAG 会在后续知识库阶段系统学习，本课只建立直觉。
  2. CoT（Chain-of-Thought，思维链）。让模型分步推理再给结论，而不是一步跳到答案。把大跳跃拆成小步骤，能减少"跳步式"的逻辑错误——这也是 L20 推理模型的主题。
  3. Self-Consistency（多采样比较）。同一问题采样多次，观察答案是否收敛；明显发散就升级核查。多数投票可减少部分随机错误，但多个样本可能共享同一个错误，不能代替真值来源。
  4. 提示词允许"我不知道" + 要求引用。直接在 prompt 里写明"不确定就说不知道、不要编"、"每条结论必须给出处"。这等于在推理阶段手动纠正第 2 节那个"惩罚弃权"的错误激励——给弃权重新"发分"。

参考实践清单：Hallucination Mitigation Techniques。记住组合拳心法：RAG 给依据、分步推理减少部分逻辑跳步、Self-Consistency 暴露不稳定、允许弃权兜底。每一招都有边界，关键事实仍应交给外部来源或确定性工具核验。

🎤 面试高频 · 必背题：「如何减少幻觉？」
满分回答要覆盖 5 点：① RAG 提供可核验依据，但仍检查召回与引用；② 分步推理减少部分逻辑跳步；③ Self-Consistency 用发散筛出高风险项，不把一致当真值证明；④ 允许弃权——不确定就说不知道并升级人工；⑤ 风险分层——金额、法律承诺等关键事实交给外部工具/人工核验。最后承认：工程目标是降低发生率和影响，不是承诺归零。
Q 关于缓解幻觉，下面哪种说法是对的？
RAG、分步推理、Self-Consistency 和允许弃权分别作用于证据、推理、稳定性与风险兜底，但每项都有失败模式。工程上应组合缓解 + 外部核验 + 风险分层，而不是承诺某个单一技巧能保证所有回答正确。

5. Agent 关联：幻觉会级联放大

为什么幻觉对 Agent 是"核心问题"而不只是"一个缺点"？因为 Agent 不是把模型输出直接给人看——它会基于这段输出去调用工具、做决策、触发下一步。一个幻觉会像多米诺骨牌一样级联放大：

普通聊天：幻觉 → 人看到假答案 → （人可能识别）→ 到此为止

Agent：  幻觉 → Agent 当成事实 → 调用了错误的工具 / 传了错误参数
              → 拿到错误结果 → 又基于错误结果继续推理
              → 再调用下一个工具 → 错误层层叠加、越走越偏
              → 最终产出一个"每一步都很自信"的错误结果

差别在于：聊天里幻觉止于人眼；Agent 里幻觉会被自动执行并喂给下一步，没有人当场把关。所以 幻觉治理（检测 + 缓解）是 Agent 可靠性的核心——本课学的 RAG、Self-Consistency、要出处、允许弃权，之后都会作为 Agent 的"护栏"反复出现。

🧪 Agent 场景练习：为一个"客服 Agent"设计幻觉检测方案（先自己想，再展开看参考答案）

题目：你在做一个电商客服 Agent，它会回答"退货政策""订单状态""某商品是否支持某功能"等问题。已经出现过它编造退货天数、编造不存在的功能的事故。请设计一套方案，在回答发给用户前尽量拦下幻觉。

参考答案（组合拳）：

  • RAG 作地基：政策/商品信息从官方知识库检索，订单状态从业务数据库或 API 获取；回答必须绑定证据。检索不到、资料冲突或证据不足时不直接作答。
  • 强制出处 + 程序验证：要求模型每条结论都附知识库文档 ID；发送前用程序核对该 ID 真实存在且内容支持这句话，查无依据就拦截（对应检测法③）。
  • 关键问题上 Self-Consistency：对"退货天数""是否支持某功能"这类高风险事实，多次采样；答案不一致就不直接回复，转人工或反问澄清（对应检测法①）。
  • 允许并鼓励弃权：prompt 明确"知识库里没有就说'我帮您转人工'，绝不能编"——把"弃权"变成体面且被鼓励的选项（对应缓解④）。
  • LLM-as-judge 兜底：发送前用另一个模型快速核查"这条回答是否被引用材料支持"，不通过则拦截（对应检测法②）。
  • 诚实边界：承认无法 100% 拦净，因此对涉及金额/承诺的高危回答设人工复核，把残余幻觉的影响降到可接受。

看出来了吗——这套方案就是把本课第 3、4 节的检测与缓解手段，按风险分层组装成一条 Agent 护栏管线。

本课最佳实践验收：合成医疗设备事件公告发布门

任务目标

为合成医疗设备公告建立证据驱动的发布门，证明样本一致性只用于识别风险，精确证据和风险等级才决定发布、拒绝或人工升级。

操作清单

  1. 定义带 claim ID、evidence IDs、risk tier 与生成样本的公告条目。
  2. 准备一致但错误、发散且有多数派、试探措辞但无支持、低风险证据支持、高风险证据不独立五类 fixture。
  3. 先用语义 claim 分歧决定升级，不用多数票判真。
  4. 再逐条验证 evidence ID 存在且精确支持 claim。
  5. 高风险条目只有多个独立来源支持才可发布，否则记录人工升级。

通过标准

  • 一致错误与“可能……”式无支持 claim 都不能发布。
  • 发散样本即使多数派得到证据支持也必须升级。
  • 证据精确支持的低风险 claim 可以发布。
  • 高风险 claim 即使有两个 evidence ID，只要来源不独立仍必须人工升级。
  • 程序离线、纯标准库、确定性运行；标准输出只有最终标记。

from dataclasses import dataclass


@dataclass(frozen=True)
class BulletinClaim:
    claim_id: str
    statement: str
    samples: tuple[str, ...]
    evidence_ids: tuple[str, ...]
    risk_tier: str


EVIDENCE = {
    "E-ALARM-09": {"source": "alarm-test", "supports": "event:alarm-not-audible"},
    "E-LOG-17": {"source": "device-log", "supports": "event:screen-freeze"},
    "E-TECH-22": {"source": "technician-note", "supports": "event:manual-restart"},
    "E-PAUSE-31": {"source": "device-log", "supports": "event:therapy-paused"},
    "E-PAUSE-32": {"source": "device-log", "supports": "event:therapy-paused"},
}


def gate_claim(case):
    base = {
        "claim_id": case.claim_id,
        "evidence_ids": case.evidence_ids,
        "risk_tier": case.risk_tier,
    }
    claims = set(case.samples)
    if len(claims) > 1:
        return {**base, "decision": "escalate", "route": "manual", "reason": "divergent-samples"}

    claim = next(iter(claims))
    supporting = [
        evidence_id for evidence_id in case.evidence_ids
        if EVIDENCE.get(evidence_id, {}).get("supports") == claim
    ]
    if not supporting:
        return {**base, "decision": "reject", "reason": "unsupported-claim"}

    independent_sources = {EVIDENCE[evidence_id]["source"] for evidence_id in supporting}
    if case.risk_tier == "high" and len(independent_sources) < 2:
        return {
            **base,
            "decision": "escalate",
            "route": "manual",
            "reason": "high-risk-needs-independent-evidence",
        }
    return {**base, "decision": "release", "reason": "exact-evidence-support"}

迁移提示：这是安全的合成公告 fixture，不用于医疗决策。真实发布门还要验证来源权限、版本、时间、冲突记录与人工责任链；本验收只锁定“分歧负责升级、证据负责发布、高风险需要独立证据”三条边界。

阶段实践检查点：可靠性门

任务目标

为非确定的档案征集输出建立可审计可靠性门，证明可复现对象是冻结的运行规格，分歧负责升级、来源证据负责发布。

操作清单

  1. 冻结模型、prompt、tools、controls、fixture 与 evaluator，生成稳定指纹。
  2. 对同一捐赠档案声明收集多份非确定输出。
  3. 分开检查语义 claim、一致性风险与登记证据。
  4. 覆盖措辞不同但 claim 相同、均匀发散、存在严格多数但仍发散、共识错误四条路径。

通过标准

  • 键顺序不改变规格指纹，受控条件变化会改变。
  • 措辞不同不构成失败，只要 claim 相同且证据支持即可。
  • claim 发散必须升级；共识错误必须拒绝。
  • 标准输出只有检查点标记。

先独立完成：只使用 L17 的“规格可复现而非字节复现”和 L19 的“分歧是风险、证据才判真”；不要引入下一课的 effort 路由。

import hashlib
import json


def fingerprint(spec):
    return hashlib.sha256(json.dumps(spec, sort_keys=True, separators=(",", ":")).encode()).hexdigest()


def gate(outputs, registry_claim):
    claims = {output["claim"] for output in outputs}
    if len(claims) > 1:
        return "escalate"
    only_claim = next(iter(claims))
    return "release" if only_claim == registry_claim else "reject"


SPEC = {
    "model": "fictional-acquisition-model",
    "prompt": {"version": 2, "text": "Assess the donor claim."},
    "tools": [{"name": "registry_lookup", "version": 1}],
    "controls": {"mode": "evidence-only"},
    "fixture": {"collection": "ACQ-77"},
    "evaluator": {"version": "acquisition-gate-v3"},
}
assert fingerprint(SPEC) == fingerprint(dict(reversed(list(SPEC.items()))))
changed_values = {
    "model": "fictional-acquisition-model-v2",
    "prompt": {"version": 3, "text": "Assess the donor claim."},
    "tools": [{"name": "registry_lookup", "version": 2}],
    "controls": {"mode": "open"},
    "fixture": {"collection": "ACQ-78"},
    "evaluator": {"version": "acquisition-gate-v4"},
}
for field in SPEC:
    omitted = {key: value for key, value in SPEC.items() if key != field}
    changed = {**SPEC, field: changed_values[field]}
    assert fingerprint(SPEC) != fingerprint(omitted), field
    assert fingerprint(SPEC) != fingerprint(changed), field

总结

  • 幻觉 = 生成的事实性内容相对相关证据或上下文错误或无支持；流畅、自信是常见危险表现，但不是定义条件
  • 两层解释：预训练统计错误让幻觉产生；许多评测偏好猜测，让不确定性表达得不到奖励——这是重要机制而非唯一根因
  • 检测：Self-Consistency 的发散是风险信号但一致不证明正确；还可用裁判、出处和外部工具核验
  • 缓解：RAG 提供依据、分步推理减少部分错误、允许弃权并对高风险事实做人机兜底
  • Agent 里幻觉会被自动执行并级联放大，所以幻觉治理是可靠性的核心
