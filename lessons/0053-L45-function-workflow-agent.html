第五阶段 · Agent 核心架构45分钟

先选函数、Workflow 还是单 Agent

固定任务与证据，比较谁决定下一步

为什么这课重要？

接手 L44 的证据问答和工单草稿项目时，换架构不应换掉验收条件。先看任务是否需要「读了才知道下一步」，再决定要不要承担 Agent 的调度和验收成本。

学习目标

能区分函数、固定工作流和单 Agent 的控制权；能用同一组用例读出各自真实的本地调用轨迹，解释何时不必升级架构。

1. 用同一份任务契约搭三条路径

先写交付条件，而不是先选框架。用同一份合成知识库：问保留期必须引用 KB-01（生成后保留 7 天）；明确要求起草时须引用 KB-01 和 KB-02（过期需重新导出），并标记待人工确认；问能否恢复时没有支持结论的政策，应返回 needs_evidence。共享的 finish 根据任务和取到的证据做这道验收；草稿只作为文本返回，不写入或提交。

  • 直接函数：把任务映射到所需来源，本例用 REQUIRED 查表，再读证据并产出。这里的「函数」指直接解题，不是说另外两种写法不能用函数。
  • Workflow（工作流）：代码定义节点及其流转。固定版先读两条再产出；也可以让代码在已知条件下分支，例如索引返回「纸质」才读纸质发票政策。需要分别验各节点时，这样拆比重写业务规则更有用。
  • 单 Agent：让模型根据目标和工具反馈决定下一步读哪里或何时停，宿主仍决定可用工具、调用上限和交付条件。下面的 plan() 是手写规则，只代演这道控制接缝；不会理解新问法或自行找到新来源。

2. 跟三种输入走一遍：数读取，也数停下前的规划

轨迹里的证据 ID 表示真的尝试读取（即使没读到）；plan 表示调用了一次本地规划函数，包括最后那次返回 None 的停止决定。不把 finish 等普通函数也记成规划或工具调用。用「读几次、规划几次」分别对账：

  • 问保留期（qa）：函数只读 KB-01（1 读、0 规划），固定工作流还读 KB-02（2 读、0 规划）。模拟 Agent 先规划读 KB-01，读完再规划并停止（1 读、2 规划）。三者都只引用 KB-01。
  • 要求草稿（draft）：都按 KB-01、KB-02 的顺序读取。函数和固定工作流各 2 读、0 规划；模拟 Agent 在两次读取前及最后停下时各规划一次，共 2 读、3 规划。含两条证据才返回 drafted。
  • 问恢复（restore）：函数知道没有可用来源（0 读、0 规划），固定工作流仍双读（2 读、0 规划），模拟 Agent 仍照默认规则读 KB-01 再停（1 读、2 规划）。相同的 needs_evidence 不代表走了相同的路。

3. 看差异出在哪里，再决定要不要升级

给草稿用例去掉 KB-01：函数和固定工作流仍尝试读取两个来源；模拟 Agent 第一次规划后读不到 KB-01，第二次规划就停止，不再试 KB-02。三者都必须返回 needs_evidence。若还有草稿，先查共享验收是否漏判必需证据；若只有多余的读取，才查选择路径或提前停止条件。已知两条缺一不可时，也可以给工作流加一条「首条缺失就停」的分支。

需要先读索引才能选证据，并不足以证明要上 Agent：索引的返回值与去向有稳定映射，预设分支仍然合适。如果遇到固定规则难以覆盖的代表性任务，才值得测试模型能否依据新发现选择下一步，并用同一批用例核对证据、拒答和调用上限。这里数的是本地尝试，不是实测的模型成本、质量或延迟；也不能用一条少读的轨迹证明线上更划算。

最佳实践：先过同一道验收门，再为动态规划付费

适用：常见导出任务的所需证据可预先列出，三条路径必须给出相同的答案、来源与缺证状态。边界：若观察结果决定接下来到哪里找证据，且固定分支难以穷举或维护，不能只用这些常规样例否决 Agent。

误判：少读一条就选 Agent

同问「保留多久」，同用 KB-01 和 KB-02，同要求答 7 天并引用 KB-01。单 Agent 只读 1 次，比固定读两条的 Workflow 少 1 次，却还规划 2 次；若读取和规划各记 1 点，实际是 3 点对 2 点。

对照：先跑直接函数，再计算总投入

相同问法、证据与验收线下，函数只读 KB-01、无需规划，交付仍是 7 天和 KB-01，合计 1 点。再用草稿和恢复询问检查它没有靠省略证据或编造结论省下调用。

取舍：已知「问法 → 所需证据」时，规划器在运行时重做了可预先确定的选择。需要独立重试、审计节点时，可以保留 Workflow 并加预设的提前停止分支；只有代表性难例超过固定方案的质量或维护上限，且动态路径仍能守住执行边界，才值得试 Agent。这些点数只是本地计数，不是线上价格或延迟；上线比较要纳入规划、重试与失败的实测成本。

  1. 运行 三条路径的对照自检，先对齐输出与来源，再分开数读操作和规划。
  2. 对照双来源草稿；然后在调用中去掉 KB-01，检查业务状态和轨迹是否符合各自的停止规则。

结果诊断：正常草稿都读 2 次，单 Agent 另规划 3 次。缺 KB-01 却交付草稿是验收门漏检；单 Agent 此时还读 KB-02，说明没有用已知缺证来提前停止。只看到「少读」却算不出总调用，应检查是否漏计规划和最终停止决策。

Q 规则已知，直接函数已通过所需用例。当前只需实现这些任务，应先选什么？
既有规则已满足契约，不必为了能动态选工具而增加规划和调度；先证明存在固定路径解决不好的用例再升级。

展开参考实现与离线自检
KB = {"KB-01": "导出文件生成后保留 7 天。", "KB-02": "超过保留期需重新发起导出。"}
REQUIRED = {"qa": ("KB-01",), "draft": ("KB-01", "KB-02"), "restore": ()}


def finish(task, facts):
    ids = REQUIRED[task]
    if not ids or any(not facts.get(key) for key in ids):
        return "needs_evidence", (), None
    text = "".join(facts[key] for key in ids)
    if task == "draft":
        return "drafted", ids, "需人工确认：" + text
    return "answered", ids, text


def run(architecture, task, kb=KB):
    trace, facts = [], {}

    def read(key):
        trace.append(key)
        facts[key] = kb.get(key)

    def plan():
        trace.append("plan")
        if "KB-01" not in facts:
            return "KB-01"
        if task == "draft" and facts["KB-01"] and "KB-02" not in facts:
            return "KB-02"
        return None

    if architecture == "agent":
        for _ in range(3):
            key = plan()
            if key is None:
                break
            read(key)
    elif architecture in {"function", "workflow"}:
        keys = REQUIRED[task] if architecture == "function" else ("KB-01", "KB-02")
        for key in keys:
            read(key)
    else:
        raise ValueError("未知执行方式")
    return finish(task, facts), trace


missing = ("needs_evidence", (), None)
answers = [("answered", ("KB-01",), KB["KB-01"]),
           ("drafted", ("KB-01", "KB-02"), "需人工确认：" + KB["KB-01"] + KB["KB-02"]), missing]
traces = {"function": ["KB-01", "KB-01 KB-02", ""], "workflow": ["KB-01 KB-02"] * 3,
          "agent": ["plan KB-01 plan", "plan KB-01 plan KB-02 plan", "plan KB-01 plan"]}
for route, expected in traces.items():
    for task, result, steps in zip(("qa", "draft", "restore"), answers, expected):
        assert run(route, task) == (result, steps.split()), (route, task)
    expected_steps = "plan KB-01 plan" if route == "agent" else "KB-01 KB-02"
    assert run(route, "draft", {"KB-02": KB["KB-02"]}) == (missing, expected_steps.split())
print("L45 ACCEPTED")

本课最佳实践验收：按发票类型查附件入口

发票索引返回电子或纸质，只有这一步之后才知道该读哪条附件政策。用同一组夹具比较固定双读、预设分支和模拟 Agent，要求答复与来源一致，未知类型或缺政策时不给答复。读一次记 1 点、规划一次记 2 点；先全过用例，再从单例最高成本不超过 3 点的方案中选最低者。删去预设流程的纸质分支再选一次：这是在验质量门，不是在模拟规划器能发现新政策。

独立完成后展开参考程序（离线，Python 3.11+）
POLICIES = {"INV-E": "在发票详情下载。", "INV-P": "在档案柜领取。"}
ROUTES = {"digital": "INV-E", "paper": "INV-P"}
MISSING = ("needs_evidence", None, None)
TRIALS = [
    ({"index": "digital", **POLICIES}, ("answered", "INV-E", POLICIES["INV-E"])),
    ({"index": "paper", **POLICIES}, ("answered", "INV-P", POLICIES["INV-P"])),
    ({"index": "unknown", **POLICIES}, MISSING),
    ({"index": "paper", "INV-E": POLICIES["INV-E"]}, MISSING),
]


def run(mode, kb, branches):
    facts, trace = {}, []

    def read(key):
        trace.append(key)
        facts[key] = kb.get(key)

    def plan():
        trace.append("plan")
        if "index" not in facts:
            return "index"
        source = ROUTES.get(facts["index"])
        return source if source and source not in facts else None

    if mode == "agent":
        while (source := plan()) is not None:
            read(source)
        source = ROUTES.get(facts["index"])
    else:
        read("index")
        source = (branches if mode == "branch" else ROUTES).get(facts["index"])
        if mode == "eager":
            for key in POLICIES:
                read(key)
        elif source:
            read(source)
    text = facts.get(source)
    return (("answered", source, text) if text else MISSING), trace


def measure(branches):
    scores = {}
    for mode in ("eager", "branch", "agent"):
        passed, costs = True, []
        for kb, expected in TRIALS:
            result, trace = run(mode, kb, branches)
            passed = passed and result == expected
            costs.append(sum(2 if step == "plan" else 1 for step in trace))
        scores[mode] = (passed, max(costs))
    return scores


def choose(scores, cap):
    eligible = [(cost, mode) for mode, (passed, cost) in scores.items() if passed and cost <= cap]
    return min(eligible)[1] if eligible else "hold"


scores = measure(ROUTES)
assert scores == {"eager": (True, 3), "branch": (True, 2), "agent": (True, 8)}
assert choose(scores, 3) == "branch"
assert choose(scores, 1) == "hold"  # 不放宽门槛，也不硬选某条路
without_paper = {"digital": "INV-E"}
assert run("branch", TRIALS[1][0], without_paper) == (MISSING, ["index"])
assert measure(without_paper)["branch"] == (False, 2)
assert choose(measure(without_paper), 3) == "eager"
print("L45 TRANSFER PASSED")

结果诊断：唯一输出应为 L45 TRANSFER PASSED。最高成本分别是 3 / 2 / 8 点，完整分支方案胜出。删掉纸质分支后，即使该用例少读一次，也应改选固定双读；仍选分支就是把成本放在正确性之前。把上限改为 1 点应得到 hold，不是拣一个最接近的方案。

面试自查

先合上答案，按「结论 → 理由 → 如何验证」作答，再展开追问。

Q1查导出保留期只需 KB-01；草稿则要先取齐证据，再生成待确认的文本，且两个阶段要分别重试和审计。两类任务各选什么？

参考回答：保留期用直接函数，按已知映射只读 KB-01；草稿用预设工作流，把取证和起草拆成独立节点。步骤和验收都已知，不必让模型选下一步。核对问答只引用 KB-01；用节点失败的夹具验证只重试失败的节点，缺任一来源不出草稿，证据齐备也只返回待确认的文本。

追问：要先读发票索引才知道读电子还是纸质政策，这就变成 Agent 了吗？

答题要点：不是。只要「电子 → INV-E、纸质 → INV-P」由代码规定，仍是工作流；分别喂入两个索引值，核对实际读取的来源即可。关键是由谁选路径，不是有没有分支。

Q2发票练习读一次记 1 点、规划一次记 2 点，单个用例最多 3 点。固定双读、预设分支和模拟 Agent 都通过业务验收时，选哪条路？

参考回答：选预设分支。固定双读最坏是索引加两条政策，共 3 点；预设分支是索引加命中的政策，共 2 点；模拟 Agent 最坏是 2 次读取、3 次规划（含停止），共 8 点。逐例对照答案、来源和缺证状态，再按实际轨迹求各方案的最高点数，不能只看平均值。

追问：漏掉纸质分支后，纸质用例只读了索引，是否更值得选？

答题要点：不。索引为 paper 且有 INV-P 时，必须答出它的政策并引用它。分支方案未通过这条用例；上限仍为 3 点时，改选通过全部用例的固定双读。

Q3草稿缺 KB-01，模拟 Agent 的轨迹是「plan → KB-01 → plan」，却返回了草稿。先查哪一层？

参考回答：先核对进入 finish 的证据。轨迹中的 KB-01 只表示尝试过；若证据确实未取到，finish 应阻止交付。用仅有 KB-02 的测试数据跑三条路径，断言都是 needs_evidence、无引用、无草稿，再核对各自的读取轨迹。

追问：固定工作流仍尝试读取了 KB-02，却正确返回缺证，是同一个故障吗？

答题要点：不是，交付边界守住了，多读属于路径取舍。如果两条证据缺一不可，可加「KB-01 缺失就停」的分支，并验证少一次读取但交付结果不变。

Q4模拟 Agent 查保留期比固定工作流少读一条，但多了两次本地规划。上线前，怎样验证是否值得替换？

参考回答：先不凭本地计数决定。让候选方案和最简单的可用基线跑同一批代表性任务：常规问答、双来源草稿、缺证，以及确实需要根据新发现选来源的难例。先核对引用、拒答和调用上限，再在目标环境量端到端耗时和每个完成任务的成本，计入规划、重试和失败消耗。

追问：能只报成功请求的平均耗时吗？

答题要点：不能只报这一项。快速失败或超时的任务会被漏掉；同批样本还要分开报告成功、缺证和运行失败的数量与耗时，再判断改动有没有真正改善服务。
