第十一阶段 · 部署与迭代 · 必修50分钟

事故响应与评估驱动迭代

保留可复现的因果，不保留证据正文；只凭独立回归保留规则

为什么这课重要？

L97 负责停下之后接住审批。恢复服务不是事故的终点：如果不把失效条件写成回归，下次可能仍会引用已经撤权的缓存；如果一律转人工，又会拦住本可回答的问题。本课只用本地合成案例，记录系统行为，不记录人员评分或原始材料。

学习目标

  • 把一次受控的引文误选缩成结构化事故记录，分开观察、期望、处置和复核条件。
  • 在版本化开发集与保留集上执行旧规则和一个变更；用独立金标决定是本地保留还是撤回复核。
  • 独立汇总门禁、灰度、回滚与评估证据，明确哪些生产条件仍未满足。

1. 先限制影响，再保留最小复现

选中引文不等于已经发给用户。本课事故观察点是在输出前：在训练证据库读到一段此前可见的导出政策作为缓存，随后本地 SQLite 的授权记录被撤销；旧规则仍选中缓存。独立枚举当前授权集合显示它已不可见。演练不生成对外答复，更不发送；只记 selected = true、selection_current = false，不把该结果延伸成「已经泄露」。

  1. 处置：阻止候选晋级、停止扩大作用，不让缓存接管宿主权限；如涉及实际服务，先按授权流程控制影响，再由负责人核对接触范围。
  2. 脱敏复现：local-incident-01 仅允许固定字段：本地编号、夹具版本、案例 ID、结构化观察和预期、处置、规则范围与复核条件。删原引文、请求正文、用户标识、令牌及连接串；不要用散列真人身份替代删除。
  3. 区分两列：观察是撤权后旧缓存仍被选中；期望是交接人工且不选引文。回归根据预期验收，事故事实仍保留一次失败记录，不能把两者写成同一个 passed。

minimize() 只投影这一个已知合成观察；未实际看见缓存命中、当前不可见、仍错误选中时不产出该事故。它不是通用清洗器，不接收真实工单做自动脱敏。若真实审计另需保存原始事实，应在授权范围内隔离保管，不进入本地测试或返回报告。

2. 变更只动一个规则，独立读回再判定

固定同一组 Case（案例 ID、宿主作用域、精确证据键和读取后的状态转换），每案每臂重新开启同一份 Phase 7 内存库。基线 cached-citation-v1 按首次读到的缓存选引文；候选 exact-current-citation-v2 只改一件事：缓存命中后，按同一租户、主体和精确键重读，当前结果不同就不选引文并交人工。未命中仍返回 needs_evidence，不追加读取；不扩大作用域、不自动换新版、不做保存。

例如保留集的「政策升版」不是把标签从可见改为不可见：真正写入合成 v2 后，按旧 v1 键重读找不到它，基线却仍选 v1，候选交接。另一条正控使用同一证据键：运维租户看到 30 天，客服租户看到 7 天。若把运维案错送客服，即使查到当前有效的 7 天也必须失败。内部金标独立写下原案的批次、主体、证据键、全文和状态转换；用原作用域另做 authorized() 读回，核实际查找参数、初次证据和选中内容。报告只给固定编号、状态、布尔值、次数和差异码，不输出主体或原文。

独立版本的全案组；分数是符合预写标签的案例数
夹具版本与任务基线候选
citation-dev-v1：撤权复现、合法引文、原本就缺证据2/33/3
citation-held-out-v1：政策升版、附录撤权、另一租户同键正控、仍获授权的附录正控2/44/4

expected 是另外写的 ID 到（终态、是否选中、所选内容是否现行）的映射；observations 保留两个版本实际行为；verdict 对齐 ID 后逐项给出差异。缺项、额外样本与重复 ID 拒绝比较。候选在开发集只增加两次重读，在保留集增加四次；这是本地操作数，不是生产耗时。两个集都提升并达到全通过，选择 retain_local_rule；若只修复开发复现，却把另一租户的授权文档也扣下，选择 revert_and_review。不能根据保留集边看边改再把同一分数称为独立证据；用于调试的保留样本应转入开发集，冻结新的独立保留集。

决策卡：用负例和正控决定是否留下单一变更

适用：已有能脱敏重放的误选条件，且当前宿主视图有可比较的读取边界。不适用：不能用一次精确复查宣称不存在检查后再撤权的竞态，也不能代替草稿保存授权。

只修发生过的一案

条件写成案例特判，或把所有结果交人工，都会让那一案看似通过。

一项规则，两套独立夹具

较新版本和不同来源撤权均被识别，同时合法的同键引文和附录还能用。

代价：缓存命中多一次读取，失败转人工会增加排队；替代方案是缓存失效通知或与交付同一授权快照，仍需验证延迟、失效与竞态。

  1. 记录为何只改选引文规则，核对两臂独立运行和读回。
  2. 更换租户与证据变化，用正控主动反证「全阻断也算修复」。

复核：授权或文档版本语义变化、合法引文被扣下时重跑；候选不达标就撤回复核，不将旧基线视为可对外放行。

Q 候选挡住两条例外，但也拦住仍被授权的附录。下一步？
正确拒绝不抵消合法任务的退化。撤回本地变更也没有给旧规则生产许可。

面试自查

先给结论、再解释证据与决策边界。

Q1 审计显示选了撤权引文，能说用户一定看到了吗？

参考回答：不能。选中发生在交付前；先限制影响，再单独核对交付链路。

追问：如何不复制正文仍能重现？

答题要点：留下版本、合成案型、先命中后撤权这一个状态转换、观察与预期。

Q2 规则把撤权案转了人工，开发集通过，能留下吗？

参考回答：仍要用未参与修订的保留集核查同类错误与合法正控。

追问：已用保留集调过规则怎么办？

答题要点：记录它已成为开发输入；另冻结含独立正反例的新保留集。

Q3 精确重查都通过了，授权还能在交付前撤销吗？

参考回答：能；本地示例只验证一次重查前已发生的变化。

追问：需要什么新增证据？

答题要点：在真实宿主核对交付与授权快照的时间边界，测试重查后撤权的并发情况。

Q4 本地交接全绿，但真实旧检查点环境仍缺。可以启用灰度吗？

参考回答：不能。全绿只证明这些本地合同和演练，生产准入仍阻塞。

追问：应该交付什么，而不再重跑相同脚本？

答题要点：列明缺失的旧状态验证、产物和环境身份、负责授权的人与预先约定的线上停止条件。
