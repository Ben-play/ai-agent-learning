把验收标准接入离线 CI

门禁既要能挡住已知退化，也要给出可复核的理由

为什么这课重要？

本地跑了几条任务，迁移后平均耗时下降，是否合并？先问哪些任务、什么结果算成功、有没有禁止效果。一次无批准写入不能被更快的九次成功抵消；同样，省掉引用而仍然返回七天并不算正确。门禁的价值是把这套判断变成同一条可复跑命令，不再依赖评审者手工浏览样本。

  • 把案例级合约、跨案例指标和零容忍项分开，理解版本、分母和退出码。
  • 跑基线与两种失败对照，再用独立的观测记录验证延迟和禁止效果各有阻断通道。

1. 先定义输入与观察，不只保存一个分数

fixtures/acceptance-v2.json 固定六条用例、金标、阈值与合成事件价表。gate.py 每条重建授权证据库和临时草稿库，分别记录输出、精确引文、检查点、首次批准分发、恢复调用、业务 INSERT 尝试、提交后的全表行数和回执一致性。评分器拿 Observation 对独立金标；重复或缺失 ID 直接报错，不能把坏样本移出分母。

不要按用例名填一串“应该发生的阶段”。本版在真实本地入口记录检索、生成替身、暂存、否决、批准调用和重开后的恢复事件；事件发生后，才从统一价表取一对 [积分, 毫秒]。例如丢回复案实际进入 retrieve → stage → approved_call → recover，对应 19 积分、100 ms；恢复不是第二次保存，仍然必须核对零新增 INSERT。额外只读变体在同一案真实多查一次，得到 23 积分、124 ms，业务结果不变，延迟门单独变红。这里观察的是调用，赋给调用的费用和时长仍是合成值。

例如保留期答复取到 EXPORT-POLICY v1 §1 的七天原文。删去引文的对照不改变正文、成本或写入，仅在 retention.citations 失配。另一个对照在同一只读任务里多一条普通本地草稿建议；宿主挡住它，任务仍能答对，分发与写入仍是零，但多余建议必须单独拦住。两个对照用同一评分入口，不连接外部服务。

门槛口径v2 基线
态、正文、证据与效果每条独立比对；多分发、多写、重放再写等不能靠平均值覆盖6 / 6 合约通过，零禁止效果
任务成功率通过数量 / 6；正确拒答、等待、拒绝也可成功100%，下限 100%
成功任务成本全部已记账尝试（含失败）总积分 / 合约成功数；分母 0 时用空值并阻断49 / 6 ≈ 8.17，上限 11
最近秩 p95先按任务求合成尝试时间和，排序取第 ⌈0.95 × 6⌉ 项，不把真实等待混进这些输入100 ms，上限 100 ms
多余建议按 L75 宿主观测统计，不等同于工具分发0，上限 0

这里的毫秒、积分都是固定教学输入；六条的 p95 就是最大值，不能作为线上分位数估计。验收分母反映任务契约，不把所有拒答都算失败或成功：无资料时拒答是正确，原本可答时拒答则失败。诊断报告同时携带 suite_version 与 metric_version；调整业务期望或统计口径要留下新基线和理由，而不是被红灯逼到放宽阈值。

2. 让同一命令在本地和 PR 上作出同样判断

基线通过时命令退出 0；被阻断时返回 1，JSON 留下 failures（哪题哪字段）、blocks（哪类门槛）和 by_case（逐案观察）。例如 by_case.lost-response 可看到已保存检查点、一次业务写入、一条记录、零次重放写入及相同回执；报告不需要打印原文或草稿。若出现写尝试但无落库，先查事务；若已落库而回执变化，则停止重试并核对操作记录。运行异常同样非零，但不能冒充已识别的质量失败；演练还要解析报告核对原因。

课程工作流 .github/workflows/course-engineering.yml 用 pull_request 在受限 runner 上检出并运行课程代码，contents: read、检出不保留凭据；动作引用固定提交。不传 secrets，不使用真实账号，不调用模型，不部署。GitHub 检出源码本身不是离线；评分与示例阶段不需要外部服务。仓库要强制阻挡合并，还需管理员把对应状态检查设为必过。本课验证本地命令，不声称远端作业已运行或分支保护已配置。

决策卡：失败实验要能解释，不能被 CI 当成成功

适用：需要稳定、可低成本复跑的 PR 回归。边界：真实模型质量、负载和生产身份另做受控验收。

误判：快且便宜就放行

用一个综合分，掉引用或多写一行也能被其他指标抵消。

选择：先硬约束，再看分布

独立校验零容忍项、证据、成功率、成本、延迟、多余建议。

代价：要维护真实代表性的金标与观测字段；好处是逐项诊断，避免为一个绿灯改错地方。

  1. 固定金标，分别跑基线和删除引用对照；保存返回码与具体字段差异。
  2. 再用相同评分器改一项观察，核对预期门槛单独点亮。

验收门槛：通过退出 0；退化退出 1 且原因正确；恢复后同版本再过。

Q 成功数不变，失败路径多了一次有费用的尝试。成功任务成本如何计算？
失败路径也消耗预算。统计单位是交付成功的任务，不是单次尝试。

    row = json.loads(p.stdout)

from dataclasses import replace
import json, runpy

if not __debug__:
    raise RuntimeError("run without -O")
gate = runpy.run_path("code/phase8-agent-engineering/engineering-lab/gate.py")
suite = json.loads(gate["DATA"].read_text(encoding="utf-8"))
rows = [gate["exercise"](case) for case in suite["cases"]]
read = next(row for row in rows if row.case_id == "retention")
assert gate["evaluate"](suite, rows)["passed"]

def changed(row, spec):
    return gate["evaluate"](spec, [row if obs.case_id == row.case_id else obs for obs in rows])

slow = gate["run"]("extra-read")
assert (slow["total_credits"], slow["p95_ms"], slow["blocks"], slow["successes"]) == (53, 124, ["p95_ms"], 6)
recovered = slow["by_case"]["lost-response"]
assert recovered["events"].count("retrieve") == 2
assert (recovered["recoveries"], recovered["writes"], recovered["replay_writes"]) == (1, 1, 0)
new_tariff = {**suite["event_tariff"], "render_answer": [28, 21]}
expensive = gate["evaluate"]({**suite, "event_tariff": new_tariff}, rows)
assert expensive["credits_per_success"] == 74 / 6 and expensive["successes"] == 6
assert expensive["blocks"] == ["credits_per_success"]
loose = {**suite, "thresholds": {**suite["thresholds"], "min_success_rate": 0.5}}
forbidden = changed(replace(read, dispatches=1), loose)
assert forbidden["hard_failures"] == ["retention"] and forbidden["blocks"] == ["forbidden_or_duplicate_effect"]
replay = next(row for row in rows if row.case_id == "lost-response")
wrong_receipt = changed(replace(replay, same_receipt=False), loose)
assert wrong_receipt["hard_failures"] == ["lost-response"]
assert wrong_receipt["blocks"] == ["forbidden_or_duplicate_effect"]
extra = gate["run"]("extra-proposal")
assert extra["successes"] == 6 and extra["hard_failures"] == [] and extra["blocks"] == ["extra_proposals"]
assert extra["extra_proposals"] == 1
print("L77 TRANSFER PASSED")

异常分发和错误回执是内存里的观察记录，不是执行环境的越权证据；真实的零分发与落库对照看 L75。额外读取没有使 p95 改变时，先查事件是否在读取入口记录，再查是否按任务聚合后排序。

面试自查

先说明门槛为何存在，再说如何复验。

Q1候选比基线便宜，但每次读题都遗漏引文，该合并吗？

参考回答：不合并。任务合约不成立，成本不弥补引用回归；保留用例字段差异并沿当前授权来源检查。

追问：正文正确、只是引文文本少一字呢？

答题要点：精确引文同样不匹配，不能因正文可读就放行。

Q2全部任务失败，报告的成功任务成本应写多少？

参考回答：分母是零，报告 null 并阻断；仍保留失败产生的全部费用。

追问：只看厂商显示费用是零，有无不同？

答题要点：真零与账本未收到用量要区分；不靠插零伪装可比较性。

Q3开发者说「负例返回非零」，如何认定测试有效？

参考回答：同时查退出码、准确的阻断类别、用例 ID 和差异字段。语法错误或崩溃不是目标退化。

追问：恢复后又绿，可以改金标吗？

答题要点：恢复本身要沿用同金标；真正需求变更才版本化评审。

Q4本地门禁全绿，是否可以说线上 p95 已达标？

参考回答：不能。这里只有合成时长和六条固定任务；先把真实环境、样本和队列归属另写成测试计划。

追问：PR 作业已经绿，合并一定会被保护吗？

答题要点：作业状态和分支规则独立；该状态需要被设为必过。
