类、对象与 @dataclass

@dataclass 是 Agent 数据模型的起点 — Message、ToolCall、AgentState 都从这里来

💡 为什么这课重要？

Agent 系统里到处是"数据模型"：一条消息、一次工具调用、整个 Agent 的状态。用普通 dict 存这些数据，字段拼错了也不报错；用 @dataclass，字段清晰、自带比较和打印，代码立刻规整。

到 L14 你会进一步用 Pydantic 定义带运行时校验、可导出 Schema 的模型。@dataclass 提供标准库的数据类基础，Pydantic 则在相似的字段声明之上增加边界校验等能力；搞清楚“什么时候用 dataclass、什么时候上 Pydantic”是高频面试题。

本课关键决策：可信内部数据可用 dataclass；用户、LLM、API 等不可信边界先校验，再进入内部模型。

学习目标

完成本课后，你将能够：

  • 写一个类，区分实例属性、类属性、self
  • 区分实例方法 / @classmethod / @staticmethod
  • 用 @dataclass 快速定义数据模型
  • 用 field(default_factory=...) 安全地给可变默认值
  • 用 frozen=True 禁止字段重绑定，并说清它不等于深不可变

1. 类的基础：属性与方法

类是"把数据和操作它的函数打包在一起"的模板——它本身不是数据，只是造数据的图纸。前面学的函数是零散的动作，而一个 Agent 既有状态（名字、配置、对话历史）又有行为（回复、调工具）——用类正好把两者收在一处。

写 class Agent: 只是定义模板；真正产生一个能用的对象要靠实例化——调用类本身，像函数一样传参：Agent("bot")。这一步会先造出一块空白的实例，再自动调用 __init__，把传进来的参数写成这个实例自己的属性。a = Agent("bot") 之后，a 就是指向这个具体实例的变量；同一个类可以实例化出无数个互不影响的对象。__init__ 里第一个参数 self，指的就是"正在被创建、正在被初始化的那个实例"——之后每次通过 a.xxx 调用方法，Python 都会把 a 自动传进去，绑定成方法内的 self。

认清一个类的"三件套"：类属性（定义在类体里，默认所有实例共享读取）、实例属性（每个实例独有，通常在 __init__ 里用 self.xxx = ... 设置）、方法（类里定义的函数，按用途分三种，不是"第一个参数永远是 self"）。

class Agent:
    default_model = "claude"          # 类属性：定义在类体里

    def __init__(self, name):
        self.name = name              # 实例属性：每个实例独有

    def greet(self):                  # 实例方法：约定第一个参数是 self
        return f"{self.name}@{self.default_model}"

    @classmethod
    def make_default(cls):            # 类方法：拿到类本身(cls)，常用作"工厂"
        return cls("default")

    @staticmethod
    def is_valid(name):               # 静态方法：不接收隐式的 self/cls
        return bool(name)

a = Agent("bot")              # 实例化：调用类 → 创建实例 → 自动执行 __init__
print(a.greet())              # bot@claude
print(Agent.make_default().name)   # default
print(Agent.is_valid(""))    # False
  • 实例化：Agent("bot") 这一步——调用类本身，产出一个新实例，并自动触发 __init__ 初始化字段
  • self：实例方法里指向"当前这个实例"；只是约定俗成的命名，不是语法关键字
  • 实例方法：惯例上第一个参数是 self，Python 调用 a.greet() 时自动把 a 传进去
  • @classmethod：第一个参数是类本身 cls，常用来写"另一种构造方式"（工厂方法）
  • @staticmethod：不接收隐式的 self/cls，只是逻辑上归属这个类的普通函数
⚠️ 类属性遮蔽与共享陷阱：

访问 a.default_model 时，Python 先找实例自己有没有这个属性，没有才去类上找——所以类属性其实是"默认从类上读取"。写 a.default_model = "gpt" 并不会修改类属性，只是给 a 这个实例新建了一个同名的实例属性，把类属性遮蔽掉了；其他实例和类本身都不受影响。

真正危险的是可变类属性：如果类属性是 list/dict 这类可变对象，比如 history = []，那么所有没有遮蔽它的实例都在共享同一个对象——一个实例 a.history.append(x) 会让 b.history 也看到这条记录。这才是"共享状态陷阱"，和 L03 讲的可变默认参数是同一类坑。

Q @classmethod 的第一个参数是什么？
类方法的第一个参数是类本身 cls，所以能用 cls(...) 创建实例——这让它很适合写工厂方法（如 from_dict、make_default）。实例方法用 self，静态方法两者都不要。

2. @dataclass：一行省掉一堆样板

手写数据类要写 __init__、__eq__、__repr__…很啰嗦。@dataclass 自动帮你生成：

from dataclasses import dataclass, field

@dataclass
class Message:
    role: str
    content: str
    meta: dict = field(default_factory=dict)   # ⚠️ 可变默认值必须用 default_factory

m1 = Message("user", "你好")
m2 = Message("user", "你好")
print(m1)          # Message(role='user', content='你好', meta={})  ← 自动 __repr__
print(m1 == m2)    # True  ← 自动 __eq__（按字段比较）

最佳实践：可变默认值用 default_factory 创建

适用场景：字段可省略、实例创建后又会被原地修改，且每条 Message 或每个 AgentState 都应拥有自己的 list/dict。若业务明确要求共享容器，应由调用方显式传入，而不是藏在默认值里。

❌ 直接写可变默认值
@dataclass
class Message:
    meta: dict = {}  # 类定义时抛 ValueError

dataclass 会主动拒绝这类共享默认对象。

✅ 让工厂为每个实例创建对象
@dataclass
class Message:
    meta: dict = field(default_factory=dict)

每次实例化都会调用一次 dict()。

为什么更优：default_factory 在每次实例化且字段被省略时才创建新容器，阻断了实例间的隐式别名，从而提升状态隔离性与可测试性。代价是每个实例都要分配容器，且工厂不承担输入校验；若状态应共享或字段必填，改由调用方显式传入共享对象或必填值，外部数据则在构造前设置独立校验 seam（边界函数或 Pydantic 模型）。

动手自检（整块复制即可运行）：
from dataclasses import dataclass, field

@dataclass
class Message:
    role: str
    meta: dict = field(default_factory=dict)

first = Message("user")
second = Message("user")
first.meta["id"] = "m1"
assert first.meta == {"id": "m1"}
assert second.meta == {}
assert first.meta is not second.meta

结果解释：两个省略字段的实例拿到不同 dict；这里继续保留现有近迁移练习，课末验收再验证“显式传入共享对象”这条边界。

边界：default_factory 只在调用方省略字段时创建对象，不复制显式传入的容器，也不提供输入校验；来自用户、LLM 或 API 的数据仍应在系统边界校验。

3. frozen：禁止字段重绑定

加 frozen=True，实例的字段就不能被重新绑定——适合防止调用记录的字段被意外替换，但若字段引用 dict/list，记录仍不是深不可变：

from dataclasses import FrozenInstanceError, dataclass


@dataclass(frozen=True)
class ToolCall:
    name: str
    args: dict


tc = ToolCall("search", {"q": "python"})
try:
    tc.name = "calc"
except FrozenInstanceError as exc:
    print(type(exc).__name__)  # FrozenInstanceError

tc.args["q"] = "changed"     # ✅ 浅冻结：嵌套 dict 仍可原地修改
print(tc.args["q"])           # changed

try:
    hash(tc)
except TypeError:
    print("not hashable")      # frozen 不保证字段或实例可 hash
⚠️ frozen 只禁止字段重绑定：

上例已显示边界：frozen=True 只禁止字段重新绑定，不递归冻结 list/dict 内部内容。

因此含 dict 的 ToolCall 不保证可 hash，也不会自动线程安全；这些能力取决于字段自身是否可 hash 及并发设计。

如果需要把 ToolCall 放进 set 或用作 dict key，字段本身也要可 hash，比如把 args: dict 换成规范化后的 args_json: str：

@dataclass(frozen=True)
class ToolCallKey:
    name: str
    args_json: str      # 字段均可 hash → 此示例实例可 hash

print(hash(ToolCallKey("search", '{"q":"python"}')))  # 正常输出一个整数

这里的 JSON 字符串是规范化边界：同一数据必须固定键顺序、空白等序列化规则，否则语义相同的参数仍可能得到不同字符串和不同 key。

Q dataclass 里给 list/dict 默认值，正确写法是？
可变默认值必须写 field(default_factory=list)，让每个实例各拿一个新列表。直接 = [] 会触发可变默认值共享的陷阱（dataclass 实际上会直接报错阻止你这么写）。这是 dataclass 版的"可变默认参数陷阱"。

4. dataclass vs Pydantic（面试高频）

@dataclassPydantic BaseModel
来源标准库，零依赖第三方库
数据校验不校验（类型注解只是提示）运行时校验；可能按模型与配置进行类型转换
用途内部纯数据容器外部输入/输出、Tool Schema
JSON Schema不支持一键导出（喂给 LLM）

选择原则：内部传数据用 dataclass（轻、快）；一旦数据来自外部（用户、LLM、API）需要校验，或要生成工具 Schema，就用 Pydantic（L14 深入）。

知识图谱

类基础
├── 实例属性(self.x) vs 类属性(默认从类读取，实例可遮蔽)
├── 实例方法(self)
├── @classmethod(cls) → 工厂方法
└── @staticmethod → 归属类的工具函数

@dataclass
├── 自动 __init__ / __eq__ / __repr__
├── field(default_factory=...) → 可变默认值正解
└── frozen=True → 禁止字段重绑定（浅层），非深度不可变/不保证可 hash

dataclass vs Pydantic
├── dataclass：内部数据、不校验、零依赖
└── Pydantic：外部输入、运行时校验、导 JSON Schema（→ L14）

练习：用 @dataclass 定义 Agent 数据模型

  3. AgentState：messages（Message 列表，默认空）、step（int，默认 0）、done（bool，默认 False）

from dataclasses import dataclass, field

@dataclass
class Message:
    role: str
    content: str
    meta: dict = field(default_factory=dict)

@dataclass(frozen=True)
class ToolCall:
    name: str
    args: dict

@dataclass
class AgentState:
    messages: list = field(default_factory=list)
    step: int = 0
    done: bool = False

    def add(self, msg: Message):
        self.messages.append(msg)
        self.step += 1


state = AgentState()
state.add(Message("user", "北京天气？"))
state.add(Message("assistant", "晴，25°C"))
print(state.step)              # 2
print(len(state.messages))     # 2
print(ToolCall("search", {"q": "天气"}))   # ToolCall(name='search', args={'q': '天气'})

思考题

先自己想，再点开对答案。

Q1如果 Message.content 传进来的是数字 123，dataclass 会报错吗？

不会报错。Message(role="user", content=123) 会照常创建，content 里就老老实实存着整数 123。

关键在于：dataclass 里的 content: str 只是类型注解，不是校验。Python 的注解在运行时不强制，@dataclass 也只拿它来生成 __init__/__repr__ 等样板，完全不检查你传进来的值是不是真的 str。所以传 123、None、一个列表，都能塞进去，直到后面某处把它当字符串用（比如 .strip()）才可能意外炸掉。

这正是「数据一旦来自外部（用户、LLM、API）就该用 Pydantic」的理由：换成 Pydantic BaseModel，content: str 会在构造时按模型与配置进行校验，并可能进行类型转换；不满足规则时抛错，把脏数据挡在门口。dataclass 负责「内部可信数据的容器」，校验的活交给 Pydantic（L14 深入）。

Q2为什么 ToolCall 适合 frozen，而 AgentState 不适合？frozen 的 AgentState 会发生什么？

ToolCall 更像一次事实记录，而 AgentState 要随循环持续变化。

具体的浅冻结、可变容器和 hash 边界见第 3 节；这里抓住选择原则即可：记录字段不应重绑定时可用 frozen，承载过程状态时通常保持可变。

本课最佳实践验收：区分默认隔离与显式共享

任务目标

用 RunState 明确运行状态的所有权，证明默认容器归各实例独立持有，而调用方显式传入的同一对象会按引用共享。

操作清单

  1. 定义两个 default_factory 字段。
  2. 验证省略字段的两个实例互不共享。
  3. 把同一外部列表显式传给两个实例。
  4. 证明显式输入按引用共享。

通过标准

  • 断言省略字段时，两个实例的 errors/usage 都是新对象
  • 断言显式传入同一列表时，两个实例都保留该对象的身份
  • 断言修改共享列表后，两个实例都观察到同一内容
  • 程序执行完毕并打印唯一的 L07 ACCEPTED
课末自检：证明默认隔离不等于复制显式输入
from dataclasses import dataclass, field

@dataclass
class RunState:
    errors: list[str] = field(default_factory=list)
    usage: dict[str, int] = field(
        default_factory=lambda: {"input_tokens": 0, "output_tokens": 0}
    )

first = RunState()
second = RunState()
first.errors.append("timeout")
first.usage["input_tokens"] = 120
assert second.errors == []
assert second.usage == {"input_tokens": 0, "output_tokens": 0}
assert first.errors is not second.errors
assert first.usage is not second.usage

shared_errors = []
third = RunState(errors=shared_errors)
fourth = RunState(errors=shared_errors)
shared_errors.append("shared-by-caller")
assert third.errors is shared_errors
assert fourth.errors is shared_errors
assert third.errors is fourth.errors
assert third.errors == fourth.errors == ["shared-by-caller"]
print("L07 ACCEPTED")

结果诊断：标准输出必须只有一行 L07 ACCEPTED。默认身份断言失败表示省略字段时没有创建新对象；显式身份断言失败表示调用方传入的对象被复制或替换；共享内容断言失败表示一次原地修改没有被两个实例共同观察到。

参考验收程序（独立完成后展开）：
from dataclasses import dataclass, field
from inspect import signature


@dataclass
class RouteState:
    events: list[str] = field(default_factory=list)
    counters: dict[str, int] = field(default_factory=dict)


def make_route_callback(label, route):
    def callback():
        return {"label": label, "route": route}

    return callback


def build_callbacks(specs):
    return [
        make_route_callback(spec["label"], spec["route"])
        for spec in specs
    ]


first = RouteState()
second = RouteState()
first.events.append("started")
first.counters["attempts"] = 1
assert first.events is not second.events
assert first.counters is not second.counters
assert second.events == []
assert second.counters == {}

shared_events = []
third = RouteState(events=shared_events)
fourth = RouteState(events=shared_events)
shared_events.append("visible-to-both")
assert third.events is shared_events
assert fourth.events is shared_events
assert third.events is fourth.events
assert third.events == fourth.events == ["visible-to-both"]
assert third.counters is not fourth.counters

specs = [
    {"label": "document-created", "route": "/index"},
    {"label": "invoice-paid", "route": "/notify"},
    {"label": "run-failed", "route": "/retry"},
]
callbacks = build_callbacks(specs)
assert str(signature(make_route_callback)) == "(label, route)"
assert str(signature(build_callbacks)) == "(specs)"
assert [str(signature(callback)) for callback in callbacks] == [
    "()", "()", "()"
]
assert [callback() for callback in callbacks] == [
    {"label": "document-created", "route": "/index"},
    {"label": "invoice-paid", "route": "/notify"},
    {"label": "run-failed", "route": "/retry"},
]

specs[0]["label"] = "changed"
specs[1]["route"] = "/changed"
assert callbacks[0]() == {
    "label": "document-created", "route": "/index"
}
assert callbacks[1]() == {
    "label": "invoice-paid", "route": "/notify"
}
assert callbacks[2]() == {
    "label": "run-failed", "route": "/retry"
}

print("P1 CHECKPOINT STATE-OWNERSHIP PASSED")

结果诊断：标准输出必须只有一行 P1 CHECKPOINT STATE-OWNERSHIP PASSED。失败断言会定位到默认容器隔离、显式共享身份、共享修改可见性、回调零参数协议或 label/route 创建时绑定。

面试常见问题

Q1：@dataclass 帮你自动生成了哪些方法？

答：主要是 __init__、__repr__、__eq__（按字段比较）；加 frozen=True 会阻止字段重新绑定，但若字段本身是 dict/list，内部仍可变，实例也不保证可 hash。省掉大量样板代码。

Q2：dataclass 和 Pydantic 有什么区别？怎么选？

答：dataclass 是标准库、不做校验，适合内部纯数据；Pydantic 会在运行时校验，并可能按模型与配置进行类型转换，也能导出 JSON Schema，适合外部输入/输出和工具 Schema。数据来自外部或需要 Schema 就用 Pydantic。

Q3：dataclass 里怎么正确给列表/字典默认值？

答：用 field(default_factory=list)。直接写 = [] 会因可变默认值共享而被 dataclass 直接报错。

Q4：@classmethod 和 @staticmethod 区别？

答：classmethod 接收类 cls，能用来构造实例（工厂方法）；staticmethod 不接收 self/cls，只是逻辑上归属该类的普通函数。

总结

  • 实例属性归各实例；类属性默认从类上读取，实例可用同名属性遮蔽（可变类属性才是共享陷阱）
  • 实例方法惯例第一个参数是 self；@classmethod 拿 cls（写工厂方法），@staticmethod 归属类的工具函数
  • @dataclass 自动生成 __init__/__eq__/__repr__，写数据模型神器
  • 可变默认值用 field(default_factory=...)，别写 = []
  • frozen=True → 禁止字段重新绑定（不递归冻结内部对象），不保证可 hash，也不自动保证线程安全
