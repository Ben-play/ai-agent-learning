文件、JSON 与 Dict 深度操作

LLM 说的是 JSON — 读写文件、解析流式响应，是 Agent 的日常 I/O

💡 为什么这课重要？

LLM 的输入输出、工具调用参数、配置文件、缓存——全是 JSON。Agent 每一步都在做 JSON 的序列化（对象→字符串）和反序列化（字符串→对象）。

而流式响应（streaming）返回的是一行一个 JSON的数据流（JSON Lines），要能逐行解析、拼接、还要扛住坏行和截断。这是处理真实 LLM 输出的硬技能。

学习目标

完成本课后，你将能够：

  • 用 with open() 安全读写文件
  • 用 pathlib 优雅地处理路径
  • 熟练 json.dumps / json.loads 及常用参数
  • 逐行解析 JSON Lines 流式响应，并容错
  • 知道 orjson 何时能提速

1. 文件读写：永远用 with

from pathlib import Path

# 写
with open("config.json", "w", encoding="utf-8") as f:
    f.write('{"model": "claude"}')
# with 块结束自动关闭文件，即使中途出错也保证关闭

# 读
with open("config.json", "r", encoding="utf-8") as f:
    text = f.read()

# pathlib：更现代的路径处理
p = Path("data") / "logs" / "run.json"   # 用 / 拼路径，跨平台
p.parent.mkdir(parents=True, exist_ok=True)   # 确保目录存在
p.write_text('{"ok": true}', encoding="utf-8")   # 一行读写
print(p.read_text(encoding="utf-8"))

要点：永远用 with（自动关闭）、永远指定 encoding="utf-8"（避免中文乱码），路径用 pathlib 而非字符串拼接。

Q 用 with open(...) 读文件，最大的好处是？
with（上下文管理器，L10 详讲）保证代码块结束时自动关闭文件——即使中途抛异常也会关。不关文件会泄露句柄。速度和编码不是它解决的问题。

2. JSON 序列化与反序列化

import json

obj = {"name": "search", "args": {"q": "python"}, "ok": True}

# 序列化：对象 → 字符串
s = json.dumps(obj, ensure_ascii=False, indent=2)
# ensure_ascii=False → 中文正常显示（不转成 \uXXXX）
# indent=2 → 美化缩进（存文件时好读）

# 反序列化：字符串 → 对象
back = json.loads(s)
print(back == obj)    # True

# 直接读写文件
with open("c.json", "w", encoding="utf-8") as f:
    json.dump(obj, f, ensure_ascii=False)   # dump 写文件（没有 s）
with open("c.json", "r", encoding="utf-8") as f:
    data = json.load(f)                       # load 读文件

记忆法：带 s 的（dumps/loads）操作字符串；不带 s 的（dump/load）直接操作文件。

💡 面试常见问题：

"json.dumps 的中文变成 \uXXXX 怎么办？"

答：加 ensure_ascii=False。它默认为 True 会把非 ASCII 转义；关掉后中文原样输出（记得文件用 utf-8 编码）。

3. 解析流式响应（JSON Lines）

LLM 流式输出通常是一行一个 JSON 对象。要逐行解析、拼接内容，还得扛住空行/坏行/截断：

import json

# 模拟流：每行一个事件，中间可能有空行或坏行
stream = '{"tok":"Hel"}\n{"tok":"lo"}\n\n{坏行}\n{"done":true}\n'

tokens = []
done = False
for line in stream.splitlines():
    line = line.strip()
    if not line:
        continue                       # 跳过空行
    try:
        event = json.loads(line)
    except json.JSONDecodeError:
        continue                       # 坏行跳过，别让整个流崩掉
    if "tok" in event:
        tokens.append(event["tok"])
    if event.get("done"):
        done = True

print("".join(tokens), done)   # Hello True

这是处理真实 LLM streaming 的核心骨架（结合 L04 的字符串方法 + 后面 L12 的生成器）。关键是容错：网络流可能有半行、心跳空行、格式异常——健壮的解析必须"坏行跳过、继续处理"，而不是一异常就全挂。

Q 解析流式 JSON 行时，遇到一个格式坏行应该？
流式场景里坏行/半行很常见（心跳、截断、编码抖动）。健壮做法是 try/except json.JSONDecodeError 后 跳过该行、继续，避免一个坏行让整段响应作废。生产 Agent 的解析必须容错。

4. json vs orjson（性能）

标准库 json 足够日常使用。当你要序列化大量或超大 JSON（如批处理、日志管线）时，第三方 orjson 快得多（常见快 3–10 倍），且原生支持 datetime、dataclass 等。

# 用法几乎一样，但 orjson 返回 bytes
import orjson
data = orjson.loads(b'{"ok": true}')
raw = orjson.dumps({"ok": True})   # b'{"ok":true}'

原则：先用标准库 json；确认序列化是性能瓶颈时，再换 orjson。别过早优化。

知识图谱

文件 I/O
├── with open(..., encoding="utf-8") → 自动关闭 + 防乱码
└── pathlib：Path("a")/"b"、mkdir、read_text/write_text

JSON
├── dumps/loads → 操作字符串（带 s）
├── dump/load → 操作文件（不带 s）
├── ensure_ascii=False → 中文原样
└── indent=2 → 美化

流式解析（JSON Lines）
├── splitlines() 逐行 + strip()
├── 空行跳过、坏行 try/except 跳过（容错！）
└── 拼接 tok、检测 done

json vs orjson → 大量序列化时 orjson 快 3–10x

实战练习

练习：解析 LLM 流式响应

模拟 LLM 返回的 JSON Lines 流，逐行解析、拼接完整内容、统计用量，并容错。先自己写，再看答案。

任务清单

  1. 输入是多行字符串，每行可能是：{"type":"token","text":"..."}、{"type":"usage","tokens":N}、{"type":"done"}，也可能有空行/坏行
  2. 逐行解析，拼接所有 token 的 text 成完整回答
  3. 累加 usage 的 tokens
  4. 坏行/空行跳过、不崩溃
  5. 返回 {"text": 完整回答, "total_tokens": N, "done": bool}
💡 点击查看参考答案 
import json

def parse_stream(stream: str) -> dict:
    parts = []
    total_tokens = 0
    done = False

    for line in stream.splitlines():
        line = line.strip()
        if not line:
            continue
        try:
            ev = json.loads(line)
        except json.JSONDecodeError:
            continue                       # 容错：坏行跳过

        kind = ev.get("type")
        if kind == "token":
            parts.append(ev.get("text", ""))
        elif kind == "usage":
            total_tokens += ev.get("tokens", 0)
        elif kind == "done":
            done = True

    return {"text": "".join(parts), "total_tokens": total_tokens, "done": done}


stream = (
    '{"type":"token","text":"你好"}\n'
    '{"type":"token","text":"，世界"}\n'
    '\n'                                   # 空行
    '{oops bad line}\n'                    # 坏行
    '{"type":"usage","tokens":42}\n'
    '{"type":"done"}\n'
)
print(parse_stream(stream))
# {'text': '你好，世界', 'total_tokens': 42, 'done': True}

面试常见问题

Q1：json.dump 和 json.dumps 区别？

答：带 s 的 dumps/loads 在字符串和对象之间转换；不带 s 的 dump/load 直接读写文件对象。

Q2：为什么读写文件推荐用 with？

答：with 是上下文管理器，块结束时自动关闭文件（即使异常也关），避免句柄泄露。比手动 f.close() 更安全。

Q3：解析 LLM 流式响应要注意什么？

答：逐行解析、容错——空行跳过、坏行/半行用 try/except JSONDecodeError 跳过，避免单行错误让整段响应作废；同时拼接内容、检测结束标志。

Q4：什么时候用 orjson 而不是标准库 json？

答：当 JSON 序列化成为性能瓶颈（大量或超大数据、高频调用）时。orjson 通常快数倍，并原生支持 datetime/dataclass。日常仍可用标准库。

总结

  • 永远用 with open(..., encoding="utf-8")，路径用 pathlib
  • dumps/loads 操作字符串；dump/load 操作文件
  • ensure_ascii=False 让中文原样输出
  • 流式解析 = 逐行 + strip + 空行/坏行容错跳过 + 拼接
  • 健壮的 LLM 响应解析绝不能因一个坏行整段崩溃
  • 大量序列化才考虑 orjson，别过早优化
