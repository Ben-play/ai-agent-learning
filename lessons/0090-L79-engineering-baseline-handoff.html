第八阶段 · Agent 工程化50分钟

交付可复核的工程基线

交接的不只是绿灯，而是别人能重做的判断

为什么这课重要？

下一位同事拿到 PR，看到「6/6 通过、p95 100 ms、草稿流程上线就绪」。这句话把数据、推断和承诺混到了一起。六条是合成的受控场景，100 ms 来自账本，不来自时钟；检查点和提交重放成功也只发生在临时 SQLite。可靠的交接应该让对方能复现判断、知道它没证明什么，再决定哪些线上验证必须另做。

  • 交付可复跑的报告、独立脱敏轨迹样本和架构决策；每份证据注明来源。
  • 同版本做一次绿→红→绿回归，提交用例、字段、动作效果和恢复证据，而不是只交一张截图。

1. 把交接包拆成三份独立证据

证据最小形状能够复核什么
门禁复验baseline/regression/restored 各有 exit_code/report；报告带逐案效果、度量版本和失败字段，另附独立评估集的重复试验摘要独立金标能抓到缺引用，恢复后同口径再次通过；重复试验不是门禁六条的重复计分。
脱敏轨迹样本本地接收器的合成 task_id/trial_id/trace_id、投影版本、终态、阶段名和秒数接收器可读与投影结果可看，不代表这个 trace 记录了门禁里某次实际草稿保存。
设计决定case_id、方案、停止／恢复策略、写入归属、取舍、复议条件为什么用宿主管理审批的 workflow；若有受限自适应取证也只是只读候选，不继承写权。

复跑 handoff.py 会调用三次真实本地门禁。基线与恢复须一致；故意只去掉保留期引用时仍显示七天，实际报告却给出 retention.citations。和预期的红比对比「有非零就行」更强：程序崩溃、缺文件不能当质量门抓到回归。恢复在这里是回到基线代码路径，不修改阈值，也不宣称修复了线上故障。

inputs 按门禁、评估、遥测、设计、交接列出相对路径和 SHA-256；每组还有整组指纹。三次门禁都必须报告同一组指纹。文件内容在计算前把文本换行统一，避免 Windows 和 Linux 的检出差异；修改一条金标仍应改变指纹。它只证明清单中的代码和夹具一致，不证明解释器、系统状态或运行结果相同。轨迹的 projection_version 表示本地字段约定，otel_genai_version 是参考的语义版本，两者分开记录。

批准草稿用的是同步时间。报告里的 Phase 7 精确证据是 SYNC-POLICY v1 §1，Phase 5 草稿存的旧编号是 KB-03。本地流程在批准保存前核对事实和约定的来源对应，不声称两个系统共享文档模型。持久效果由写入观察者和独立重开查行报告；遥测附件起自另一个固定试验。遇到真实故障应通过同一任务、试验与轨迹 ID 去关联，不能靠事后拼相似的名字。

2. 给下一位维护者一个能执行的决定

保留期的一次授权查询可以直接用函数；同步草稿要停在待审、否决或按回执恢复，因此选择确定性 workflow，保存权留给持有当前批准的宿主。遇到证据分支不可预知，只有在受限授权读取、预算、失败交接和同负载评估都成立时，才单独考虑有界 Agent。更灵活不改变编辑、审批和持久化的权力归属。

交班里具体写「先验证测试环境身份映射与真实 scope；再核对受控样本质量和已知账单；然后在固定并发与冷暖条件下测队列及端到端延迟；演练故障恢复并核对真实回执」。每项都要有负责人、环境和通过门槛。只有实验通过而没有环境检查，应标记为「本地基线可复跑，生产准入未判定」。

评审者如果读到「恢复均成功」，先从 restored.report.by_case 找 lost-response：检查点仍是 saved，首次批准分发 1、恢复调用 1、整体写入 1、已存行 1、重放写入 0、回执相同。若查到两行，即使最终回答相同也必须阻断；若轨迹样本显示成功但该案没有回执，按真实效果观测排查，不拿另一次的轨迹补证。评审记录可以压成「场景 → 观察 → 限制 → 下一项验证」，不写一个宽泛的「通过」。

决策卡：事实、验收结果和上线资格分开

适用：将一个本地可验证的 Agent 功能交给评审者。边界：课程只交合成证据与后续计划。

误判：有图有绿灯就齐了

粘一张报告，把另一个试验的 trace 叫作同案证据。

选择：给出版本与复跑路由

列命令、结果、影响范围、独立附件与未验事项，并记录错误恢复。

代价：多维护三个小证据；换来能诊断回归、能复查责任、也不会误读为上线批准。

  1. 先跑基线，再让一个已知缺陷出现，保存具体失败字段与退出码。
  2. 恢复同口径后复核数据与硬门槛，再附上标明来源的轨迹和设计记录。

门槛：0 → 1 → 0，并证实是目标回归；来源与未测项不省略。

Q 合成 trace 有工具阶段，但来自另一条本地试验。交接如何处理？
同在本地不表示同次执行。独立附件能够验证字段投影，不能替代本案的写入或回执。

面试自查

先说范围，再给证据，最后说何时复议。

Q1团队说「绿灯、已经解决可靠性」，你怎么看？

参考回答：列出本地六条任务的含义，并确认引用故障确实红过、恢复同版本又绿；结论只覆盖本地合同。

追问：报告没附失败字段怎么办？

答题要点：仅凭非零不能区别业务阻断和环境异常，要求复跑并保留具体字段差异。

Q2审批草稿和普通问答共用 UI，一定要用 Agent 吗？

参考回答：问答现有授权函数足够，草稿需暂停和恢复，用 workflow；批准留给宿主。

追问：后来常出现未知的证据分支？

答题要点：用失败样本衡量有界只读方案的增益；不改变写入边界。

Q3草稿提交后没回执，观测平台显示「执行失败」，该重发吗？

参考回答：先基于稳定操作 ID 检查业务回执，区分提交后的丢回复和真正回滚；轨迹不替代存储状态。

追问：外部系统既没有幂等键，又查不到回执？

答题要点：标记结果未知，停下等待人工对账；本地 SQLite 不能替外部系统许诺恰好一次。

Q4另一部门要用本地 100 ms 预算填上线 SLA，怎么制止误用？

参考回答：把合成阈值和真实负载目标分列；后者需定义入口、并发、失败和等待条件，在测试环境重新测量。

追问：某些线上请求没返回 usage，还能直接比较成本吗？

答题要点：先做账本覆盖率与未知试验标记，不默认记零；不能无条件比较。
