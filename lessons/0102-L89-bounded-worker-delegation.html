单 Agent 与 Orchestrator–Worker 对照

只委托一次只读取证；看交接和归并成本是否真的换来收益

为什么这课重要？

L88 的全批结论是保留 workflow。本选修不是推翻它，而是在团队已使用单 Agent 来选证据的假设下，检验「把附录交给专门 worker」是否有独立收益。只复用 L88 的三条过期请求（正常、缺权、超时），因为这三条才可能到达委托点；不能删掉两个失败，也不能把不会委托的常规查询加入本组稀释代价。

学习目标

  • 把选路、派工、读权限、归并与人工接管分开，写出可验证的最小交接。
  • 用同批的精确事实、授权、分发与预算证据，判断不采用委托何时才是正确选项。

1. 同一个选择者，只替换第二次读的路径

单 Agent 基线就是 L88 的 single：选择并读取主政策，再按原文选择附录，直接请宿主读。编排者用同样的本地选择器，但把第二次读封装成一次 worker 调用；它不把新目标交给 worker 自行探索。worker 是同进程 Python 函数，不是独立模型、线程、子进程或远程服务。它只有一个可用一次的读回调：不能换键、换租户、指定调用者身份、访问数据库句柄、写入或再委托。这个能力约束描述课程中的调用接口，不是能运行不受信任代码的沙箱。

正常过期任务的派工与归并边界
位置数据形状与检查
派工输入{case: "expiry", actor: ("support", "mei"), key: ("EXPORT-OPS", 1, "§2"), max_reads: 1, credits: 3}。由宿主绑定比对；credits 是最坏读预留、不是额外额度。缺字段或换主体，在分发前拒绝这次委托。
worker 读回调只接收指定键，最多进入一次读分发；实际仍用 L88 的 EvidenceStore.source(tenant, user, key) 同一授权查询。support/lin 看不到附录，不会退到另一身份。
结果归并归还任务绑定和附录证据元组；宿主对照刚才实际读取的回执（作用域、键、原文），相等才与主政策拼接。正常交付按顺序引用 EXPORT-POLICY/v1 §1「导出文件生成后保留 7 天。」与 EXPORT-OPS/v1 §2「导出文件过期后，需重新发起导出。」
失败接手无权、超时、缺字段、归并不符或不够预算都不能返回半份答案。保留已发生的调用，只交本地人工工单替身；不补读、不切租户、不补预算。

三条案型、每条的 (tenant, user)、事实与停止金标和 12 积分 / 2 次读 / 1 次 worker 都不变。宿主在派工前从剩余额度预留最坏读取、worker、归并和人工工单；额度不是由下游自己申报消耗。一次 worker 算 1 分／4 模拟毫秒，一次归并算 1 分／2 模拟毫秒。worker 已启动后若读超时，归并没有发生：worker 和失败读照样入账，不能把未达归并的一段也算进去。

2. 先抓遗漏，再看是否有净收益

正常案型增加 worker 与归并各一次，缺授权和超时各只增加一次 worker。两臂的精确证据和授权读序列完全相同；候选多 4 分，尾部多 4 模拟毫秒。两次失败也入账，所以每正确答复为 21 分与 25 分，不是仅给成功那一条计费。最近秩 p95 对全批计算，三条时就是超时那条。先独立核对精确答复、实际读与事件，再按独立价表检查逐笔积分、模拟毫秒、总计和预算。计量出错不会把正确答复变成错答；基线账本不过关须停止复核，只有候选不过关则不采用候选。

当前两臂通过合同，但委托没有净收益；即便在 单 Agent 已在用 的假设下也应保留它。独立测试还给候选一个更快的尾时、同时增加总成本，检查当前决策规则仍拒绝候选；实际产品阈值须在测量前约定。

故障注入时，按分发前、读取时、归并后分别找证据
只改变一项现象和诊断
丢掉派工积分字段，或把主体换成运维invalid_handoff；先前读主政策算一次，随后零 worker、零附录读；不能让 worker 靠默认值补齐。
交回空证据、改附录版号或换结果主体invalid_worker_result；worker 和附录读已经发生，归并发现遗漏、来源或主体不符，停止、不外发。
同一个 worker 重复使用读回调read_lease_denied；第二次调用回调被拒绝，不产生第二次附录分发或归并。
两臂同降为 9 分单 Agent 仍可答；委托在派工前 budget_exhausted。即使事后看到成功读只花 2 分，也不能取消事前最坏预留。

决策卡：有可测的瓶颈，才切出读子任务

适用：同一单 Agent 负载确有可隔离、可独立验收的读瓶颈。不适用：为了显得并行，或让第二个角色补第一臂没有的权限。

误判：先派工，再靠归并修错

只看最终有无答案，让遗漏的作用域、额外读取或失败分发藏在报告里。

选择：先约束能力，再过净收益门

派工前验证绑定、预算与次数，归并时对真实读取回执，没改善就不采用。

  1. 冻结同批正负例；先跑 L88 原单 Agent，不写一个更弱的基线。
  2. 核对工单遗漏、来源错配、绝对用量和超成本，再查分发增量是否换来目标改善。

复议：只有新增一种有独立边界的附录任务，在固定预算下补齐可授权证据或降低开销，再用回归证据支持试用。本课不验证并行速度、外部互操作或生产权限。

Q 同批结果和实际授权读取完全相同，但委托多 4 分，尾时也多 4 毫秒。当前怎么选？
当前没有覆盖、成本或尾时的净收益。两臂换不同预算或剔除失败都破坏对照。

面试自查

每题先说判断和责任人，再说需要哪笔证据。

Q1 worker 返回准确文字，但工单里的主体不对，可以归并吗？

参考回答：不能；派工前就应该拦截，若结果的主体不符也不能归并。

追问：另一个主体碰巧能读同一本政策呢？

答题要点：个人和租户授权不能互换；只接受本任务授权视图里实际读到的回执。

Q2 告诉 worker「最多读一次」就足够吗？

参考回答：不够；由宿主提供一次性回调并检查固定键，重复调用在读前拒绝。

追问：复用失败后怎样证明没有多读？

答题要点：既看实际读适配器的事件，也对 SQLite 授权查询入口计数；不能只看 worker 自报。

Q3 只返回一条证据但最终交人工，能说这条案子零取证成本吗？

参考回答：不能。已进入的 worker、读与失败归并按各自事件计算；交人工也要计量。

追问：怎么与派工前就被拦住的案子区分？

答题要点：后者没有 worker 与附录读事件，但可能已经读主政策，分别查分发边界。

Q4 在这个本地实验加快了某个成功样本，值得部署协作吗？

参考回答：不够；要审同批覆盖、授权、预算、总成本、全量 p95 与维护代价。

追问：什么时候才到下一课的 A2A？

答题要点：只有确需不同系统之间互操作才评估协议；同进程的职责拆分或读瓶颈不自动产生远程需求。

小结与一手参考

交接是有绑定、预算与结果的读合同，不是复制整个任务。当前同批没有净收益，保持单 Agent 对照，不把本地函数委托当成远程执行。

  • Anthropic · Building effective agents：Orchestrator–Worker 模式用于不能提前写死子任务的场景；不要求所有团队都采用。
  • Python 3.11 · unittest：把正控与各条负对照写成可回归的检查。
  • L75 工具与权限边界：授权必须由实际分发宿主实施。
