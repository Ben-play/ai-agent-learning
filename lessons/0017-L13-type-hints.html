类型提示系统

给代码标注类型 — Agent 的工具签名、状态、配置，靠它才严谨可查

💡 为什么这课重要？

类型提示是"写给人和工具看的契约"。标注清楚后，IDE 能自动补全、mypy 能在运行前抓出类型 bug，队友一眼看懂参数该传什么。

更关键的是：下一课 Pydantic、以及 L11 的 @tool，都读取你的类型注解来生成工具 Schema。类型标不准，Schema 就不准，LLM 就会传错参。这一课打好类型基础。

※ 泛型 Generic/TypeVar、结构化子类型 Protocol 属进阶，放到 Phase 5（Agent 状态管理）需要时再深讲，本课聚焦最常用的部分。

学习目标

完成本课后，你将能够：

  • 给变量、参数、返回值加基本类型标注
  • 用 Optional 表达"可能为 None"
  • 用 Union 表达"多种类型之一"
  • 用 Literal 约束稳定、封闭的有限取值（如 Role / ToolMode / OutputStyle）
  • 用 Callable 标注函数参数、用类型别名简化复杂类型，并会阅读/使用 mypy 报错且知道如何运行它

1. 基本标注

def build_prompt(role: str, max_tokens: int = 100) -> str:
    return f"[{role}] limit={max_tokens}"

name: str = "search"
temperature: float = 0.7
tools: list[str] = ["search", "calc"]           # 3.9+ 可直接用内置泛型
config: dict[str, int] = {"max": 5}

注意：类型注解本身不会在调用边界拒绝错误类型——Python 不会仅因实参与注解不符就自动报错；但函数体随后对该值执行的操作仍可能抛出 TypeError 等运行时异常。真正按注解抓错的是 mypy 这类静态检查工具，以及 IDE 的实时提示。要在调用边界做运行时强制校验，得用 Pydantic（下一课）。

💡 面试常见问题：

"类型提示会在运行时强制类型吗？"

答：不会。它是给静态检查器（mypy）、IDE 和运行时内省工具看的元信息；注解本身不会在调用边界拒绝错误类型，但函数体仍可能因不支持该值而报错。要按注解做运行时校验用 Pydantic。

2. Optional：可能是 None

from typing import Optional

def find_system_prompt(role: str) -> Optional[str]:
    # 返回 str 或 None
    return "你是助手" if role == "system" else None

# Optional[str] 完全等价于 Union[str, None]
result = find_system_prompt("user")   # 可能是 None，用前要判断
if result is not None:
    print(result.upper())

Optional[X] 就是"X 或 None"。Agent 里大量字段可能缺失（工具可能没返回、配置可能没设），用 Optional 明确标出来，提醒调用方"记得判空"。

Q Optional[str] 等价于下面哪个？
Optional[X] 是 Union[X, None] 的简写，表示"值可能是 X，也可能是 None"。它不代表"参数可省略"（那是默认值的事），只表示类型里包含 None。用它提醒调用方判空。

3. Union & Literal

Union：多种类型之一

from typing import Union

def to_text(x: Union[str, bytes]) -> str:
    return x.decode() if isinstance(x, bytes) else x

# 3.10+ 也可写成 str | bytes（更简洁）
def size(x: str | list) -> int:
    return len(x)
🔑 别被两种写法搞混：| 就是 Union 的新写法。

你会在代码里看到两套等价写法并存，它们含义完全一样，| 只是 Python 3.10+ 的简写：

老写法（需 import）新写法 |（3.10+，推荐）含义
Union[str, bytes]str | bytesstr 或 bytes
Optional[str]str | Nonestr 或 None
Union[int, str, None]int | str | None三者之一

所以 Optional[X]、Union[X, None]、X | None 是同一件事的三种写法。新代码优先用 |（不用 import、更短）；读老代码时认得 Union/Optional 即可。

Literal：只能是这几个值

from typing import Literal

Role = Literal["system", "user", "assistant"]
ToolMode = Literal["auto", "required", "none"]
OutputStyle = Literal["short", "detailed"]

def run(role: Role, mode: ToolMode, style: OutputStyle) -> None:
    ...

run("user", "auto", "short")       # ✅
run("admin", "auto", "short")      # ❌ mypy：非法 Role
🔑 Agent 开发关联：

Literal 适合消息角色、工具模式、输出风格等稳定封闭集合。模型目录、插件名等会动态增长的开放集合应保留为 str，由配置或 registry 校验。Literal 只有在 Schema 转换器支持时才会导出 enum：L11 的四原子类型简易生成器并不支持；L14 的 Pydantic 可以导出 enum，并在运行时校验。

最佳实践：Literal 描述封闭内部状态，不可信边界显式解析

适用：消息角色、固定策略、协议动作等封闭、稳定、规模小的字符串集合。不适用：插件名、用户自定义标签、频繁新增的模型名等开放集合；这类值通常保留为 str，由配置或注册表决定。若值还需要运行时身份、行为和遍历能力，可用 Enum；若整份外部数据都要解析校验，可在下一课用 Pydantic。

❌ 裸 str，或误以为注解会运行时强制
def set_mode(mode: str) -> str:
    return mode

set_mode("requried")  # 注解本身不拒绝；该函数体会原样返回

str 没列出合法状态；即使改成 Literal，普通 Python 函数也不会仅凭注解自动拒绝非法值，但函数体仍可能因不支持实际值而报错。

✅ Literal 描述内部契约 + 边界显式解析
from typing import Literal, cast

Mode = Literal["auto", "required", "none"]

def parse_mode(raw: str) -> Mode:
    if raw not in ("auto", "required", "none"):
        raise ValueError(f"非法 mode: {raw!r}")
    return cast(Mode, raw)

内部函数接收收窄后的 Mode；环境变量、JSON、CLI、LLM 输出先经过 parser。

为什么更优：Literal 把允许的内部状态记录为明确元数据，供读者、IDE 与静态检查器使用；本卡自检证明元数据与 parser 同源，而课末锁定 mypy 验收再证明静态拒绝。显式 parser 则守住不可信运行时边界。代价是合法值变化时要同步类型、解析器、Schema、文档和测试，可用 get_args 复用一份允许值来减少漂移。开放集合应由配置、注册表或普通 str 承载；需要带行为的封闭集合可选 Enum，复杂外部对象的运行时校验可交给 Pydantic。

自检：证明 Literal 是元数据，非法值仍能运行，而 parser 会拒绝
from typing import Literal, cast, get_args, get_type_hints

OutputStyle = Literal["short", "detailed"]


def render(style: OutputStyle) -> str:
    return f"style={style}"


def parse_output_style(raw: str) -> OutputStyle:
    allowed = get_args(OutputStyle)
    if raw not in allowed:
        raise ValueError(f"unsupported style: {raw!r}")
    return cast(OutputStyle, raw)


allowed = ("short", "detailed")
assert get_args(OutputStyle) == allowed
assert get_args(get_type_hints(render)["style"]) == allowed

# 注解仍被普通函数保存为元数据，但 Python 不自动执行校验。
assert render("verbose") == "style=verbose"

try:
    parse_output_style("verbose")
except ValueError as exc:
    assert "verbose" in str(exc)
else:
    raise AssertionError("边界 parser 应拒绝非法值")

assert render(parse_output_style("short")) == "style=short"

结果诊断：退出码为 0 且断言无失败即通过，本自检只用 Python 运行时内省，不依赖也不冒充 mypy。元数据断言失败，说明注解或允许值已漂移；render("verbose") 若被自动拒绝，说明测试前提不再是普通函数；parser 未抛 ValueError，说明不可信边界没有真正收口；合法值失败，则校验与内部契约不同步。

4. Callable & 类型别名 & mypy

前面标注的都是"数据"的类型。这一节收尾三样更进阶的工具：Callable（把函数本身也标注出类型——Agent 里工具就是函数，得能描述它）、类型别名（给又长又重复的类型起个短名）、以及 mypy（把类型检查真正跑起来，在运行前抓错）。

Callable：把函数当参数

from typing import Callable

# Callable[[参数类型...], 返回类型]
def apply(fn: Callable[[int], int], x: int) -> int:
    return fn(x)

apply(lambda v: v + 1, 41)     # 42

# Agent 场景：工具就是"接收 dict、返回 dict"的可调用体
ToolFn = Callable[[dict], dict]

类型别名：给复杂类型起名

from typing import TypeAlias

# 一长串类型写多遍很啰嗦，起个别名
Messages: TypeAlias = list[dict[str, str]]

def run(history: Messages) -> Messages:
    return history + [{"role": "assistant", "content": "ok"}]

mypy：用课程项目的锁定工具运行

# 从仓库根执行；--directory 固定项目发现，--locked 禁止锁文件漂移：
uv --directory code/phase1-python/part-a-basics/agent-hello \
  run --offline --locked mypy your_file.py
# 它会诊断“传了 str 给需要 int 的参数”“可能为 None 却没判空”等问题

课程项目已在 [dependency-groups].dev 声明并锁定 mypy。把静态正例、静态负例与运行时实验分成不同文件：正例应得到 Success: no issues found，负例应出现预期的 Literal/Optional 错误；运行时实验则单独用锁定 Python 执行，不能用其中故意违反类型契约的调用要求 mypy clean。--offline 保证验收不访问网络，前提是锁定包已在本机缓存/环境中可用。

Q Literal["a", "b"] 类型的作用是？
Literal 把类型收窄到指定的几个具体值（这里只能是 "a" 或 "b"）。传别的值 mypy 会报错。适合 role、工具模式、输出风格等稳定封闭集合；动态模型目录、插件名等开放集合通常用 str 配合配置或注册表。

知识图谱

基本标注 → 参数/返回/变量；注解本身不在调用边界拒绝实参
├── list[str] / dict[str, int]（3.9+ 内置泛型）
└── 函数体仍可能因错误类型报错；边界校验用 Pydantic(L14)

Optional[X] = Union[X, None] → 可能为 None，提醒判空
Union[A, B] / A | B(3.10+) → 多种类型之一
Literal["x","y"] → 稳定封闭集合（role/工具模式/输出风格）；动态模型目录用 str + registry
Callable[[参数], 返回] → 函数作参数（工具 = ToolFn）
TypeAlias → 给复杂类型起名

mypy → 静态检查，把类型错误挡在运行前
（Generic/TypeVar/Protocol 进阶 → Phase 5）

任务清单

  1. Role：用 Literal 定义为 system/user/assistant
  2. make_message(role, content)：role 用 Role，返回 dict[str, str]
  3. get_tool(name)：按名字查工具，可能查不到 → 返回 Optional[Callable[[dict], dict]]
  4. truncate(x, n)：x 标注为 str | list，返回值也标注 str | list，取前 n 项（注意：这个注解只表达"输入输出都是 str 或 list 之一"，不表达"传 str 就一定返回 str"这种关联——运行时切片确实会保持原类型，但 str | list 这套基础注解本身描述不出这层关联，见下方说明）
  5. 用 typing.get_type_hints 查看运行时元数据；再用课程项目已锁定的 mypy 检查独立静态正例与负例
🔑 老实说：str | list -> str | list 表达不出"同类型"

看下面这段：

def truncate(x: str | list, n: int) -> str | list:
    return x[:n]

truncate("hello", 3)      # 运行时确实返回 'hel'（str）
truncate([1,2,3,4], 2)    # 运行时确实返回 [1,2]（list）

x[:n] 这行代码本身、在运行时，切片操作确实会保持容器类型（str 切片还是 str，list 切片还是 list）——这是 Python 语言行为，不是类型注解带来的。

但 str | list -> str | list 这个类型签名，只是分别声明"参数可能是 str 或 list 之一""返回值可能是 str 或 list 之一"，它没有能力表达"这两者必须是同一种"。可以先用运行时内省查看注解元数据：

from typing import get_type_hints
print(get_type_hints(truncate))
# {'x': str | list, 'n': <class 'int'>, 'return': str | list}

get_type_hints 是运行时内省，这里只展示函数保存的注解元数据，不能代替 mypy 静态检查。mypy 会读取同一个签名；按类型系统语义，参数和返回值是两个独立的 Union，因此它也无法从这个签名推出“传 str 进去就一定拿到 str”。课程项目已把 mypy 声明为锁定开发依赖；从仓库根用 uv --directory code/phase1-python/part-a-basics/agent-hello run --offline --locked mypy your_file.py 运行，静态检查证据应与运行时实验分开保存。

要让静态检查器保留这种"输入决定输出"的关联，可以使用合适的受约束 TypeVar，也可以为各输入类型编写 overload；PEP 695 泛型函数语法则能用新语法表达相应的泛型关系，并不要求把 TypeVar 与 overload 组合使用。具体写法放到 Phase 5（Agent 状态管理）需要精确类型推断时再讲；这里先如实说清楚基础 Union 注解的局限，不要求你现在实现。

from typing import Optional, Literal, Callable

Role = Literal["system", "user", "assistant"]
ToolFn = Callable[[dict], dict]

def make_message(role: Role, content: str) -> dict[str, str]:
    return {"role": role, "content": content}

_TOOLS: dict[str, ToolFn] = {
    "echo": lambda args: args,
}

def get_tool(name: str) -> Optional[ToolFn]:
    return _TOOLS.get(name)          # 查不到就是 None

def truncate(x: str | list, n: int) -> str | list:
    return x[:n]


msg = make_message("user", "你好")
print(msg)                           # {'role': 'user', 'content': '你好'}

tool = get_tool("echo")
if tool is not None:                 # Optional → 必须判空
    print(tool({"q": "x"}))          # {'q': 'x'}

print(truncate("hello", 3))          # hel
print(truncate([1, 2, 3, 4], 2))     # [1, 2]

思考题

先自己想，再点开对答案。

Q1如果把 make_message("admin", ...) 交给 mypy，会发生什么？

【结论】mypy 会在运行前报类型错误："admin" 不在 Role = Literal["system","user","assistant"] 允许的取值里；但如果直接 python 跑，注解本身不会拒绝这次调用。本例函数体只把值放进 dict，所以会正常返回；其他函数体仍可能因错误类型而报错。

Role 是 Literal 类型，它把合法值收窄到那三个字符串。make_message 的第一个参数标注成 Role，等于告诉静态检查器"这里只接受这三个值之一"。传 "admin" 时 mypy 立刻标红。

但类型提示运行时不强制（这是 L13 的核心结论）：Python 解释器不会仅凭注解拒绝 make_message("admin", ...)；本例函数体能处理该字符串，因此会正常返回 {"role": "admin", ...}。若函数体执行了与实际值不兼容的操作，仍可能抛运行时异常。要在调用边界拦住非法值，得靠下一课的 Pydantic。

所以两者分工：mypy 在写代码/CI 阶段抓错，越早越省事；Pydantic 在数据进门时兜底，尤其面对不可信的 LLM 输出。

Q2这里的 Role、ToolFn 到 L14 会怎样变成 Pydantic 模型的字段类型？

【结论】同一个类型注解，在 dataclass/普通函数里只是"静态提示"，搬进 Pydantic BaseModel 后就变成"运行时强制的字段约束"——非法值会在创建实例时抛 ValidationError。

Role（Literal["system","user","assistant"]）可以直接当 Pydantic 字段的类型，例如 class Message(BaseModel): role: Role。这时传 role="admin" 不再只是 mypy 标红，而是运行时直接被拒——正好接住 LLM 可能吐出的非法角色。

ToolFn（Callable[[dict], dict]）主要是静态描述工具注册表中的调用形状。Pydantic 对 Callable 字段通常只检查值是否 callable()，不会验证参数列表和返回值真的匹配该签名；真正需要签名检查时应在注册阶段用 inspect.signature。

因此 L14 的重点是把工具参数数据建成 Pydantic 模型并校验/导出 Schema，函数对象仍由 registry 保存；不能把 Callable 注解说成完整的运行时函数契约。

本课最佳实践验收：把缓存策略守在运行时边界

换到不同领域的 CachePolicy = Literal["use", "refresh", "bypass"]：先保存一份可通过 mypy 的静态正例，再用独立负例核对预期 Literal 错误；运行时实验另行证明普通函数不自动校验，而 parser 才把外部字符串转换为可信内部值。

操作清单

  1. 定义三个缓存策略。
  2. 保存静态正例并运行 mypy。
  3. 用独立负例核对预期 Literal 错误。
  4. 单独运行 Python，证明注解不自动校验。
  5. 让 parser 拒绝非法值、合法值进入内部函数。
通过标准
  • 正例 mypy 无问题
  • 负例报告非法 Literal
  • 运行时元数据准确
  • 普通调用不自动校验
  • parser 拒绝非法边界输入
  • 运行时脚本打印 L13 ACCEPTED
课末自检（从仓库根运行；离线调用锁定 mypy）：
import subprocess
from pathlib import Path
from tempfile import TemporaryDirectory


project = Path(
    "code/phase1-python/part-a-basics/agent-hello"
).resolve()
assert (project / "pyproject.toml").is_file(), "请从仓库根运行"

module_source = '''from typing import Literal, cast, get_args, get_type_hints

CachePolicy = Literal["use", "refresh", "bypass"]


def fetch_document(policy: CachePolicy) -> str:
    return f"fetch:{policy}"


def parse_cache_policy(raw: str) -> CachePolicy:
    allowed = get_args(CachePolicy)
    if raw not in allowed:
        raise ValueError(f"unsupported cache policy: {raw!r}")
    return cast(CachePolicy, raw)
'''

ok_source = '''from cache_policy import fetch_document, parse_cache_policy

assert fetch_document("use") == "fetch:use"
assert fetch_document(parse_cache_policy("refresh")) == "fetch:refresh"
'''

bad_source = '''from cache_policy import fetch_document

fetch_document("stale")
'''

runtime_source = module_source + '''
# 运行时元数据与 Literal 定义保持一致。
hints = get_type_hints(fetch_document)
assert get_args(CachePolicy) == ("use", "refresh", "bypass")
assert get_args(hints["policy"]) == get_args(CachePolicy)
assert hints["return"] is str

# 普通 Python 不会仅因 Literal 注解自动拒绝实参。
assert fetch_document("stale") == "fetch:stale"
try:
    parse_cache_policy("stale")
except ValueError as exc:
    assert "stale" in str(exc)
else:
    raise AssertionError("运行时 parser 必须拒绝非法边界值")
print("RUNTIME OK")
'''

base = [
    "uv", "--directory", str(project),
    "run", "--offline", "--locked",
]
with TemporaryDirectory() as directory:
    evidence = Path(directory)
    (evidence / "cache_policy.py").write_text(
        module_source, encoding="utf-8"
    )
    ok = evidence / "cache_policy_ok.py"
    bad = evidence / "cache_policy_bad.py"
    runtime = evidence / "cache_policy_runtime.py"
    ok.write_text(ok_source, encoding="utf-8")
    bad.write_text(bad_source, encoding="utf-8")
    runtime.write_text(runtime_source, encoding="utf-8")

    lock = subprocess.run(
        ["uv", "--directory", str(project),
         "lock", "--check", "--offline"],
        text=True, capture_output=True,
    )
    assert lock.returncode == 0, lock.stderr

    positive = subprocess.run(
        [*base, "mypy", str(ok)], text=True, capture_output=True,
    )
    assert positive.returncode == 0, positive.stdout + positive.stderr
    assert "Success: no issues found" in positive.stdout

    negative = subprocess.run(
        [*base, "mypy", str(bad)], text=True, capture_output=True,
    )
    diagnostic = negative.stdout + negative.stderr
    assert negative.returncode != 0
    assert diagnostic.count("[arg-type]") == 1, diagnostic
    assert "stale" in diagnostic and "fetch_document" in diagnostic

    runtime_check = subprocess.run(
        [*base, "python", str(runtime)], text=True, capture_output=True,
    )
    assert runtime_check.returncode == 0, runtime_check.stderr
    assert runtime_check.stdout.strip() == "RUNTIME OK"

print("L13 ACCEPTED")

结果诊断：标准输出严格为一行 L13 ACCEPTED 即通过。锁检查失败表示依赖声明与 uv.lock 漂移；正例非零表示合法调用不符合静态契约；负例没有唯一 [arg-type] 或未提到 stale/fetch_document，说明最强的 Literal 静态收窄主张没有被证明；运行时脚本失败则表示“注解不强制、parser 守边界”的分工已漂移。三份临时证据彼此分离，并在结束时自动清理。

面试常见问题

Q1：Python 类型提示在运行时生效吗？

答：注解本身不会在调用边界强制类型。它是给 mypy/IDE 和运行时内省工具使用的元信息；传入不匹配的值后，函数体仍可能因不支持该值而报错。要按注解做运行时校验用 Pydantic。

Q2：Optional[str] 是什么意思？和"参数可省略"一样吗？

答：它等于 Union[str, None]，表示值可能是 str 或 None。和"参数可省略"（那由默认值决定）不是一回事。

Q3：Literal 有什么用？

答：把类型收窄到稳定、封闭的几个具体值，适合 role、工具模式、输出风格。动态模型目录或插件名应使用 str 配合配置/registry；普通 Python 调用不会仅因 Literal 自动校验。

Q4：怎么标注"接收函数作参数"？

答：用 Callable[[参数类型...], 返回类型]。例如工具函数是 Callable[[dict], dict]。装饰器、回调、策略注入都会用到。

总结

  • 类型提示是给人/工具看的契约，注解本身不在调用边界强制类型；函数体仍可能报错（边界校验用 Pydantic）
  • Optional[X] = Union[X, None]，标出"可能为 None"
  • Union[A,B] / A|B（3.10+）表达多种类型之一
  • Literal 收窄稳定封闭集合；动态模型目录等开放集合用 str + 配置/registry
  • Callable[[参数],返回] 是静态调用形状；Pydantic 通常只验证 callable，不验证完整签名
  • 会用课程项目锁定的 mypy 运行静态正负例并阅读诊断；Generic/Protocol 留到 Phase 5
