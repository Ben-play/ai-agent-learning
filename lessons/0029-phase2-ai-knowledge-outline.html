阶段 2 · AI 知识与模型选型

从"调 API 的人"升级为"懂 LLM 的人"——看透模型的本质、局限、选型与成本，覆盖 9+ 道面试高频题。

📚 共 3 个模块 · 8 课 ⏱ 预计 1.5 周完成
为什么 Phase 1 之后先学这个？
你已经能写健壮的 Python 了，但在真正搭 Agent 前，必须先看透手里这个 LLM 到底是什么：
· 不懂"概率预测"本质 → 调 temperature/top_p 只能靠玄学，还会误以为它在"检索事实"
· 不懂 Token → 算错成本、爆掉上下文窗口、被"中文更费钱"的谣言误导
· 不懂幻觉的成因 → 上线后被"一本正经胡说八道"反复打脸，不知道怎么治
· 不会选型/算成本 → 要么全用最贵的模型烧钱，要么用错模型质量不达标
先看懂模型，再驾驭模型。本阶段每一课都直接对应一道面试必答题。
Module 2.1 · LLM 本质与核心概念

抛开神秘感，把 LLM 拆成"下一个 Token 预测机"，并掌握你每天都在设的旋钮。

2.1

本质、Token 与生成参数

L17
LLM 本质与生成参数 AI 面试
语言模型本质（基于概率的下一个 Token 预测）、注意力机制直觉（不写代码）、Transformer 直觉；生成参数解密：Temperature（缩放分布）、Top-P（核采样裁剪）、frequency/presence 惩罚、不同任务的参数组合；反直觉真相：temperature=0 也不保证逐字节可复现（浮点非结合 + 硬件差异）
给同一个 Prompt 设不同 temperature/top_p，观察输出如何从"稳定"变"发散"，并为抽取/创作/代码三类任务各选一组参数
L18
Token 与 Tokenization 深入 AI 面试
Token 是子词片段（非字/词/字母）、BPE 算法与 byte-level 原理、中文 vs 英文 Token 差异（取决于分词器：同句中文 cl100k=11、o200k=5）、用 tiktoken 精确计数、Token 与成本关系（输出通常 3~5× 输入）
用 tiktoken 数自己的 system prompt，切换 cl100k / o200k 编码对比，再把 Token 数换算成 API 成本
Module 2.2 · 模型能力、局限与选型 面试重灾区

模型能做什么、做不到什么、怎么在几十个模型里选对——资深面试的核心战场。

2.2

幻觉、推理模型与能力边界

L19
幻觉全解（校准视角） AI 面试
什么是幻觉、为什么发生（校准视角：训练/评估激励"猜"而非"弃权"，见 OpenAI/arXiv《Why Language Models Hallucinate》）、检测方法（Self-Consistency / LLM-as-judge / 引用核查）、缓解策略（RAG / CoT / Self-Consistency，且无法根除）
为一个客服 Agent 设计幻觉检测方案——用多次采样一致性 + 要求引用来源，标注哪些回答高风险
L20
推理模型与 Extended Thinking AI 面试
标准模型 vs 推理模型、long CoT（先"想"再答）、Extended Thinking 与 thinking budget（用 Token 预算换推理深度）、何时用哪个（OpenAI 官方决策规则：简单明确用标准、困难多步用推理）、成本/延迟权衡、推理模型的提示词差异
给一批任务（抽取字段 / 解多步数学题 / 总结长合同风险）判断各该用标准还是推理模型，并说明理由
L21
模型能力边界与 Base vs Instruct AI 面试
Base Model vs Instruction-Tuned（指令微调 refine 执行/对齐，不显著增加知识）、RLHF 一句话；能做什么 vs 六大局限（知识截止、不擅精确计算、幻觉、上下文有限 + lost-in-the-middle、无持久记忆、不知私有/实时数据）→ Agent 如何用工具/RAG/记忆各个击破
给几个用户请求（今日股价 / 大数运算 / 记得我的偏好吗 / 总结刚上传的 PDF），指出各触碰了哪条局限、Agent 该用什么能力补
L22
看懂 Benchmark 与模型选型 AI 面试
MMLU-Pro（知识广度）/ GPQA（专家推理）/ SWE-bench（真实工程）/ ARC-AGI（抽象推理）各测什么、榜单为何失真（数据污染 / 过拟合 / 场景不匹配）、开源 vs 闭源权衡（自托管成本拐点）、可落地的选型决策框架（别信榜单信自建评测集）
为"处理敏感内部合同、预算有限、月调用量大"的 Agent 用决策框架给出选型建议（倾向开源自托管 + 自建评测集 + 成本核算）
Module 2.3 · Token 经济学

生产级 Agent 的必修课——把成本从"随便烧"变成"精打细算"，并综合实战收官。

2.3

成本工程与综合实战

L23
Token 经济学与降本杠杆 AI 面试
各主流模型价格对比（输出通常 3~5× 输入）、隐藏成本（历史累加 / system prompt 每次都算 / 工具循环）、成本计算公式、Token 预算制定；两大降本杠杆：Prompt Caching（缓存读 ~0.1×、写 ~1.25×，官方文档实锤）+ Model Routing（便宜模型兜底、贵模型只接难题），真实案例：缓存降本 59~70%、路由降本 40~85%；压缩历史 / 批处理
给定"2000 token 固定 system prompt + 每次 200 token 问题 + 300 token 回答、日 10 万次"，算不加缓存的日成本，再算 Prompt Caching 能省下哪部分、大致多少
L24
Phase 2 综合实战项目 综合
收官项目「模型体检报告」：整合 L17–L23——用 tiktoken 做成本估算、用 httpx + async 并发调多个模型做能力对比、用 Self-Consistency 做幻觉测试、汇总成综合报告（模型 × 质量 × 幻觉率 × 成本），并用选型框架给出结论
写一个脚本对同一批任务对比不同模型 + 幻觉测试 + 成本核算（含 Prompt Caching 前后对比），输出一份"模型体检报告"

学习建议

Module 2.1 打底——LLM 本质 + Token 是后面一切的地基，务必用 tiktoken 亲手数一遍，建立"Token=钱"的体感。
Module 2.2 是面试重灾区——幻觉成因（校准视角）、推理模型何时用、六大能力局限、benchmark 判读 + 选型框架，每一条都是资深岗必问。别死记结论，理解"为什么"。
Module 2.3 收尾——成本工程是生产级思维的起点（Phase 3 起会一直用"原生缓存优先 + 路由"），最后用 L24 把整个 Phase 2 串成一个能跑的项目。
