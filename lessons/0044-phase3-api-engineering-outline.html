阶段 3 · LLM API 工程实践

从"会调 API"到"能上生产"——把 LLM 调用做成健壮、可观测、低成本的工程系统，覆盖 14+ 道面试高频题。

📚 共 5 个模块 · 14 课 ⏱ 预计 3 周完成
为什么这是分水岭阶段？
"调通一次 API" 谁都会；但 Agent 在生产环境要面对：
· 模型会限流、会超时、会挂 → 不会退避+抖动+Fallback，一上量就崩
· 工具调用会重复执行 → 不会幂等，"扣款"重试一次就是真金白银损失
· 输出格式不可靠 → 不会Structured Outputs，下游代码天天崩
· 成本失控 → 不会缓存分层 + 路由，月账单翻几倍
· 线上出问题查不出 → 没有可观测性，Agent 上线即失控
这一阶段就是把这些"生产级"能力一个个补上。每课直接对应一道面试必答题。
Module 3.1 · API 基础

把三大厂商的 API 用一套心智模型拿下，并让回复像 ChatGPT 一样流式蹦出来。

3.1

调通 API 与流式输出

L2520min
主流 LLM API 上手 API
统一心智模型（messages: system/user/assistant，模型无状态需回传历史）、OpenAI Chat Completions / Anthropic Messages 两家 SDK 正确写法与差异（max_tokens、system 位置、返回字段）、OpenAI 兼容模式（base_url 切厂商）、Key 走环境变量铁律
用 openai / anthropic 两个 SDK 各发一次请求，对比返回结构；再用 base_url 兼容模式一套代码切厂商
L2635min
Streaming 流式输出 API
为什么要流式（降低首字延迟 TTFT、改善长回复体验）、原理是 SSE 逐块推送、OpenAI stream=True + delta.content 增量拼接、Anthropic messages.stream、工程注意（流式下的 usage 统计 / 增量拼工具调用 / 中途断连）
把一个非流式调用改成流式，逐 token 打印（打字机效果），处理 delta 为 None 的情况
Module 3.2 · 核心能力（Agent 必备）

让 LLM 能"用工具"、能"输出可靠结构"、能"看图听声"——Agent 的三大基础能力。

3.2

Function Calling · 结构化输出 · 多模态

L2735min
Function Calling 原理 Agent 核心 面试
关键澄清：模型自己不执行代码，只输出结构化的"调用意图"，执行+回填由你的代码做；完整流程（发工具定义 → 模型返回 tool_calls → 执行 → 回填 role:"tool" → 继续）、工具定义结构、tool_calls 里 arguments 是 JSON 字符串需 json.loads、多工具选择
设计一个"查数据库"工具的定义，说明模型会如何返回调用、你的代码如何解析参数
L2830min
Structured Outputs（约束解码） Agent 核心 面试
面试高频区分题：纯 prompt < JSON mode（只保证合法 JSON）< Structured Outputs（strict / 约束解码，token 级保证符合 JSON Schema）；约束解码原理、配合 Pydantic（呼应 L14）、无法保证时的验证+重试兜底、refusal 处理。Structured Outputs ≠ JSON mode
从一段用户评论抽取 {sentiment, score, keywords}，用 Pydantic 定义 schema，说明 Structured Outputs 如何保证输出可直接用
L2925min
多模态 API API
Vision 图片理解（image_url / base64 传图，放进 content 数组）、音频转录（Whisper 类）、隐藏成本：图片按分辨率折算成大量 token（呼应 L18/L23）、工程注意（大图先压缩、能力矩阵以官网为准）
写出"传一张本地图片（base64）问它内容"的 messages 结构，并估算图片的 token 开销
Module 3.3 · 工程实践（生产级） 生产必修

让调用"扛得住真实世界"——上下文管理、错误重试、高可用、可观测。

3.3

Context · 重试 · Fallback · 可观测性

L3025min
Context Window 管理 Agent 核心
窗口有限 + 越滚越长 + lost-in-the-middle + 成本随长度涨（呼应 L21/L23）；三大策略：滑动窗口 / 摘要记忆（compaction）/ 压缩精简；用 tiktoken 计数触发；保 system + 关键信息、压中间冗余
给"对话已到 8000 token、上限 8192"的场景，选择策略并重组 messages
L3140min
错误处理、退避与幂等 Agent 核心 面试
区分可重试（429/5xx/超时）vs 不可重试（400/401）、指数退避（呼应 L10 tenacity）、抖动（full jitter，防重试风暴/惊群）、重试预算、幂等键（idempotency key，让"扣款"这类有副作用的工具调用重试也只生效一次）
给"调扣费工具时超时、不知道扣没扣"的场景，说明幂等键如何让重试安全
L3240min
路由、Fallback 与 AI Gateway Agent 核心 面试
单点故障 → Fallback（主备模型自动切换）、Model Routing（便宜模型兜底、贵模型接难题，呼应 L23）、AI Gateway 模式（LiteLLM 自托管 / OpenRouter 托管 / Portkey 治理，统一成 OpenAI 格式，底层即 L25 兼容原理）、为什么用网关而非自己写
给"主模型突然 100% 返回 429"的场景，设计 Fallback + 路由策略
L3325min
LLM 可观测性 面试
三大支柱（Traces 调用链 span 树 / Metrics token·延迟·成本·错误率 / Logs）、要追踪什么（模型/token/TTFT/成本/工具/错误）、OpenTelemetry GenAI 语义约定（gen_ai.* span，厂商无关标准，semconv 已到 1.42）+ Langfuse、基于成本 metrics 设告警
列出"一次 Agent 任务该记录哪些 span 属性"，说明为什么用 OTel 标准字段而非自定义
Module 3.4 · 工具工程与 Function Calling P0 实战必修

工具是 Agent 的"手"——把工具设计、调用循环、健壮性、可扩展注册做扎实。

3.4

Tool Schema · FC 循环 · 健壮性与注册

L3435min
Tool Schema 设计 Agent 核心 面试
工具定义 = 模型的"说明书"，description 质量直接决定模型选不选得对、填不填得对；用 Pydantic/JSON Schema 定义、好 vs 坏 description 对比、enum/Literal 约束取值、strict mode（同 L28 约束解码机制）、工具定义的 Token 开销、设计原则清单
给"查订单状态"工具，用 Pydantic 写出参数 schema + 清晰的 Field description + Literal 约束
L3535min
完整 Function Calling 循环 Agent 核心 面试
把单步 FC（L27）跑成 while 循环——这就是 Agent Loop 的骨架：模型请求工具 → 执行 → 回填（带 tool_call_id） → 继续，直到无 tool_calls；并行工具调用全部执行各自回填（可 asyncio.gather 提速）、多轮 vs 并行之别、设最大轮数防死循环
给"查天气再据此推荐穿搭"（需两步）的场景，说明循环会怎么跑几轮
L3640min
工具健壮性与注册系统 Agent 核心
健壮性：参数校验失败把错误回填给模型让它重试（不崩）、流式下增量拼接工具调用参数、工具定义的 Token 开销控制；Tool Registry：用装饰器（呼应 L11）自动注册+分发，闭合 Phase 1「手写 @tool」线，看懂框架 @tool 底层
写一个 @tool 装饰器骨架，说明它如何自动收集函数名+参数 schema 并登记到 registry
Module 3.5 · 成本工程与综合实战

把成本从"随便烧"变成"精打细算"，并用一个项目串起整个 Phase 3。

3.5

缓存分层降本 · 综合实战

L3730min
成本工程：2026 降本优先级 面试
按性价比排序的完整清单：① 原生 Prompt Caching（前缀逐字节命中）→ ② 语义缓存（按 embedding 相似度命中、跳过整次调用，与前缀缓存的区别是面试高频题） → ③ 模型路由 → ④ 提示压缩（LLMLingua）→ ⑤ 小模型蒸馏 → ⑥ Batch API；组合心法「原生缓存优先」
给"客服 Agent 大量重复相似问题"场景，说明为什么语义缓存比前缀缓存更省，以及误命中的阈值风险
L3845min
Phase 3 综合实战 综合
收官项目「生产级多模型 Agent 客户端」：整合 L25–L37——统一客户端（L25/L32）+ 重试+Fallback（L31/L32）+ 完整 FC 循环（L35/L36）+ 结构化输出/流式（L28/L26）+ 成本追踪/可观测（L33/L37），构建一个"能上生产的 LLM 调用层"
写一个多模型 Agent 客户端：流式 + FC 循环 + 结构化输出 + 退避重试 + Fallback + 缓存 + 成本追踪

学习建议

Module 3.1–3.2 打基础——先把 API 调通、流式、Function Calling、Structured Outputs 拿下，这是后面一切的地基。Structured Outputs 与 JSON mode 的区别务必讲清（面试必问）。
Module 3.3 是生产分水岭——退避+抖动、幂等、Fallback、可观测性，每一条都是"demo 能跑"和"敢上生产"的差距。幂等和抖动是资深护城河。
Module 3.4 是 Agent 命脉——Tool Schema 设计 + FC 循环（Agent Loop 骨架）+ 工具注册，学完你能看懂 LangChain 等框架 @tool 的底层。
Module 3.5 收尾——成本工程（缓存分层）是生产必修，最后用 L38 把整个 Phase 3 串成一个能跑的客户端。
