阶段 3 · LLM API 工程实践

从调通 API 到可验收的调用与执行骨架：原生接口、工具边界、终态、评估与负载驱动成本决策。离线通过不等于生产准入。

📚 共 5 个模块 · 14 课 · 605 分钟 ⏱ 预计 3 周完成
为什么这是分水岭阶段？
"调通一次 API" 谁都会；但 Agent 在生产环境要面对：
· 模型限流与超时 → 区分单次等待、任务截止、安全重试和合格回退
· 工具可能重复执行 → 先核对审批、操作身份和真实持久效果
· 响应形状不可靠 → 用终态守卫、Schema 和宿主验证分层处理
· 成本或延迟上升 → 比较同批成功任务和完整账本，再采用缓存或路由
· 出错难定位 → 用受控追踪定位请求、分派和终态，不采无关正文
每课以可操作验收收束。本地通过不代替线上验证。

Module 3.1 · API 基础

复用业务目标，分别理解 Responses、Messages 与 Chat Completions；不把接口兼容误当能力等价。

3.1

调通 API 与流式输出

L2535min
主流 LLM API 上手 API
OpenAI Responses 新项目实践、Anthropic 原生 Messages、Chat Completions兼容基础；输入/事件/终态/usage与手动或服务端状态管理，显式Adapter和凭证边界
先完成离线接口辨认验收；可选在线对比需确认预算，并记录模型/API/SDK版本、终态与usage
L2645min
Streaming 流式输出 API
区分 Chat delta、Responses typed events、Messages内容块；文本临时显示≠成功完成，按终态/异常验收、关闭流资源并处理未知用量
把一个非流式调用改成流式，逐事件打印（chunk不等于token），处理 delta 为 None 的情况

Module 3.2 · 核心能力（Agent 必备）

让 LLM 能"用工具"、能"输出可靠结构"、能"看图听声"——Agent 的三大基础能力。

3.2

Function Calling · 结构化输出 · 多模态

L2735min
Function Calling 原理 Agent 核心 面试
以 Responses 自定义函数为主：模型提出调用，应用授权、校验并执行，按 call_id 回填；Chat Completions 只作兼容对照。
离线验证正常参数得到对应 function_call_output，坏参数和越权得到受控错误。
L2845min
Structured Outputs（约束解码） Agent 核心 面试
面试高频区分题：纯 prompt < JSON mode（只保证合法 JSON）< Structured Outputs（strict / 约束解码，在受支持Schema、正常完成且无拒答/截断时约束结构）；约束解码原理、配合 Pydantic（呼应 L14）、无法保证时的验证+重试兜底、refusal 处理。Structured Outputs ≠ JSON mode
从一段用户评论抽取 {sentiment, score, keywords}，用 Pydantic 定义 schema，说明结构约束的范围与拒答/截断、授权和业务校验
L2945min
多模态 API API
Responses 的 input_image / input_file；直接读 PDF 不等于 RAG。保留文件转录，实时语音为选读；按模型和 detail 核算图像费用。
区分图片与 PDF 的请求结构，并说明怎样验证该模型的输入用量。

Module 3.3 · 工程实践（生产级） 生产必修

让调用"扛得住真实世界"——上下文管理、错误重试、高可用、可观测。

3.3

Context · 重试 · Fallback · 可观测性

L3045min
Context Window 管理 Agent 核心
窗口有限 + 越滚越长 + lost-in-the-middle + 成本随长度涨（呼应 L21/L23）；三大策略：滑动窗口 / 摘要记忆（compaction）/ 压缩精简；使用目标模型专用计数接缝；按完整工具交互组重组、保留信任边界，预留输出并在压缩后复算，不可容纳时明确失败
给"对话已到 8000 token、上限 8192"的场景，选择策略并重组 messages
L3145min
错误处理、退避与幂等 Agent 核心 面试
区分安全重试与瞬态错误、退避与抖动、单次超时和整项截止。稳定操作键由执行端兑现；外部结果未知时先查证。
用假时钟核对各次剩余预算，用 SQLite 验证提交前回滚、提交后读回及同键不同请求被拒绝。
L3230min
路由、Fallback 与 AI Gateway Agent 核心 面试
先筛工具能力、数据范围与共享依赖，再按成本路由；临时失败后仅切换可安全重放的合格路线，网关按复用和治理需求采用
用离线调用轨迹验证合格切换、无路线及未知写入；独立判断共享配额的备选是否值得保留
L3345min
LLM 可观测性 面试
区分 trace、metric 和 log；以 OpenTelemetry GenAI 独立版 v0.1.0（Development）核对字段与单位，默认只采元数据。成本从 usage 和费率推导，不把未知记作零。
给一次模型调用选择遥测字段，核对指标名称、单位和正文采集边界；真实后端另验。

Module 3.4 · 工具工程与 Function Calling P0 实战必修

工具是 Agent 的"手"——把工具设计、调用循环、健壮性、可扩展注册做扎实。

3.4

Tool Schema · FC 循环 · 健壮性与注册

L3445min
Tool Schema 设计 Agent 核心 面试
工具定义 = 模型的"说明书"，description 质量直接决定模型选不选得对、填不填得对；用 Pydantic/JSON Schema 定义、好 vs 坏 description 对比、enum/Literal 约束取值、strict mode（同 L28 约束解码机制）、工具定义的 Token 开销、设计原则清单
导出真实 Pydantic v2 Schema，对照必填、可空与宿主默认，并验证缺键、多键、错类型不会进入工具。
L3540min
完整 Function Calling 循环 Agent 核心 面试
用 Responses 实现有界循环：先检查终态和预算，逐个执行并按 call_id 回填全部结果。区分一轮多调用、多轮依赖和应用并发执行。
用固定响应验证多调用配对、原始 Items 保留、拒答或预算耗尽时不再执行。
L3645min
工具健壮性与注册系统 Agent 核心
用装饰器关联参数模型与实现；分开展示清单和执行授权，dispatch真正接入运行时校验、受控错误回填及零执行断言；工具搜索作为后续按需进阶
验证合法输入成功，未知/未授权/非法参数均不执行；不把Schema导出等同运行时校验

Module 3.5 · 成本工程与综合实战

把成本从"随便烧"变成"精打细算"，并用一个项目串起整个 Phase 3。

3.5

缓存分层降本 · 综合实战

L3745min
成本工程：负载驱动的成本决策 面试
先测质量门槛、成功任务总成本和延迟；再按负载选择缓存/Batch/effort/路由/压缩。核验API、模型、TTL、写读价和命中边界；语义缓存需权限/租户/知识版本隔离
用虚构负载淘汰质量不达标方案，比较成功任务成本与缓存写/读盈亏；不能用fixture宣称真实降幅
L3860min
Phase 3 综合实战 综合
收官项目「可验收的Agent客户端」：完全离线的fixture adapter、消息/工具ID配对、有界重试与fallback、执行权限、text/json/本地流消费、usage账本。明确真实SDK、原生缓存、网络流和持久执行仍需集成
独立运行自检，覆盖成功、拒答、截断、非法/未授权工具、工具失败、预算、fallback和缓存计费算法；再定义真实模型重复试验

学习建议

Module 3.1–3.2 打基础——先把 API 调通、流式、Function Calling、Structured Outputs 拿下，这是后面一切的地基。Structured Outputs 与 JSON mode 的区别务必讲清（面试必问）。
Module 3.3 核对可靠性边界——分开重试调度、单次超时和任务截止；有合格备用且可安全重放才换路，未知写入先核对。
Module 3.4 是 Agent 命脉——Tool Schema 设计 + FC 循环（Agent Loop 骨架）+ 工具注册，学完你能看懂 LangChain 等框架 @tool 的底层。
Module 3.5 收尾——按负载做成本决策，L38 验证执行不变量和失败分支。完成后用 Phase 3 工程实践复盘检查交付证据，不以一次漂亮答案代替环境结果。

关于版本号：模型型号、价格、缓存折扣迭代极快，本阶段刻意不写死具体数字，一律以各厂商当时官方文档为准；重点是工程模式与决策方法。
