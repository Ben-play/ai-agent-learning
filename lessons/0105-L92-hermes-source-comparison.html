第十阶段 · 选修25分钟

只读对照 Hermes 的状态与恢复边界

保存对话、确认操作、查到回执是三件事

为什么要读源码，而不是只看功能表？

客服窗口重启后能看见上一句「已确认」。这证明对话可以续读，但不能说草稿一定获得了可信批准，更不能断定已经写过。学一个现成项目不是把其全部架构搬来，而是查清它在哪一层解决了什么，再用自己的验收补上没有证据的边界。本课只读固定版 Hermes；可执行练习是课程自己的只读记录观察器。

学习目标

  • 根据固定源码区分存储装配、兼容入口、补救记录与隔离说明。
  • 用同一份合成任务判断等待人工、仅可交宿主复核、已核实回执和待对账；不把历史语句当批准或提交。

1. 固定版本，分别找权威来源

本课只看 Hermes Agent v0.23.4（提交 8fc0374447313e276f6b9a2764bfc750190c966a）。下表是针对这些文件的有限判断，不是整个项目的安全评估。不要根据名称把「保存」推断成「持久业务状态」，也不要从版本号推断部署配置：同一存储抽象下可以有不同的权限边界。

固定源码可支持的结论仍缺什么
hermes_state.py为旧插件保留已文档化名称的兼容入口，自己不持有数据库连接兼容导入不等于所有旧状态都能迁移
persistence_assembly.py装配按 profile 选择的存储句柄；独立只读句柄能查看已有库仅凭这个文件不能说明某次恢复选中哪个会话，或证明租户隔离
session_rescue.py运行时发现状态库被替换时，为队列中的消息保留备用文本记录保留消息不等于恢复了业务回执，也不是外部效果去重保证
SECURITY.md设计声明将操作确认与进程隔离分开；确认用于避免错误，不承担隔离这里未追踪批准的实际决策入口或主体检查，也未验证本机或生产环境是否启用隔离

阅读顺序：先查应用把状态交给谁，再看异常时保住了什么，最后在独立安全说明里查批准与环境的责权。比如备用文本保存了原始消息，就可以为「用户看到了什么」提供线索；要回答「业务写了吗」，必须从业务存储或服务的权威回执另取证。不要从相邻概念中补出缺失保证。

2. 给这次任务三份互不替代的记录

本地例子是 support/mei 的同步时间草稿（第 2 稿）。transcript 是对话片段；task.binding 是任务身份、动作、修订与正文摘要；approval 是独立业务审批；receipts 是只读观察到的实际确认记录。课内 inspect() 仅分类，永远不执行。其 ready_for_host_review 只是把案子交给宿主，不承诺已经写过或允许绕开当前来源验收。

固定对话中两段语句均不变，拿掉批准或改指旧稿时应返回 wait_for_review。若状态暗示已提交，分别按操作 ID 和完整任务绑定查记录，两边都必须恰好找到同一行，再校验正文摘要。即使已有一个匹配的 ID，同一绑定又出现第二个 ID 也是冲突；另一任务的正常记录则不影响本次判断。缺失、冲突或改文都先 reconcile，不能发起新写。异租户不返回回执。这样的宿主校验是课堂抽象，并非从 Hermes 的说明推断它实际这样授权；代价是要维护绑定和观察点，但不会把最后一句话当事实。

决策卡：只复用有证据的能力

适用：需要评估某框架能否替换现有在途恢复。边界：只读源码及合成分类，没有执行器、模型或生产恢复。

误判：会话能重开，就以恢复的消息批准业务。
选择：流程状态、业务批准与回执在各自权威来源验证。

代价：维护证据映射与对账；系统没有在途副作用时，优先使用更薄的读取和人工核对。

  1. 固定提交，列出原文支持与未测的声明。
  2. 保留同一段对话，只变批准或回执；对照等待、核验与停止。

诊断：如果删除回执仍判断完成，先查评分是否用编排字段或文字代替了读回结果。

对话存在，但提示已存的任务找不到对应回执，接下来怎么做？
没有独立确认不能推断成功，也不能推断未写。先对账。

from dataclasses import replace
import runpy

if not __debug__:
    raise RuntimeError("run without -O")
lab = runpy.run_path("code/phase10-framework-evolution/evolution-lab/source-study/lab.py")

second = replace(receipt, operation_id="another-fixture-receipt")
other = replace(second, binding=replace(second.binding, task="other-training-task"))
wrong_text = replace(receipt, body="同步任务每天 03:00 运行。")
for data, tenant, expected in (
    (old, "support", ("wait_for_review", None)),
    (replace(row, transcript=()), "support", ("receipt_verified", "fixture-receipt-02")),
    (replace(row, receipts=(receipt, second)), "support", ("reconcile", None)),
    (replace(row, receipts=(receipt, other)), "support", ("receipt_verified", "fixture-receipt-02")),
    (replace(row, receipts=(wrong_text,)), "support", ("reconcile", None)),
    (row, "operations", ("not_available", None)),

    result = lab["inspect"](data, tenant=tenant, actor="mei")

面试自查

Q1 旧插件还能读导入入口，能推断所有旧会话能继续吗？

参考回答：不能，导入契约和数据/流程契约不同。

追问：测试只有全新会话呢？

答题要点：用相同旧快照对照，特别检查在途节点与业务回执。

Q2 备用记录保住了消息，能确认草稿落库吗？

参考回答：只能证实消息保存，找独立业务记录与操作 ID。

追问：操作 ID 对了，但回复正文和持久内容不同？

答题要点：先对账，不把半匹配当回执，也不重试写入。

Q3 有人工确认，就可以不用环境隔离吗？

参考回答：不可以，确认与运行环境的约束不同。

追问：如果只是读取合成记录呢？

答题要点：仍限定主体与数据；没有需求就不启用执行能力。

Q4 源码有大部分边界，是否值得替换现有编排？

参考回答：先说明本项目可测瓶颈，再用同任务比较迁移、支持与维护成本。

追问：候选架构更全，但旧任务恢复没有证据？

答题要点：不替换主线，先验证兼容与回退。选修比较不解除部署前置。
