生成器与 Streaming 模式

生成器是"边算边给" — LLM 的逐字流式输出，本质就是一个生成器

💡 为什么这课重要？

你用 ChatGPT 时那种"一个字一个字蹦出来"的体验，靠的就是流式（streaming）——服务端算一个 token 就推一个，不用等整段生成完。在 Python 里，承载这种"边算边给"的正是生成器（generator）。

掌握生成器，你才能优雅地处理 LLM 流式响应、边收边解析、以及惰性处理大数据而不爆内存。这是 Part C（Agent 工程技能）的第一块拼图。

学习目标

完成本课后，你将能够：

  • 用 yield 写生成器，理解它"惰性、可暂停"的本质
  • 区分生成器表达式和列表推导式，知道何时用哪个
  • 理解迭代器协议（__next__ / StopIteration）
  • 用生成器处理 LLM 流式响应（逐 token）
  • 了解 send() 能向生成器"回传"数据

1. yield：让函数"边算边给"

普通函数 return 一次就结束。生成器用 yield 产出一个值后暂停，下次取值再从暂停处继续：

def stream_tokens(text, n=3):
    for i in range(0, len(text), n):
        yield text[i:i+n]          # 产出一块，暂停，等下次取

for chunk in stream_tokens("HelloWorld", 3):
    print(chunk, end="|")          # Hel|loW|orl|d|

关键：stream_tokens(...) 调用时不会立刻执行函数体，只返回一个生成器；每次 for 取值才推进到下一个 yield。这就是"惰性"——用到才算。

🔑 Agent 开发关联：

LLM 的 streaming API 返回的就是这种"一块一块"的流。用生成器包装它，上层代码就能写成 for chunk in llm_stream(prompt):，边收边显示/边处理，用户体验和内存都更好。

Q 调用一个含 yield 的函数，会发生什么？
含 yield 的函数是生成器函数，调用它只返回一个生成器对象，函数体一行都不先跑。只有当你迭代（for / next）时，才推进到下一个 yield。这种"惰性"正是流式处理的基础。

2. 生成器表达式 vs 列表推导式

# 列表推导式：立刻算出全部，占内存
squares_list = [x*x for x in range(1000000)]     # 一百万个数全在内存里

# 生成器表达式：惰性，用一个算一个，几乎不占内存
squares_gen = (x*x for x in range(1000000))      # 括号，不是方括号

# 生成器是"一次性"的，消费即耗尽
gen = (c.upper() for c in "abc")
print(next(gen))          # A
print("".join(gen))       # BC   ← A 已被取走，只剩 BC

差别就一对括号：[] 立刻生成整个列表，() 生成一个惰性生成器。处理大数据、或只需遍历一次时，用生成器省内存。

💡 面试常见问题：

"列表推导式和生成器表达式的区别？"

答：列表推导式立即计算并把所有元素放进内存；生成器表达式惰性求值、逐个产出、几乎不占内存，但只能遍历一次。大数据或流式场景用生成器。

3. 迭代器协议（背后的机制）

for 循环能作用于生成器、列表、文件，是因为它们都遵守迭代器协议：能被 iter() 拿到迭代器、能被 next() 取下一个、取完抛 StopIteration：

it = iter([1, 2])
print(next(it))    # 1
print(next(it))    # 2
next(it)           # StopIteration（for 循环内部捕获它来结束循环）

生成器天生就是迭代器——这就是它能直接用在 for 里的原因。

4. send()：向生成器回传数据（进阶）

yield 不只能"产出"，还能"接收"。gen.send(x) 把 x 传回给暂停处的 yield 表达式：

def accumulator():
    total = 0
    while True:
        x = yield total       # 产出 total，同时等待 send 传入的值
        if x is not None:
            total += x

acc = accumulator()
next(acc)              # 启动到第一个 yield（必须先 next 一次）
print(acc.send(10))    # 10
print(acc.send(5))     # 15

这在需要"双向流"的场景（如可交互的 Agent 步骤流、协程式状态机）有用。日常处理 LLM streaming 通常只用单向 yield，send 了解即可。

Q 生成器表达式 (x for x in data) 相比列表推导式，主要优势是？
生成器表达式惰性求值——用一个算一个，不把整个序列放进内存，处理大数据或流时省内存。代价是它一次性、不能重复遍历、也不能按下标索引。列表推导式则相反。

知识图谱

生成器
├── yield → 产出即暂停，惰性、可恢复
├── 调用生成器函数 → 只返回生成器，不先执行
├── 生成器表达式 (x for x in ...) → 惰性省内存、一次性
└── send(x) → 向 yield 回传数据（双向，进阶）

迭代器协议
├── iter() 取迭代器 / next() 取下一个
└── 取尽抛 StopIteration（for 内部捕获）

Streaming 应用
├── 包装 LLM 流：for chunk in llm_stream(...)
├── 边收边处理、边显示（低延迟、低内存）
└── 拼接流式 token（呼应 L09 的流解析）

实战练习

练习：实现一个 LLM Streaming 模拟器

用生成器逐 token 输出一段"回答"，并支持在中途根据条件暂停/停止。先自己写，再看答案。

任务清单

  1. 写生成器 stream(text)，逐字符 yield（模拟 token）
  2. 写 collect(gen, stop_at=None)：消费生成器、拼接输出；若遇到 stop_at 字符就提前停止（模拟"遇到停止词就中断")
  3. 统计实际产出了多少 token
  4. 体会：因为是惰性的，stop_at 之后的 token 根本不会被生成
💡 点击查看参考答案 
def stream(text):
    for ch in text:
        yield ch                      # 逐 token 产出（惰性）

def collect(gen, stop_at=None):
    parts = []
    count = 0
    for tok in gen:
        if stop_at is not None and tok == stop_at:
            break                     # 遇到停止词，中断——后面的 token 不再生成
        parts.append(tok)
        count += 1
    return {"text": "".join(parts), "tokens": count}


print(collect(stream("你好，世界！")))
# {'text': '你好，世界！', 'tokens': 6}

print(collect(stream("答案是42。附注..."), stop_at="。"))
# {'text': '答案是42', 'tokens': 4}   ← "。"及之后没有被消费


# 进阶：用生成器表达式做惰性过滤（只在需要时计算）
events = ({"type": "token", "text": c} for c in "abcd")
answer = "".join(e["text"] for e in events if e["type"] == "token")
print(answer)   # abcd

面试常见问题

Q1：生成器和普通函数的区别？

答：生成器用 yield，产出一个值后暂停、保留状态、可恢复；调用它只返回生成器对象，函数体惰性执行。普通函数 return 一次性算完返回。

Q2：列表推导式和生成器表达式怎么选？

答：需要多次遍历、随机访问、或数据不大 → 列表推导式；只遍历一次、数据很大或是流 → 生成器表达式（惰性、省内存）。

Q3：迭代器协议是什么？

答：对象能被 iter() 得到迭代器、被 next() 逐个取值、取尽时抛 StopIteration。for 循环正是基于它工作，生成器天生满足该协议。

Q4：生成器在 LLM 应用里有什么用？

答：承载流式响应——服务端逐 token 产出，用生成器包装后上层可 for chunk in stream: 边收边处理，降低首字延迟和内存占用；遇停止条件可提前中断，省掉后续计算/请求。

总结

  • yield = 产出即暂停，生成器惰性、可恢复
  • 调用生成器函数只返回生成器，函数体不立即执行
  • 生成器表达式用 ()，惰性省内存但一次性
  • 迭代器协议（iter/next/StopIteration）是 for 循环的基础
  • 生成器是承载 LLM streaming、惰性处理大数据的利器
  • send() 可向生成器回传数据（双向流，进阶了解）
