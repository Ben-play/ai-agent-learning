Function Calling 原理

用 Responses 跑通一次自定义工具调用：模型提出请求，应用决定是否执行

为什么这课重要

问模型「北京现在下雨吗」，它不一定有实时数据。你可以给它一个 get_weather 工具，让它表达「我要查北京天气」。对应用自定义函数来说，模型输出的是请求，不是执行凭证：应用检查工具名称、权限与参数后才执行，并把结果交还模型。由厂商托管的内置工具是另一种执行边界。

本课只练一轮工具调用：写工具定义、读调用、按 ID 回填。多轮循环见 L35，生产分发的校验与授权见 L36。

1. 一次工具调用的五步

  1. 应用发送：把用户输入和 tools 列表交给 Responses。
  2. 模型提出调用：从 response.output 找 type == "function_call" 的 Item。它有 name、arguments（JSON 字符串）和 call_id。也可能没有调用或一次有多个；不要假定第一个 Item 就是工具请求。
  3. 应用执行：先确认正常响应，再检查工具名、权限、输入格式与业务约束。任一不合格时不执行，返回受控错误。
  4. 应用回填：保留原始输入和全部输出 Items；每个结果追加一个 function_call_output，用原来的 call_id 配对。
  5. 模型继续：发送下一次请求。模型可以用工具结果答复，也可能再申请工具；后一种由 L35 的有界循环处理。
Q 模型请求自定义工具后，谁负责授权和执行？
应用不能把模型意图当授权：先检查权限和参数，再决定是否执行；即使 Schema 合法也一样。

2. 主练习：写一个 Responses 工具

Responses 把 name、description 和 parameters 放在工具对象顶层。描述写清「何时用」以及输入含义，实际执行还要另外检查。这里用一个必填字段、固定城市和虚构天气，不访问天气服务。

import json

WEATHER_TOOL = {
    "type": "function",
    "name": "get_weather",
    "description": "查询练习中的北京天气；只在需要北京天气时使用。",
    "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string", "enum": ["北京"]}},
        "required": ["city"],
        "additionalProperties": False,
    },
    "strict": True,
}


def weather_output(call, *, allowed):
    # allowed 由应用给出，不读模型参数中的权限声明。
    if call.name != "get_weather" or call.name not in allowed:
        result = {"ok": False, "error": "tool_unavailable"}
    else:
        try:
            args = json.loads(call.arguments)
        except json.JSONDecodeError:
            args = None
        if args != {"city": "北京"}:
            result = {"ok": False, "error": "invalid_arguments"}
        else:
            result = {"ok": True, "temp_c": 3, "wind": "大风", "fixture": True}
    return {
        "type": "function_call_output",
        "call_id": call.call_id,
        "output": json.dumps(result, ensure_ascii=False),
    }

call_id 标识这次调用，要原样回填；不要用 Item 自身的 id 替代它。strict 约束受支持模型正常生成的参数形状，不替代运行时授权或业务校验。工具描述的写法见 L34。

Q Responses 根据什么把工具结果与请求配对？
同一个工具可能在一轮里被调用多次。回填使用工具请求的 call_id，不是工具名、列表下标或 Item 的 id。

3. 离线验收：正确配对，错误不执行

先独立完成：让一条合法调用返回虚构天气，并让损坏参数、未授权工具得到错误结果。把第 2 节代码和以下断言存进同一个 Python 文件，用 python -I 文件名.py 运行。不读取密钥或访问网络；所有断言通过才打印 L27 ACCEPTED。

决策卡：用调用 ID 配对，不用工具名或列表下标

适用：应用执行自定义工具并回填结果，即使首版只允许一项调用。不适用：普通文本响应没有自定义调用，不造回填 Item。

误判：同名就视为同一次

一轮两次查天气，一条成功、一条参数非法。按 get_weather 存结果会覆盖其中一条；按顺序回填也可能串到另一条。

对照：成功和错误各归其位

同两条查询，校验后用各自的 call_id 回填天气或受控错误；交换结果顺序也不改变对应关系。

取舍：要保留原调用和关联 ID，但不再依赖同名调用的到达顺序；ID 只负责关联，不赋予工具执行权限。

  1. 运行下面的天气验收，对照 id 和 call_id。
  2. 再做课末变式，把同名结果按相反顺序回填。

结果诊断：正例和错误都应保留各自的 call_id；如果覆盖或配串，先查是否用工具名、Item ID 或索引当了关联键。

from types import SimpleNamespace

call = SimpleNamespace(id="fc_123", call_id="call_abc", name="get_weather",
                       arguments='{"city":"北京"}')
allowed = {"get_weather"}
reply = weather_output(call, allowed=allowed)
assert reply["type"] == "function_call_output"
assert reply["call_id"] == "call_abc" and reply["call_id"] != call.id
assert json.loads(reply["output"]) == {
    "ok": True, "temp_c": 3, "wind": "大风", "fixture": True,
}
assert json.loads(weather_output(call, allowed=set())["output"]) == {
    "ok": False, "error": "tool_unavailable",
}
for bad in ('{"city":', '["北京"]', '{"city":"上海"}', '{"city":"北京","admin":true}'):
    call.arguments = bad
    assert json.loads(weather_output(call, allowed=allowed)["output"]) == {
        "ok": False, "error": "invalid_arguments",
    }

4. 可选在线与 Chat Completions 对照

若已确认调用预算并配置 OPENAI_API_KEY 和支持 Responses 自定义函数及 tool_choice 的 OPENAI_MODEL，可以把下段接在第 2 节代码之后。为观察单次往返，第一轮指定查天气，第二轮禁用工具调用；实际 Agent 不必强制调用。2026-11-17 发布的 GPT‑6.2 Astra / Sol 能使用 Chat Completions 做普通生成，但二者的工具调用须用 Responses；不能只换模型 ID 而保留旧工具请求形状。

在线集成片段：读取第一次调用并回填
import os
from openai import OpenAI

client = OpenAI()
model = os.environ["OPENAI_MODEL"]
items = [{"role": "user", "content": "请用练习工具查询北京天气，并注明是虚构数据。"}]
response = client.responses.create(
    model=model, input=items, tools=[WEATHER_TOOL], store=False,
    tool_choice={"type": "function", "name": "get_weather"},
    parallel_tool_calls=False,
)
if response.status != "completed" or any(
    part.type == "refusal" for item in response.output
    if item.type == "message" for part in item.content
):
    raise ValueError("响应未完成或被拒答")
calls = [item for item in response.output if item.type == "function_call"]
if len(calls) != 1:
    raise ValueError("本练习预期一次调用；多工具见 L35")
items.extend(response.output)
items.append(weather_output(calls[0], allowed={"get_weather"}))
# 仅打印终态和输出类型；不要把未完响应当业务答案。
follow_up = client.responses.create(
    model=model, input=items, tools=[WEATHER_TOOL], tool_choice="none", store=False,
)
print(follow_up.status, [item.type for item in follow_up.output])

本课最佳实践验收：展馆查询倒序回填

同一轮提出两次展馆开放时间查询。JSON 都可解码，但一次参数合法、一次不合法。复制起点，实现 run_calls(calls, allowed)：先查名单，再验参数是仅含已知 room 的对象；错误分别记为 tool_unavailable 或 invalid_arguments。倒序回填时，西厅的错误应排在前面，但读取记录里只能有东厅；不用前面的天气代码。

import json
from types import SimpleNamespace

hours = {"东厅": "10:00–16:00"}
reads = []


def read_hours(room):
    reads.append(room)
    return hours[room]

def run_calls(calls, allowed):
    results = []
    for call in reversed(calls):
        if call.name != "room_hours" or call.name not in allowed:
            result = {"error": "tool_unavailable"}
        else:
            args = json.loads(call.arguments)  # 起点中的 JSON 均可解码
            room = args.get("room") if isinstance(args, dict) and set(args) == {"room"} else None
            if not isinstance(room, str) or room not in hours:
                result = {"error": "invalid_arguments"}
            else:
                result = {"hours": read_hours(room)}
        results.append({"type": "function_call_output", "call_id": call.call_id,
                        "output": json.dumps(result, ensure_ascii=False)})
    return results


results = run_calls(calls, {"room_hours"})
assert [row["call_id"] for row in results] == ["call_west", "call_east"], results
assert all(row["type"] == "function_call_output" for row in results)
assert {row["call_id"]: json.loads(row["output"]) for row in results} == {
    "call_east": {"hours": "10:00–16:00"}, "call_west": {"error": "invalid_arguments"},
}
assert reads == ["东厅"], reads
blocked, = run_calls(calls[:1], set())
assert blocked["call_id"] == "call_east"
assert json.loads(blocked["output"]) == {"error": "tool_unavailable"}
assert reads == ["东厅"], reads

总结与参考

记住三件事：模型请求不等于动作已执行；解析 JSON 不等于参数合法；结果必须用同一个 call_id 回填。下次从空白写出这三步，再去 L35 处理多轮和终态。
