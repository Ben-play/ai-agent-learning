P0 必改/会误导 P1 应补/明显缺口 P2 可增强/锦上添花

阶段体检结论建议
1 · Python 基础 保持。Agent 导向（@tool 装饰器、Streaming 生成器、Pydantic Schema）切入点很对，零基础友好。 P2 补一节 Git / 版本控制（JD 高频、目前几乎缺失）。
2 · AI 知识与选型 扎实。Token 经济学、幻觉、推理模型都在点上。 P1 模型清单别写死版本号（易过时），改成「选型决策框架 + 课程时点最新」；补「上下文窗口 vs 长期记忆」一题。
3 · LLM API 工程 很好。重试/Fallback/AI Gateway/可观测性基础齐全。 P0 紧随其后新增「工具工程与 Function Calling」专章（见下）。P1 成本一节把原生 Prompt Caching 提到第一杠杆。
4 · Prompt / Context 保持。已包含 Context Engineering 基础，方向正确。 P2 标注「Context Engineering 术语仍在演化」，避免包装成已固化标准。
5 · Agent 核心架构 强。Agent Loop + Harness + ReAct/Reflexion + 工具设计哲学，是全大纲含金量最高的一段。 P2 Harness/Ratchet 引用 Anthropic 工程博客原文，强调是「工程实践」而非「行业标准术语」。
6 · 框架入门 + MCP 好。轻量框架（Pydantic AI / OpenAI Agents SDK）先上手的思路对。 P1 把 MCP 从「前沿」升级为「必修基础设施」；补一节「框架选型与 tradeoff」（面试常问 LangGraph vs CrewAI vs SDK 何时用）。
7 · 数据 + RAG 扎实，已含 Agentic RAG / GraphRAG / RAGAS。 P2 把 Agentic RAG（Self-RAG / Corrective / Adaptive）从「列举」做成「动手实现 + 何时用」。
8 · 工程实践 缺口。可观测性偏「只讲 LangSmith」，评估不成体系，无系统设计。 P1 评估升级为 Agentic Metrics（Tool Correctness / Plan Quality / Step Efficiency）+ promptfoo/Braintrust/DeepEval + 公开基准；可观测性讲生态 + OpenTelemetry GenAI 标准。P1 新增「LLM/Agent 系统设计」模块。
9 · 高级能力 方向对。Extended Thinking / Computer Use / Agentic Coding 都是热点。 P2 Computer Use 补 browser-use（开源、模型无关）；Agentic Coding 用 OpenHands / Claude Code 作真实案例。
10 · 生产框架 + 多 Agent 必修。LangGraph/CrewAI/多 Agent 模式没问题；案例 OpenClaw / Hermes 已核实为真实热门项目（非虚构）。 P2 案例可保留，但建议链接到真实仓库、引用 README 原文，并补一个编码类真实案例（OpenHands / SWE-agent）做对照；AutoGen 降为历史、提示后继 MS Agent Framework；ANP/AGNTCY 标注「生态未定，关注即可」。
11 · 部署与迭代 偏薄。只有 FastAPI+Docker+Serverless；安全深度不足。 P1 补云托管 Agent 服务（Bedrock AgentCore / Vertex AI Agent Engine / Azure AI Foundry Agent Service）+ Temporal；安全补间接注入 / 过度代理 / MCP 权限 / 人在环审批。工程习惯前移到 Phase 3 起。

Top 7 改项（按优先级）

P0 ① 新增「工具工程与 Function Calling」（Phase 3 后，2 课）— 所有厂商 API 的 Agent 基础、面试必考、手撕高频，是当前最大的实战缺口。
Tool Schema（Pydantic / JSON Schema / strict mode）→ 完整 Function Calling 循环（多轮 / 并行 / 参数校验失败处理 / 流式中解析）。

P2 ② 巩固 Phase 10 案例（已核实为真实） — OpenClaw / Hermes 无需替换，但建议链接真实仓库、引用 README 原文，并加一个编码类真实案例做对照。
候选对照：OpenHands、SWE-agent、Claude Code —— 让「协调型 vs 自主型 vs 编码型」三类各有真实样本。

P1 ③ 成本工程重排优先级 — 原生 Prompt Caching（零改动、输入成本最高降 ~90%）＞ 模型路由（LiteLLM）＞ 提示压缩（LLMLingua）＞ 蒸馏 ＞ Batch API。
关键是「静态前缀 + 动态后缀」的缓存键设计 —— 系统提示/工具定义在前，用户查询在后。

P1 ④ 新增「LLM / Agent 系统设计」模块（并入 Phase 8 或独立）— 2026 面试的 system-design 主战场。
设计 RAG 系统 / 多 Agent 客服 / LLM 网关 / 长时运行 Agent / Agent 评估框架。

P1 ⑤ 评估升级为「评估驱动开发 + Agentic Metrics」 — 不止 answer relevance，要测 Tool Correctness / Plan Quality / Step Efficiency / 过度代理。
工具：promptfoo（CI/CD + 红队）、Braintrust、DeepEval、RAGAS；基准：SWE-bench Verified、τ-bench、GAIA。

P1 ⑥ 部署 + 安全补强 — 部署补云托管 Agent 服务与 Temporal；安全补间接 Prompt Injection、过度代理（excessive agency）、MCP 工具权限链、人在环审批。
OWASP LLM Top 10 仍以现行版为准；MCP 既是能力也是攻击面。

P2 ⑦ 工程化硬技能渗透 — Git（Phase 1 补）、系统化测试（pytest + Mock LLM）、可观测性/容器化习惯从 Phase 3 起渗透，而非全堆到 Phase 11。
