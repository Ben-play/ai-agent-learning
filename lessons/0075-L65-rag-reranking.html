第七阶段 · 数据与 RAG45分钟

对同一候选集重排

候选池里有答案，不代表最先送进上下文的那条能回答问题

为什么这课重要？

客服问「导出的文件已经过期，我现在应该怎么做？」系统查到了两条证据：一条说导出文件保留七天，另一条说过期后需要重新发起导出。沿用 L64 的混合检索器，本课改用粗粒度查询表示后，保留期排在第一。它和提问有关，却没有给出下一步动作。上下文只给一条证据时，增加模型参数或换回答模板都不能保证找回那句动作说明。先定位：是候选没找到，还是候选找到了却没被送进去？

学习目标

  • 固定授权池和候选截断，只切换重排，检验指定证据是否晋升并真正进入上下文。
  • 统计完整证据包的字符数与 UTF-8 字节数；分开报告确定性评分、工作量和墙钟延迟。

1. 冻结输入，再谈排序收益

宿主指定 (tenant, user) = (support, mei)。SQLite 先找当前可读的 tuple[Chunk]：导出保留期、导出过期处理和同步时间。每条片段有文档 ID、版本、定位、标题、正文、手工词项和固定向量；key = (doc_id, version, locator) 识别片段，而租户和用户另行绑定。检索输入 Query(("导出", "保留"), (1., 0., 0.)) 是粗粒度的意图表示，不是完整提问。它来自手写夹具，不是分词或 Embedding 的输出。

混合检索在这个池内融合词法和向量排名，截断为 candidate_k=2，返回 tuple[Hit]，每条包括 chunk 和首阶段 score。保留期（EXPORT-POLICY v1 §1）第一，过期处理（EXPORT-OPS v1 §2）第二。同步政策虽然授权，但不在这批候选里；仅审计者可见的内部留存文档不在授权池，更不该被评估。实验让两条路径接收同一个候选元组：第一条保持输入顺序；第二条只对它重排。不要一边把截断从 2 改到 5、一边打开重排，不然即使答对也无法把收益归因给重排。

重排的输入追加任务线索 ("过期", "重新生成")，用去重后的线索与候选词项取交集，命中几个记几分。过期处理得 2 分，保留期得 0 分；按分数降序，同分沿用候选顺序。新分数不是概率，更不能与 RRF 分相加。实现对每条候选核对版本定位键和完整片段值，遇到重复、缺键、当前无权或同键内容不符就拒绝该批输入，而不是用标题相似度猜一条替代品。合法的输出必须是输入候选的排列；仅检查「输出键在授权池」还不够，因为这会容许偷偷补入没过截断的同步政策。

同一个授权池里的过期处理题：预先标定有效证据为 EXPORT-OPS v1 §2
控制条件截断后的候选顺序打包前顺序进包证据（字符 / 字节）
基线：不重排保留期 → 过期处理保留期 → 过期处理保留期（47 / 88），没有动作说明
只开启重排保留期 → 过期处理过期处理 → 保留期过期处理（47 / 100），动作说明入包
单独反例：候选截断提前到 1保留期保留期保留期（47 / 88），没有动作说明

第三行不是公平对照的一边，而是独立的召回反例：即使授权池里仍有动作证据，重排也无法把没拿到的候选变出来。排查时分开记录三个位置：授权池是否有目标、首阶段前 candidate_k 是否召回、打包后前 top_k 是否保留。候选已经漏召回，应回到切分、查询或首阶段截断；候选已提升仍没进包，应看预算而不是追加召回。

2. 算完整证据块，不拿字节猜令牌

本例的 top_k=1 是最多装一条，不是只检查第一条。证据块由「证据：」标题及换行、每条引用标签、空格、标题、全角冒号、正文、条目分隔与末尾换行组成。len(context) 数 Python 字符串的 Unicode 码点，不等于人眼看到的字形数；len(context.encode("utf-8")) 数编码后的字节。示例每尝试加入一条，都先重新生成完整块检查两个上限；放不下就跳过整条，不把一个引用和它的正文截成两半。用 64 字符上限时，动作证据在 100 字节上限处刚好装下；字节上限降为 99，即使它排名第一仍被跳过，且随后 88 字节的保留期能进包。得到非空上下文，不等于支持了当前问题。若把条数放宽为 2 并允许两条都进包，则合计 90 字符、178 字节；不能把 88 和 100 直接相加，因为两条共用一份证据标题。

这两个上限覆盖的是 序列化证据块，不是模型请求总长。实际要用目标模型对应的 tokenizer 或计数接口，按最终消息结构计算系统指令、用户问题、历史、工具定义及包装开销，为模型输出留余量。不同语种、标点与 tokenizer 的拆分不同，没有固定的字符或字节到 token 转换系数。不要只统计命中的正文，也别把调用不到真实模型时算出的本地字符数当成模型用量。

基线不做额外候选评分，重排对两条候选各评分一次；两边各调用一次打包。授权池核对、排序和字符串构建也是工作，不能把「2 次」直接换算成时间。下面的本地报告把查询和授权池读取移到计时外，只比较「打包」与「重排并打包」。若换成 CrossEncoder，每个问句与候选配对评分，可批处理，但计算、网络和排队会改变延迟。两条夹具的耗时只说明本地对照怎么做，不是端到端或生产延迟。

决策卡：哪一段失败，就改哪一段

适用：目标已在候选中，但经常被相邻话题挤出证据包。不适用：正确来源不在授权池或没有进入首阶段截断；前者不是检索质量问题，后者不是重排问题。

误判：相关分变高，就部署重排

同时放宽候选、增大上下文，还用新评分代替证据命中；上线后无法解释收益来自哪里。

对照：候选与预算相同，只切排序

先过授权与原候选排列的硬门槛，再按人工标定的「动作、例外、时限」检查进包覆盖；没有稳定收益就保留简单基线。

代价：更大的候选截断给重排更多机会，也多花逐候选评分和检查的成本。若覆盖增益在代表性题集上不能抵消尾延迟或成本增长，就不保留重排。

  1. 保存输入候选、标定的来源键、打包字节数和每段工作量，再做对照。
  2. 召回负例、预算负例分别只改一个边界，不用同一个失败推出两个结论。

诊断：出现不在输入中的键，先修契约；正确证据排名上升却没进包，先看完整序列化成本。

选修的触发条件：同义改写长期漏召回时，可试 HyDE，用生成的假设文档构造检索向量，但引用必须来自实际授权来源；多步取证需要根据缺口换查询时，可试 Agentic RAG，并设迭代、延迟与停止条件；跨文档关系或全局主题是主要误差时，再评估 GraphRAG，还要承担索引更新和衍生摘要的权限管理。三者不是这个重排实验的升级顺序，也不能补授予记录或把推测变成证据。

Q正确的过期处理证据已排第一，但 99 字节上限让它跳过，保留期入包。先查哪里？
前两阶段已把正确证据放到首位；装包仍要求完整证据块不超限，高分绕不过这一关。

展开参考：同批候选、召回与预算三组断言
import runpy

if not __debug__:
    raise RuntimeError("run without -O")
lab = runpy.run_path("code/phase7-data-rag/rag-lab/lifecycle/main.py")
Hit, Query, pack, rerank = (lab[name] for name in ("Hit", "Query", "pack", "rerank"))
policy = ("EXPORT-POLICY", 1, "§1")
ops = ("EXPORT-OPS", 1, "§2")
internal = ("EXPORT-INTERNAL", 1, "§1")
query = Query(("导出", "保留"), (1., 0., 0.))
cues = ("过期", "重新生成")

with lab["open_demo"]() as db:
    pool = db.authorized("support", "mei")
    candidates = db.search("support", "mei", query, mode="hybrid", k=2)
    assert tuple(h.chunk.key for h in candidates) == (policy, ops)
    ranked = rerank(candidates, pool, cues)
    assert tuple((h.chunk.key, h.score) for h in ranked) == ((ops, 2), (policy, 0))
    assert {h.chunk.key for h in ranked} == {h.chunk.key for h in candidates}
    assert all(db.source("support", "mei", h.chunk.key) == h.chunk for h in ranked)

    limits = dict(top_k=1, max_chars=64, max_bytes=100)
    baseline = pack(candidates, **limits)
    adjusted = pack(ranked, **limits)
    assert (baseline.citations, baseline.chars, baseline.utf8_bytes) == ((policy,), 47, 88)
    assert (adjusted.citations, adjusted.chars, adjusted.utf8_bytes) == ((ops,), 47, 100)
    assert adjusted.context == "证据：\n[EXPORT-OPS v1 §2] 导出过期处理：导出文件过期后，需重新发起导出。\n"
    assert pack(ranked, **dict(limits, max_bytes=99)).citations == (policy,)

    short = db.search("support", "mei", query, mode="hybrid", k=1)
    assert pack(rerank(short, pool, cues), **limits) == baseline
    other_pool = db.authorized("support", "lin")
    other = db.search("support", "lin", query, mode="hybrid", k=2)
    assert tuple(h.chunk.key for h in rerank(other, other_pool, cues)) == (policy,)

    current = db.source("support", "mei", ops)
    foreign = db.source("support", "auditor", internal)
    missing = lab["Chunk"]("NOT-INDEXED", 1, "§1", current.title, current.text,
                           current.terms, current.vector)
    for key in (internal, missing.key):
        assert db.source("support", "mei", key) is None
    for rejected in (foreign, missing):
        try:
            rerank(candidates + (Hit(rejected, 99),), pool, cues)
        except ValueError:
            pass
        else:
            raise AssertionError("accepted candidate outside the authorized current pool")
print("L65 ACCEPTED")

本课最佳实践验收：同步时间被导出话题挤到末位

独立任务：用户在夜班交接问「同步任务什么时候跑？」混合检索的固定向量仍偏向导出，手工词项含同步和导出噪声。比较同样三条候选、同样只装一条时的结果。然后只减少候选截断，证明目标掉出候选时无法恢复；最后恢复候选，单独把字符或字节各缩 1，证明即使排名正确也可能进不了包。

import runpy

if not __debug__:
    raise RuntimeError("run without -O")
lab = runpy.run_path("code/phase7-data-rag/rag-lab/lifecycle/main.py")
pack, rerank = lab["pack"], lab["rerank"]
query = lab["Query"](("同步", "导出", "保留"), (1., 0., 0.))
cues = ("同步", "02:00")
policy, ops, sync = (("EXPORT-POLICY", 1, "§1"), ("EXPORT-OPS", 1, "§2"), ("SYNC-POLICY", 1, "§1"))

with lab["open_demo"]() as db:
    pool = db.authorized("support", "mei")
    base = db.search("support", "mei", query, mode="hybrid", k=3)
    assert tuple(h.chunk.key for h in base) == (policy, ops, sync)
    ranked = rerank(base, pool, cues)
    assert tuple((h.chunk.key, h.score) for h in ranked) == ((sync, 2), (policy, 0), (ops, 0))
    limits = dict(top_k=1, max_chars=64, max_bytes=100)

    assert pack(ranked, **limits).citations == (sync,)
    narrowed = db.search("support", "mei", query, mode="hybrid", k=2)
    assert pack(rerank(narrowed, pool, cues), **limits).citations == (policy,)

    exact = pack(ranked, top_k=1, max_chars=46, max_bytes=81)
    assert (exact.citations, exact.chars, exact.utf8_bytes) == ((sync,), 46, 81)
    assert "同步任务每天 02:00 运行。" in exact.context
    for chars, byte_limit in ((45, 81), (46, 80)):
        refused = pack(ranked, top_k=1, max_chars=chars, max_bytes=byte_limit)
        assert (refused.context, refused.citations) == ("", ())

面试自查

按「结论 → 理由 → 如何验证」作答，再展开追问。

Q1拉长候选并启用重排后，离线答对更多。如何证明不是拉长候选的功劳？

参考回答：同一身份、语料、查询、截断和预算，保存首阶段候选，只改变重排开关，逐题核对真正入包的标定来源。然后单独比较不同的候选截断，量化召回变化。

追问：动作证据只在授权池但不在候选里，重排应把它捞上来吗？

答题要点：不应；那是新增检索，不是重排。单独检查首阶段召回与截断。

Q2供应商重排返回同文档、同定位但不同版本的片段，能按标题相同接收吗？

参考回答：不能。应让评分只对应输入候选，核对授权的当前键和内容。版本改变时重取当前候选，不替它改一个版本标签就继续返回。

追问：如果返回的是另一个同样获授权的当前片段呢？

答题要点：仍要拒绝，因为授权集合比本批候选大；重排输出必须来自同一候选集。

Q3正确证据已晋升，回答仍说不出操作，你会查什么？

参考回答：先确认证据是否进入最终请求，而非停在排序列表。核对完整证据块、条数、上限和源键；若有准确原文却仍答错，再单独测生成环节。

追问：工具报告 100 字节，能向模型成本表填 100 token 吗？

答题要点：不能；用目标模型消息格式实测 token，预留生成空间，字符与字节只说明本地预算。

Q4本地多了两次候选打分，可以承诺线上只多几毫秒吗？

参考回答：不能。工作量是可重复的操作计数，实时时间还受输入长度、批处理、硬件、网络和排队影响。在目标负载上分阶段对照，并同时报告覆盖、成本和尾延迟。

追问：如果投诉主要是新文档没被召回，要不要先上 GraphRAG？

答题要点：先查入库时效、授权、切分和候选覆盖；只有跨文档关系或全局问题存在可量化缺口，才值得为图索引和摘要做单独对照。
