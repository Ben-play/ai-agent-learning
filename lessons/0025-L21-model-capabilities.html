模型能力边界与 Base vs Instruct

搞懂 LLM 天生做不到什么——因为 Agent 架构，本质就是来补这些短板的

💡 为什么这课重要？

你调的 API 背后，是一个会聊天、会听指令的模型。但它并不是天生就会——纯预训练出来的 base model 根本不听指令，你问它问题，它可能反手给你续写更多问题。它是怎么变成今天这个"助手"的？这是第一个必须搞懂的分水岭。

更关键的是它的能力边界：知识会过时、不会精确算术、会一本正经地幻觉、上下文有限还会"迷失在中间"、默认没有记忆……这些不是 bug，是 LLM 的先天局限。而这，正是 Agent 存在的全部意义——用工具、检索、记忆去补 LLM 的先天短板。学完这课，你会明白 Agent 每个组件到底在"救"哪条局限。这也是面试最爱问的一类问题。

学习目标

完成本课后，你将能够：

  • 说清 Base Model 和 Instruction-Tuned Model 的本质差别
  • 用一句话解释 RLHF 在做什么、以及"指令微调不增加知识"这个关键洞察
  • 列出 LLM 能做的核心任务清单
  • 准确说出 LLM 的 6 大局限（面试常考），并解释每条为什么发生
  • 把每条局限映射到 Agent 用什么能力去补——建立贯穿全课程的主线

1. Base Model vs Instruction-Tuned Model

同一个模型，训练分两大阶段，产出两种"人格"：

Base Model（基座）Instruction-Tuned（指令模型）
怎么来的纯预训练：海量文本上学"预测下一个 Token"base 之上做指令微调 + RLHF
会干什么只会续写 / 补全文本能听懂并执行指令、对齐人类偏好
你问它问题可能续写出更多问题（它以为你在列清单）直接回答你的问题
典型代表Llama-3-Base、各家 -base 权重GPT / Claude / Gemini 的 chat 版

直觉例子：给 base model 输入"中国的首都是"，它可能补全成"中国的首都是北京，日本的首都是……"——它在模仿文本分布，不是在应答。指令模型才会理解成"你在问我，我该回答'北京'"。差别来自训练方式（见 Toloka: Base LLM vs Instruction-Tuned LLM）。

关键洞察（务必记住）：指令微调主要 refine 的是"任务执行 / 对齐"，并不显著增加模型的知识——知识几乎全部来自预训练阶段。有 arXiv 研究专门指出这点（arXiv 2402.05119）：指令微调教会模型"如何回应、如何对齐偏好"，而不是"知道更多事实"。所以你想让模型知道它训练时没见过的东西（你的私有数据、最新新闻），微调不是首选——该上检索（RAG）。

对 Agent 开发者的意义：你日常调的 API（GPT / Claude / Gemini 的 chat / instruct 版）都是 instruction-tuned 的——正因为它们听得懂指令，你才能用自然语言下达任务、写 system prompt、做 function calling。base model 一般不直接拿来做 Agent。

Q 关于 base model 和 instruction-tuned model，哪句最准确？
知识几乎全部来自预训练；指令微调 + RLHF 主要 refine 的是"听懂并执行指令、对齐人类偏好"，并不显著增加知识（arXiv 2402.05119）。所以想让模型"知道"训练时没见过的东西，靠 RAG 而不是靠微调。base 与 instruct 的知识量大体相当，差别在"会不会应答"。

2. RLHF 一句话

RLHF = Reinforcement Learning from Human Feedback（基于人类反馈的强化学习）。一句话讲清它的三步：

  1. 让人类对模型的多个回答排序（哪个更好）；
  2. 用这些偏好数据训练一个奖励模型（reward model），学会给回答打分；
  3. 用奖励模型作为信号，对齐（强化学习微调）LLM，让它的输出更有用（helpful）、无害（harmless）、诚实（honest）。

这就是为什么 chat 版模型会礼貌应答、会拒绝有害请求、会尽量给你想要的格式——它被"人类偏好"对齐过。数学细节这里点到即止，你只需记住：RLHF 让"会续写的 base model"变成"会当好助手的 instruct model"。

记忆钩子：预训练给模型知识，指令微调 + RLHF给模型教养（听话、对齐、有用无害诚实）。知识 vs 教养，分得清就不会误以为"微调能让它知道最新新闻"。

3. LLM 能做什么

指令模型的能力面相当宽，绝大多数是语言层面的任务：

  • 语言理解与生成：写文案、对话、续写
  • 总结 / 翻译 / 改写：长文压缩、跨语言、换语气
  • 抽取 / 分类：从文本里抠出结构化字段、打标签、判情感
  • 代码：生成、解释、调试、转写
  • 基于给定上下文的推理与问答：你把资料喂进 prompt，它据此回答（这正是 RAG 生效的基础）
  • 遵循复杂指令：多步骤、带约束、指定输出格式
  • 调用工具（function calling）：输出结构化调用意图，交给外部系统执行——这是 Agent 的技术地基

注意最后两条："遵循复杂指令" + "调用工具"正是让 LLM 从"聊天机器人"升级成"Agent"的两块拼图。而"基于给定上下文问答"则告诉我们——只要把正确的资料放进上下文，模型就能用；问题只在于怎么把正确资料找来放进去（下一节的局限会揭晓答案）。

4. LLM 不能做什么 / 六大局限（面试重点）

这一节是全课的核心。请把这张表背下来——它既是面试高频，也是理解 Agent 架构的钥匙。每条局限，右侧就是 Agent 用什么能力去补：

局限为什么会发生Agent 如何补
知识截止
(knowledge cutoff)		 只知道训练数据截止日之前的事；问最新事件会过时或干脆编造 联网 / 检索工具：搜索、调 API 拉实时数据（RAG）
不会精确计算 本质是概率预测下一个 Token，不是真在"算"；大数运算、精确计数容易错 代码 / 计算器工具：把算式交给 Python / calculator 执行
幻觉
(hallucination)		 会一本正经编造看似合理实则错误的内容；无法根除（见 L19） RAG + 引用校验 + 工具核对：让答案有据可查
上下文窗口有限 超长输入会被截断 / 丢信息；且"迷失在中间"(lost in the middle)——长上下文中间部分利用率低 检索 + 压缩 + 分块：只放相关片段，把关键信息放头尾
没有持久记忆 默认无状态，跨对话不记得你是谁、上次说了啥 外部记忆系统：把历史 / 偏好存库，需要时检索回来（Phase 5）
不知私有 / 实时数据 训练语料里没有你的内部文档、数据库、当下状态 RAG：把你的私有数据检索进上下文再作答

两个高频细节值得展开：

  • "迷失在中间"(lost in the middle)：当相关信息被放在超长上下文的中间位置时，模型的利用率明显低于放在开头或结尾。这意味着"上下文窗口大"不等于"信息就一定被用上"——工程上要把最关键的资料放到头尾。
  • 知识截止是硬边界：无论模型多强，它对截止日之后的世界一无所知。别去让 LLM"记住日期"或猜"现在最新版本是几"——那种问题必须走工具。（本课也刻意不写死任何模型的具体截止日期，因为它随版本变、且很快过时。）
Q 用户问"今天的天气怎么样"，纯 LLM 答不好的根本原因是？
"今天天气"是实时 / 训练后的信息，落在模型的知识截止之外，模型内部也没有实时数据源——硬答只会过时或幻觉。正解是让 Agent 调联网 / 天气 API 工具把实时数据取回，再交给 LLM 组织语言。这和参数量、温度、窗口大小都无关。

5. 贯穿主线：Agent 就是来补 LLM 短板的

把第 4 节反过来读，你就理解了 Agent 架构存在的全部意义——它不是给 LLM"加聪明"，而是用外部能力补齐 LLM 的先天短板。一一对应：

LLM 先天短板          →   Agent 补的能力
─────────────────────────────────────────
知识截止 / 不知实时     →   联网工具 / 检索（RAG）
不会精确算术           →   代码 / 计算器工具
幻觉                   →   RAG + 引用校验
上下文有限 + 迷失中间   →   检索 + 压缩 + 头尾摆放
没有持久记忆           →   外部记忆系统
不知私有数据           →   RAG（私有知识库）

换句话说：LLM 是 Agent 的"大脑"，但大脑没有手、没有笔记本、也不上网。工具是它的手，记忆是它的笔记本，检索是它的联网。之后学到的每一个 Agent 组件——tool use、RAG、memory、planning——你都可以问自己一句："这是在补哪条局限？"这条主线会一直贯穿到课程结束。

Agent 场景练习：下面 4 个用户请求，各触碰了哪条 LLM 局限？Agent 该用什么能力补？先自己想，再展开对照。

  1. "今天 XX 公司的股价多少？"
  2. "帮我算一下 1234 × 5678 等于几。"
  3. "你还记得我上周说过我更喜欢简洁的回答吗？"
  4. "总结一下我刚上传的这份 PDF。"
点击查看参考答案
  • ① 今天的股价 → 局限：知识截止 + 无实时数据。补：联网 / 行情 API 工具拉当前价，再让 LLM 组织语言。
  • ② 1234 × 5678 → 局限：不会精确计算（概率预测，大数易错）。补：代码 / 计算器工具执行算式，返回精确结果。
  • ③ 还记得我的偏好吗 → 局限：没有持久记忆（默认无状态，跨对话不记得）。补：外部记忆系统——把偏好存库，本轮检索回来注入上下文。
  • ④ 总结刚上传的 PDF → 局限：不知私有数据（训练语料里没有你的文件），若 PDF 很长还会撞上上下文有限 / 迷失中间。补：RAG——把 PDF 切块检索相关段落放进上下文，再让 LLM 总结。

发现没：这 4 个再普通不过的请求，纯 LLM 没有一个能独立答好——而配上工具 / 记忆 / RAG 的 Agent 全都能。这就是 Agent 的价值。

Q "让 Agent 记住用户的跨对话偏好"，主要是在补 LLM 的哪条局限？
LLM 默认无状态：一轮请求只看得到本次上下文，跨对话不记得你是谁、说过什么。要"记住偏好"就得靠外部记忆系统——把信息存库，需要时检索回来注入上下文（Phase 5 主题）。这与知识截止、算术、幻觉是各自独立的另外几条局限。
⭐ 面试高频："LLM 有哪些做不到的事？" 满分答法一次答全 6 条、并说清 Agent 怎么各个击破：① 知识截止 → 联网/检索工具；② 不擅精确计算 → 代码工具；③ 幻觉（无法根除）→ RAG + 引用校验；④ 上下文有限 + lost in the middle → 检索/压缩/头尾摆放；⑤ 无持久记忆 → 外部记忆系统；⑥ 不知私有/实时数据 → RAG。结尾点睛一句："Agent 架构的意义，就是用工具、检索、记忆去补 LLM 这些先天短板"——这句能让面试官眼前一亮。

总结

  • Base 只会续写、不听指令；Instruct = base + 指令微调 + RLHF，才会应答对齐——你调的 API 都是后者
  • 关键洞察：知识来自预训练，微调主要负责"执行 / 对齐"，几乎不加知识 → 想让它"知道"新东西该上 RAG
  • RLHF：人类排序 → 训奖励模型 → 对齐 LLM，让输出有用 / 无害 / 诚实
  • 六大局限：知识截止、不会精确算、幻觉、上下文有限 + 迷失中间、无持久记忆、不知私有 / 实时数据
  • 贯穿主线：Agent 架构的意义，正是用工具 / 检索 / 记忆去补 LLM 这些先天短板——之后每个组件都能对号入座
