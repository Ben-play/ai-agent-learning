L01 开发环境搭建 1 问
Q为什么要用虚拟环境（venv）？直接 pip install 到全局不行吗？
A

可以跑，但迟早会踩坑。全局装包意味着所有项目共用一套依赖：项目 A 要 httpx==0.24、项目 B 要 httpx==0.28，全局只能留一个版本，另一个项目就坏了。

虚拟环境给每个项目一个独立、隔离的包目录，互不干扰；删项目时连 venv 一起删干净，不留垃圾。Agent 项目依赖多（openai / anthropic / pydantic / tenacity…），隔离几乎是必须的。习惯：python -m venv .venv → 激活 → 再 pip install。

L02 Python 运行机制与模块系统 1 问
Q跑 tests/test_core.py 报 ModuleNotFoundError: No module named 'agent'——python tests/test_core.py 报、pytest 也报。agent/ 明明就在旁边，为什么找不到？
A

不是 import 写错了，是「搜索起点」错了。Python 找包只在 sys.path 里找；而 agent/ 包住在项目根 agent-hello/，你两次运行都让搜索起点落在了 tests/ 目录，那里当然没有 agent/。两个报错是同一个病根：

① python tests/test_core.py：Python 的铁律——用 python 某脚本.py 直接跑脚本时，sys.path[0] = 脚本所在目录（这里是 tests/），既不是你当前所在目录、也不是项目根。于是只在 tests/ 里找 agent → 找不到。

② pytest：pytest 9 默认 prepend 导入模式，会把 test 文件的「包根」插进 sys.path。「包根」= 从 test 往上、第一个没有 __init__.py 的目录。你的 tests/ 没有 __init__.py → pytest 认定 tests/ 自己是包根 → 把 tests/（而非项目根）加进路径 → 一样找不到 agent。而 pyproject.toml 里没有 [tool.pytest.ini_options]，没有 pythonpath 兜底，全凭 rootdir 猜，所以脆、换个上下文表现就不同。

一句话记牢：python xxx.py 看「文件在哪」，搜索起点 = 文件目录；python -m xxx 看「你在哪」，搜索起点 = 当前目录。包在项目根，就得让搜索起点是项目根。

怎么修（首选，一劳永逸、跟在哪跑无关）：往 pyproject.toml 末尾加——

[tool.pytest.ini_options]
pythonpath = ["."]
testpaths = ["tests"]

之后在项目根 agent-hello/ 下直接 pytest 就稳过（实测 1 passed）。备选：给 tests/ 加个空的 __init__.py（让 pytest 一路往上找到项目根）；或临时 PYTHONPATH=. pytest（治标）。手动跑单文件用 python -m tests.test_core（在项目根），别用 python tests/test_core.py。
