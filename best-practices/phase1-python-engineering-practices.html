工程主题 · Environment

让执行环境、依赖输入与秘密来源都可证明

阶段规则

项目代码从目标 uv 根目录执行；依赖以已跟踪且一致的清单与锁文件为准；本地秘密只加载、不回显。

触发 / 非触发

触发：解释器不一致、拉取后依赖漂移、密钥进入源码或日志。非触发：一次性无依赖脚本且不读取秘密。

因果机制

uv run 将解释器绑定到项目；版本化输入可审查重放；布尔诊断避免泄露凭据材料。

代价 / 替代

要维护锁文件、忽略规则和编辑器配置；部署环境改用平台的锁定构建与秘密存储，不复制本地 .venv。

依赖

项目根含 pyproject.toml/uv.lock，Git 可用，.env 与 .venv 均未被跟踪。

工程主题 · Modules

把包入口、导入位置与依赖方向视为同一边界

阶段规则

只再导出稳定名称，普通运行时 import 默认置顶，包内依赖保持从入口与业务层单向指向底层模型。

触发 / 非触发

触发：内部文件改名波及调用方、函数内藏依赖、底层模块反向导入上层。非触发：有说明的可选或昂贵依赖可局部延迟。

因果机制

稳定包入口隔离文件布局；置顶 import 暴露加载依赖；有向无环关系阻止部分初始化和循环导入。

代价 / 替代

需维护精确 __all__ 并支付启动导入成本；实验性或重模块保留显式子模块入口，例外使用窄 allowlist。

依赖

先定义公开 API 承诺与模块分层；AST 检查必须基于项目实际 import，而不是理想化目录图。

工程主题 · State Ownership

显式决定可变状态与延迟回调归谁所有

阶段规则

每次调用或实例需要独立容器时现场创建；循环生成的延迟回调在创建时固定当次绑定；共享必须由调用方明示。

触发 / 非触发

触发：后一次调用携带前次数据、实例间串状态、全部回调指向循环末项。非触发：业务明确共享同一对象，或回调不捕获循环变量。

因果机制

默认参数与闭包都保存引用；函数内新建、default_factory 和每轮工厂调用把引用生命周期收窄。

代价 / 替代

增加分支、分配和工厂层；长期共享状态改用显式状态对象，复杂不变量改用配置类型与可调用类。

依赖

必须先区分“省略值”“合法的 None”与“共享对象”；固定绑定不是深复制。

工程主题 · Boundary Contracts

从容器语义到工具执行建立分层数据契约

阶段规则

先按语义选容器；嵌套读取遵守字段契约；JSON object 以关键字映射到明确签名；类型提示描述内部状态，Pydantic 守住不可信运行时边界。

触发 / 非触发

触发：LLM、HTTP、队列或 CLI 交来原始 mapping。非触发：同一信任域内已持有且未重新序列化的已验证模型实例。

因果机制

容器表达顺序/命名/不变/去重；**mapping 让字段名进入签名绑定；解析器与模型实例执行运行时拒绝。

代价 / 替代

契约与模型需随输入演化维护；开放值集合保留 str，简单内部对象可用 dataclass，性能热点可在边界验证后传递窄类型。

依赖

safe_get() 是课程辅助函数而非标准库；签名、类型注解、Pydantic v2 模型和工具实现必须表达同一字段语义。

工程主题 · Bounded Control

让循环终止条件与 Prompt 渲染都保持可判定

阶段规则

Agent Loop 对步骤、终态和未知动作设显式边界；Prompt 可选片段集中收集并只执行一次稳定连接。

触发 / 非触发

触发：模型不返回终态、adapter 给出未知动作、开关改变无关空行或顺序。非触发：单次纯函数调用或无需条件片段的固定文本。

因果机制

有限状态迁移阻止无界消耗；片段列表把条件决策与最终格式分离，减少分支间格式耦合。

代价 / 替代

过低步数会截断合法任务；长任务用可恢复状态机。复杂模板可用 Jinja；外部调用超时与预算仍由 adapter/运行器负责。

依赖

必须定义动作集合、终态、耗尽结果和固定渲染契约；字符串结构本身不提供 prompt injection 防护。

工程主题 · Extensibility

扩展频率决定分发结构，失败原子性决定注册顺序

阶段规则

固定小集合用显式分支，频繁增长的实现用注册表；注册时先完整 build + validate，最后只提交一次。

触发 / 非触发

触发：新增实现总要修改执行器，或装饰器失败后留下半条目。非触发：两三个稳定实现，分支更直接且更易审查。

因果机制

名称到可调用对象的映射把扩展变成数据；所有可失败步骤前置，使唯一写入成为原子提交点。

代价 / 替代

注册表增加间接查找并隐藏可用集合；小集合保留分支。多写者场景需锁、不可变快照或集中 owner。

依赖

条目需有唯一名称、可检查签名、受支持类型和明确 callable；参数校验、权限与超时仍在注册表之外。

工程主题 · Resource Lifecycle

更新持久状态要原子，停止消费外部流要显式

阶段规则

重要 JSON 先写完同目录唯一临时文件再替换；持有外部资源的流在正常结束、提前停止与异常路径都关闭或取消。

触发 / 非触发

触发：更新失败仍须保留旧文件，或迭代器背后是 HTTP/SSE/文件/进程。非触发：无外部资源的本地有限生成器。

因果机制

同文件系统 os.replace 将可见切换收敛为一步；显式关闭把消费者的 break 传播到上游资源。

代价 / 替代

临时文件与清理路径增加复杂度，原子替换也不等于断电持久；多写者需锁。纯内存流自然耗尽即可。

依赖

临时文件必须与目标同目录；流接口必须暴露 context manager、close() 或取消协议，并明确 owner。

工程主题 · Failure Ownership

异常语义、重试策略与批次隔离只由正确层负责

阶段规则

只翻译能增加业务语义的具体异常；每条传输调用链只有一个重试 owner；调度层只做逐项并发与独立失败隔离。

触发 / 非触发

触发：需给调用方稳定错误、SDK 与包装层都可能重试、批次成员彼此独立。非触发：契约破坏应原样暴露，强一致组应 fail-fast。

因果机制

raise ... from 同时保留业务分类与根因；单一重试 owner 防尝试次数相乘；逐项捕获避免一个尾部失败扩散。

代价 / 替代

要维护异常映射和 transport policy；严格顺序用串行，组内同生共死用 TaskGroup，按完成顺序消费用 as_completed()。

依赖

先分类临时/永久错误与幂等性；共享并关闭 Client；注入的 async adapter 必须先兑现 L15 的最终传输语义。

离线综合项目：把 8 个决策接成一条调用链

项目位于 code/phase1-python/phase1-practices-capstone/。它不访问网络、不读取真实密钥；一个 PracticeAgent 隐藏注册、传输、并发和持久化实现，只暴露稳定的运行接口。

架构

RunRequest → Pydantic 边界 → 有界运行器 → 已验证 registry
                                  ↓
Batch coordinator → PracticeAgent → OfflineGateway(MockTransport)
                                  ↓
                         原子 JSON 持久化

公共接口

RunRequest、RunReport、BatchOutcome、PracticeAgent、build_offline_agent。批次只需传入 parallelism 与 deadline_s。

反事实

项目包含“重试整个批次”和“只导出 Schema、不实例验证”两个故意失败的变异；若它们成功退出，说明错误方案没有被检查发现。

离线运行命令 
cd code/phase1-python/phase1-practices-capstone
uv lock --check --offline
uv run --offline --locked pytest -q
uv run --offline --locked mypy phase1_practices tests main.py
uv run --offline --locked python main.py

通过：测试与 mypy 无错误，主入口只输出阶段接受标记；两个 counterfactual 模块必须因预期断言而非零退出。

阶段验收总览

展开 8 项阶段验收（打印时自动展开）
  1. 环境：解释器属于目标项目，锁文件一致且受版本控制，秘密未进入源码、Git 或诊断输出。
  2. 模块：公开入口稳定，普通 import 可见，运行时依赖图没有反向边或导入副作用。
  3. 状态：省略的可变值彼此隔离，显式共享可追踪，延迟回调保留各自绑定。
  4. 契约：容器符合语义，原始 mapping 在副作用前完成嵌套读取、签名绑定与运行时验证。
  5. 控制：未知动作与耗尽都有结果，循环不会无界运行，Prompt 组合保持稳定格式。
  6. 扩展：新增实现不改执行器，任何注册失败都不会改变 registry。
  7. 资源：失败更新不破坏旧 JSON，正常、提前与异常退出都会释放真实流资源。
  8. 失败：异常保留根因，每条调用链只有一个重试 owner，独立批次项互不扩散失败。
