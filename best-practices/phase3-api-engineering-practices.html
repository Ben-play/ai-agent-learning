这不是新课。先做各课独立变式，再用下面四项复核 L38 的交接。不重抄示例代码，也不以离线校验代替真实模型集成。

1. 输出何时才可用？

按原生协议保留终态和上下文。候选文字、成功终态与合法结构是不同证据；流断、截断、拒绝不能交给业务解析或当最终答复。完整 JSON 也不能证明事实与权限。

L26 流终态 · L28 结构合同 · L29 按输出类型验收

2. 失败后留在原路、换路，还是停止？

分开单次超时、重试安排与任务截止。备用必须满足能力、数据范围和重放条件；未知写入先核对原回执。比较同批负载的成功结果、费用和时间，缺测保留未知。

L31 截止与重放 · L32 合格路线 · L37 成本取舍

3. 有调用意图，真的能执行吗？

校验实际 Schema、参数与宿主授权；可空不是可省略。发工具前还要留回传预算，并核整批 ID。保留完整交互组和结果关联；协议 ID 不是跨进程业务幂等键。

L34 导出检查 · L35 原生循环 · L36 分派边界

4. 如何交接，而不是只报自检通过？

随 L38 独立验收保留输入、预期、观察到的终态、模型尝试数、实际工具效果与缺失记录。对坏输入至少证明一次「有模型尝试、没分派工具」；说明真实 SDK、缓存、成本与业务结果哪些尚未验证。下一阶段用同样证据纪律定义客服问答与草稿任务。
