Phase 6 · LangGraph 与 MCP 工程实践复盘

先通过单课的跟做与变式，再用这页检查迁移报告。不要把一个通过标记当作图、协议和授权三层都验过。

1. 迁移改变了什么？

判断：节点安排可以换，保证不能换。固定问题和证据，对照终态、来源与实际分派；加零预算或最后一次可成功的例子，防止一刀切。

证据：L55 迁移对照。不报线上延迟或模型质量。

2. 图停住时，业务真的没写吗？

判断：分别读取图的下一步、匹配的人工决定和业务结果。模拟提交后丢响应时，图未结束、业务一行可以同时成立；按原操作身份重跑，而不是新增插入。

证据：L56 持久恢复。记录是否真换进程和故障点；SDK 未实跑时如实记「待验证」。

3. 哪种 MCP 连接已经验证？

判断：先确定传输、协议修订、两端实现，再查对应的帧。stdio 的 stdout 只传协议；HTTP POST 可以返回 JSON 或 SSE。旧版独立 GET 流不等于新版 SSE 响应。

证据：L57 子进程 · L58 loopback 矩阵。未测的 SDK 或协议功能不要填「兼容」。

4. 工具被发现后，什么时候才允许动作？

判断：知识库证据与 Skill 模板决定预览写什么，不决定是否能保存。发现、scope、资源权限与当前批准分别判断。每次只改一个条件，核对是哪个门拒绝、会不会触及保存入口，以及正控保存的是不是原预览。外部操作仍需独立验收。

证据：L59 授权矩阵 · 阶段检查点。用合成凭证，不把本地 fixture 称为生产 OAuth。
