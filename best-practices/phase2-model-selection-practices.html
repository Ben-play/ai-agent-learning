工程主题 · Request Contract

让控制字段、运行规范与 Token 口径都归目标模型所有

阶段规则

业务层表达“要稳定、要多样、要多少推理投入”等语义意图；provider adapter 根据模型能力映射请求字段，并用目标模型自己的计数方式估算，调用后再以 usage 对账。

触发 / 非触发

触发：跨模型、跨版本或跨厂商调用，参数/Tokenizer/响应 usage 不同。非触发：单一固定模型的短期实验，且调用代码已被一个受控 adapter 完整封装。

因果机制

能力 profile 阻止无效字段进入请求；运行规范指纹记录可控变量；模型原生计数避免把另一套词表或消息开销冒充账单。

代价 / 替代

需要维护能力目录、adapter 与用量对账。只接一个模型时可保留一个直接 adapter，但业务层仍不应散布厂商字段；模型能力变化时以官方文档或 Models API 更新。

依赖与边界

必须固定 model、prompt、tools、控制配置与 evaluator；离线 profile 只能验证映射逻辑，不能证明线上模型当前支持某字段，调用前计数也不是最终账单。

工程主题 · Reliability Gate

把输出稳定性当风险信号，把事实发布权交给证据

阶段规则

重复观测用于发现发散和升级风险；事实结论必须由 ground truth、可验证引用、确定性工具或人工 rubric 支持，一致回答不得自动获得发布资格。

触发 / 非触发

触发：回答包含外部事实、金额、法律承诺或将驱动后续工具动作。非触发：纯创意任务没有外部真值，或结果会被确定性 verifier 完整判定。

因果机制

发散暴露模型对答案不稳定；独立证据区分“一致地对”与“一致地错”；硬发布门阻止流畅错误继续触发 Agent 副作用。

代价 / 替代

多次采样、检索和人工核验增加成本与延迟。低风险文本可只记录风险信号；可程序验证的计算、ID 和库存应优先直接调用确定性工具。

依赖与边界

题目必须有可判定证据契约，并允许弃权或升级。Self-Consistency 不能发现所有共享偏差；LLM-as-judge 也只是带误差的 evaluator。

实践索引：L19 · 可靠性发布门检查点

工程主题 · Capability Policy

先定位缺口，再决定推理投入与外部能力

阶段规则

用业务 eval 选择满足门槛的最低 effort；若任务缺的是新鲜数据、私有证据、确定性计算或跨会话状态，就分别接工具、直接上下文/RAG、代码和应用状态，而不是继续提高模型思考投入。

触发 / 非触发

触发：提高 effort 后质量仍无增益，或失败可归因于知识/工具/状态缺口。非触发：输入完整、真值可从上下文推出，错误主要来自多步推理不足。

因果机制

effort 只改变模型的响应投入；外部能力把模型原本拿不到的数据、计算或状态真正带入系统。先诊断可避免用更贵推理掩盖缺失依赖。

代价 / 替代

需要维护试验集、工具、检索质量和状态生命周期。稳定且重复的行为技能、有充足训练数据时可把微调列为候选；小文档直接放上下文通常比先建 RAG 简单。

依赖与边界

effort 是软指导而非硬 Token 预算；能力映射必须区分“模型不会推理”和“系统没有提供所需信息”。增加 RAG 或工具也不自动保证正确。

工程主题 · Private Evaluation

公开成绩只缩小候选，隔离业务评测才有拍板权

阶段规则

先用公开资料和硬约束筛选候选；固定开发集用于改 prompt、adapter、effort 与工具，隔离测试集只在方案冻结后比较，最终记录模型、scaffold、预算、运行次数和失败样本。

触发 / 非触发

触发：模型将进入生产、承担风险或存在多种配置可调。非触发：低风险探索只需粗筛，尚未形成可重复任务和验收 rubric。

因果机制

业务样本让评测分布贴近真实请求；隔离 holdout 阻止反复调参把测试集变成开发集；固定 scaffold 避免把提示和工具差异误归因给基础模型。

代价 / 替代

需要采样、标注、版本管理和重复运行。数据少时可先用专家 rubric 与人工双评；高风险场景还要做灰度 A/B 和持续漂移监控。

依赖与边界

必须先定义业务损失、硬门槛和样本切分。一次 toy eval、公开 benchmark 或单个平均分都不能证明线上适用性。

实践索引：L22 · 私有评测阶段检查点

工程主题 · Cost-aware Routing

按完整成本构成优化，并只路由到已证明达标的策略

阶段规则

分别计算未缓存输入、缓存写、缓存读、输出、重试和升级成本；路由器自身的计算与运维开销另列为系统成本；静态前缀先规范化再测命中；路由只在业务 eval 达标的候选之间选择最低预期成本。

触发 / 非触发

触发：重复前缀、多档模型/effort、难度混合流量或重试/升级占比可观。非触发：调用量低、流量同质、前缀太短或频繁变化，固定单模型更易维护。

因果机制

成本分项暴露真正金额热点；字节稳定前缀创造缓存命中条件；质量门槛和升级概率阻止“便宜首调 + 高频返工”伪装成降本。

代价 / 替代

需要 tracing、价目版本、命中率和路由漂移监控。非实时大批量任务可比较厂商 Batch；输出占比最高时先收紧输出，比引入路由更直接。

依赖与边界

缓存倍率、最小前缀与厂商价格会变化，应查当前官方文档和 usage；本地 digest 只证明前缀稳定，不证明服务端命中；第三方案例比例不是收益承诺。

最终决策纪律：先过硬门槛，再比较相对优劣

归一化与加权只能形成合格候选的比较排名，不能把安全、事实或合规缺陷折算成“价格便宜一点就可以接受”；它也不等同于后续按最低期望成本执行的每请求路由。回到 L24 · 先门槛后排名，检查无候选合格时是否明确返回“需要调整方案或人工决策”，而不是强行选一个最高分。

离线综合项目：从 provider 契约到选型报告

项目位于 code/phase2-model-selection/phase2-practices-capstone/。它只读取固定的虚构 provider、观察值、证据目录和价格 fixture，不访问网络、真实模型或密钥。离线证据目录用内容摘要和封闭 ID 验证教学 fixture 的身份与防篡改；它不声称能自动证明任意自然语言材料蕴含某个事实，生产系统仍需确定性解析器或人工 rubric。

                 repeated assessment

Evidence metrics + full cost → hard gates ─┬→ qualified comparison ranking
                                             └→ minimum-expected-cost route policy

这些类型属于模块实现；调用者不需要跨过内部 seam。

公共接口

build_offline_lab(fixture_root=None) 构建实验室；调用者只需执行 AssessmentLab.assess() 获取不可变报告。计数、控制映射、证据、成本和排名留在实现内部。

反事实

“把一致当真值”和“先排名后门槛”两个模块必须到达明确的 CounterfactualReached 失败哨兵并以非零状态退出；若成功退出或未到达该哨兵，说明最关键的可靠性纪律没有被验收。

阶段验收总览

展开最终验收项（打印时自动展开）
  1. 请求契约：业务意图不等于厂商字段；每个 adapter 只发送目标模型支持的控制，并使用目标模型计数方式。
  2. 运行证据：模型、prompt、工具、控制、fixture、evaluator 和重复次数可追踪；非确定输出不被要求逐字节相等。
  3. 可靠性：发散会升级风险，一致不会自动发布；事实结论有 ground truth、证据、工具或人工 rubric。
  4. 能力策略：推理不足才调整 effort；数据、证据、计算和状态缺口由对应外部能力补齐。
  5. 私有评测：开发集与隔离测试集职责分开，固定 scaffold、预算、rubric 与运行次数，公榜只负责初筛。
  6. 成本路由：成本分项完整，缓存命中用 usage 验证，路由考虑质量门槛、误路由与升级成本。
  7. 最终选择：所有硬门槛在归一化和加权前执行，无合格候选时不强行给出赢家。
