Agent Harness 架构参考

2026 年 Agent 开发的主流架构模式。Harness Engineering 正在取代 Prompt Engineering 成为核心技能。

什么是 Agent Harness？

Agent Harness 是围绕 LLM 的脚手架系统，决定 Agent 如何运行、何时停止、如何处理错误。它不是单个 Prompt，而是整个运行环境的设计。

"A harness decides which context is loaded, which tools are available, what 'done' actually means, what checks must pass before progress is accepted."
— Agent Harness: The Architecture that will Dominate 2026

四层架构

Layer 1: Agent Reasoning（推理层）

LLM 的核心推理能力。包括：

  • Chain-of-Thought 推理
  • Extended Thinking（深度推理）
  • 规划和决策能力
  • 自我反思和纠错

Layer 2: Context Engineering（上下文工程）

决定 Agent 能"看到"什么信息。包括：

  • 上下文窗口管理（200K+ tokens）
  • 动态上下文加载和卸载
  • 记忆系统（短期/长期）
  • RAG 检索结果整合
  • 工具调用结果缓存

Layer 3: Tooling（工具层）

Agent 能"做"什么。包括：

  • 工具注册和发现（MCP 协议）
  • 工具调用调度和并发控制
  • 权限管理和安全沙箱
  • 工具执行结果处理

Layer 4: Persistence（持久化层）

Agent 的状态如何保存。包括：

  • 会话状态持久化
  • 检查点和恢复
  • 日志和可观测性
  • 审计追踪

Prompt Engineering vs Harness Engineering

Prompt Engineering（旧范式）

  • 关注单个 Prompt 的措辞
  • 手动调优 few-shot 示例
  • 静态的指令设计
  • 适合单轮对话
  • 2023-2025 主流

Harness Engineering（新范式）

  • 关注整体运行环境设计
  • 动态上下文管理
  • 工具编排和错误处理
  • 适合多轮 Agent 循环
  • 2026 主流

关键设计原则

  1. 可观测性优先：每个决策都要可追踪、可调试
  2. 优雅降级：工具失败时有备用方案
  3. 上下文效率：只加载必要的上下文，避免窗口溢出
  4. 安全边界：关键操作需要人工确认
  5. 状态管理：支持中断恢复和长时运行
