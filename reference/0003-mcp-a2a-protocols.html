MCP & A2A 协议参考

2026 年 AI Agent 通信的两大标准协议。理解它们的区别和适用场景是 Agent 开发的必备技能。

协议全景

协议 全称 发起方 解决的问题 类比
MCP Model Context Protocol Anthropic Agent 如何访问外部工具和数据 USB-C（统一接口）
A2A Agent-to-Agent Protocol Google Agent 之间如何相互通信 HTTP（通信协议）
ACP Agent Communication Protocol 社区 Agent 间消息传递的语义标准 SMTP（消息格式）
ANP Agent Network Protocol 社区 分布式 Agent 网络发现和通信 DNS（服务发现）

MCP（Model Context Protocol）

核心问题：Agent 如何统一地访问各种外部工具和数据源？

MCP 定义了 Agent 与外部资源交互的标准方式。无论你用的是数据库、API、文件系统还是其他工具，都通过统一的 MCP 接口访问。

关键特性

  • 工具标准化：所有工具通过统一接口暴露
  • 上下文注入：动态向 LLM 注入相关上下文
  • 权限控制：细粒度的工具访问权限管理
  • 跨框架兼容：不同 Agent 框架可以共享工具

典型使用场景

  • Agent 需要查询数据库获取用户信息
  • Agent 需要调用外部 API 发送邮件
  • Agent 需要读取本地文件处理文档
  • Agent 需要访问企业内部系统

代码示例（Python）

# MCP 工具定义
from mcp import Tool, Server

# 定义一个工具
@server.tool()
async def get_weather(city: str) -> str:
    """获取指定城市的天气信息"""
    weather = await fetch_weather(city)
    return f"{city}今天天气：{weather}"

# Agent 调用工具
result = await agent.call_tool("get_weather", {"city": "北京"})

A2A（Agent-to-Agent Protocol）

核心问题：不同框架构建的 Agent 如何相互通信和协作？

A2A 定义了 Agent 之间通信的标准协议。当一个 Agent 需要另一个 Agent 帮忙时，使用 A2A 进行协调。

关键特性

  • Agent 发现：如何找到能完成特定任务的 Agent
  • 任务委托：如何将子任务分配给其他 Agent
  • 状态同步：如何跟踪远程 Agent 的执行状态
  • 结果聚合：如何整合多个 Agent 的结果

典型使用场景

  • 研究 Agent 委托写作 Agent 生成报告
  • 前端 Agent 与后端 Agent 协调 API 设计
  • 主 Agent 调度多个专家 Agent 并行工作
  • 不同公司的 Agent 之间安全协作

代码示例（Python）

# A2A 任务委托
from a2a import AgentCard, Task

# 发现远程 Agent
writer_agent = await discover_agent(
    skill="technical_writing",
    min_rating=4.5
)

# 委托任务
task = await writer_agent.delegate(
    task="撰写技术博客文章",
    context={"topic": "Agent Harness", "length": 2000},
    timeout=300
)

# 等待结果
result = await task.wait()

MCP vs A2A：何时用哪个？

场景 使用协议 原因
Agent 需要查询数据库 MCP 这是工具访问，不是 Agent 间通信
Agent 需要调用天气 API MCP 外部 API 是工具，用 MCP 标准化
Agent 需要另一个 Agent 帮忙写代码 A2A 这是 Agent 间协作，需要任务委托
多个 Agent 并行处理子任务 A2A 需要协调多个 Agent 的执行
Agent 需要访问企业内部系统 MCP 内部系统是工具资源
不同公司的 Agent 安全协作 A2A 需要跨组织的 Agent 互操作

2026 年协议生态

根据 Google 开发者指南（2026-03），Agent 协议正在标准化：

  1. MCP 成为工具集成的事实标准
  2. A2A 成为 Agent 间通信的标准
  3. ACP 和 ANP 补充特定场景需求
  4. 协议之间互补而非竞争，需要同时掌握
