# Phase 2 L17–L20 Course Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven development and review each lesson before proceeding.

**Goal:** 修复 L17–L20 的厂商边界、Token 计数、幻觉因果与 Claude 推理 API 过时问题，使四课对初学者准确、连续、可验证。

**Architecture:** 每课独立修复；正文、Quiz、折叠练习、速查卡、总结与大纲同步。所有强声明查一手来源，所有 claimed output 实跑。时长变化同步 lesson header、`assets/lesson-times.json`、`assets/course-bar.js`、Phase 2 大纲。

**Tech Stack:** 静态 HTML、Python 3.11+、Anthropic Python SDK、tiktoken、共享课程 CSS/JS。

## Global Constraints

- 主代理逐课完整通读，不用抽样或代理报告替代。
- 专项检查“是什么 / 怎么来的 / 如何区分 / 何时使用”。
- Claude 代码只使用官方 Anthropic SDK；不发真实付费 API 请求。
- 不修改 `code/`，不提交、不推送。
- 每课验证 HTML 标签、Quiz、链接、Q&A 锚点和 claimed output。
- Quiz 正确项位置逐步重新平衡，四个选项保持平行。

## Task 1: L17 解码概念与厂商参数

- 区分通用解码概念与厂商 API 字段。
- 标明当前 Claude Opus 4.8/4.7、Sonnet 5 不接受 sampling 参数；seed 也不是通用字段。
- 限定 temperature=0 的复现讨论适用范围。
- 增加折叠实践题并同步复习区。

## Task 2: L18 Token 计数边界

- tiktoken 只对匹配 OpenAI 编码精确；Claude 用 `messages.count_tokens`。
- 区分请求前计数、跨厂商估算与响应实际 usage。
- 验证 arXiv 引用和本地 token 数；增加折叠练习。

## Task 3: L19 幻觉因果与检测边界

- 把校准/评估激励改为重要机制而非唯一根因。
- 明确一致不等于正确、RAG 不保证无幻觉。
- 修复 RAG 指向 L20 的错误链接；同步练习和复习区。

## Task 4: L20 Adaptive Thinking 重写

- 分离推理能力、adaptive thinking、effort。
- 当前示例使用 `claude-opus-4-8` + `thinking={"type":"adaptive"}` + `output_config.effort`。
- `budget_tokens` 仅作为旧模型兼容知识；解释 display、计费、max_tokens 和 overthinking。
- 同步全部正文/Quiz/练习/速查卡/总结/大纲并重算时长。

## Task 5: 批次回归与审查

- 运行全部可执行代码和 tiktoken claimed output。
- 检查 HTML/Quiz/链接/Q&A/时长四处一致性与 JS 语法。
- 对完整批次做独立审查，修复所有 Critical/Important 问题。
