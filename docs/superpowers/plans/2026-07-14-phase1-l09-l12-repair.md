### Task 2: 修复 L10 异常、日志与 Tenacity 边界

**Interfaces:**

- Produces: 资源清理/超时/重试分责；只对临时异常重试的可运行 Tenacity 示例。

- [ ] **Step 1: 修正课程定位**

将“上下文管理器保证超时/清理/重试”改为：上下文管理器保证进入/退出和清理机会；超时由客户端/`wait_for`，重试由 Tenacity/SDK 实现。

- [ ] **Step 2: 修正 logging `exc_info=True` 示例**

把 error 日志放进真实异常上下文：

```python
try:
    1 / 0
except ZeroDivisionError:
    logger.exception("LLM 调用失败")
```

说明 `logger.exception` 只应在 except 中使用；无活动异常时 `exc_info=True` 只会显示 `NoneType: None`。

- [ ] **Step 3: 给 `@contextmanager`/`@retry` 最小装饰器前置**

说明 `@name` 会在定义后把函数交给装饰器转换，L11 深讲；当前只需使用标准组件，不把装饰器机制作为本课考点。

- [ ] **Step 4: 补 tenacity 安装**

加入 `uv add tenacity` / `pip install tenacity`，与 L01 环境衔接。

- [ ] **Step 5: 只重试临时异常**

定义教学异常：

```python
class TemporaryAPIError(Exception): pass
class InvalidRequestError(Exception): pass
```

Tenacity 示例：

```python
@retry(
    retry=retry_if_exception_type(TemporaryAPIError),
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=1, max=10),
    reraise=True,
)
```

说明 `stop_after_attempt(3)` 是总尝试3次，最多等待两次；`reraise=True` 耗尽后直接抛最后异常。400/401类确定错误不重试。

- [ ] **Step 6: 运行离线 Tenacity 验证**

临时错误前两次失败第三次成功；InvalidRequestError只调用一次；一直临时失败最终抛原异常而非 RetryError。验证日志 traceback 有真实 ZeroDivisionError。

- [ ] **Step 1: 区分字符、模型 Token、Chunk/Delta**

将练习命名为“逐字符模拟器”，变量 `ch/characters`，统计字段改 `characters`；明确真实 SDK 一次 delta 可能含多个/部分 token，不能用字符数估账单，账单以 usage 为准。

- [ ] **Step 2: 修正迭代器协议**

说明 list/file 是 iterable，`iter(obj)` 返回 iterator；生成器对象同时是 iterable 和 iterator；`next(list)` 报 TypeError，`next(iter(list))` 正常。实跑验证。

- [ ] **Step 3: 修正停止字符消费语义**

说明 for 已从生成器取出停止字符后才 break：停止字符被产出/消费但未追加计数；只有它之后的字符未请求。注释与输出同步。

- [ ] **Step 4: 修正 break/取消/费用保证**

普通生成器 break 停止本地迭代；真实 HTTP/SSE 中 break 不自动保证服务端停止或免计费。必须退出/关闭 stream 上下文或显式取消，并检查 SDK/厂商语义；即使取消也以最终 usage/账单为准。

- [ ] **Step 5: 修正内存结论**

当前 `parts.append` + `join` 仍累计完整回答，空间 O(n)，只是省掉额外 `list(gen)` 中间列表；真正近似常量额外内存需边收边写/显示，不保留全文。思考题 Q2 重写。

- [ ] **Step 6: 加真实 stream 接口边界卡**

承接 L09：原始SSE需解析事件；SDK通常暴露 text delta/chunk；生成器只是Python消费接口，不表示每次 next 发一个新HTTP请求。
