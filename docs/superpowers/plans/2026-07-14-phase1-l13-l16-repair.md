### Task 2: 修复 L14 Pydantic Schema 和安全边界

**Files:**
- Modify: `lessons/0018-L14-pydantic.html`

- [ ] **Step 1: 分离模型 Schema 与厂商工具定义**

说明 `model_json_schema()` 生成参数 JSON Schema，但厂商外层不同：

```python
# OpenAI
{"type":"function","function":{"name":...,"description":...,"parameters": schema}}
# Anthropic
{"name":...,"description":...,"input_schema": schema}
```

练习增加两个 adapter 或只展示对照，不再称 Anthropic 使用 parameters。

- [ ] **Step 2: 说明 Schema 导出不执行 validator**

模型类的 `field_validator` 只在构造 BaseModel 时执行；把 schema 发给模型后，执行工具前仍要：

```python
validated = CalcInput(**raw_args)
result = calculate(validated.expression)
```

Registry/handler 必须保存模型类或验证函数。

- [ ] **Step 3: 移除 import 黑名单的虚假 RCE 保证**

删除“含 import 即可防注入/RCE”的安全结论。将示例改为普通业务校验（例如表达式只允许数字和 `+ - * / . ( )`），但明确字符白名单仍不是通用 Python sandbox，课程示例**不调用 eval**。

可进一步将 CalcInput 改成明确字段：

```python
class CalcInput(BaseModel):
    a: float
    b: float
    operation: Literal["add","subtract","multiply","divide"]
```

执行器用分支，不接收自由 Python 表达式。这是推荐方案。

### Task 3: 修复 L15 AsyncClient 生命周期与 HTTP/SSE 边界

**Files:**
- Modify: `lessons/0019-L15-httpx.html`

- [ ] **Step 1: 共享 AsyncClient**

把单请求函数内部创建客户端改为依赖注入：

```python
async def call(client, prompt):
    r = await client.post("/v1/chat", json={"prompt": prompt})
    r.raise_for_status()
    return r.json()

async def main():
    async with httpx.AsyncClient(base_url="https://api.example.com", timeout=30) as client:
        result = await call(client, "你好")
```

说明批次/应用生命周期创建一个 client，复用连接池；不要在 hot loop 每次创建。

- [ ] **Step 2: 处理异步前置**

429、408/网络、部分5xx通常可重试；400/401通常不可重试，但是否可重试应由异常类型、幂等性和厂商 `Retry-After`/错误码决定，不把全部4xx/5xx绝对化。SDK可能已有自动重试，避免双重叠加。

### Task 4: 修复 L16 协程、限流和重试组合

**Files:**
- Modify: `lessons/0020-L16-async-concurrency.html`

- [ ] **Step 1: 区分协程函数与协程对象**

```python
async def call_llm(...): ...  # coroutine function
coro = call_llm(...)          # coroutine object, body未执行
result = await coro
```

说明 Task 是被事件循环调度的协程包装，基础只建立印象。

- [ ] **Step 2: 收敛 await 语义**

await 等待未完成对象时当前 Task 挂起，事件循环可运行别的任务；若对象已完成，不保证发生任务切换。出现 await 不等于自动并发。

- [ ] **Step 3: 区分并发限制和速率限制**

Semaphore 控制同时在飞数量，保护连接池/并发资源；RPM/TPM 需要令牌桶/时间窗口、Retry-After、厂商限流器。Quiz/思考题/总结同步，不再称 Semaphore 足以避免429。

- [ ] **Step 4: 共享 AsyncClient**

批次 `batch()` 中创建/接收一个 AsyncClient，传给 call_one；真实示例不得每请求创建客户端。可用 MockTransport。

- [ ] **Step 5: 让 Tenacity 看见异常**

结构分层：

```python
@retry(...)
async def request_once(client, prompt):
    # retryable错误向外抛

async def call_one(...):
    try:
        result = await asyncio.wait_for(request_once(...), timeout=...)
        return {"ok": True, ...}
    except Exception as e:
        return {"ok": False, ...}
```

外层捕获在重试耗尽之后；不要先吞异常再装饰。明确 Semaphore 范围选择：若希望退避时释放并发名额，将 semaphore 放在每次 HTTP attempt 内而非整个重试周期外。

- [ ] **Step 6: 运行离线异步验证**

使用 fake_llm/MockTransport 验证协程对象、gather、Semaphore最大并发、批次耗时、共享client；Tenacity若本机无库，复用 L10 已诚实标注的结构静态核对，不伪造实跑。

- [ ] **Step 7: 同步图谱/练习/思考题/面试/总结**

全文清除“async def定义协程”“await必切换”“Semaphore=完整限流”“直接给吞异常call_one加retry”。

- [ ] **Step 8: HTML/Quiz/时长检查**

20分钟若增加明显则25并同步四处。
